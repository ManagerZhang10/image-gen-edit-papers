# 大白话深读《Lumina-DiMOO》

## 1. 30 秒定位

Lumina-DiMOO 是一个开源统一多模态基础模型，由上海 AI 实验室等机构提出，论文发布于 2025 年 10 月 7 日（arXiv:2510.06308）。它的核心特点是：用完全离散扩散（discrete diffusion）建模同时处理文本与图像，而不是像 Chameleon、Lumina-mGPT 那样使用纯自回归（AR），也不是像 BLIP3-o、BAGEL 那样在 AR 后接扩散头。这个选择让它在文本到图像（T2I）、图像到图像（I2I，包括编辑、主题驱动、可控生成、风格迁移等）以及图像理解（MMU）任务上共享同一个 Transformer。论文给出的关键收益是采样效率：文本到图像生成比代表性 AR 模型 Lumina-mGPT 2.0 快约 32 倍：Lumina-mGPT 2.0 在 768 分辨率下耗时 545 秒，而 Lumina-DiMOO 在 1024 分辨率下仅 45 秒；再配合训练无关的 ML-Cache，还能获得约 2.05 倍加速，降至 22 秒。同时，离散扩散的掩码机制天然支持零样本 inpainting 与外推，并催生了“交互式精修”（Interactive Retouching）。在 GenEval、DPG、UniGenBench 等基准上，Lumina-DiMOO 超过多个开源统一模型，其中 GenEval 总体 88%，加 Self-GRPO 后 91%。需要注意，论文中“SOTA”是限定在开源统一多模态模型范围内的，并非对所有生成模型的全口径优势：例如在 TIIF 基准上，FLUX.1 [dev] 以 71.47 仍高于 Lumina-DiMOO 的 70.90。

## 2. 为什么这篇论文会出现

这篇论文要解决的是统一多模态生成与理解中“架构不统一”和“速度慢”两个长期问题。早期纯 AR 统一模型（如 Chameleon、Lumina-mGPT）用 next-token prediction 一次性建模文本和图像，训练接口简单，但推理时必须按光栅顺序逐 token 解码。论文 Figure 12(a) 给出直接证据：Emu3-Gen 生成图像耗时 710 秒，Lumina-mGPT 2.0 需要 545 秒，这种分钟级延迟严重破坏用户体验。同时，纯 AR 模型的图像生成质量也不理想：Chameleon 的 GenEval 总体只有 39%。为了提升质量，MetaQueries、BLIP3-o 等模型在 AR 之后加一个连续扩散头来解码图像，BLIP3-o 在 GenEval 上达到 80%，但这样又破坏了“单一模型、单一目标”的统一性，训练和推理链路里出现两套机制。Show-o（1.3B 参数）尝试在同一个 Transformer 中结合 AR 与离散扩散，让文本用 AR、图像用离散扩散，但其 GenEval 仅 53%、MMMU 仅 26.7%，说明文本侧并未充分利用离散扩散，整体探索不够彻底。

与此同时，文本侧的离散扩散大语言模型（dLLM）在 LLaDA 等工作之后开始成熟。LLaDA 用掩码扩散训练 8B 参数模型，在文本理解上接近 LLaMA3 8B，说明离散扩散可以支撑大规模语言建模。并发工作 MMaDA 首次在统一生成与理解任务上验证了纯离散扩散的可行性，但 MMaDA 只支持固定 512×512 分辨率（Figure 6 明确标注），下游生成任务覆盖有限，GenEval 仅 63%、DPG 仅 69.97、MMMU 仅 30.2，性能明显落后。于是作者认为，时机已经成熟：可以用 LLaDA 作为文本底座，扩展视觉词表，建立一个真正单一离散扩散框架的多模态模型，同时解决速度、质量和任务覆盖问题。论文的定位就是“开源、统一、高速、多功能”的离散扩散基础模型，其架构演进脉络在 Figure 2 中总结为三条路线：纯 AR → AR+离散扩散 → 纯离散扩散。

## 3. 读懂前需要的最小概念

离散扩散（discrete diffusion）与连续扩散不同，它作用在有限类别词表上，而不是高斯噪声。本文采用的掩码扩散（masked diffusion）是其中最简单的一种：前向过程随机把一些 token 替换成特殊 [MASK]，反向过程让模型并行预测被掩码位置的原 token。这跟 BERT 的完形填空类似，但 BERT 只做一次预测，而扩散模型会迭代多次，每次重新掩码部分低置信度 token，逐步逼近干净序列。因为模型能看到所有未掩码位置，所以使用双向注意力（Bidirectional Attention），这带来并行解码和灵活的生成顺序，但也导致不能像 AR 那样用 KV-Cache 无损复用历史键值。论文 Section 2 指出，掩码扩散已成为离散扩散的“de facto standard”（事实标准），因为它简单且有效，类似 BERT 的前向过程。

图像 tokenizer 把连续图像变成离散 token 序列。本文使用 aMUSEd-VQ，采用 16×16 下采样，每张 1024×1024 图像约对应 4096 个 image token（论文在 Self-GRPO 部分写明长度 L=4096）。其视觉词表大小是 8,192。对比之下，SBER-MoVQGAN 是 8×8 下采样，高分辨率时 token 数量会多很多，计算更贵；作者也探索过 Chameleon-VQ 和 Open-MAGVIT2，前者重建质量略差，后者重建好但 token 格式与建模需求不对齐（Section 3.1）。aMUSEd-VQ 的缺点是缺乏图像语义信息，作者通过扩大理解数据规模来弥补（Section 3.1 末尾明确说明）。1024×1024 图像在 16×16 下采样下产生 64×64=4096 个 token，每个 token 来自 8,192 大小的视觉码本。

统一词表是 Lumina-DiMOO 的基础：LLaDA 原有 126,345 个文本 token，加上 8,192 个视觉 token，再加上 <IMAGE>、</IMAGE>、<end-of-line> 等特殊 token，模型在所有模态上用一个 softmax 输出。另一个关键概念是任意分辨率表示：因为 LLaDA 使用 1D RoPE，不同宽高比的图像展平后长度相同会丢失结构信息。作者在每行图像 token 后插入 <end-of-line>，让 1D 序列能恢复 2D 布局，无需重新设计位置编码。对比之下，MMaDA 因共享相同架构却只处理固定 512×512 分辨率。

分类器无关引导（CFG）是图像生成中的常见策略，通过在训练时引入 <uncondition> token 并在推理时做有/无条件输出的插值，增强条件遵循能力。Self-GRPO 是本文提出的强化学习阶段，它把 T2I 生成和 MMU 理解放在同一个 GRPO 风格的轨迹一致目标里，用生成图像回答选择题的正确数作为奖励。

## 4. 方法全景：先看数据流

下图先给出训练和两种推理的简化数据流。训练时文本与图像统一进入同一个序列，随机掩码后让双向 Transformer 预测被掩码 token；T2I 推理时图像 token 从全掩码开始，循环预测-采样-重掩码；MMU 推理时答案 token 分块生成。

```
训练：
text tokens + image tokens
        |
   [随机 mask 文本和图像占比 m]
        |
Lumina-DiMOO (双向注意力, LLaDA初始化)
        |
  预测被掩码位置的原始 token
        |
   cross-entropy loss

T2I 推理：
text prompt -> text tokenizer
        |
  text tokens + [全部 image tokens 置为 [MASK]]
        |
循环 T 步: 预测 -> 限制到视觉词表 -> 采样最高概率 -> 按余弦调度重掩码低置信 token
        |
  最终 image token 序列 -> aMUSEd-VQ decoder -> 图像

MMU 推理：
image + question -> tokenizer -> 混合序列
        |
  答案文本块从 [MASK] 开始
        |
  块内并行预测，块间顺序解码；检测到 </answer> 则早停
        |
  text decoder -> 回答
```

核心组件有五块，下面逐一拆解其输入、输出、目的与假设。

第一，图像 tokenizer（aMUSEd-VQ）：输入是连续图像，输出是离散 token 序列及其反变换。目的是在尽量少 token 的情况下保持重建质量，假设是 16×16 下采样能平衡分辨率与计算成本。其视觉词表大小 8,192，1024×1024 图像对应 4096 token。不足是语义信息弱，需要通过数据规模弥补。

第二，统一离散扩散骨干：以 LLaDA-Base 为初始化，论文明确写明“without any structural modifications”（无任何结构修改）。输入是混合 token 序列（文本 token + 视觉 token + 特殊 token），输出是每个被掩码位置在整个联合词表上的 logits。其目的是提供跨模态的填空能力，假设是预训练 dLLM 的文本语义理解和生成能力能作为多模态训练的起点。只有新引入的视觉 token 和特殊 token 的嵌入与输出头需要从头训练（Section 3.2 明确说明）。

第三，特殊 token 系统（Table 1）：用 <IMAGE> 和 </IMAGE> 框定图像边界；用 <canny>、</canny>、<depth>、</depth>、<openpose>、</openpose>、<hed>、</hed> 分别标识不同控制图（Canny 边缘图、深度图、骨架图、HED 边缘图）；用 <system>、</system>、<user>、</user>、<answer>、</answer> 区分系统提示、用户指令和模型回答；用 <end-of-line> 保留任意分辨率的行结构；用 <uncondition> 支持 CFG。目的是让同一模型兼顾 T2I、I2I、MMU、可控生成等任务，假设是特殊 token 作为任务路由和边界标记足够有效。需要注意的是，<end-of-line> 只插入在每行图像 token 之后，而 <IMAGE> 与 </IMAGE> 作为图像边界标记；这些特殊 token 与 LLaDA 原始词表里的 <|startoftext|> 和 <|endoftext|> 并存，训练时在文本部分使用后者，图像部分使用前者。

第四，采样调度器：T2I 使用余弦掩码调度（公式 4）划分阶段，MMU 使用半自回归块采样（block-wise）。目的是在解码质量和计算开销间做权衡，假设是 MaskGIT 式“先粗后细”策略适用于统一离散扩散。T2I 总步数 64，分为四个阶段（Section 3.3.1 明确说明“partition the image generation process into four stages”），MMU 块长 256、总步数 128（Section 7.1 明确设定）。

第五，ML-Cache：在推理中根据最大 logit 选择高置信 token 复用前一步的表示。输入是上一步每个 token 的最大 logit 和 K/V 表示，输出是减少后的待计算 token 子集及复用后的完整 K/V。其目的是降低单步双向注意力的计算成本，假设是“高 max logit 的 token 其隐表示跨步稳定”。Figure 4 展示了一个例子：top 94% 最大 logit 的 token 与上一步的余弦相似度超过 0.99。该方法需要设置 cache_ratio、warmup_ratio、refresh_interval 三个超参数，但论文未披露具体数值。

方法的关键假设是：文本与图像可以在同一个离散 token 空间中被统一建模，且掩码扩散中的预测-采样-重掩码循环能在有限步内产出高质量图像和文本。

## 5. 核心公式与直觉

公式（1）定义掩码构造。给定混合文本-图像序列 x=(x₁,...,x_L)，从 {1,...,L} 中采样掩码集合 ℳ，其大小是 ⌊L×m⌋，其中 m∈(0,1] 是掩码比例。被选中的位置替换为 [MASK]，其余保留：

```
~x_i = [MASK]   if i∈ℳ
       x_i       otherwise
```

这个公式直觉上就是“随机遮住一部分，让模型填空”。工程上，训练时 m 是随机采样，这让模型既见过少量掩码，也见过大量掩码，推理时可以根据不同任务设定不同掩码量。论文没有给出训练时 m 的具体分布，但 Stage-III 中提到只掩码 answer 部分，说明 m 在 SFT 阶段作用于答案序列。

公式（2）定义模型如何对掩码位置预测原 token 的分解：

```
p_θ( ~x_ℳ | ~x_{ℳ^c}, c ) = ∏_{i∈ℳ} p_θ( ~x_i | ~x_{ℳ^c}, c )
```

其中 ~x_{ℳ^c} 表示未掩码上下文，c 是可选条件（如文本提示）。直觉上，模型假设被掩码位置之间在给定未掩码上下文和条件时是条件独立的，因此可以并行预测。这一分解是并行解码的理论基础。工程上，模型一次前向就能同时输出所有被掩码位置的 logits。

公式（3）给出训练损失：

```
L(θ) = E_{x,m,ℳ} [ - Σ_{i∈ℳ} log p_θ( x_i | ~x_{ℳ^c}, c ) ]
```

其中期望在数据分布、掩码比例 m 和掩码集合 ℳ 上取。优化动作是最大化被掩码 token 的条件似然，等价于最小化 masked cross-entropy。这个损失同时应用到文本和图像位置，让模型学习跨模态填空：可以看图补文，也可以看文补图，这是理解与生成统一的数学基础。在训练实现中，只在被掩码位置计算 loss，未掩码位置不贡献梯度。

公式（4）是图像推理的余弦掩码调度。设 T 为总解码步数，L'_t 为第 t 步已解码图像 token 中还需要重掩码的数量：

```
k_t = ⌈ cos( π t / (2T) ) · L'_t ⌉
```

直觉是：早期 t 小，cos 值接近 1，重掩码比例高，只有最高置信的 token 被保留；随着 t 增大，重掩码比例降低，最终全部 token 被确定。这个调度类似 MaskGIT，控制“先粗后细”的解码节奏。工程上 T 设为 64（Figure 12 上下文），分四阶段，每阶段分别处理不同比例的 token，具体比例未在论文中披露。

公式（5）是 Self-GRPO 的目标：

```
L(θ) = - Σ_{g=1}^{G} w^(g) ( ℓ^(g)_T2I + ℓ^(g)_MMU ) + β KL( p_θ ‖ p_ref )
```

其中 g 索引 G 个候选图像样本，w^(g) 是奖励加权，由公式（6）softmax 归一化得到。ℓ^(g)_T2I 是所选时间步上图像 token 的对数似然平均（公式 7），ℓ^(g)_MMU 是基于生成图像回答 N 个问题的平均对数似然（公式 8）。优化动作是提升高奖励样本的生成与理解联合似然，同时用 KL 项防止策略离参考模型太远。工程对应：只保留当前策略采样轨迹，在选定时间步 T_sel 上计算梯度，减少显存。公式（7）中图像序列长度 L=4096（1024×1024），ℓ^(g)_MMU 基于 N 个选择题生成答案的条件对数似然；β 是 KL 系数，G 是候选图像数，N 是每张图的问题数，α 是温度，这些超参数数值均未在论文中给出。

## 6. 训练到底怎么跑

训练分四个阶段，每阶段目标和数据配置不同，但底层都是掩码扩散损失。论文 Table 2 给出超参数：Stage-I/II 学习率 2e-4，AdamW β=(0.9,0.95)，64×A800；Stage-III 学习率 2e-5，仍然 64×A800；Stage-IV 学习率 3e-6，AdamW β=(0.9,0.99)，仅 8×H20。所有阶段权重衰减 0.1，梯度范数裁剪 1.0，学习率调度器全程使用 Constant。值得注意的是 Stage-IV 优化器 β₂ 从 0.95 改为 0.99，论文未解释原因，但通常是为了提高二阶矩估计的稳定性。Batch Size：Stage-I 为 1024，Stage-II/III 为 512，Stage-IV 仅 48。

Stage-I 是多模态预训练，目标是让 LLaDA 从纯文本模型过渡到图文对齐。数据约 80M 图文对：30M 来自 LAION-400M 和 CC12M 重标注，用于理解；50M 来自 Lumina-Image 2.0 和 Lumina-mGPT 2.0，用于生成。一个训练 step 的格式是：<|startoftext|> 文本 token <|endoftext|> <|IMAGE|> 图像 token <|/IMAGE|>。然后随机掩码文本和图像中一定比例 token（红区表示可被掩码的区域），模型并行预测这些位置，计算 CE loss。这个阶段用任意分辨率，生成和理解分辨率都从 256 渐进到 512（Table 2）。“约 256×256 对应约 256 token”这个数字说明 256 分辨率下每张图约 256 个 token，512 分辨率下约 1024 token。作者提到“红区表示可被掩码的区域”，但没有在草稿中体现；实际上训练时只对序列中的一部分 token 进行掩码，而不是全部，因为未掩码 token 提供上下文。

Stage-II 是 mid-training，引入多样化 I2I 任务和复杂视觉理解，如表格、图表、UI、数学几何。数据约 3M 图像，来自 MMTable（表格）、TinyChart（图表）、AutoGeo（几何）、MAVIS（数学）、MultiUI（用户界面）等，用 Qwen2.5-VL 打标。I2I 数据来源包括 UltraEdit、OmniEdit、OminiControl 和 Lumina-mGPT 2.0。与 Stage-I 不同，此阶段只对目标任务计算 loss：T2I/I2I 只算目标图像 token，MMU 只算目标文本 token。因为 I2I 要处理两张以上图，序列更长，I2I 分辨率设为 512，T2I 用 1024，MMU 用动态分辨率：保持原分辨率在 512~1024 之间，超过 1024 的降到 1024，低于 512 的升到 512（Section 4.2 明确说明）。这种动态分辨率在 Table 2 中标注为 “Dynamical & Native”。

Stage-III 是监督微调，目标是对齐用户指令和提升质量。数据分理解和生成各 15M。理解部分来自 2M MAmmoTH-VL 和 13M InternVL-2.5-SFT 数据集；生成部分来自 Lumina-Image 2.0 精选（只选最高质量数据）、Blip3o-60k、ShareGPT-4o-Image 及内部合成数据。I2I 则加入 VisualCloze 的 subject-driven、controllable、dense prediction、style transfer 各 200K，UniWorld 的 500K 图像编辑，Lumina-OmniLV 的 200K low-level 任务（超分、去雾、去噪等），以及多视图数据。训练时 system prompt 和 user prompt 不被掩码，只有 answer 部分被掩码并计算 loss（Section 4.3 明确说明）。一个关键失败模式是：论文明确承认 Lumina-DiMOO 在 low-level vision 任务上表现差（Section 5 末尾），但未分析原因。

Stage-IV 是 Self-GRPO，只用文本 prompt 数据，来自 GenRef 子集（Section 5 明确说明）。每个 prompt 用 DSG（Davidsonian Scene Graph）方法抽取 (entity, relation, value) 三元组，构造单选题。为了生成干扰选项，维护全局候选池，为实体、关系、数量、颜色分别选取语义上接近正确答案的干扰项。一个强化学习 step 是：采样 G 个候选图像，对每个图像回答 N 个问题，按正确数定义奖励，加权联合 T2I 和 MMU 负对数似然，再加 KL 项。为了省显存，不维护旧策略模型（跟随 UniRL 的做法），只保留当前策略采样轨迹，在选定时间步 T_sel 上算梯度。梯度计算只基于 T_sel 中选定的时间步，这些时间步的输出会被用来计算公式（7）的 T2I log-likelihood 平均。论文没有给出 G、N、β、α 的具体数值。

## 7. 推理到底怎么跑

T2I 推理从“文本 token + 全掩码图像 token”开始，没有图像内容。Lumina-DiMOO 把要生成的全部图像 token（不包括 <end-of-line>）当作一个整体生成块，而不是逐行或逐块 AR 解码。总步数 T 通常设为 64（Figure 12 上下文 64 sampling steps）。每步执行四件事：第一，预测所有当前被掩码图像 token 的概率分布，输出维度是 L'_t × K，其中 L'_t 是当前被掩码图像 token 数，K 是整个联合词表大小；第二，把概率限制在 8,192 个视觉 token 的词汇表内，每个位置取最大概率 token 并以其概率作为 confidence，已解码 token 的 confidence 设为 -∞，防止它们参与重掩码；第三，用余弦调度公式（4）计算本步需要重掩码的 token 数 k_t；第四，按 confidence 选择最低的 k_t 个 token 重掩码。这个过程循环到 T 步结束，所有图像 token 确定，再交给 aMUSEd-VQ decoder 得到图像。推理中使用了无分类器引导（CFG，通过 <uncondition> token 实现），并支持任意分辨率，因为图像 token 序列带 <end-of-line> 分隔符。

MMU 推理处理的是图像+问题，输出文本答案。它不采用全局并行掩码，而是采用半自回归块采样（block-wise parallel sampling）。答案序列开始时全部为 [MASK]，划分为多个块。块内 token 并行预测，块间按顺序解码。论文设置 block length 为 256，总采样步数 128。这种设计能丰富输出细节（如 MMaDA 所示），但对生成长度和步数敏感。在极端情况下，如果每步只预测两个 token，半自回归过程就退化为标准逐 token 预测。为了减少冗余，如果当前块完成后检测到 </answer>，就立即停止。这与 T2I 的全局并行不同，因此 MMU 的速度提升不如 T2I 明显：Figure 12(b) 中 Lumina-DiMOO 约 31.7s，加 ML-Cache 后 17s，而 BAGEL 47.1s，Emu3-Chat 33.7s。MMU 速度优势较小，因为文本生成受块数和步数双重影响，而图像生成是一个全局解码块。

ML-Cache 是训练无关的加速策略，可用于两类推理。每步计算前，根据上一步最大 logit 选择一定比例（cache_ratio）的高置信 token，直接复用其前一步的 K/V 表示和 logits，只把剩余 token 送入网络。为避免早期上下文差导致误差，前 warmup_ratio 比例步全部计算；每 refresh_interval 步也全量计算一次。论文没有披露这三个超参数的具体数值，但报告 T2I 加 ML-Cache 后从 45s 降到 22s，约 2.05 倍加速；MMU 从 31.7s 降到 17s，约 1.87 倍加速，但显存从 38.9 GB 升到 45.9 GB（Section 7.1 明确说明）。Figure 4 展示了一个实验例子：logits 中 top 94% 最大 logit 的 token 与上一步的余弦相似度超过 0.99，说明高置信 token 的表示确实稳定，是 ML-Cache 有效性的经验支撑。需要注意的是，ML-Cache 只跳过前向计算中某些 token 的键值更新，但双向注意力仍然需要完整的 K/V 序列，因此显存反而增加。

消融部分有两个关键实验。第一个是 LLaDA 初始化（Section 7.2）。论文设计了两组对照：一组用 LLaDA-SFT 初始化，一组从头训练。为保证公平，从 Stage-III 数据（Section 5）中随机选 5M 生成样本和 5M 理解样本，跳过预训练，直接在 256 分辨率 SFT，所有训练和评估参数保持不变，只改初始化。结果显示，从头训练模型连基本的图像生成或理解都无法有效完成，训练中还出现非常大的梯度范数；而 LLaDA 初始化能正常支持两类任务。这证明在离散扩散多模态训练中，强大的文本底座不仅能降低训练资源，还在稳定性和收敛上起关键作用。注意论文没有给出从头训练的具体指标数值，只做了定性描述，说明从头训练的结果“falls short in generating images or performing image understanding”（无法有效完成生成或理解），因此不需要定量比较。

第二个是 ML-Cache。在相同设置下，加 ML-Cache 使 T2I 生成时间从 45s 降到 22s（2.05 倍），MMU 从 31.7s 降到 17s（1.87 倍）。但论文也指出它是有损近似，会增加 GPU 显存（从 38.9 GB 到 45.9 GB，Section 7.1 明确说明），并未报告加 ML-Cache 后生成质量或理解分数的定量变化，因此质量损失大小未知。

尚未证明的主张包括：第一，ML-Cache 是否几乎无损地保持生成质量，论文只给了 logits 余弦相似度（Figure 4）和时间收益，没有 GenEval 等指标对照；第二，Self-GRPO 的收益只体现在 GenEval 的 +3%，没有在其他 T2I 或 MMU 基准上复测；第三，论文承认 low-level vision 任务表现差（Section 5 末尾），但没有深入分析原因；第四，视频、音频等模态扩展仍停留在 future work（Section 8），没有实验证据；第五，交互式精修（Figure 13）虽然展示样例，但没有定量评估“保持未标注区域不变”的能力。

## 9. 与前作怎么选

最接近的方案是 MMaDA。两者都是 8B 纯离散扩散统一模型，都用 LLaDA 初始化。但 MMaDA 只支持固定 512×512，生成覆盖窄，GenEval 63%、DPG 69.97、MMMU 30.2，明显弱于 Lumina-DiMOO。选择 MMaDA 的场景非常有限：如果你只需要研究极简的离散扩散多模态基线，且分辨率固定在 512，可能作为参考实现更轻便；否则在论文报告范围内没有理由优先选 MMaDA。

BAGEL 是 AR+Diff 混合模型，14B 参数，在部分 MMU 指标上更强（MME-P 1687.0 vs DiMOO 1534.2），但在 GenEval 82%、DPG 85.07、UniGenBench 61.53 上都低于 Lumina-DiMOO，且不是纯离散扩散，缺乏统一掩码带来的零样本 inpainting 灵活性。如果你主要做图像理解、需要更强 MME-P 且不介意混合架构，BAGEL 可以选；如果同时需要生成、任意分辨率、交互式精修，Lumina-DiMOO 更合适。

Janus-Pro 是 7B 纯 AR 统一模型，GenEval 80%、MMMU 41.0%，速度和生成质量都不如 DiMOO，且 Janus-Pro 固定 768×768（Figure 6 明确标注）。BLIP3-o 是 8B AR+Diff 模型，理解部分如 MMB 83.5、SEED 77.5 和 MME-P 1682.6 有竞争力，但生成综合不如，且需要外部扩散解码器。OmniGen/OmniGen2 是连续扩散路线，OmniGen2 的 UniGenBench 63.09、DPG 83.57，弱于 DiMOO；OmniGen 在部分 I2I 任务上有可用性，但缺乏统一离散 token 空间。

因此选 Lumina-DiMOO 的典型条件：你要一个单一离散 Transformer 同时做生成和理解；需要快速并行图像生成（尤其图生成比 AR 快 32 倍）；需要任意分辨率输出；需要零样本 inpainting 或交互式编辑；希望开源可复现。不选的典型条件：你只追求纯理解且非常看重 MME-P，或只追求低层视觉增强，或希望用连续扩散模型实现极致图像质量，或你的任务需要逐 token 自回归的确定性和 KV-Cache 效率。

## 10. 工程判断：可行性、风险与上限

从数据看，Lumina-DiMOO 依赖大量现有公开数据和内部合成数据，Stage-I 约 80M，Stage-III 约 30M 多模态指令（理解 15M + 生成 15M，I2I 另有约 1M）。论文没有披露数据清洗、去重、过滤细节，复现时最大的不确定性在数据配方而非模型代码。不同数据源之间质量差异很大，例如 Stage-III 生成数据只有 Lumina-Image 2.0 经过精选，Blip3o-60k 和 ShareGPT-4o-Image 的标注质量可能参差。算力方面，Stage-I/II/III 各用 64×A800，Stage-IV 用 8×H20，单卡显存压力在 Self-GRPO 和高分辨率 1024×1024 时显著。T2I 推理 1024×1024 加 ML-Cache 显存从 38.9 GB 升到 45.9 GB，说明 ML-Cache 不是零成本。此外，Batch Size 在 Stage-IV 骤降到 48（Table 2），说明强化学习阶段对显存的要求更高，单步训练代价大。

实现难点有三处。一是任意分辨率需要正确插入 <end-of-line>，如果数据预处理中行分隔符位置错误，解码后图像会出现几何错乱。二是 Self-GRPO 的轨迹一致性：因为图像生成是多步采样+重掩码，必须在保存完整采样轨迹的前提下只对选定时间步计算梯度，否则梯度会明显偏离真实采样路径。论文提到 T2I 中主要内容可以在早期时间步生成（引用 MaskGIT），因此只在 T_sel 选中时间步算梯度，但如何选择 T_sel 未披露细节。三是 ML-Cache 的近似误差：高 max logit 只表示 token 置信度高，不代表隐状态完全稳定；如果 warmup_ratio 或 refresh_interval 设置太激进，大概率出现生成质量下降。另外，ML-Cache 虽减少了前向计算 token 数，但 K/V 序列长度不变，显存反而增加（38.9→45.9 GB），实际加速比受 cache_ratio 和硬件带宽限制。

可能的失败环节：低层视觉任务（超分、去雾、去噪等）论文已明确表现差；目标移除和风格编辑在 ImgEdit 上分数不高（Remove 2.76 vs UniWorld-V1 3.24，Style 4.18 vs BAGEL 4.49）；MMU 中 MME-P 未达到专用混合模型 BLIP3-o/BAGEL 的水平；ML-Cache 在质量上的损失未量化；Self-GRPO 只在 GenEval 上验证，扩展性存疑。监控信号应至少包括：masked cross-entropy 是否稳定下降、梯度范数是否突然增大（从头训练时会出现，Section 7.2 明确提到）、GenEval 分项、推理时间、GPU 显存占用、以及 ML-Cache 开启/关闭时的输出差异。特别地，如果采用 ML-Cache，应该对比同一批 prompt 在开启/关闭下的图像质量和文本一致性分数（如 CLIP-Score、GenEval），而不是只看时间收益。

指标上限方面，论文展示的是开源统一模型范围内的领先，而不是对所有生成模型的压倒性优势。在 TIIF 上，FLUX.1 [dev] 的 71.47 仍高于 Lumina-DiMOO 的 70.90。在 MME-P 上，BLIP3-o 的 1682.6 和 BAGEL 的 1687.0 都高于 Lumina-DiMOO 的 1534.2。更重要的是，论文未回答：当扩展到视频、音频时，aMUSEd-VQ 这类图像 tokenizer 无法复用，需要重新设计多模态 tokenizer；序列长度会剧烈膨胀，64 步并行扩散是否仍高效；交互式精修在真实用户场景下能否稳定保持未标注区域一致，目前只有定性样例（Figure 13）。此外，Self-GRPO 目前只用了选择题形式的奖励，是否能迁移到开放式生成和复杂推理场景尚未验证。

## 11. 放回研究脉络并收束

统一多模态模型的架构演进大致是：早期纯 AR（Chameleon、Emu3、Lumina-mGPT）追求简洁，但受困于光栅顺序生成质量与速度；随后 AR+连续扩散头（MetaQueries、BLIP3-o、BAGEL）用外部扩散解码器提升图像质量，却破坏单一优化目标；Show-o 尝试 AR+离散扩散混合，但文本侧没有真正拥抱离散扩散。LLaDA 等文本 dLLM 的出现证明离散扩散可以规模化，MMaDA 初步把这一思路拓展到多模态，但性能不足。Lumina-DiMOO 站在这个节点上，用 LLaDA 底座、aMUSEd-VQ 视觉词表、任意分辨率、ML-Cache 和 Self-GRPO，把纯离散扩散统一模型推到了开源统一模型中的领先位置。

读完必须记住的 5 件事：

1. Lumina-DiMOO 用完全离散扩散统一文本和图像，训练时统一做 masked cross-entropy（公式 3），推理时图像全局并行（T2I 四步循环）、文本分块半自回归（MMU 块长 256），两者共享同一个双向 Transformer 和联合词表。
2. 它的图像 tokenizer 是 aMUSEd-VQ，16×16 下采样，8,192 个视觉 token；1024×1024 图像对应 4096 个 image token；用 <end-of-line> 实现任意分辨率，不改变 LLaDA 原有 1D RoPE。
3. T2I 采样遵循 MaskGIT 式四步循环：预测、限制视觉词表、按最高概率采样、余弦调度重掩码低置信 token；总步数 T=64，分四阶段；推理顺序是整体生成块，而非逐行 AR。
4. ML-Cache 用最大 logit 作为置信度代理，复用高稳定 token 的 K/V 和 logits，T2I 约 2.05 倍加速、MMU 约 1.87 倍加速，但有损且增显存（38.9→45.9 GB）；它依赖 cache_ratio、warmup_ratio、refresh_interval 三个未披露数值的超参数。
5. Self-GRPO 把 T2I 与 MMU 放在同一轨迹一致强化学习目标中（公式 5），用生成图像上选择题正确数做奖励（公式 6），只对选中时间步算梯度（公式 7）；LLaDA 初始化消融证明从头训练无法正常收敛，文本底座不可或缺。

5 道自测题：

1. 为什么纯 AR 统一模型生成速度慢，Lumina-DiMOO 的离散扩散怎么从机制上缓解这一点？请结合公式（4）的余弦调度和整体图像生成块解释。
2. <end-of-line> token 解决的问题是什么？如果去掉它，任意分辨率生成会怎样？MMaDA 为什么无法做到？
3. T2I 推理中为什么要把预测概率限制到 8,192 个视觉 token 而不是全词表？confidence 的作用是什么？已解码 token 的 confidence 为什么设为 -∞？
4. ML-Cache 为什么不能直接照搬 AR 的 KV-Cache？论文用什么信号选择可复用 token？为什么显存反而增加？
5. Self-GRPO 的奖励来自哪里？公式（5）中的 ℓ_T2I 和 ℓ_MMU 分别衡量什么？轨迹一致性为什么重要？论文如何降低 RL 阶段的显存压力？

最终一句话总结：Lumina-DiMOO 通过“LLaDA 文本底座 + 统一离散扩散 + 任意分辨率图像 token 化 + 有损缓存加速 + 生成理解联合强化学习”，在开源统一多模态模型中验证了纯离散扩散路线在速度、覆盖和性能上的可行性，但低层视觉、部分 MMU 指标、视频音频扩展和 ML-Cache 质量损失仍是明确的上限问题。
