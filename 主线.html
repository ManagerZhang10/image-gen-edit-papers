2022–2023 全部精力在「怎么改图」，2024 下沉到骨干和数据，2025 之后上移到「什么算改对了」。 主线不是模型变大，而是 控制权一层层往上挪——最后卡在没人能可靠判断一次编辑到底对不对。

先破一个误解

4 组对照

最容易想当然的一个认知错误：只要把图像、指令和文本一起交给更大的统一多模态模型，编辑一致性和评估可靠性就会自动变好。

你以为实际
统一序列把源图、文本、目标图放在一起，未编辑区域自然保持不变 统一序列仍出现条件泄漏和像素漂移。InternVL-U 必须把理解特征与 VAE 潜变量解耦；Qwen-Image-Layered 要输出多层 RGBA 才能显式隔离编辑区域
用更大的 VLM / 奖励模型当裁判，评估与 RL 更可靠 EdiVal-Agent 换 OWL-ViT 后人类一致率从 81.3% 跌到 53.67%；banana100 里传统 NR-IQA 给后轮退化图更好或同等分数；T2I-R1 的单一 VQA 奖励会被策略 hack
合成编辑数据越多，下游模型越好 NoHumansRequired 的基准提升仅 +0.03 且置信区间重叠；OpenGPT-4o-Image 数据从 30k 扩到 40k 已经出现回退
强化学习进入生成轨迹后，推理编辑任务会稳定提升 reward hacking 只能缓解不能根除，多篇只能靠提前停止、正则或选早 checkpoint 规避；DanceGRPO 只用 HPS 会产出油腻图像

这些失败指向同一件事：把「更大 / 更统一」当成路线本身，会掩盖真正的瓶颈——细粒度跨图比较、局部信用分配、表示解耦。模型规模没有解决编辑里「局部保持 ↔ 语义对齐」的矛盾，只是把问题转移到了奖励设计、评测锚点和数据验证上。

01

六个转折点

主线

哪些算转折是判断题，不是算出来的。这里的标准是「之后大部分工作都改了做法」，而不是「这篇有影响力」——所以只有六条，很多更有名的工作没进来。

2022 H2

控制权从外部掩码搬进模型内部的注意力

触发 · Prompt-to-Prompt
之前

SDEdit 加噪重绘、Blended-Latent-Diffusion 在潜空间按掩码混合——编辑区域必须由外部 mask 指定。

之后

注入或引导交叉注意力图。换词、加短语这类语义编辑，不再绑定像素级掩码。

2022 H2 – 2023 H1

指令编辑从单图反演变成可训练的双条件扩散

触发 · InstructPix2Pix
之前

缺可扩展的成对监督，真实图编辑多是 per-image inversion 或注意力注入。

之后

GPT-3 生成指令 + Stable Diffusion / Prompt-to-Prompt 合成配对图，训练双条件潜扩散。MagicBrush、HIVE、HQ-Edit、UltraEdit 全部沿用并改进这套数据与条件范式。

⚠ 六条里证据最薄的一条。素材对指令线明确的后续转折是「真实数据 + MLLM 编码器替代」；把 IP2P 本身列为全局转折，主要靠后续多篇沿用它的范式，而不是素材直说。

2023 H2

显式反演可以被绕开

触发 · InfEdit 的 DDCM 虚拟反演
之前

真实图编辑先做 DDIM 反演，或用 Null-text Inversion 逐步优化空文本嵌入——单图 40–120 秒。

之后

用特殊方差参数让去噪退化成一致性采样，完全跳过显式反演。ReNoise、TurboEdit 等少步模型直接适配，速度进到数秒甚至亚秒。

2024 H1

骨干从 UNet cross-attention 转向 MM-DiT 的 token 共享注意力

触发 · SD3-RectifiedFlow
之前

ControlNet / IP-Adapter 用特征加法或独立 cross-attention 注入条件，受 UNet 架构限制。

之后

FLUX-Kontext 的序列拼接、Qwen-Image 的双编码，把参考图和文本直接放进同一序列。生成与编辑统一到同一个 token 化底座。

2025 H1

推理步骤本身成为可训练的策略

触发 · Flow-GRPO、DanceGRPO
之前

GoT 等只把显式推理链当成静态文本条件，喂给扩散模型。

之后

用 SDE 给确定性 ODE / 流匹配采样注入随机探索，GRPO 组内优势训练生成模型。T2I-R1、Meta-CoT 把规划和生成步骤本身当作策略来优化。

2025 H2 – 2026 H1

评估器自己被证明不可信

触发 · EdiVal-Agent、banana100
之前

用整图 VLM 开放打分，或传统 NR-IQA 指标度量编辑质量。

之后

引入检测框 ROI 二值判断、HDR 开/关灯真值、场景图事实网格这类可验证锚点，把「真伪」和「好不好」分开测量。

这条不是前五条直接触发的。是上游方法大量产出「看起来对」的结果之后，评测端自己暴露出检测器可替换、NR-IQA 会给反向分数的问题。

02

谁站在谁肩上

四层结构

十五条脉络不是并列的十五个话题，是四层。越靠上的层越晚成熟，也越是现在的主战场。

2022 – 2023

怎么改图。注意力控制、反演精度、条件注入、局部编辑，全在中间层打。

2024

下沉。骨干换成 MM-DiT，数据线开始工业化，编辑方法反而没有大动作。

2025 之后

上移。奖励模型和评测成主战场——因为方法已经能产出「看起来对」的结果了。

01训练-free 扩散编辑：靠注意力和反演改图14 篇
2021-08 ~ 2026-03　·　C 编辑方法本体

不训练、不微调预训练扩散模型，编辑信号只能从模型内部的注意力图、中间特征或反演轨迹里借。这些信号本来就不是为编辑优化的。

转折点 · 卡在哪 · 论文
转折点

Prompt-to-Prompt——交叉注意力图已经编码了词与像素的空间绑定，控制权可以从外部掩码搬进模型内部表示。此后大多数方法都围绕注意力图的注入、引导或跨图混合展开。

还没解决的

注意力图分辨率受 U-Net 瓶颈限制，编不了精细纹理和像素级边界；空间移动、计数、未见姿态直接失败——方法超不过基座能力。

03指令式编辑：说人话改图，以及数据从哪来18 篇
2022-11 ~ 2026-07　·　C 编辑方法本体

只给一句话和一张图，不给 mask、不做 per-image inversion，模型要同时做到「听懂改什么」和「只改该改的」。而真实成对监督数据稀缺。

转折点 · 卡在哪 · 论文
转折点

两处。一是从纯合成数据转向真实锚点、人工标注与专家过滤管线（MagicBrush / UltraEdit / OmniEdit）——早期失败被反复归因到数据分布而不只是模型容量；二是从 CLIP 文本编码器转向 MLLM 条件建模。

还没解决的

计数、空间推理、局部 grounding；自动指标与人类偏好错位——CLIP 相似度会奖励保守编辑，方向相似度在 HQ-Edit 里与人评负相关。

04条件控制：结构、身份、参考图怎么注入14 篇
2023-02 ~ 2026-04　·　C 编辑方法本体

结构图、身份参考图、多参考 token 这些条件进不了文本序列，必须在冻结主干的前提下另开表示通道。空间对齐与语义对齐会互相压制。

转折点 · 卡在哪 · 论文
转折点

两个。一是 UNet→DiT 迁移让特征加法失效，OminiControl 把条件变成 token 才重开统一接口；二是多条件组合暴露串扰和推理成本，EasyControl 的 KV Cache 与 care-edit 的稀疏专家指向同一判断——条件不能只被注入，还要被隔离或按需激活。

还没解决的

身份保真与文本可控的权衡：IP-Adapter 明确达不到 DreamBooth 的主体一致，InstantID 的人脸嵌入耦合属性使编辑困难。DiT 条件 token 的延迟/显存没有通用压缩方案。

06局部与对象级：抠图、补全、搬物体12 篇
2022-11 ~ 2026-06　·　C 编辑方法本体

区域内按条件改、区域外像素级不变、边界自然融合——三个要求互相牵制，还会集中出现复制粘贴退化、条件被上下文淹没、编辑泄漏三类失败。

转折点 · 卡在哪 · 论文
转折点

不是单一模型，而是从「改主干」转向冻结主干 + 可训练条件分支 / 任务提示，把 where（掩码、边缘、参考位置）和 what（文本、身份、任务）分开注入。SAM 把 where 从手工掩码变成模型交互，但没解决条件融合。

还没解决的

细粒度计数、形状、文字/logo 渲染系统性失败；多区域、多主体或复合指令同时编辑基本没做——多数方法还是单 mask 假设。

07拖拽与点控编辑4 篇
2023-05 ~ 2024-02　·　C 编辑方法本体

用户只给稀疏的手柄点→目标点位移，但生成模型内部没有天然的像素坐标对应。文本编辑表达不了「把这个局部挪到那里」。

转折点 · 卡在哪 · 论文
转折点

DragonDiffusion——把目标从「跟踪手柄点、优化 latent」改写成「改变中间特征对应 + 沿采样路径做梯度引导」，拖拽不再绑定 GAN inversion 和逐点优化，任务扩展到移动、缩放、外观替换。

还没解决的

亚像素精度不可达；单图准备加推理十几到几十秒，做不到实时交互。这条线 2026 年在 1123 篇候选里没有一篇够 4 分——可能真沉寂了，也可能是检索式没覆盖到。

08统一多模态：理解与生成同一个模型20 篇
2023-12 ~ 2026-06　·　C 编辑方法本体

同一批参数同时做理解与生成。理解要语义抽象，生成要连续潜变量或离散码本；离散文本、连续视觉表示、不同训练目标在同一个 Transformer 里抢容量。

转折点 · 卡在哪 · 论文
转折点

不在单一模型，而在 Transfusion 与 BLIP3-o 确立的组合——受控比较显示连续 VAE/CLIP 特征配扩散/流匹配，比把图像离散成 token 更有语义和效率优势。随后 MetaQuery、OmniGen2、UniWorld-V1 把理解骨干冻结、只训生成接口。

还没解决的

理解与生成的梯度/容量冲突未消除，共享参数下生成梯度可比理解梯度大一个数量级；OCR 与文本渲染受编码器和分辨率限制。

09生成骨干：编辑方法赖以运行的底座10 篇
2021-12 ~ 2026-05　·　D 骨干与数据

骨干为了降采样成本、提文本跟随，不断压缩表示、做全局去噪、转向大 Transformer——而这些手段恰好削弱编辑需要的像素保真、局部不泄漏和多轮一致。

转折点 · 卡在哪 · 论文
转折点

SD3-RectifiedFlow——MM-DiT 的双流 token 共享注意力替掉 UNet 的固定 cross-attention，参考图、文本、目标图从此能进同一个序列。此前的 LDM/CFG/PixArt 只是降本或改条件注入，还没把生成和编辑统一到同一 token 化底座。

还没解决的

全局去噪导致编辑泄漏与多轮漂移——FLUX-Kontext 六轮后出现身份漂移和 artifacts；效率主张缺统一硬件口径，多数论文不披露单图延迟。

10推理、强化学习与评测8 篇
2025-03 ~ 2025-05　·　B 推理与 RL

编辑不能只停在「直接执行指令」，得先完成语义、空间、知识推理再落到像素。但推理是隐式的，优化目标只能建在生成结果和人类偏好上。

转折点 · 卡在哪 · 论文
转折点

Flow-GRPO / DanceGRPO 用 SDE 把确定性 ODE / 流匹配采样改造成可随机 rollout 的策略——推理规划或生成步骤第一次成为可训练策略，而不再只是喂给扩散模型的静态文本。

还没解决的

奖励模型可靠性：T2I-R1 的单一 VQA 奖励会被 hack，DanceGRPO 只用 HPS 会产出油腻图像；自动评测相关性上限低（Complex-Edit 的 IF/IP/PQ 最高约 0.53/0.23）。

11奖励模型与在线 RL（2025H2 起）9 篇
2025-09 ~ 2026-08　·　A 评测与奖励

策略优化器已经不是瓶颈。奖励信号要同时做细粒度跨图比较、绝对质量校准、低方差反馈，还不能在训练中被策略反向利用。

转折点 · 卡在哪 · 论文
转折点

EditScore / EditReward 之后——问题从「用不用 VLM」转向「跨图比较与伪影盲区」。SpatialReward 和 reward-hacking-t2i 把失败模式显式化后，路线分化成两条：给奖励加空间/伪影正则，或干脆放弃专用编辑奖励，转向冻结似然与 T2I 迁移。

还没解决的

reward hacking 只能缓解不能根除，多篇只能靠提前停止、正则或选早 checkpoint 规避；细粒度执行与像素级身份保持无法被全局标量完整编码，区域级信用分配仍是 future work。

12会推理再动手：think-then-edit7 篇
2025-10 ~ 2026-06　·　B 推理与 RL

「想」与「改」的接口。MLLM 不被显式激活时自发发现隐含约束的召回只有 0.461；而推理一旦写成自然语言，又无法保证和像素编辑结果一致。

转折点 · 卡在哪 · 论文
转折点

两个。CoCo / Meta-CoT 把推理从自由文本转向可执行、可奖励、可分解的中间表示（代码沙盒渲染确定性草稿；CEC Reward 直接约束「说到的」与「改到的」一致）；mind-the-gap 把瓶颈从「验证失败」前移到「发现失败」。

还没解决的

04

反复出现的模式

跨脉络的六个共用招式

这六个做法在互不相干的脉络里被独立重新发明。它们不是某一篇的贡献，而是这个领域目前真正达成共识的部分——新做一件事之前先看看这里，多半已经有人踩过。

冻结主干，只训适配器 / LoRA / 连接器

条件控制 ControlNet、T2I-Adapter、IP-Adapter、EasyControl　·　个性化 Custom-Diffusion 只更新 cross-attention 的 KV　·　局部编辑 AnyDoor、PowerPaint、BrushNet　·　统一多模态 MetaQuery、BLIP3-o、OmniGen2　·　InstructX 用 LoRA 微调 VLM 再经连接器接 DiT

保留预训练先验、避免灾难遗忘，同时以很低的参数成本新开一条条件通路。

反演轨迹缓存 + 注意力 Value / 特征注入

训练-free Prompt-to-Prompt、Plug-and-Play、MasaCtrl、Self-Guidance　·　反演精度线的 Value 注入与特征共享　·　拖拽 DragDiffusion、DragonDiffusion 缓存潜变量与自注意力 K/V　·　统一编辑 VAREdit、Qwen-Image-Layered 的源图潜变量注入

去噪早期绑定源表示能保住布局与身份，后期释放才允许语义改变——结构保持与编辑自由度的折中点在时间轴上。

VLM 当裁判或奖励，但必须给局部锚点

指令式 HQ-Edit、MGIE、ICEdit　·　RL T2I-R1、Flow-GRPO、GoT　·　奖励模型 EditScore、EditReward、read-it-back　·　推理编辑 UniREditBench、Meta-CoT　·　数据 NoHumansRequired、X2Edit　·　评测 EdiVal-Agent

自然语言视觉判断能近似人类偏好且可规模化；但整图打分容易幻觉，把判断限制在检测框 ROI 或场景图事实里做原子判定才可靠。

合成数据 + 自动过滤栈冷启动

InstructPix2Pix 用 Prompt-to-Prompt 造配对图，MagicBrush 人工补强，UltraEdit 真实锚点 + 自动区域　·　SAM 数据引擎、MimicBrush 视频帧自监督　·　NoHumansRequired、X2Edit、OpenGPT-4o-Image　·　UniREditBench 合成 100K CoT

成对编辑监督天然稀缺，自动合成是唯一能规模化的路——代价是必须再加一层过滤器压住分布偏置和伪正确样本。

分阶段训练：先对齐接口，再联合微调

统一多模态先对齐视觉接口再联合微调　·　ReasonEdit 先训 MLLM LoRA、再训 DiT、最后联合　·　UniReason 先训生成分支再全参联合　·　Meta-CoT 先 SFT 后 Flow-GRPO 且 RL 只更新生成专家　·　PixArt-α 三阶段复用

早期就联合优化会造成语言先验与图像先验冲突、容量失衡；分段能保护已有能力，后期再解冻有限参数。

组内归一化 / 自集成压低奖励方差

Flow-GRPO、DanceGRPO 的 GRPO 组内优势　·　qwen-image-rl 按 prompt 组归一化　·　Edit-R1 阈值过滤低方差组　·　read-it-back 的 sequence-level advantage　·　EditScore 的 Avg@4

不同 prompt 的难度和奖励尺度差很多，组内标准化能消掉跨题噪声；自集成提高排序准确率且不额外吃显存。
