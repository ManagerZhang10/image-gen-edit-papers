# GPT Image 2 官方资料核验笔记

## 一句话结论

GPT Image 2 是 OpenAI 的闭源图像生成与编辑 API 模型，官方定位是更强指令遵循、灵活尺寸和高保真图像输入；它适合做产品效果上限或 API 方案，但截至 2026-08-29 没有公开正式论文、架构、训练数据或可复现实验，不能拿产品文档反推技术路线。

## 问题与能力边界

官方模型页确认 `gpt-image-2` 同时接受文本和图像输入并输出图像，支持 image generation 和 image edit 端点。官方 prompting guide 把它定位为新项目默认图像模型，并列出写实、文字渲染、复杂版式、风格控制、编辑中的人脸/身份保持和多步工作流等能力。

这些属于官方产品能力陈述，不等同于公开论文中的可复现实验证据。文档没有披露参数规模、扩散/自回归/混合架构、训练目标、训练集组成、身份损失或局部保持机制。

## 架构、训练与数据

未公开。能确认的只有 API 行为：

- 模型别名 `gpt-image-2`，官方页列出固定快照 `gpt-image-2-2026-04-21`；
- 图像输入和输出均支持；音频、视频不支持；
- 支持 generation/edit 端点；不支持微调；
- 官方 guide 表示该模型默认就是 high-fidelity input，不使用旧模型的 `input_fidelity` 参数；
- 输出质量有 low / medium / high，尺寸规则比 GPT Image 1.x 更灵活；透明背景 PNG/WebP 在 guide 中标为 preview。

## 评测与关键结果

官方资料没有公开论文式 benchmark 表、训练数据规模或身份保持数值。因而不能写“在某基准第一”“身份相似度达到多少”或“局部像素保持有保证”。所有这类结论都需要自行评测。

## 局限

- 闭源 API，无法做结构级复现、LoRA 微调或内部损失改造。
- 官方能力陈述缺少公开统一 benchmark；模型迭代也可能使别名行为变化，生产应锁快照。
- 高保真输入不等于未编辑区像素级不变；生成式编辑仍应做局部差异和身份验证。
- 成本、延迟、内容策略和数据治理属于部署约束，需以当时 API 文档和目标账号实测为准。

## 对技术决策的意义

- **简单人像编辑**：可作为闭源强基线和快速上线候选，尤其适合不愿维护 GPU 推理栈的场景。
- **身份保持**：官方明确把 identity-sensitive edits 作为推荐用例，但没有公开量化证明；必须在自有肖像集上测 ArcFace/AdaFace、多人身份串扰和多轮衰减。
- **局部保持**：应测蒙版外像素差、LPIPS、背景 OCR 和配饰漂移。不要把“high-fidelity image inputs”翻译成“像素锁定”。
- **研发选型**：若目标是研究可复现机制或训练自有模型，这个条目只能作为效果参照，不能作为架构蓝图。
