# 大白话深读《tuna-2》

## 1. 30 秒定位

《Tuna-2: Pixel Embeddings Beat Vision Encoders for Multimodal Understanding and Generation》提出原生统一多模态模型 Tuna-2。它把视觉理解和图像生成都放在像素空间（pixel space）里做，彻底去掉了预训练视觉编码器：既不用 VAE（变分自编码器）把图像压到低维隐空间，也不用 CLIP/SigLIP 这类表征编码器（representation encoder）提取语义特征。Tuna-2 只用一层简单的 patch embedding 把原始图像切成 16×16 的 patch 变成视觉 token，然后让一个 Qwen2.5-7B-Instruct 单 Transformer 解码器同时处理视觉与文本 token。生成部分采用像素空间 flow matching，预测干净图像并用速度损失回归。论文还提出掩码特征学习策略，在训练后期随机遮蔽部分视觉 patch，以稳定高维像素空间表征学习。论文的图 1 明确画出了从 Tuna 到 Tuna-R 再到 Tuna-2 的减法路径：Tuna 含 VAE 与表征编码器，Tuna-R 只保留表征编码器，Tuna-2 什么都不留。实验显示，在 7B 规模原生 UMM 中，Tuna-2 在 GQA、MMVP、V*、CountBench 等理解基准（Table 1）以及 GenEval、DPG-Bench 生成基准（Table 2）上达到或接近最优；尤其细粒度视觉理解超过带表征编码器的 Tuna-R（Table 1），而生成质量与 Tuna-R 接近、多样性更好（Table 3）。核心论断是：预训练视觉编码器并非多模态建模必需，端到端像素空间学习可以同时支撑生成与感知。

## 2. 为什么这篇论文会出现

传统统一多模态模型（Unified Multimodal Models, UMMs）的核心难点是如何编码输入图像，使同一表示能同时服务理解与生成。早期方法采用解耦表征：理解侧用 CLIP 等表征编码器，生成侧用 VQ-VAE 等重建导向编码器，代表如 Janus-Pro（Table 1/2 中列出的 7B 模型）和 BAGEL（14B）。这带来表示错位（representation mismatch）：理解分支的语义 token 与生成分支的重建 token 并不共享，两个视觉模块各自预训练，模型无法从原始像素端到端优化。后来 Tuna、Show-o2 等改用共享视觉编码器统一两任务，但仍依赖预训练 VAE 和表征编码器，架构呈模块化，连接器需要单独对齐训练。这种设计虽然缓解了错位，但保留了固定的视觉编码器归纳偏置，比如固定输入分辨率、对低层细节的不完整保留。

与此同时，两条并行线索出现：在纯理解方向，Mono-InternVL、NEO、Fuyu 等表明可以不用预训练表征编码器，直接用 patch embedding 加单 Transformer 处理图像，且可规模化。在纯生成方向，PixelFlow、JiT 等工作证明像素空间 flow matching 可以匹配甚至超过隐空间扩散模型，暗示 VAE 压缩可能不是高保真生成的必需品。论文作者正是观察到这两股趋势后提出一个尚未被充分回答的问题：能否完全抛弃预训练视觉编码器，用端到端原生建模直接从原始像素构建 UMM？

为了可控地研究这个问题，论文设计了渐进的架构简化路径。先去掉 VAE 但保留表征编码器，得到中间版本 Tuna-R；再进一步去掉表征编码器，只留 patch embedding，得到最终 Tuna-2。Tuna-R 的作用不是最终产品，而是对照实验的锚点：它隔离了“像素空间 vs 隐空间”的变量，因为 Tuna-R 与 Tuna 的差异只在于是否经过 VAE 压缩；Tuna-2 再隔离“编码器先验 vs 单体学习”的变量，因为 Tuna-2 与 Tuna-R 的差异只在于是否保留 SigLIP 2 表征编码器。论文的核心动机不是刷榜，而是验证一个设计假设——在足够的统一多模态预训练下，简单单体结构能否学习出比预训练编码器更强的细粒度视觉表征，同时不牺牲生成质量。论文进一步指出，固定输入分辨率和有限低层细节是预训练表征编码器的两个关键限制（§2.1），而 encoder-free 设计可以避免这些归纳偏置。这个假设若成立，将简化训练管线、避免连接器阶段，并为原生 UMM 提供可扩展的新范式。

## 3. 读懂前需要的最小概念

**统一多模态模型（UMM）**：在一个模型框架内同时完成视觉理解（如图像问答、OCR、图表理解）和视觉生成（如文生图、编辑）的模型。常见做法是共享 Transformer 骨干，但对视觉表示的解码方式不同。论文的 Table 1 和 Table 2 分别展示理解与生成基准，并用同一个 7B 模型完成两类任务。

**表征编码器（representation encoder）**：通常指 CLIP、SigLIP 这类视觉-语言对比预训练模型，输出具有语义对齐能力的视觉特征 token。它把图像压缩成高维语义向量，常见分辨率固定（如 SigLIP 2 So400M 输入 384×384）。其优点是语义先验强，缺点是固定输入分辨率、低层细节信息可能被丢弃。论文在 Tuna-R 中采用 SigLIP 2 So400M，该编码器本身也用掩码预测目标预训练过（§3.4）。

**VAE（变分自编码器）**：在扩散模型中常用来把高维图像压缩到一个低维 latent space（潜空间），例如 256×256×3 图像变成 32×32×4 的 latent。生成模型在 latent 上做扩散，最后用 VAE decoder 还原图像。论文提到的 SD-VAE、FLUX.1[dev]-VAE 等属于此类。去 VAE 意味着直接在 RGB 像素张量上做去噪或流动，不需要额外的 latent 编解码器。

**flow matching 与 rectified flow**：一种生成模型训练目标。给定真实图像 \(x_1\) 和噪声 \(x_0\sim\mathcal{N}(0,I)\)，构造线性插值 \(x_t = t x_1 + (1-t)x_0\)，让模型学习从噪声到真实图像的速度场（velocity field），推理时用 ODE 求解器逐步积分去噪。相比 DDPM 的噪声预测，flow matching 更直接，样本路径近乎直线。论文采用 rectified flow 的线性 schedule（Equation 1），推理用 Euler 求解器。

**x-prediction 与 v-loss**：模型输出可以是干净图像 \(x_\theta\)（x-prediction），也可以是速度 \(v_\theta\)。论文采用 JiT 的做法：骨干输出 \(x_\theta\)，再根据当前时间 t 变换为 \(v_\theta\)（Equation 3），损失函数回归真实速度 \(v = x_1 - x_0\)（Equation 4）。这种组合有利于训练稳定，也方便推理时 Euler 更新。

**patch embedding**：把图像按固定大小（如 16×16）切成不重叠 patch，每个 patch 拉平后经过一个可学习线性层映射为 token 向量。与 ViT 的 patch embedding 相同，但这里没有后续预训练编码器的深层块，只有一层映射。论文设置 patch embedding size 为 16（§3.1），因此 512×512 图像会产生 32×32=1024 个视觉 token。

**掩码特征学习**：训练时随机把一部分视觉 token 替换为可学习的掩码 token，迫使模型在部分视觉信息缺失时完成理解或生成。该论文将其作为正则化手段，用于稳定高维像素空间学习。在生成任务中，模型需同时预测掩码与未掩码区域的干净图像；在理解任务中，模型需基于被遮蔽的视觉输入回答文本（§2.2）。

## 4. 方法全景：先看数据流

**Tuna-2 总体数据流（训练与推理共用核心，差异在输出分支）**：

```
原始图像 I (H × W × 3)
        │
        ▼
Patchify / Patch Embedding  (patch size=16, 线性映射)
        │
        ▼
视觉 token 序列 [V1, V2, ..., Vn]
        │                              文本 prompt
        │                                  │
        └────────────► 拼接 ◄──────────────┘
                        │
                        ▼
              单 Transformer 解码器
          (Qwen2.5-7B-Instruct, 共享参数)
                        │
          ┌─────────────┴──────────────┐
          ▼                            ▼
  Language Modeling Head         Flow Matching Head
  (预测下一个文本 token)          (预测干净图像 xθ)
          │                            │
          ▼                            ▼
   文本回答                       像素空间图像
```

**Tuna-R 与 Tuna 的差异**：Tuna-R 在“Patchify / Patch Embedding”之前插入一个 SigLIP 2 So400M 表征编码器，把图像编码成语义 token，再接 connector（MLP）投影到 LLM 维度；生成时仍走像素空间 flow matching，没有 VAE。原始 Tuna 则先过 VAE encoder 得到 latent token，再送入表征编码器，生成时用 VAE latent 空间扩散；其生成头输出 latent，再经 VAE decoder 还原。图 1 清晰地画出了三者的减法关系：Tuna 的视觉路径包含 VAE Encoder、Representation Encoder、Patchify Layer；Tuna-R 去掉 VAE Encoder，保留 Representation Encoder 和 Patchify Layer；Tuna-2 再去掉 Representation Encoder，只保留 Patchify Layer。图 1 还显示 Tuna-2 在多个基准上比 Tuna-R 和 Tuna 更好。

**核心组件及其输入/输出/目的/假设**：

- **Patch embedding 层**：输入为原始 RGB 图像块（16×16 patch）；输出为视觉 token。目的是用最少的预处理将像素转换为 Transformer 可处理的向量。其隐含假设是模型后续的 Transformer 块能自行学习低层边缘、纹理和高层语义，不需要预训练编码器的归纳偏置。训练时，部分视觉 token 可能被替换为可学习的掩码 token（§2.2）。
- **单 Transformer 解码器**：输入为拼接的视觉 token 与文本 token；输出为对每个位置的下一个 token 分布。其目的一方面通过因果注意力完成自回归文本生成，另一方面为 flow matching 头提供条件化表示。假设是统一序列建模足以同时承载视觉与语言任务。论文选择 Qwen2.5-7B-Instruct 作为 LLM 解码器（§3.1），没有额外视觉专家模块。
- **Language modeling head**：将 Transformer 输出映射到词表概率。用于理解任务（图像问答、OCR）和文本生成。其损失是标准交叉熵（CE）。
- **Flow matching head**：将 Transformer 对噪声图像 token 的输出映射为干净图像预测 \(x_\theta\)。输入还包括时间步 t 和条件 c（文本或文本+图像）。输出尺寸与输入 patch 一致，经 unpatchify 恢复图像。其目的在像素空间直接预测去噪结果。图 1 中显示为 “Unpatchify Layer”。
- **掩码 token**：训练时随机替换部分视觉 patch。对生成任务，模型预测掩码与未掩码区域的干净图像；对理解任务，要求模型在部分遮挡下回答问题。假设这能迫使模型学习上下文化的鲁棒表示，而不是依赖像素冗余快捷路径。训练后期以 50% 概率对样本应用掩码，遮蔽比例从 0% 到 50% 随机采样（§3.1）。

值得注意的是，理解与生成共享同一个 Transformer 权重，但输出头不同。理解任务走语言头，生成任务走 flow matching 头。训练时根据数据采样选择其中一个损失；论文未明确指出同一 batch 内是否混合两种任务，但从数据配比和 Figure 5 的 loss 曲线来看，两种损失是交替或批次间混合的。

## 5. 核心公式与直觉

论文的核心生成目标来自 JiT 的像素空间 flow matching。理解公式只需抓住四个式子：

**线性噪声调度**  
\[
x_t = t x_1 + (1-t)x_0,\quad t\in[0,1]
\]
其中 \(x_1\) 是真实图像，\(x_0\sim\mathcal{N}(0,I)\) 是高斯噪声。当 \(t=0\) 时完全噪声，\(t=1\) 时完全真实图。这个线性插值就是 rectified flow 的前向轨迹。直觉上，它把生成问题变成“沿直线从噪声走到图像”，路径最短，推理步数可以较少。训练时 t 在 [0,1] 内随机采样，论文未披露具体采样分布，但从标准 rectified flow 通常是从均匀分布或 logit-normal 分布采样。

**模型预测干净图像**  
\[
x_\theta = \pi_\theta(x_t, c, t)
\]
\(\pi_\theta\) 是统一骨干加 flow matching 头。注意模型不是预测噪声，而是直接输出对干净图像 \(x_1\) 的估计。这与 DDPM 的噪声预测不同。预测干净图在像素空间更直观，但数值范围大；论文通过下一式的速度变换规避直接回归 \(x_1\)。\(c\) 是条件信号，文生图时为文本，图像编辑时为文本+源图像。

**速度变换**  
\[
v_\theta = \frac{x_\theta - x_t}{1-t}
\]
这是把干净图预测反推为速度场。因为在 rectified flow 中，真实速度是常数 \(v = x_1 - x_0\)。给定 \(x_t\) 和 \(x_\theta\)，在 \(t\) 处的速度估计就是上式。当 \(t\to 1\) 时，分母 \(1-t\to 0\)，数值不稳定，但论文未明确处理这一边缘，训练时通常 t 在 (0,1) 内采样。工程上可能对 t 采样做保护或对分母加小量截断，论文未写但实践中必须处理。

**损失函数**  
\[
\mathcal{L}_{\text{flow}} = \mathbb{E}_{t,c,x_1,x_0}\|v_\theta - v\|_2^2,\quad v = x_1 - x_0
\]
就是均方误差回归速度。工程上，模型输出 \(x_\theta\)，再转换成 \(v_\theta\) 参与损失。直觉：虽然目标是 x-prediction，但用速度损失稳定了训练，避免直接回归高维像素带来的方差。推理时用 Euler 求解器：  
\[
x_{t'} = x_t + (t'-t)v_\theta
\]
从 t=0 逐步积分到 t=1 得到生成图。论文的推理流程描述为“根据 Equation 3 将 \(x_\theta\) 变换为 \(v_\theta\)，然后使用 Euler 求解器从更噪的 \(x_t\) 预测 \(x_{t'}\)”（§2.1）。需要注意的是，对于理解任务，损失是标准的语言建模交叉熵，论文没有给出公式，但可以从 Table 1 评测指标推断。

## 6. 训练到底怎么跑

论文训练分两个阶段，Tuna-2 完全端到端，不需要单独训练连接器。

**Stage 1：全模型预训练。** 数据上，使用 550M 内部图像-文本对（§3.1），其中 30% 是图像描述（image captioning）用于理解任务，70% 是文生图（text-to-image generation）数据。另外加入 Nemotron 文本-only 数据，占预训练总数据的 20%。所以实际多模态对约占 80%，文本对占 20%。论文没有给出每个 batch 的具体组织方式，但数据配比是全局采样比例。显存设置每个 GPU 序列长度 pad 到 16k tokens。优化用 AdamW，学习率 \(1\times10^{-4}\)，总共 300k 步，在 64 个节点上训练。一个 step 会从数据混合中采样一个 batch，内含理解样本或生成样本。理解样本：输入图像 patchify 后与问题/提示拼接，要求模型自回归生成答案，损失是语言模型的交叉熵。生成样本：取真实图像 \(x_1\)，采样噪声 \(x_0\) 和时间 t，构造 \(x_t\)，把 \(x_t\) 的 patch token 连同文本 prompt 和时间步送入 Transformer，flow matching 头输出 \(x_\theta\)，转成 \(v_\theta\) 后与真实速度 \(v\) 做 MSE（Equation 4）。需要注意的是，论文并没有说明理解与生成样本是否在同一 batch 内混合，但数据比例是全局采样比例。

**掩码特征学习。** 不是从头就加掩码。论文明确在预训练的最后 40% 步才启用（§3.1）。在这 40% 中，对 50% 的训练样本应用掩码，遮蔽比例从 0% 到 50% 随机采样。被遮蔽的视觉 token 替换为可学习的掩码 token，然后再进 Transformer。理解样本遮了也要照常回答；生成样本遮了也要预测完整干净图。§3.4 的消融实验表明，这种“先标准预训练后掩码预训练”的课程式安排比从头加掩码更合理，因为掩码机制应在模型已获得基本多模态知识后作为表征增强手段。

**Stage 2：监督微调（SFT）。** 用更低的 \(2\times10^{-5}\) 学习率，训练 50k 步。数据包含：约 13M 个来自 FineVision 的对话/指令样本用于图像指令跟随（image instruction-following）；约 2M 个 OmniEdit 样本用于图像编辑；还有高质量图像生成数据。SFT 目的是提升指令跟随、编辑能力和图像质量。所有阶段的序列长度都 pad 到 16k tokens（§3.1）。

**Tuna-R 额外步骤。** Tuna-R 因为还有 SigLIP 表征编码器与 LLM 之间的 connector，需要在 Stage 1 之前加一个仅训练 connector 的 alignment 阶段，只用图像描述和文生图数据训 3k 步，学习率 \(5\times10^{-4}\)（§3.1）。这一步是模块化设计的“税收”，Tuna-2 没有这个负担。Tuna-R 的 LLM 解码器同样用 Qwen2.5-7B-Instruct，表征编码器用 SigLIP 2 So400M，与 Tuna 前作一致。

## 7. 推理到底怎么跑

**理解任务推理**：输入图像先 patchify 成视觉 token，与用户问题 token 拼成序列，送入 Transformer。模型用语言头自回归生成下一个文本 token，直到产生终止符。由于没有表征编码器，视觉 token 数量取决于 patch size：以论文的 patch=16 为例，512×512 图像切成 32×32=1024 个 patch。论文没有写动态分辨率的做法，实验设定 patch embedding size=16（§3.1）。理解任务只需要一次前向（自回归生成多步），没有去噪过程。

**文生图推理**：给定文本 prompt c，采样初始噪声 \(x_0\sim\mathcal{N}(0,I)\)。从 t=0 开始，用 Euler 求解器分多步积分到 t=1。每一步：把当前 \(x_t\) patchify 成 token，拼接文本 prompt token 和时间步 t，输入 Transformer；flow matching 头输出 \(x_\theta\)，用 Equation 3 转成 \(v_\theta\)；然后按 \(x_{t'} = x_t + (t'-t)v_\theta\) 更新到下一个时间步 \(t'\)。最后 \(x_1\) 就是生成图。论文没有披露采样步数，但从 Euler 求解器和已有 flow matching 习惯推断，可能几十步到上百步。生成时同样没有 VAE decoder，直接得到像素图，无需额外的 latent 解码器。

**图像编辑推理**：论文没有详细写推理协议，但根据训练数据与 Table 4，编辑任务应该会把源图像 patchify 作为条件 token，与编辑指令文本 token 拼接；可能还采用与文生图类似的 flow matching 过程，但初始噪声未必是纯噪声，可能是源图像加噪后的 \(x_t\)。具体细节论文未明确披露，只能依据“text+image editing”训练（§2.3：SFT 包含 OmniEdit 2M）推断。

**推理计算特点**：每一步去噪都要过一次完整 Transformer，且 patch token 数量大（512×512 图像 1024 token，若 1024×1024 则 4096 token），与 latent 空间相比没有 token 数优势（例如 32×32 latent 也是 1024 token），但每个 token 携带原始像素，模型内部计算没有减少。优势是省掉 VAE 编解码和表征编码器，架构单体。多步采样会放大延迟，尤其是高分辨率下。

**最关键消融**：掩码特征学习。因为论文的核心难点是“像素空间高维冗余导致学习困难”，而掩码机制正是针对性措施。Table 6 用 1.5B 小模型做了控制实验：在 50k 步基线后，分两组各训 50k 步，一组标准预训练，一组以 50% 概率加掩码（遮蔽比例 0%~50%）。结果表明，无论 Tuna-R 还是 Tuna-2，加掩码都提升四项指标；且 Tuna-2 收益更大（如 OCRBench +1.4 vs Tuna-R +0.9，MMVP +3.4 vs +1.3）。论文归因于 SigLIP 2 本身已用类似掩码目标预训练（§3.4），所以 Tuna-R 边际收益小。这意味着对于完全从零开始或缺乏预训练编码器的单体设计，掩码正则尤其重要。

**尚未证明的主张**：第一，“像素空间生成完全可以与隐空间竞争”只在 GenEval、DPG-Bench 与 LLM 偏好上得到支持，缺少人类主观大规模评测、高分辨率（≥1024）和长尾风格控制。Table 2 显示专用生成模型 LongCat-Image 在 GenEval 0.87、DPG 86.80，Qwen-Image 在 DPG 88.32，Tuna-2 未超过最强的专用模型。第二，“encoder-free 设计在 scalable 后更强”的证据来自 7B 模型和 Figure 6 的趋势曲线，并非真正扩大模型参数量到数十 B 的结果。论文未进行更大规模的 scaling 实验。第三，论文没有给出视频生成或视频理解的实验，所有基准均为图像任务。第四，掩码特征学习仅在小模型 1.5B 上做消融，7B 最终模型采用该策略但没有 7B 对照，其绝对提升幅度不明确。

## 9. 与前作怎么选

**Tuna（前作）**：有 VAE 和表征编码器，latent 空间统一表示。优点是生成质量成熟，图像编辑在 Table 4 中总分 4.31 最高，GenEval Overall 0.90 也最高；缺点是细粒度理解弱，V* 52.4、CountBench 73.5 低于 Tuna-2，且需要多阶段训练多个视觉模块。Tuna 的视觉路径包含 VAE encoder、表征编码器、patchify、unpatchify、VAE decoder，架构最复杂。

**Tuna-R（中间版本）**：去掉 VAE，保留 SigLIP 2 表征编码器，像素空间 flow matching。优点是生成质量最好（GenEval 0.88，Table 3 质量也略高），理解早期收敛快（Figure 6）；缺点是固定编码器分辨率、无法完全端到端，需要额外 connector alignment（3k 步），且细粒度低层细节仍然受限（V* 57.6、CountBench 77.8 低于 Tuna-2）。

**Tuna-2（本作）**：完全 encoder-free，只用 patch embedding。优点是架构最简、理解指标最全面领先（Table 1 的 12 项中多数优于 Tuna-R），多样性显著好（Table 3），训练管线无 connector 阶段；缺点是生成略逊 Tuna-R（GenEval 0.87 vs 0.88，Table 2），编辑略逊 Tuna（ImgEdit 总分 4.09 vs 4.31，Table 4），训练初期收敛慢（Figure 6），像素空间训练需要掩码正则。

**何时选哪个？** 如果应用强依赖图像编辑和生成质量，且能接受模块化复杂性，Tuna 或 Tuna-R 仍是稳妥选择（Table 4 和 GenEval）。如果主要需求是细粒度视觉问答、OCR、计数等感知任务，或者希望最简单体架构便于规模扩展，Tuna-2 更合适。如果数据规模极大、希望消除预训练编码器的输入分辨率瓶颈，Tuna-2 的 patch embedding 方案可塑性更强。但如果算力有限、只做小规模训练，Tuna-R 利用 SigLIP 先验可能更划算，因为 Tuna-2 早期表现差，需要更多数据才能反超。

与 Show-o2、Emu3 等 latent UMM 相比，Tuna-2 的优势在像素级任务，但 Table 2 的 GenEval 显示 Show-o2 只有 0.76，Emu3 只有 0.66，Tuna-2 大幅领先，说明像素空间并不必然失败。但与 BAGEL（GenEval 0.88）、Mogao（GenEval 0.89）等强 UMM 比，Tuna-2 没有全面胜出，更多是理解端领先而生成端互有胜负。因此在“统一模型选型”场景下，需要根据任务权重做取舍，而非单看一个综合分数。

## 10. 工程判断：可行性、风险与上限

**数据**：550M 图像-文本对是较大的数据量（§3.1），但 30% 描述 70% 文生图配置说明生成任务占据主导。文本数据 20% 用于保持语言能力。如果团队没有类似规模的内部图文对，复现门槛高。FineVision 13M 是开源，可用于图像指令跟随；OmniEdit 2M 也是开源。数据管线本身的可行性中等偏上，但高质量内部 550M 对需要大量清洗与标注投入。

**算力/延迟**：训练在 64 节点 300k 步，每个 GPU 序列长度 16k（§3.1）。论文未披露节点所用 GPU 型号和 batch size，因此无法精确推算 FLOPs，但 64 节点 × 300k 步 × 16k 序列长度意味着较大的资源消耗。推理方面，像素空间图像 token 数随分辨率平方增长：512×512 图像是 1024 patch，1024×1024 则是 4096 patch，与 latent 空间在相同分辨率下有可比 token 数，但 latent token 可以更低（如 32×32 对应 512 分辨率）。生成多步采样，每次过 7B Transformer，延迟较大。理解任务单次前向即可，与普通 LMM 相当。

**实现难点**：像素空间的 flow matching 损失在高维上可能波动大，需要掩码正则；t 近 1 时速度变换分母趋零（Equation 3），需要在工程上截断或对 t 采样做保护，论文未写但实践中必须处理。另一个难点是 patchify/unpatchify 的边界对齐，以及不同分辨率图像如何 pad 到统一 token 数。论文在训练时 pad 到 16k tokens，推理时需要对任意图像做相应处理，但未披露细节。

**失败环节**：最可能失败的是生成质量在大规模高分辨率上不稳定。论文在 512 分辨率下做重建/生成评估，但 Table 5 的 rFID 仍差 FLUX VAE 一个量级（0.15 vs 0.06），意味着像素空间表征的高频细节仍可能比 KL 正则 VAE 略差，更高分辨率可能放大此差距。另一个风险是掩码特征学习只在 1.5B 上验证（Table 6），7B 上是否绝对必要无对照，若在 7B 上启用可能导致训练时间延长而收益不明确。此外，Flow matching head 与语言头共享骨干，若生成任务占据了 70% 数据，理解能力可能受到稀释，但 Table 1 的理解结果尚好。

**监控信号**：训练时要看两条 loss 曲线：语言建模 CE 和 flow matching MSE。图 5 表明 MSE 对数据比例敏感，如果生成 loss 震荡应调低生成数据比例或增大掩码概率。论文建议生成/理解比例 7:3 为最佳权衡（Figure 5）。推理前应定期在 GenEval、DPG-Bench、OCRBench 上评测，同时可参考 Figure 6 观察数据规模增加时的性能收敛趋势。还要监控注意力图质量（§3.6），以防语言先验污染视觉定位，尤其是存在误导性文本场景时。

**指标上限**：GenEval 0.87、DPG 86.54 尚未超过专用生成模型 LongCat-Image（0.87、86.80）、Qwen-Image（0.87、88.32）的整体组合；理解在 7B 中领先但离更大模型或专用 LMM 仍有差距。论文的表 1 中理解分数整体都在 40~80 区间，说明模型虽好但未达到“通用人类水平”。像素空间统一模型的真实上限未被证明，论文只是展示一条可行路径，而不是声称解决了所有问题。

**未回答问题**：更小 patch size（8 或 14）会不会更好？动态分辨率怎么做？视频数据如何整合？如何把掩码训练与 RLHF/偏好优化结合？这些问题论文均未涉及。此外，论文指出并发工作 SenseNova-U1 也探索了相似 encoder-free 架构（§4.1），但未做直接对比。

## 11. 放回研究脉络并收束

这篇工作处在“原生多模态模型去编码器化”的交叉点。它从 LLaVA 式表征编码器 + LLM 的传统起步，经过 Tuna 的统一 latent 表示，跳到 Tuna-R 的像素空间 + 表征编码器，再跳到 Tuna-2 的完全 encoder-free。其研究脉络与 Fuyu、Mono-InternVL、NEO 的理解侧一致，也与 PixelFlow、JiT 的生成侧一致，但首次在 7B 规模 UMM 上把两者合并（§4.2 明确说之前的 pixel-space 生成模型通常局限于 ImageNet 等小规模 class-conditioned 场景，而 Tuna-2 扩展到了大规模统一多模态预训练）。论文的图 1 同时展示架构演进与性能比较，图 2 展示精心挑选的编辑样例，表 1~5 覆盖理解、生成、编辑、重建多个维度。

**读完必须记住的 5 件事**：

1. Tuna-2 = 原始像素 patch embedding + 单个 Transformer 解码器 + flow matching 头，无 VAE、无表征编码器。视觉编码路径只有一步 patchify（patch size 16）。
2. 生成目标不是噪声预测，而是 x-prediction 加 v-loss 的 rectified flow，速度 \(v=x_1-x_0\)，损失 \(\|v_\theta-v\|_2^2\)（Equation 4）；推理用 Euler 求解器逐步积分。
3. 掩码特征学习在预训练最后 40% 步使用，以 50% 概率对样本应用、遮蔽比例 0%~50% 随机；对理解任务是正则化，对生成任务是部分观测去噪，显著提升 Tuna-2 的表征鲁棒性（Table 6）。
4. Tuna-R 与 Tuna-2 的对照揭示：编码器先验帮助早期收敛和生成质量（Figure 6 生成曲线），但数据规模足够后 encoder-free 在细粒度理解上反超（Table 1 的 V*、CountBench、VisuLogic）。
5. 像素空间 UMM 的重建质量接近 FLUX VAE（Table 5），但生成编辑仍略逊于隐空间强 UMM（GenEval 0.87 vs Tuna-R 0.88，ImgEdit 4.09 vs Tuna 4.31），说明该路径可行但尚未全面超越。

**5 道自测题**：

1. \(x_t = t x_1 + (1-t)x_0\) 中当 \(t=0.5\) 时，\(x_t\) 是何含义？模型此时应预测什么？
2. 为什么 Tuna-R 在训练初期理解性能高于 Tuna-2，后期却被反超？（提示：先验 vs 可扩展性）
3. 掩码特征学习在生成任务和理解任务中分别扮演什么角色？

5. 根据 Table 2 和 Figure 6，Tuna-2 的生成相对 Tuna-R 的差距最终如何变化？这说明什么？

最终一句话总结：Tuna-2 用“原始像素 patch + 单体 Transformer + 掩码正则”验证了预训练视觉编码器并非统一多模态建模的必需品，但像素空间生成通向大规模高分辨率仍需进一步证明。
