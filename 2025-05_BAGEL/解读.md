# 大白话深读《BAGEL》

## 1. 30 秒定位

BAGEL 是字节跳动 Seed 等机构在 2025 年 7 月发布的一个开源统一多模态基础模型，论文全称《Emerging Properties in Unified Multimodal Pretraining》（arXiv:2505.14683）。它要解决的核心问题是：能否让一个单一 Transformer 同时做多模态理解和多模态生成，并通过大规模交错数据训练，涌现出复杂多模态推理能力。BAGEL 采用 Mixture-of-Transformer-Experts（MoT）架构，总参数 14B、激活参数 7B，基于 Qwen2.5 LLM 初始化，并在每个注意力块中加入 QK-Norm。它有两个视觉编码器：理解侧是 SigLIP2-so400m/14 ViT，生成侧是 FLUX 预训练 VAE。训练包括 Alignment、Pre-training、Continued Training、SFT 四个阶段，总计约 5.2T tokens。在标准基准上，BAGEL 7B 在 MMMU 达到 55.3、MM-Vet 达到 67.2，超过同规模统一模型；GenEval 总体为 82%（不加 LLM rewriter）和 88%（加 rewriter），优于 FLUX.1-dev 82%、SD3-Medium 74%、Janus-Pro 80%。复杂编辑任务 IntelligentBench 得到 44.9，加思维链后 55.3，但仍明显低于 GPT-4o 的 78.9。论文还通过“涌现曲线”声称，智能编辑等复杂能力要在大约 3.61T tokens 后才显著出现。

## 2. 为什么这篇论文会出现

统一多模态理解与生成是近年热门方向。此前工作可大致分为三条路线。第一条是量化自回归（Quantized AR）：用离散视觉 tokenizer 把图像变成离散 token，然后沿用 Next-Token-Prediction 范式训练，代表如 Janus-Pro、Chameleon、Show-o。它的好处是能直接复用现有 LLM 训练基础设施，实现简单；缺点是视觉生成质量通常弱于扩散模型，而且自回归逐步解码导致推理延迟高。第二条是外部扩散器（External Diffuser）：把预训练 LLM/VLM 通过轻量适配器接到扩散模型上，代表如 DreamLLM、MetaQuery-XL。这种方法收敛快、数据消耗少，有时也能在标准评测上拿到很高分数；但 LLM 上下文会被压缩成少量语义条件 token，形成一个显式信息瓶颈，在长上下文、多图像推理中可能丢失重要信息。第三条是集成 Transformer（Integrated Transformer）：把自回归 Transformer 和扩散 Transformer 融合进同一个模型，代表如 Transfusion、LlamaFusion。它没有理解与生成模块之间的瓶颈，但训练计算量显著更高。

论文观察到，学术界的统一多模态模型与 GPT-4o、Gemini 2.0 等闭源系统之间存在明显差距，而且这个差距不只体现为单项指标，更体现在自由形式图像操控、未来帧预测、3D 操控、世界导航等复杂任务上。作者认为，造成差距的关键不在模型结构的小技巧，而在数据：大多数统一模型仍主要用标准图像-文本对训练，缺少大规模交错结构。交错数据更接近真实世界中的多模态序列，包含概念关系、时间连续性、物理连续性和跨模态交互。作者因此假设：一旦用大规模交错数据扩展训练，模型会涌现出现有基准无法捕捉的能力。这一假设需要新的数据管道、无瓶颈架构和新评价方法。于是论文提出 BAGEL，用 MoT 架构缓解理解和生成目标的冲突，用视频和网页交错数据提供丰富监督，并引入类似 DeepSeek-R1 的推理增强数据，试图缩小开源与闭源系统的差距。

## 3. 读懂前需要的最小概念

**Rectified Flow（校正流）**：一种生成模型训练范式。它把数据生成过程建模为从噪声分布到数据分布的一条简单路径上的速度场预测。训练时对干净潜变量加噪，模型学习预测该路径上的速度向量，用 MSE 作为损失。BAGEL 在视觉生成侧使用这一范式，预测对象是 VAE 潜变量，而不是像素。这样既保留了扩散模型的高质量输出，又能与 Transformer 的自回归文本预测共存。

**VAE latent 与 ViT token**：BAGEL 对视觉信息做两种表示。生成侧使用 FLUX 预训练 VAE，把图像压缩到 8 倍下采样、16 通道的潜空间，再经过 2×2 patch embedding 降低空间尺寸并匹配 LLM 隐藏维度；这组 token 主要保留像素级、可重建的低层信息。理解侧使用 SigLIP2 ViT 将原图编码成语义 token，再经两层 MLP connector 对齐到 LLM 维度；这组 token 主要负责语义概念、OCR、空间关系等理解信号。两套编码器使模型既能“看懂”也能“画好”。

**MoT（Mixture-of-Transformer-Experts）**：把整个 Transformer 的可训练参数复制一份作为生成专家，原始参数作为理解专家。每个 token 根据模态被硬路由到对应专家：文本和 ViT tokens 走理解专家，VAE tokens 走生成专家。两个专家在每一层共享 self-attention 的 QKV 计算，但 FFN 参数独立。总参数因此翻倍，但每个 token 只激活一个专家，所以前向 FLOPs 与 Dense 相同。论文认为理解与生成目标会把参数拉向参数空间的不同区域，分离容量可以缓解优化冲突。

**广义因果注意力（Generalized Causal Attention）**：不是简单地在所有 token 上套用一个因果掩码。序列被按单模态 split 分段：文本 split 内部保持因果注意力，视觉 split 内部保持双向注意力；任何后续 split 都可看到前面 split 的全部 token。训练中每个图像有三套 token：加噪 VAE、干净 VAE、ViT。加噪 VAE 只用于计算生成损失，不能成为后续 token 的条件；干净 VAE 和 ViT 可以作为后续图像或文本的条件。这样既保证了扩散训练的正确性，又保留跨图像的条件信息。

**Diffusion Forcing 与 Classifier-Free Guidance（CFG）**：多图像或视频训练时，不同图像独立施加不同噪声级别，每个图像以前面图像的带噪表示作为条件；同时随机将相邻图像分组，组内使用全注意力来增强一致性。CFG 用于推理，训练时以一定概率丢弃文本、ViT、干净 VAE token，推理时组合有条件和无条件预测。论文设定的丢弃概率是文本 0.1、ViT 0.5、干净 VAE 0.1。

## 4. 方法全景：先看数据流

训练与推理的数据流总体如下。

```text
输入样本：文本 / 图像 / 视频帧 / 网页交错
        │
        ├─ 文本 → 文本 tokenizer → text tokens
        ├─ 理解图像 → SigLIP2 ViT（原生分辨率，NaViT）→ ViT tokens
        └─ 生成图像 → FLUX VAE encoder → latent → 2×2 patch embed
                        │ 训练时加噪 / 推理时从纯噪声逐步去噪
                        ▼
                  noised VAE tokens / clean VAE tokens
                        │
        ┌───────────────┴───────────────┐
        │ 按模态顺序交错拼接，添加扩散时间步嵌入   │
        ▼
   [广义因果注意力 mask + 共享 self-attention]
        │
        ├─ text/ViT tokens → 理解专家 FFN → logits → CE loss
        └─ noised VAE tokens → 生成专家 FFN → velocity → MSE loss
                        │
                        ▼
              反向传播更新（VAE 冻结）
```

推理时，如果是文生图，文本 tokens 作为条件，初始纯噪声 VAE tokens 逐步去噪；如果是图像编辑，输入图像的干净 VAE tokens 和 ViT tokens 作为条件，目标图像的噪声 VAE tokens 逐步去噪；最后将预测的干净 VAE latent 送入 FLUX VAE decoder 得到像素。

各核心组件的输入、输出、目的和假设如下。

**文本 tokenizer**：来自 Qwen2.5，把文本编码为离散 token。输入是自然语言或结构化描述，输出是文本 token 序列，用于自回归语言建模和作为视觉生成的条件。

**理解编码器**：SigLIP2-so400m/14 初始化，固定 384 分辨率起步，位置嵌入插值到最大 980×980，并用 NaViT 支持原生宽高比。输入是原始图像，输出是语义 ViT tokens。目的是捕捉对象、文字、空间关系等高层语义。假设是原图分辨率对 OCR 和细节理解很重要，因此支持动态分辨率。

**生成编码器**：FLUX 预训练 VAE，训练中冻结。输入是原始图像，输出是 8 倍下采样、16 通道的潜变量，再经 2×2 patch embedding 得到 VAE tokens。目的是保留可重建的像素级信息。假设是冻结 VAE 能稳定潜空间，避免联合训练增加不确定性。

**MoT 专家**：复制 Qwen2.5 LLM 的全部可训练参数作为生成专家。硬路由：文本和 ViT tokens 走理解专家，VAE tokens 走生成专家。每个 block 中先做共享 self-attention，再按 token 模态进入对应 FFN。输入是交错 token 序列，输出是对应模态的隐藏状态。目的就是隔离优化目标，假设两个任务需要不同的参数空间。图 3 显示在 1.5B LLM 上，MoT 的 CE 和 MSE 损失均低于 Dense 和 MoE，且在生成任务上的优势更明显。

**位置编码与时间嵌入**：ViT 和 VAE tokens 使用 2D 位置编码；扩散时间步嵌入直接加到 VAE tokens 初始隐藏状态，而不是使用 AdaLN。这样结构更简洁，同时保持性能。训练中当生成分辨率提高时，扩散时间步 shift 从 1.0 增加到 4.0，以调整噪声级别分布。

**广义因果注意力**：用 PyTorch FlexAttention 实现，训练时相比朴素 scaled-dot-product attention 达到约 2 倍加速。推理时只缓存干净 VAE 和 ViT tokens 的 KV；一旦图像生成完毕，其 noised VAE tokens 在上下文中的 KV 被替换为干净版本，供后续 token 使用。这大大节省多轮编辑或长序列生成的重复编码成本。

**MoT 架构动机**：论文通过受控实验比较 Dense、MoE、MoT 三种变体。MoE 只复制每 block 的 FFN 作为生成专家；MoT 复制全部可训练参数。三者的 FLOPs 相同，但 MoT 参数更多。结果表明 MoT 的 MSE 损失收敛最快且最终最低，CE 损失也整体更优，说明完全分离理解与生成容量更有利于解决模态目标冲突。

## 5. 核心公式与直觉

论文没有给出单个统一数学公式，但训练目标可以归纳为两个损失的加权和。从 Table 3 的 `Loss weight (CE : MSE)` 一栏可得到权值。

**第一个核心公式：总损失**

\[
\mathcal{L} = 0.25 \cdot \mathcal{L}_{\text{CE}} + 1.0 \cdot \mathcal{L}_{\text{MSE}}
\]

- \(\mathcal{L}_{\text{CE}}\) 是文本 token 的交叉熵损失，只在文本预测位置计算，对应多模态理解和语言建模能力。
- \(\mathcal{L}_{\text{MSE}}\) 是视觉生成的均方误差，只在加噪 VAE tokens 上计算，对应 Rectified Flow 的速度预测目标。
- 0.25:1 的比例是 PT、CT、SFT 阶段共享的设定。直觉是 CE 在数值尺度和方差上往往大于 MSE，给 MSE 更大权重可以防止生成信号被理解信号淹没。但这个比例来自经验调参，论文没有给出理论推导。

**第二个核心公式：广义因果注意力掩码**

设 token 序列被划分为连续 splits \(S_1, S_2, \dots, S_n\)，每个 split 内只含一种模态。注意力掩码允许条件可写为：

\[
M_{ij} = 
\begin{cases}
1, & \text{若 } S(i) < S(j) \text{，即前面的 split 可被看到} \\
1, & \text{若 } S(i)=S(j) \text{ 且视觉 token 存在（视觉内部双向，文本内部因果）} \\
0, & \text{否则}
\end{cases}
\]

更重要的是，每个图像有三套 token：加噪 VAE 只接受自身内部的全注意力，不能成为后续 token 的条件；干净 VAE 和 ViT tokens 可以成为后续图像或文本的条件。这样扩散训练所需的条件独立性得到保持，同时跨图像条件信息不被阻断。推理时 KV cache 只存干净 VAE 和 ViT，生成完成后把对应的加噪 VAE 替换为干净版本。Figure 15 展示了这一 mask：图 (a) 对应图文交错生成，后续图像只看前面图像的干净 VAE 和 ViT；图 (b) 对应多图像/视频生成，后续图像看前面图像的带噪 VAE，同时随机分组组内全注意力。

**第三个核心公式：MoT 硬路由**

对每个 token \(x\)，专家选择由模态决定：

\[
\text{expert}(x) = 
\begin{cases}
\text{Understanding Expert}, & x \in \{\text{text}, \text{ViT}\} \\
\text{Generation Expert}, & x \in \{\text{VAE}\}
\end{cases}
\]

这不是学习得到的软路由，而是固定规则。优点是简单稳定，避免早期训练中路由坍塌；代价是两个专家都必须有完整 Transformer 结构，总参数翻倍，但每个 token 只激活一个专家，所以前向 FLOPs 与 Dense 相当。

**第四个需注意的直觉：Rectified Flow 速度预测**。论文没有显式写出速度目标，但明确采用 Rectified Flow。训练动作是让模型在带噪 VAE token 上预测从噪声到干净潜变量路径上的速度向量，MSE 损失只施加于这些 token。训练中增加扩散时间步 shift（从 1.0 到 4.0），用来在高分辨率下调整噪声级别分布，使得训练信号不会因分辨率提高而变得过强或过弱。

## 6. 训练到底怎么跑

BAGEL 的训练分为四个阶段：Alignment、Pre-training（PT）、Continued Training（CT）、Supervised Fine-tuning（SFT）。一轮训练 step 的完整流程如下。

**数据准备**：按 Table 3 的采样比率从各数据源随机抽取样本。PT 阶段文本 5%，图像-文本对 T2I 60%，图像-文本对 I2T 10%，交错理解 10%，交错生成视频 10%，交错生成网页 5%。CT 阶段采样比例调整为文本 5%、T2I 40%、I2T 10%、交错理解 15%、交错生成视频 15%、交错生成网页 15%。SFT 阶段为文本 5%、T2I 30%、I2T 5%、交错理解 20%、交错生成视频 20%、交错生成网页 20%。每个 rank 把序列打包到 32K–36K tokens（Alignment 和 PT）或 40K–45K tokens（CT 和 SFT），以保证各 rank 负载均衡。这种打包被称为 narrow length range packing，论文没有进一步披露打包细节。

**编码**：文本 tokenize；图像根据任务走两条路径。理解图像用 SigLIP2 ViT 编码，分辨率约束为短边 224–980、长边 224–980（PT 阶段），CT/SFT 阶段短边提高到 378、长边仍为 980。生成图像先用冻结的 FLUX VAE 编码到 latent，再 2×2 patch embedding 得到 VAE tokens。如果是扩散训练，对目标 VAE tokens 采样噪声时间步 \(t\)，施加扩散噪声得到 noised VAE tokens，并加入时间步嵌入。

**序列拼装**：把 text、ViT、clean VAE、noised VAE tokens 按输入结构交错排列。每个图像对应三套 token，其中 noised VAE 只参与损失计算，不参与后续 token 的注意力条件。如果使用 diffusion forcing，多图像/视频的噪声级别独立，并随机将相邻图像分组，组内使用全注意力。分组的具体大小和随机策略论文没有披露。

**前向**：进入 decoder-only Transformer。每个 block 先做共享 self-attention（带 QK-Norm），再按 token 模态路由到理解专家或生成专家的 FFN。文本和 ViT token 产生 logits，noised VAE token 产生速度预测。模型使用 RMSNorm、SwiGLU、RoPE、GQA 等 Qwen2.5 既有设计，并在注意力中加入 QK-Norm 以稳定训练。

**损失**：对文本位置计算 CE，对 noised VAE 位置计算 MSE，按 0.25:1 加权求和。图 6 的消融表明，CE 和 MSE 对学习率有相反偏好：大学习率利于 MSE，小学习率利于 CE。因此论文没有为整个模型寻找一个折中学习率，而是分别给两个损失加权，并接受两者可能不在同一最优学习率上的事实。所有阶段都使用 AdamW 优化器，\(\beta_1=0.9,\beta_2=0.95,\epsilon=10^{-15}\)，其中 \(\epsilon\) 取值刻意设大以抑制损失尖峰。梯度裁剪阈值 1.0。PT、CT、SFT 阶段采用恒定学习率，分别是 \(1.0\times 10^{-4}\)、\(1.0\times 10^{-4}\)、\(2.5\times 10^{-5}\)，Alignment 阶段为 \(1.0\times 10^{-3}\)。Warm-up steps 分别为 250、2500、2500、500。EMA ratio 在 PT 和 CT 为 0.9999，SFT 为 0.995。

**反向更新**：所有参数除冻结的 VAE 外均更新。Alignment 阶段只训练 MLP connector，冻结 ViT 和 LLM；输入图像统一 resize 到 378×378 以匹配 SigLIP2 预训练输入。PT 阶段加入 QK-Norm 并从 LLM 同时训练全部参数。CT 阶段提高生成分辨率到短边 512、长边 1024，理解分辨率短边 378、长边 980；扩散时间步 shift 从 1.0 增加到 4.0。SFT 阶段用 72.7B tokens 做高质量指令微调，其子集来自图像-文本对数据和交错生成数据，理解侧筛选自 LLaVA-OV 和 Mammoth-VL。

另外，数据构造本身也是训练体系的一部分。视频数据先经过镜头检测、去黑边/logo、清晰度、运动稳定性、CLIP 去重等过滤；然后对每段视频平均采样 4 帧，用蒸馏出的 Qwen2.5-VL-7B 小型 captioner 生成相邻帧变化描述，caption 长度上限 30 tokens，最终得到 45M 条时间对齐的交错序列。网页数据基于 OmniCorpus，使用 fastText 主题分类和 Qwen2.5-14B 精细分类两阶段选择，再按 Table 2 的规则过滤：UI 移除、分辨率 150–20000 且宽高比 1/2–2、图像清晰度、OCR 文本密度不超过 100 token、CLIP 相关性、文档 trimming、保留 3–8 张图片。网页构造采用 caption-first 策略，每张图像前插入 Qwen2.5-VL-7B 生成的概念描述，超过 300 token 的文本段用 LLM 摘要压缩，最终得到 20M 网页文档。推理增强数据共 500k 个样本，覆盖 T2I、自由形式图像操控和概念编辑，由 Qwen2.5-72B、FLUX.1-dev 和 VLM 配合生成。

## 7. 推理到底怎么跑

推理分为无思维模式和有思维模式（Self-CoT）。

**多模态理解**：输入图像经过 SigLIP2 ViT 编码为 ViT tokens，文本 tokenize。所有 tokens 进入共享 attention，文本 token 以自回归方式逐步生成回答。理解任务只使用理解专家，不涉及 VAE。

**文生图（无思维）**：用户提示文本 token 作为起始序列。初始化一组纯噪声 VAE latent tokens，送入生成专家。模型预测 Rectified Flow 速度，结合 CFG 进行去噪。训练时 CFG 的丢弃概率为：丢弃文本 0.1、丢弃 ViT 0.5、丢弃干净 VAE 0.1。推理时对每个扩散步同时计算有条件和无条件输出，按 CFG 公式组合，但论文没有给出 CFG 强度。去噪完成后，将潜变量送入冻结的 FLUX VAE decoder 得到像素图像。若使用 LLM rewriter，则先用 LLM 把用户提示改写为更详细的生成描述，这一设置用于 GenEval 的 88% 分数。

**图像编辑与智能编辑**：输入图像通过 VAE encoder 得到干净 VAE tokens，同时通过 ViT 得到理解 tokens，两者作为条件。目标图像的噪声 VAE tokens 逐步去噪。思维模式下，模型先输出 `<think>...</think>` 内的推理轨迹，生成对任务的理解和编辑计划，然后再输出目标图像。推理轨迹是以语言形式生成的，能利用世界知识和多步规划。Figure 13 展示了这类思维链对生成和编辑的帮助。

**多模态缓存**：广义因果注意力允许缓存已生成多模态上下文的 KV。只缓存干净 VAE 和 ViT tokens 的 KV；当一幅图像生成完毕，其 noised VAE tokens 在上下文中的位置被替换成干净版本，供后续 token 注意力使用。这降低了多轮编辑或长序列生成的重复编码成本。论文没有给出具体加速比。

**世界建模推理**：导航和旋转任务中，模型根据输入图像和指令生成一组后续帧，使用相同的交错生成机制；在这个场景中，模型可以生成动态数量的图像，而不是固定长度输出。Figure 14 展示了 BAGEL 在真实街景上训练后，还能泛化到水墨画、卡通和电子游戏等不同域。

## 8. 实验和消融到底证明了什么

论文的实验分四大块：理解、生成、经典编辑与智能编辑、涌现曲线。以下表格给出关键证据。

| 任务 / 证据 | 指标与对照 | 结果 | 锚点 |
|---|---|---|---|
| 多模态理解 | MMMU、MM-Vet 等 6 个基准 | BAGEL 7B MoT 在 MMMU 达 55.3，MM-Vet 达 67.2，超过 Janus-Pro 7B 分别 +14.3、+17.1；MMBench 85.0、MathVista 73.1、MMVP 69.3 | Table 4 |
| 文生图 | GenEval Overall | BAGEL 82%，加 rewriter 88%；超过 FLUX.1-dev 82%、SD3-Medium 74%、Janus-Pro 80%、MetaQuery-XL 80% | Table 5 |
| 世界知识生成 | WISE Overall | BAGEL 0.52；加 Self-CoT 0.70；超过 MetaQuery-XL 0.55，低于 GPT-4o 0.80 | Table 6 |
| 经典图像编辑 | GEdit-Bench EN/CN 全量 | BAGEL EN 7.36/6.83/6.52（G_SC/G_PQ/G_O），CN 7.34/6.85/6.50，超过 Gemini 2.0，接近 Step1X-Edit | Table 7 |
| 智能编辑 | IntelligentBench | BAGEL 44.9，加 Self-CoT 55.3；开源 Step1X-Edit 仅 14.9；GPT-4o 78.9 | Table 8 |
| 思维链编辑 | RISEBench | BAGEL 6.1，Self-CoT 11.9；KRIS-Bench 56.21→60.18 | Table 9, 10 |
| 涌现现象 | 不同训练 token 数下各能力达到 85% 峰值所需 token | 理解约 0.18T、生成约 0.68T、经典编辑约 2.64T、智能编辑约 3.61T | Figure 7 |

GenEval 子项也能给出更细的对比：BAGEL 不加 rewriter 的单目标 0.99、两目标 0.94、计数 0.81、颜色 0.88、位置 0.64、颜色属性 0.63；加 rewriter 后为 0.98、0.95、0.84、0.95、0.78、0.77。这显示推理增强主要提升了计数、颜色、位置等复杂语义绑定能力。WISE 子项中，BAGEL 在 Space 维度上得到 0.68，加 CoT 后提升到 0.75；Chemistry 从 0.39 提升到 0.58，是所有维度中提升最大的之一，说明世界知识类生成特别受益于语言推理轨迹。

**最关键的消融**是 Figure 7 中的 ViT 作用：在经典 GEdit-Bench 上移除 ViT tokens 影响很小，但在 IntelligentBench 上移除 ViT 导致分数下降 16%。这直接支持论文论点：复杂编辑不是纯像素操作，而是依赖视觉语义推理；ViT 提供理解侧的语义上下文，生成侧 VAE 只负责像素重建。如果没有 ViT，模型只能依赖 VAE 条件，在需要世界知识或多步推理时表现显著变差。

另一个重要消融是 Figure 3 的架构对比：在 1.5B 模型、相同数据和超参下，MoT 比 MoE 和 Dense 在 MSE loss 上收敛更快、最终更低；CE loss 也整体更优。这证明参数完全解耦（而不是只复制 FFN）能更有效缓解理解与生成目标的冲突。图 3 实验的采样比为生成:理解 = 4:1，说明该结论在生成主导的数据混合下成立。

数据比例和学习率消融也很关键。Figure 5 显示，从 1g1u 提高到 4g1u，MSE loss 稳定下降约 0.4% 绝对值，而 CE loss 没有一致模式，说明生成数据应被更频繁采样。Figure 6 显示大学习率加快 MSE 收敛，小学习率有利于 CE，两者对学习率有相反响应，因此最终采用固定权重而非统一学习率折中。

**尚未证明的主张**：涌现曲线的定义依赖历史 checkpoint 的 benchmark 分数，论文自己承认评测指标可能非单调，可能导致伪涌现。虽然定性可视化（Figure 8、9）显示 3.5T 之后智能编辑行为发生明显变化，但未做严格统计检验。世界建模能力（导航、旋转、多帧生成）主要靠定性展示，没有自动定量指标。RLHF 在失败案例中被提到“可以改善”，但论文没有训练或验证。BAGEL 1.5B 的定性优势也未给出定量分数。视频生成部分没有像 T2I 那样的标准基准分数。

## 9. 与前作怎么选

**BAGEL vs Janus-Pro**：Janus-Pro 是量化自回归统一模型，使用离散视觉 token，训练和推理相对简单，可以直接复用 LLM 基础设施，但其生成质量受 tokenizer 限制，在复杂指令、文字渲染和空间关系上较弱。BAGEL 使用整流流 + VAE，生成质量更接近专用扩散模型。如果目标是简单接入现有 LLM 工具链、做快速原型，Janus-Pro 更轻；如果需要更高质量的生成、复杂编辑以及长上下文多模态推理，选 BAGEL。GenEval 上 Janus-Pro 7B 为 80%，BAGEL 为 82%（不加 rewriter）和 88%（加 rewriter），有一定优势，但 BAGEL 的训练和推理成本更高。

**BAGEL vs MetaQuery-XL**：MetaQuery-XL 是外部扩散器方案，LLM 冻结，只训练少量 adapter，训练成本低，理解侧直接复用 Qwen2.5-VL。但其上下文被压缩成少量条件 token，不适合长序列、多图像推理和复杂编辑。BAGEL 无瓶颈，长上下文交互更充分。在 WISE 上，MetaQuery-XL 0.55，BAGEL 0.52，但 BAGEL 加 CoT 达 0.70。如果数据少、算力有限，且主要做标准理解/生成评测，MetaQuery-XL 性价比较高；如果要探索世界建模、长上下文编辑和推理增强生成，BAGEL 更具潜力，但需要大规模数据和训练资源。

**BAGEL vs Transfusion**：Transfusion 是集成 Transformer 的早期代表，用单一 Dense Transformer 融合文本预测和扩散图像生成。BAGEL 继承了无瓶颈思想，但用 MoT 分离理解与生成专家、加入双视觉编码器、广义因果注意力和大规模交错数据，并加入推理增强数据。Transfusion 在 GenEval 上 0.63（Table 5），远低于 BAGEL 82%。选型上，BAGEL 是 Transfusion 的工程化加强版。若已有 Transfusion 代码但生成质量不足，可考虑迁移到 MoT + 交错数据，但需要重新设计和验证数据管道，成本显著上升。

**BAGEL vs Chameleon**：Chameleon 是早期混合模态早期融合模型，全部模态都用自回归处理。其理解能力较弱（MMMU 28.4、MM-Vet 8.3），生成也一般。BAGEL 与它的共同点是共享 backbone，但 BAGEL 的 VAE+整流流路径和交错数据管道使其远超 Chameleon。除非有特殊理由坚持全自回归视觉生成，否则在需要统一理解与生成的场景中不推荐 Chameleon。

## 10. 工程判断：可行性、风险与上限

**数据**：Table 1 给出静态数据集规模：文本 400M 数据 / 0.4T tokens，图像-文本对理解 500M / 0.5T，图像-文本对生成 1600M / 2.6T，交错理解 100M / 0.5T，视频交错生成 45M / 0.7T，网页交错生成 20M / 0.4T。但这些是数据集总量，实际训练 token 数因随机采样而不同。数据构造管线非常重：视频要经过镜头检测、去黑边/logo、清晰度、运动稳定性、CLIP 去重；网页要经过两阶段主题分类、fastText 分类器、规则过滤；图像 captioning 使用 Qwen2.5-VL-7B，蒸馏成本可观。论文未披露数据采集的版权情况、语言分布、去重比例或具体爬取时间窗口，这在实际复现时会带来合规和工程风险。

**算力/延迟**：总训练 token 数约 5.2T（PT 2.5T + CT 2.6T + SFT 72.7B + Alignment 4.9B），序列长度 32K–45K。模型激活参数 7B，总参数 14B。论文完全未披露 GPU 型号、数量、训练时长、吞吐率或单步延迟。基于公开信息只能推测训练资源极大：上万亿 token、长序列、两个完整专家和 FlexAttention 自定义 mask 意味着需要大规模多卡并行，且动态分段注意力可能引入额外通信和工程复杂度。推理时生成图像需要整流流多步去噪，步数未披露；CFG 需要额外无条件前向，几乎使生成成本翻倍。对 7B 激活模型，实时交互需要大量算力优化和推理框架支持。

**实现难点**：广义因果注意力 mask 的动态分段、跨模态 KV 替换、diffusion forcing 的分组全注意力、双编码器原生分辨率处理、QK-Norm 的稳定训练、MoT 参数初始化和硬路由、训练中 CE/MSE 学习率冲突的调参，以及数据构造中 VLM 蒸馏、caption-first 策略和推理增强样本生成的噪声控制，都是高风险点。此外，用 FlexAttention 实现时还需保证与 FlashAttention 类似的性能，论文只报出约 2 倍加速，但没有说明不同 mask 模式下的 memory 占用。

**失败环节**：Figure 17 显示，特殊 IP 生成、复杂文本渲染、精细人体姿态、多实例同时生成仍是难点；图像编辑中的物体位置交换、大量实例同时修改、去模糊等操作也失败。在复杂场景中，BAGEL 与 Gemini 2.0 都有指令遵循不准的问题，GPT-4o 则更稳定。论文建议通过增加含文字图像数据、扩大模型容量、在最终后训练阶段应用 RLHF 来改善，但这些均未在论文内实验验证。

**监控信号**：训练期主要看 CE loss 和 MSE loss 是否平稳下降、是否有尖峰；下游看 MME、MMBench、MMMU、MM-Vet、MathVista、GenEval、GEdit、IntelligentBench 等。论文强调 loss 曲线不能预测能力涌现，因此需要在多个历史 checkpoint 上定期跑复杂编辑基准，而不能只看训练损失。

**指标上限**：在 WISE 上 BAGEL 加 CoT 达 0.70，仍低于 GPT-4o 的 0.80；IntelligentBench 加 CoT 55.3，低于 GPT-4o 78.9；GEdit-Bench 也低于 GPT-4o。这说明开源模型在复杂推理生成与世界知识整合上仍有系统性差距。论文没有提供任何安全评估、多模态内容政策或模型风险分析。

**未回答问题**：推理采样步数、吞吐与延迟；更大模型（如 70B 激活）的扩展规律；RLHF/RL 后训练的实际效果；视频生成的自动评测指标；数据混合比例的科学依据（只有 1.5B 规模下的启发式结果）；涌现的统计显著性检验；以及 MoT 架构在不同数据分布下是否一致优于 Dense/MoE。

## 11. 放回研究脉络并收束

BAGEL 位于“统一多模态模型”演进链条的后半段。从 Chameleon 的早期全自回归、Janus 的双视觉编码器解耦、Transfusion 的整流流与文本预测融合、MetaQuery-XL 的外部扩散器，到 LlamaFusion、MetaMorph 等 MoE 探索，研究者一直在寻找既能保持理解质量又不牺牲生成质量的结构。BAGEL 的主要推进是把 MoT 参数分离、双视觉编码器、广义因果注意力、大规模交错数据和显式推理增强数据组合在一起，并在 5.2T tokens 规模上系统展示能力涌现。它没有提出某一全新模块，而是把多个已有组件做大规模工程验证。研究脉络上，它呼应了“瓶颈越少，统一模型越可扩展”的观点，同时用历史 checkpoint 的涌现曲线主张复杂多模态推理不能靠小规模微调获得。其数据构造协议——视频 inter-frame caption、网页 caption-first、VLM 蒸馏、CoT 增强——对后续统一模型研究具有独立参考价值，但同时也暴露出大量未公开的工程细节和评测不确定性。

**读完必须记住的 5 件事：**

1. BAGEL 是 7B 激活/14B 总参数的 decoder-only MoT 模型，理解与生成专家共享 self-attention，但 FFN 硬路由分离；采用 SigLIP2 ViT + FLUX VAE 双编码器。
2. 广义因果注意力：文本内部因果、视觉内部双向、后续 split 可看前面 split；训练中每幅图像有加噪 VAE、干净 VAE、ViT 三套 token，推理时缓存并替换 KV。
3. 大规模交错数据是核心：视频和网页数据分别提供时序物理连续性和真实世界知识；数据构造包括视频 inter-frame caption 和网页 caption-first 策略。
4. 涌现曲线显示：理解约 0.18T、生成约 0.68T、经典编辑约 2.64T、智能编辑约 3.61T tokens 才达到 85% 峰值性能；移除 ViT 使智能编辑下降 16%。
5. Self-CoT 对复杂任务提升显著：WISE 从 0.52 到 0.70，IntelligentBench 从 44.9 到 55.3，说明语言推理轨迹可以作为中间表示统一理解与生成。

**5 道自测题：**

1. BAGEL 为什么选择 MoT 而不是 Dense 或 MoE？图 3 提供了什么证据？
2. 在训练一个包含多幅图像的生成样本时，加噪 VAE、干净 VAE 和 ViT tokens 各自的注意力可见性是什么？
3. 什么是扩散强制（Diffusion Forcing）？它在多图像/视频训练中如何工作？
4. 论文如何定义“涌现能力”？哪些任务的 85% 饱和 token 数最晚出现？这能严格证明涌现吗？
5. 如果不允许使用 LLM rewriter，BAGEL 在 GenEval 上比 Janus-Pro 高多少？加上 rewriter 后是多少？

最终一句话总结：BAGEL 用无瓶颈 MoT 和大规模交错多模态数据，让理解与生成在同一 Transformer 中产生可观测的复杂推理涌现，但距离 GPT-4o 仍有系统性差距，且许多世界建模与推理增益仍依赖定性和 CoT 辅助。
