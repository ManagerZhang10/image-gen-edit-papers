# 大白话深读《arm-unified》

## 1. 30 秒定位

ARM 是一篇提出统一离散表示的自回归多模态大模型论文，核心目标是用一个 7B 的自回归 Transformer 同时完成图像理解、图像生成和指令式图像编辑，而不是像 Janus-Pro 或 Bagel 那样为理解和生成各配一套视觉编码器。论文的关键做法是三步：先训练一个“语义视觉 tokenizer”，把图像变成既保留语言对齐语义、又保留低层外观细节的离散 token；再用这些 token 和文本 token 交叠做 next-token prediction 预训练；最后用 GRPO 强化学习直接优化生成和编辑的偏好目标。论文显示，ARM 在理解上 POPE 87.3、MMMU 40.2，生成上 GenEval 0.79，编辑上 GEdit-Bench-EN G_O 5.75，RL 后分别提升到 0.86 和 6.68，且 RL 出现了跨任务正向迁移。推理时，生成的视觉 token 交给一个从 FLUX.1 [dev] 初始化的 latent diffusion decoder 做渲染，条件为视觉 token 而非文本，推理采用 28 步 rectified flow 去噪。这一结构的价值在于不再把视觉理解和生成拆成两套隐性空间，推理时也不需要同时携带两种视觉嵌入，同时离散 token 让偏好优化可以直接沿用语言模型的 token 级策略（§3.3, Table 4-6）。

## 2. 为什么这篇论文会出现

论文的背景矛盾来自“统一多模态模型”的两难。早期视觉语言模型，如 LLaVA-OneVision 和 Qwen2.5-VL，用连续的语义视觉编码器完成理解，但这类特征缺乏重建图像所需的细节，因此生成时往往要外接独立扩散模型（如 Next-GPT、SEED-X）。另一些工作，如 Chameleon、Emu3、Show-o，直接用 VQ-VAE 类重建 token 做统一自回归，但这类 token 的语义对齐弱，导致理解能力下降：例如 Table 3 中 Emu3 的 MMMU 只有 31.6，Chameleon 只有 22.4，远低于连续模型（Bagel 55.3、BLIP-3o 50.6）。为了同时取得理解和生成，Janus-Pro、Bagel、Mogao 干脆使用两套视觉编码器，理解用语义编码器，生成用重建编码器，但这带来了结构碎片化：模型必须额外学习桥接两个视觉表征空间，推理时还要在上下文中同时携带同一输入的冗余视觉嵌入，产生额外计算开销。论文指出，这类双编码器设计在编辑任务中尤其明显，上下文要同时携带两套视觉嵌入，推理开销量级增大（§1）。

ARM 的出发点就是用一个离散视觉 tokenizer 替代这两套编码器。它不再用 VQ-VAE 纯重建，也不只用 CLIP/SigLIP 纯语义特征，而是以 SigLIP2 的语义特征为底子，经过 FSQ 离散化，并同时用 caption、重建、对比和蒸馏四种损失约束 token，使 token 空间既保留识别语义，又保留生成细节。随后用 7B Qwen2.5 作为统一自回归骨干，再加 GRPO 强化学习优化视觉 token 的预测。论文特别强调，离散 token 让 RL 可以直接做 token 级策略优化，而连续扩散模型通常需要额外构造可微的生成目标。这试图解决的核心问题是：找到一个不牺牲理解、同时能保持生成和编辑质量、又不过度增加结构复杂度的统一视觉表征。相关工作也表明，纯生成导向 token 往往会显著牺牲理解性能（§1 指出 generation-oriented visual tokens compromise understanding performance），因此 ARM 的互补多目标监督是一个有针对性的方案。

## 3. 读懂前需要的最小概念

要理解 ARM，需要先准备几个基础概念。

**自回归 next-token prediction**：这是语言模型的基础，给定前面 token 预测下一个 token 的概率。ARM 把图像也转成 token，所以整条多模态序列可以用同一个交叉熵损失建模，如式 (6) 的 \(\mathcal{L}_{\mathrm{ARM}}=-\sum_{j=1}^M \log p_\theta(y_j\mid y_{<j})\)。图像理解是“视觉 token → 文本 token”，文本到图像生成是“文本 token → 视觉 token”，编辑是“参考视觉 token + 指令文本 → 新视觉 token”，三者在数学上完全统一。

**离散视觉 tokenizer**：把连续图像压缩成一维离散整数序列的模块。与 VAE 连续隐变量不同，离散 token 可以被自回归模型直接采样。ARM 使用 Finite Scalar Quantization（FSQ），即对每个标量做离散分桶，不使用显式 codebook。论文设置 \(L_i=2\) 对 \(1\le i\le16\)，对应约 65K 的 codebook 容量（§4.1）。FSQ 的好处是避免了显式 codebook 训练中的 codebook collapse 问题，但代价是量化误差需要靠语义和重建损失共同补偿。

**语义对齐与重建损失的张力**：CLIP/SigLIP 一类语义编码器适合识别，VQ-VAE 适合重建，但两者目标不同。ARM 的四个损失各自拉向一端：caption 损失把视觉 token 喂给语言模型去生成文本，强制 token 携带可被语言模型读取的语义；pixel reconstruction 损失强制 token 保留像素级信息；sigmoid 对比损失把量化视觉向量与 SigLIP2 文本向量对齐；feature distillation 损失让量化向量靠近原始 SigLIP2 视觉特征。后两个是语义正则化。论文 Table 7 显示，只用 caption+pixel 时 ImageNet zero-shot 仅 0.2，加入语义正则后骤升到 80.2，但 sigmoid 损失会轻微降低 PSNR（从 15.2 降到 9.3），说明两者需要小心平衡。

**扩散解码器**：ARM 生成的视觉 token 不是直接还原像素，而是作为条件给一个潜空间扩散模型（FLUX.1 [dev]），由扩散模型完成像素渲染。推理时扩散模型以 28 步采样，CFG 1.5，从噪声潜变量逐步去噪得到图像潜变量，再经 VAE 解码。这个解码器在训练时用一个独立的 latent DiT 模型，用式 (5) 的 rectified flow 目标学习从高斯噪声到图像潜变量的传输，条件输入是量化视觉 token \(z_q\)，替代了原始 FLUX 的文本条件。

**GRPO**：Group Relative Policy Optimization，是一种策略优化方法。ARM 对同一 prompt 采样 K=16 条视觉 token 序列，解码成图后用 GPT-o3 或 GPT-4.1 打分，在组内归一化得到优势，再按式 (7) 更新。注意 RL 只优化视觉 token 预测，不更新文本 token 输出和基于文本的理解能力。RL 的参考策略 \(\pi_{\mathrm{ref}}\) 是 SFT checkpoint 的冻结副本，KL 系数 0.01，clip ratio 0.2，保证策略更新不会偏离太远。

## 4. 方法全景：先看数据流

先看训练和推理的总体数据流。训练阶段分为 tokenizer 训练、detokenizer 训练、自回归主模型训练、RL 四大部分，但它们的数据流都围绕同一个离散 token 展开。推理时则是从输入到输出的单向流程。

```
[训练阶段 A：统一视觉 tokenizer]
图像 x ──> 冻结 SigLIP2 编码器 ──> 连续视觉特征 z
      ──> 投影模块(6层 attention) ──> 低维新特征
      ──> FSQ 量化 ──> 离散整数 code c
      ──> 对称投影模块 ──> 量化重建向量 z_q
             │
             ├─ 通过语言模型 Qwen2.5-0.5B 预测 caption  -> L_cap
             ├─ 通过轻量 Pixel DiT(24层) 做像素级 rectified flow -> L_pix
             ├─ 与 SigLIP2 文本向量做 sigmoid 对比           -> L_sig
             └─ 与原始 SigLIP2 视觉特征做余弦蒸馏           -> L_feat

[训练阶段 B：Latent Diffusion Detokenizer]
图像 x ──> 预训练 VAE 编码 ──> 潜变量 z1
视觉 token z_q ──> 替换 text condition 的 FLUX latent DiT
      ──> 预测 rectified flow 速度 v = z1 - z0 -> L_Detok (式5)

[训练阶段 C：自回归 7B 主模型]
图像输入 ──> 训练好的视觉 tokenizer ──> 视觉 token
文本输入 ──> 文本 tokenizer ──> 文本 token
交叠拼接成序列 [t1, img1_token, ..., t2, ...]
      ──> Qwen2.5-7B + 附加视觉输出线性层
      ──> next-token prediction 损失 L_ARM
      ──> 对视觉输出 token 也在同一交叉熵约束下优化

[训练阶段 D：RL 偏好优化]
prompt/参考图 ──> 主模型采样 K=16 条视觉 token 序列
      ──> 视觉 token 经 latent diffusion decoder 解码成图
      ──> GPT-o3 / GPT-4.1 奖励模型打分
      ──> 组内归一化 advantage -> GRPO 更新(仅视觉 token 部分)

[推理]
文本 prompt / 参考图 ──> 文本/视觉 tokenizer ──> token 序列 + shape token
      ──> 7B AR 逐 token 生成文本或视觉 token
      ──> 若为视觉 token：送入 FLUX latent DiT，28步 rectified flow 去噪
      ──> VAE decoder ──> 最终图像
      ──> 若为文本 token：普通文本 detokenizer
```

核心组件拆解如下。

**冻结 SigLIP2 视觉编码器**：输入一张图像，输出连续视觉特征。具体为 SigLIP2-SO400M-512 编码器（§4.1），训练时冻结以稳定优化，避免语义空间被重建任务破坏。输出特征维度较高，进入投影模块。目的是提供强语义先验：SigLIP2 本身经过语言-图像对比预训练，其视觉特征已具备良好的识别能力。

**投影模块与 FSQ**：投影模块由 6 个 transformer block 组成，把 SigLIP2 特征映射到紧凑低维子空间，然后 FSQ 对每个标量做离散分桶，\(L_i=2\)，得到离散 token。FSQ 没有显式 codebook，但容量由各维度量化级别乘积决定，约 65K。量化后还有对称投影模块把离散向量映射回原维度，供重建和对比损失使用。论文未披露投影模块的输出维度，但 FSQ 的 16 维和每个维度 2 级量化说明 token 表示是 16 维二值化标量。

**四个 tokenizer 损失**：caption 损失用冻结的 0.5B Qwen2.5 作为条件语言模型，给定 \(z_q\) 预测文本 caption，强制视觉 token 保留语言可读语义；pixel 损失训练一个 24 层 DiT 在像素空间学习 rectified flow，直接重建原始图像，避免 VAE 有损瓶颈；sigmoid 对比损失把 \(z_q\) 对齐到对应 SigLIP2 文本嵌入；feature 蒸馏损失把 \(z_q\) 拉向原 SigLIP2 视觉特征。权重为 \(\lambda_{cap}=1,\lambda_{pix}=5,\lambda_{sig}=5,\lambda_{feat}=1\)（式 4）。训练数据为 2.2B 内部图像文本对，global batch size 32768，优化器 AdamW，lr \(3\times10^{-4}\)，\(\beta_1=0.9\)，\(\beta_2=0.95\)（§4.1）。

**Latent Diffusion Detokenizer**：一个独立高容量模型，从 FLUX.1 [dev] 初始化，把视觉 token \(z_q\) 作为条件，用潜空间 rectified flow 生成目标图像潜变量。它替代原来 FLUX 的文本条件，训练目标是式 (5)。推理时负责把离散 token 渲染为真实像素。论文指出，像素级 DiT 只提供监督以保留细节，但真正的高质量 detokenization 交给这个 latent DiT，两者分工明确（§3.1）。

**7B 自回归主模型**：从 Qwen2.5-7B 初始化，增加一个线性层用于预测视觉 token。训练时把所有模态 token 拼成最长 80K 的序列，做统一 next-token prediction。视觉 token 的输入和输出使用同一 tokenizer，保证理解与生成共享隐空间。模型支持动态分辨率，通过插入 shape token 指定离散 token 网格的高度和宽度（§4.1）。

**GRPO RL 模块**：策略 \(\pi_\theta\) 从 SFT 模型初始化，参考策略 \(\pi_{\mathrm{ref}}\) 是同一 checkpoint 的冻结副本。只优化视觉 token 预测，奖励模型因任务而异：T2I 用 GPT-o3 检查物体外观、属性和空间关系，编辑用 GPT-4.1 检查指令遵循、非目标区域保持和整体质量。K=16，temperature 0.7 或 1.0，top-K 1000，top-P 1.0，KL 系数 0.01，clip ratio 0.2（Table 2）。

## 5. 核心公式与直觉

只需要掌握四个公式即可理解 ARM 的关键机制。

**式 (1)：caption 损失**
\[
\mathcal{L}_{\mathrm{cap}} = -\sum_{i=1}^{N} \log p_\phi(y_i\mid z_q, y_{<i})
\]
其中 \(y_i\) 是图像对应 caption 的文本 token，\(z_q\) 是量化视觉向量，\(\phi\) 是冻结的 0.5B Qwen2.5 语言模型，\(N\) 是文本长度。这个损失的直觉是：如果视觉 token 真的携带了足够语义，那么一个冻结的、没见过的语言模型应该能根据它描述图像。它防止 tokenizer 只学会重建纹理却丢失“这是猫还是桌子”这类高层语义。工程上，caption 损失要求提供大规模图像-文本对，这里用了 2.2B 内部图文对，确保了语言模型可以基于 \(z_q\) 生成合理的文本。

**式 (2)：像素重建损失**
\[
\mathcal{L}_{\mathrm{pix}} = \mathbb{E}_{t,x_0,x_1} \left\| D_{\mathrm{pix}}(x_t,t\mid z_q) - (x_1-x_0)\right\|_2^2
\]
其中 \(x_1\) 是目标图像，\(x_0\) 是高斯噪声，\(x_t=t x_1+(1-t)x_0\) 是线性插值，\(t\sim\mathcal{U}[0,1]\)，\(D_{\mathrm{pix}}\) 是轻量 24 层 DiT。这个损失让视觉 token 保留像素级外观细节，直接优化像素空间而不是 VAE 潜空间，避免 VAE 有损压缩导致细节丢失。直觉是：token 必须包含足够信息，让一个小扩散网络仅凭 \(z_q\) 就能还原原图。论文指出，该损失与 GAN 风格解码器相比优化更稳定（§3.1）。

**式 (6)：主模型 next-token prediction**
\[
\mathcal{L}_{\mathrm{ARM}} = -\sum_{j=1}^{M} \log p_\theta(y_j\mid y_{<j})
\]
其中 \(M\) 是整条多模态 token 序列长度，\(\theta\) 是 7B AR 模型参数。这个公式就是把文本和视觉 token 统一看成离散序列，用标准交叉熵学习。关键在于视觉 token 输入和输出共享同一离散词表，因此理解（图像输入→文本输出）和生成（文本输入→图像输出）在数学上没有本质区别。此外，该损失在最长 80K 的序列上训练，支持交错生成和长上下文建模。

**式 (7)：GRPO 目标**
\[
\mathcal{L}_{\mathrm{GRPO}} = \frac{1}{K}\sum_{k=1}^{K} \left[ \min\left(\rho_k A_k, \mathrm{clip}(\rho_k,1-\epsilon,1+\epsilon)A_k\right) - \beta \mathcal{D}_{\mathrm{KL}}(\pi_\theta(y_k\mid x)\|\pi_{\mathrm{ref}}(y_k\mid x)) \right]
\]
其中 \(\rho_k=\frac{\pi_\theta(y_k\mid x)}{\pi_{\mathrm{old}}(y_k\mid x)}\) 是概率比，\(A_k\) 是组内归一化后的优势，\(K=16\)，\(\beta=0.01\)，\(\epsilon=0.2\)。这个损失让模型提高获得高奖励的视觉 token 序列的概率，同时用 KL 惩罚防止策略偏离参考模型太远。它只对视觉 token 部分回传梯度，所以文本理解能力保持稳定。论文在 §3.3 明确“optimization is applied only to the visual token prediction”。

式 (3) 和式 (4) 的细节在此不展开，只需知道 sigmoid contrastive loss 和 feature distillation 是语义正则项，权重分别为 5 和 1。sigmoid loss 使用可学习的标量 \(\tau\) 和 \(b\) 来缩放和偏移 logits，feature loss 直接最小化量化向量 \(z_q\) 与原始 SigLIP2 视觉特征 \(z\) 的余弦距离。

## 6. 训练到底怎么跑

训练不只是一个阶段，而是四个阶段。这里按“一个训练 step”的粒度拆开，同时给出每阶段的规模与超参。

**第一阶段：统一视觉 tokenizer 训练的一个 step。** 从 2.2B 图文对中采样一个 batch，global batch size 为 32768。一步内，图像经过冻结 SigLIP2 编码器得到连续特征，投影并 FSQ 量化得到 \(z_q\)；用 \(z_q\) 分别计算四个损失：caption 损失通过冻结的 0.5B Qwen2.5 生成文本；pixel 损失用 24 层 DiT 在像素空间做 rectified flow 去噪；sigmoid 损失对 \(z_q\) 和 batch 内文本嵌入做对比；feature 损失让 \(z_q\) 靠近原 SigLIP2 特征。四个损失按 \(1,5,5,1\) 加权求和，反向传播更新投影模块、FSQ 相关可学习参数、Pixel DiT 和两个对比损失的标量参数，SigLIP2 编码器冻结。优化器 AdamW，lr \(3\times10^{-4}\)，\(\beta_1=0.9\)，\(\beta_2=0.95\)。论文明确全局 batch size 为 32,768，未披露训练步数，但数据规模为 2.2B 图文对（§4.1）。

**第二阶段：Detokenizer 训练。** 用训练好的 tokenizer 得到 \(z_q\)，然后训练从 FLUX.1 [dev] 初始化的 latent DiT，把 \(z_q\) 替换原来的文本条件，用式 (5) 的潜空间 rectified flow 目标更新。这个阶段与 tokenizer 训练分离，目标是让高容量扩散模型学会仅根据离散 token 渲染图像。论文未明确披露 detokenizer 的学习率、batch size 和训练步数，但可以推断该阶段只更新 FLUX 模型的参数，不更新视觉 tokenizer。

**第三阶段：自回归主模型 7B 训练。** 分预训练、持续训练、SFT 三个子阶段，都以一个 step 为单位。一个 step 里，从多模态数据中采样序列，文本 token 和图像 token 交错排列，最长 80K。输入到 Qwen2.5-7B 加额外线性层，计算式 (6) 的交叉熵损失，更新所有模型参数（包括附加线性层）。预训练用 2.5T token，学习率 \(2\times10^{-4}\)，200 个 GPU，训练 100K step，图像分辨率 256 或 512；持续训练再 2.5T token，分辨率提升到 512/1024，100K step，160 GPU；SFT 用 0.2B 高质量指令 token，学习率 \(5\times10^{-5}\)，40K step，80 GPU。重量衰减为 0，梯度范数裁剪 1.0，warmup 预训练和持续训练各 2K step，SFT 无 warmup。数据采样比例如 Table 1：预训练 T2I 数据占比 0.70，文本只占 0.05，Image2Text 0.10，video interleaved gen 0.10，web interleaved gen 0.05；持续训练 T2I 降为 0.55，interleaved 增至各 0.15；SFT T2I 0.50，interleaved 各 0.20，Image2Text 0.05。图像生成和编辑的分辨率限制通过插入 shape token 来显式指定目标高度和宽度（Table 1）。

**第四阶段：RL 训练的一个 step。** 用 GRPO，初始化策略 \(\pi_\theta\) 来自 SFT，参考策略 \(\pi_{\mathrm{ref}}\) 为同一权重的冻结副本。一个 step 中，采样一个 batch 的 prompt，每个 prompt 让当前策略采样 K=16 条视觉 token 序列，解码成图，用 GPT-o3（T2I）或 GPT-4.1（编辑）作为奖励模型打分，计算组内归一化优势，然后按式 (7) 更新视觉 token 预测相关的参数。RL 分 T2I RL、Edit RL 和 Joint RL，具体超参见 Table 2：T2I RL lr 3e-5，8 GPU，280 step，batch 64；Edit RL lr 5e-5，40 GPU，100 step，batch 40；Joint RL lr 5e-5，200 step。KL 系数 0.01，clip ratio 0.2，采样 temperature 0.7（T2I）或 1.0（编辑），top-K 1000，top-P 1.0，rollout 恒为 16，weight decay 0.01。

论文提到 RL 使用的是 VeRL 框架（§4.1），奖励模型为 GPT-o3（T2I）和 GPT-4.1（编辑），混合 RL 则使用 Mixed 奖励模型（Table 2）。T2I RL 提示词来自 ImageNet 类别名合成短组合 prompt 和 Share-GPT-4o 的长密集 prompt，编辑 RL 提示词来自 HQ-Editing-6000 和 Share-GPT-4o。

## 7. 推理到底怎么跑

推理根据任务不同，但总体是一条自回归生成路径，没有 RL 或梯度更新。

**图像理解**：输入一张图和问题文本。图像经过训练好的视觉 tokenizer（SigLIP2 → 投影 → FSQ → 投影），得到离散视觉 token；文本经过正常文本 tokenizer。两者拼接后喂给 7B AR 模型，模型逐 token 生成文本。生成到结束符后，文本 token 被普通文本 detokenizer 还原为自然语言。整个过程只运行 AR 模型一次前向的序列生成，不经过 diffusion decoder。

**文本到图像生成**：输入一个文本 prompt。先根据目标分辨率在 prompt 中插入 shape token，指定离散 token 网格的高度和宽度。文本 token 送进 7B AR 模型，逐个采样视觉 token。采样时可以使用 classifier-free guidance：论文对 AR 模型设置 CFG 1.5，但 Figure 4 显示即使去掉 CFG，模型仍能生成主体正确的图像，只是纹理和杂讯略多。生成完所有视觉 token 后，将这些 token 作为条件输入 FLUX.1 [dev] latent DiT decoder，该解码器从高斯噪声潜变量出发，经过 28 步 rectified flow 去噪，CFG 1.5，得到图像潜变量，再经预训练 VAE decoder 得到像素图像。文本 token 阶段如果出现则直接输出。对于 1024×1024 的图像，论文在 GenEval、DPG、WISE 基准上均采用此分辨率（§4.1）。CFG 在 AR 模型和 diffusion decoder 中通常分别设为 1.5 和 1.5，但 Figure 4 表明 AR 模型可以弱化甚至关闭 CFG，而 diffusion decoder 若关闭 CFG 仅局部纹理如头发会退化，主体语义仍由视觉 token 保持。

**指令式编辑**：输入一张参考图和一条编辑指令。参考图先被视觉 tokenizer 转成视觉 token，作为条件拼入序列；编辑指令作为文本 token 输入。AR 模型在文本指令和参考视觉 token 的双重条件下生成新的视觉 token。论文采用 two-branch guidance，分别对文本指令和参考图像设置 guidance scale 1.5 和 1.25，以加强指令遵循和内容保持。生成的视觉 token 同样送进 diffusion decoder 渲染为图像。GEdit-Bench 推理保持原始图像分辨率，以匹配基准协议，而不是固定为 1024（§4.1）。在编辑任务中，若参考图分辨率与训练不匹配，shape token 用于指定输出尺寸，参考图的分辨率可动态变化（Table 1 中编辑分辨率支持 512 到 980/1024）。

**关键点**：推理时只有 AR 模型和扩散解码器两个模型参与，不再有独立的连续视觉编码器用于理解。生成阶段 AR 模型可弱化甚至去掉 CFG，因为语义 token 已经提供了较强条件信号；扩散解码器主要负责渲染细节。这一性质说明合理设计的语义离散 token 可以减少自回归生成对 CFG 的依赖，从而省去 AR 侧额外的条件前向计算，加速推理（Figure 4）。

## 8. 实验和消融到底证明了什么

论文的实验主要回答四个问题：统一离散模型能否接近连续模型的理解？生成和编辑是否能达到可比扩散模型？四个 tokenizer 损失是否都必要？RL 是否真的带来跨任务增益且不损害理解？

**最关键消融**是 Table 7 的 tokenizer 四损失组合。事实证明：只用 caption 和 pixel 损失时，ImageNet zero-shot 只有 0.2，说明视觉 token 几乎没有可迁移的语义；加入 sigmoid 对比或 feature 蒸馏后，语义识别骤升到 79.4 或 58.1，且 PSNR 也分别变化：加入 sigmoid 后 PSNR 降低到 9.3，加入 feature 蒸馏后 PSNR 提高到 17.1。最终四损失联合得到 80.2 的 INet ZS 和 19.6 的 PSNR，视觉 token 既保留了重建细节，又具备语言对齐语义。这直接支持 ARM 的核心前提：单个 tokenizer 可以通过互补监督同时服务理解和生成，而不必像 Janus/Bagel 那样解耦。表格中的 codebook usage 和 perplexity 也显示四损失方案下词汇利用率最高（75.6，PPL 0.28），说明 token 空间的表达力更强。

**尚未证明的主张**。论文表明 RL 生成和编辑性能提升，并观察到理解保持稳定，但没有提供人类偏好 A/B 测试，也没有证明 RL 在更大规模或真实用户反馈下仍稳定。论文的“RL 带来跨任务 synergy”基于 Table 8 的有限 RL 数据（最多几百步、小 batch：T2I RL 280 step，batch 64；Edit RL 100 step，batch 40；Joint RL 200 step，batch 40），无法排除奖励模型偏差或早期过拟合的影响。此外，论文没有展示 tokenizer 在极高分辨率图像（如 4K）或复杂文本渲染上的定量上限，也没有做 scaling law 实验，所以“可扩展基础”的结论更多是方向性的，而非实验充分支撑的。编辑结果中 ARM-RL G_O 6.68 仍低于 Step1X-Edit 6.70，说明统一离散模型尚未在编辑上完全超越专门编辑模型。理解上 MMMU 40.2 与 Bagel 55.3 的差距说明离散 token 在知识密集推理上仍有损失。论文未披露主模型 RL 后理解分数为何没有下降的机制分析，仅报告了 Table 8 的保持现象。

## 9. 与前作怎么选

与 ARM 最接近的方案有三类。

**第一类：连续解耦模型，如 Janus-Pro、Bagel。** Janus-Pro 用两个视觉编码器分别服务理解和生成，因此理解分数高（POPE 87.4、MMMU 41.0），生成 GenEval 0.80；Bagel 更是到了 MMMU 55.3、GenEval 0.82。但代价是结构复杂，编辑时需要同时携带两种视觉嵌入，推理开销大。如果应用场景以单一任务为主，比如只做高质量文本生成图，或者理解任务优先且可容忍双编码器，选 Janus-Pro/Bagel 更直接；如果强调一个模型统一处理三种任务，且希望推理时无冗余视觉路径，ARM 更合适。从 Table 3 看，ARM 在 MMMU 上仍落后 Bagel 15.1 个百分点，说明单纯统一离散表示的上限尚不及连续解耦模型。

**第二类：离散统一但重建导向，如 Emu3、VILA-U、UniTok。** 这些工作也用离散 token 做统一自回归，但 token 语义对齐较弱，理解成绩较差。Emu3 MMMU 仅 31.6，VILA-U 未报告 MMMU 但 POPE 85.8 低于 ARM 的 87.3。如果只需要生成，不关心理解，Emu3 的纯重建 token 可能更容易训练；如果要求理解与生成平衡，ARM 的语义 tokenizer 明显更优。VILA-U 和 UniTok 虽然也联合优化图像文本对齐和重建，但未达到 ARM 的四损失组合及 RL 带来的提升，Table 3 显示两者 POPE 分别为 85.8 和 83.2，低于 ARM。

**第三类：混合扩散或非自回归模型，如 Show-o、Qwen-Image、FLUX。** Show-o 用非自回归 mask 生成，GenEval 0.68，低于 ARM；Qwen-Image 是连续扩散生成，GenEval 0.87、WISE 0.87，生成质量高于 ARM，但不做统一理解。如果生成质量是唯一目标，且可以接受扩散模型无法直接做视觉理解，Qwen-Image 或 FLUX 可能是更强选择；如果需要在同一模型内完成理解、生成和编辑，并希望利用语言模型的推理和 RL，ARM 的代价是生成上限略低于专用扩散模型。Bagel 的 GenEval 0.82 和 DPG 未报告，但编辑 G_O 6.52 低于 ARM-RL 6.68，说明 ARM 在统一框架下的编辑偏好对齐更具优势。

**何时不选 ARM**：当模型规模需要远大于 7B 且训练资源有限，或者任务只需要图像理解，不需要生成，那么专用连续 LMM（如 Qwen2.5-VL）更经济；当任务对生成质量要求极高，可以容忍分离生成模块，那么扩散专用模型更好；当需要编辑的图像包含大量精确文本或 logo，ARM 论文没有专门定量评估，可能需要额外验证，因为论文提到更强 decoder 对文本渲染更稳健但仍可能出现字符失真（Figure 3）。此外，如果数据只能获得远低于 2.2B 图文对或 2.5T 多模态 token，ARM 的训练配方难以直接复制。

## 10. 工程判断：可行性、风险与上限

**数据**：ARM 的数据需求巨大。视觉 tokenizer 需要 2.2B 图文对，主模型需要 2.5T + 2.5T + 0.2B token。论文没有披露这些数据的详细来源比例，但 Table 1 给出采样比：T2I 数据占比最高（预训练 0.70，SFT 0.50），文本仅 0.05，说明训练非常偏生成。这意味着复现成本集中在高质量图文对和多模态 interleaved 数据上。数据构成包括 Image2Text 的 web captions、alt-text、OCR 文档、图表和 grounding 标注；T2I 的高质量图文对和少量合成对（来自 FLUX、Gemini 2.0 Flash、GPT-4o、Seedream 等）；interleaved 来自视频序列和 web documents，以及公共编辑数据集。RL 数据相对小，但依赖 GPT-o3 和 GPT-4.1 作为奖励模型，推断成本不低，尤其 T2I RL 每个 rollout 16 个样本，需要逐图调用多模态奖励模型。

**算力/延迟**：训练方面，预训练用 200 GPU 跑 100K step，持续训练 160 GPU 再 100K step，SFT 80 GPU 40K step，总计数百 GPU×十万 step，属于大模型研究级资源。tokenizer 训练使用 global batch 32768，需要 2.2B 图文对的数据吞吐，消费大量存储和网络带宽。RL 阶段 GPU 数较少（T2I RL 8 GPU，Edit RL 40 GPU，Joint RL 40 GPU），但奖励模型调用成本高。推理方面，AR 模型本身是 7B 自回归，生成 1024×1024 图像需要生成大量视觉 token；扩散解码器是 FLUX.1 dev，28 步采样，CFG 1.5，这一步的计算量接近一次完整扩散生成。不过由于语义 token 可弱化 AR 模型的 CFG，能省去 AR 侧的额外条件前向，这是潜在加速点。总体延迟高于纯扩散模型或轻量 AR 模型，但也换来了同一骨干的理解能力。

**实现难点**：最难的可能是四个 tokenizer 损失的平衡。因为 \(\mathcal{L}_{\mathrm{sig}}\) 会轻微降低 PSNR（Table 7：加入 sigmoid 的 PSNR 9.3 vs 只用 cap+pix 的 15.2），而 \(\mathcal{L}_{\mathrm{feat}}\) 提升 PSNR，说明语义和重建之间存在张力，需要仔细调权重。此外，FSQ 没有显式 codebook，虽然容量高，但 codebook usage 和 perplexity 指标需要监控；投影模块只有 6 层，可能限制复杂场景的表达。扩散解码器的条件替换（把 FLUX 的文本条件换成 \(z_q\)）也需要专门微调，否则可能出现文本条件丢失。RL 阶段只有视觉 token 更新，但策略采样与奖励模型异步，且 GRPO 对奖励模型质量极其敏感；如果 GPT 奖励模型对编辑一致性打分不准，可能出现策略漂移。Table 2 显示 T2I RL 的 learning rate 为 3e-5，Edit RL 为 5e-5，batch 分别为 64 和 40，说明不同任务需要不同的稳定化设置。

**失败环节**：第一个可能失败点是 tokenizer 训练不稳：如果语义损失过强，重建 PSNR 会掉；如果重建损失过强，语义 token 会退化（Table 7 中只用 cap+pix 时 INet ZS 为 0.2）。第二个可能失败点是 RL 阶段：只用视觉 token 部分更新，但策略采样和奖励模型之间存在异步，且 GRPO 对奖励模型质量极其敏感；如果 GPT 奖励模型对编辑一致性打分不准，可能出现策略漂移。第三个可能失败点是动态分辨率：shape token 虽然显式指定高宽，但没有清晰细节说明它如何影响 token 网格和位置编码，长序列下可能出现空间错位。第四个可能失败点是 decoder 的鲁棒性：Figure 3 显示 SANA 解码器在文本和面部上缺陷更多，若 FLUX decoder 不充分微调，可能无法匹配训练时 token 的分布，导致图像质量不稳定。

**监控信号**：训练时应监控 tokenizer 的 ImageNet zero-shot、PSNR、codebook usage 和 perplexity（Table 7），以及下游 POPE/MMMU/GenEval/GEdit 等；RL 阶段要同时监控目标任务和未训练任务的理解分数，防止生成偏好优化破坏理解能力。尤其 Table 8 显示理解分数在 RL 过程中波动在几百之内，需要跟踪 POPE、MMBench、MME、MMMU 等保持稳定。

**指标上限与未回答问题**：ARM-RL 的生成 GenEval 0.86 仍低于 Qwen-Image 0.87 和 FLUX 类扩散模型，编辑 G_O 6.68 略低于 Step1X-Edit 6.70，说明统一离散模型尚未在生成质量上全面超越专用扩散模型。理解方面虽然超过 Emu3 等，但 MMMU 40.2 与 Bagel 55.3 差距明显，表明离散 token 的理解上限仍低于连续解耦方案。未回答的关键问题包括：更大规模 AR 模型能否缩小差距？tokenizer 能否支持视频生成？RL 的跨任务 positive transfer 在更复杂任务上是否持续？人类偏好是否与 GPT 奖励一致？论文均未明确披露。

## 11. 放回研究脉络并收束

ARM 处于“从 LMM 理解到统一多模态生成”的研究脉络中。早期的 Next-GPT、SEED-X 用连续语义编码器加外部扩散解码器，结构不统一；Chameleon、Emu3 尝试全自回归离散 token，但理解受损；Janus-Pro、Bagel 回归解耦双编码器，保住了两个方向但结构复杂；ARM 则试图用“语义+重建统一 tokenizer”解决这个矛盾，再用 RL 提升生成和编辑的偏好对齐。这种思路与 VILA-U、UniTok、TAR 等同属“统一 tokenizer”方向，但 ARM 的差异化在于引入了 RL 并证明了跨任务协同，以及用高容量扩散解码器做渲染。与 Show-o 的非自回归 mask 生成相比，ARM 坚持 next-token prediction，从而能直接利用语言模型的推理和 RL 能力。与 Transfusion 等混合扩散-AR 模型相比，ARM 不需要同时维护连续扩散分支和离散 AR 分支，结构更简洁。

**读完必须记住的 5 件事**

1. ARM 用一个离散视觉 tokenizer 统一图像理解和生成，而不是两套编码器；tokenizer 基于冻结 SigLIP2-SO400M-512，经 6 层投影和 FSQ 量化，四个损失权重 \(1,5,5,1\)，FSQ 维度 16 且每维 2 级，约 65K 容量。
2. 主要生成和编辑性能来自 RL：GenEval 从 0.79 到 0.86，WISE 从 0.50 到 0.56，GEdit-Bench-EN G_O 从 5.75 到 6.68；DPG 从 84.48 到 86.00。
3. RL 只优化视觉 token 预测，理解能力基本不变，且 T2I RL 与 Edit RL 相互正向迁移，最终 Joint RL 综合最优：T2I RL 提高 GEdit 到 5.92，Edit RL 提高 GenEval 到 0.80。
4. 语义 tokenizer 让 AR 模型可以在 CFG 很弱或关闭时仍保持主体正确，降低 AR 侧推理开销；扩散解码器主要负责渲染细节，但其 CFG 关闭时局部纹理（如头发）会退化。
5. 训练数据远超公开规模：tokenizer 2.2B 图文对，主模型 2.5T+2.5T+0.2B token，RL 用 GPT-o3 和 GPT-4.1 作为奖励模型；主模型训练配置为 AdamW lr 2e-4/2e-4/5e-5，200/160/80 GPU，100K/100K/40K step。

**5 道自测题**

1. ARM 的视觉 tokenizer 中，FSQ 的量化级别和容量是多少？为什么不用显式 codebook？投影模块层数是多少？
2. 式 (2) 的 pixel reconstruction 损失为什么直接在像素空间做而不是在 VAE 潜空间？它和式 (5) 的 detokenizer 损失有何分工？
3. GRPO 更新中，为什么 \(\beta \mathcal{D}_{\mathrm{KL}}\) 项很重要？如果 \(\beta=0\) 可能会发生什么？ARM 设置 \(\beta\) 为多少？
4. Table 8 中，为什么 T2I RL 能提高 GEdit 分数，而 Edit RL 也能提高 GenEval？这支持了什么架构假设？理解指标如何变化？
5. 推理时生成 1024×1024 图像，AR 模型和 diffusion decoder 分别承担什么角色？CFG 在两者中的取值是多少？为什么 AR 模型可以弱化 CFG？

**一句话总结**：ARM 证明了用一个语义对齐的离散视觉 tokenizer 加 7B 自回归模型，再配合 GRPO 偏好优化，可以在不牺牲理解的前提下把生成和编辑做到接近专用模型，但生成上限与连续扩散模型仍存在差距，且理解上限尚未达到连续解耦方案的水平。
