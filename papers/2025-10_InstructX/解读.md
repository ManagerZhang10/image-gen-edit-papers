# 大白话深读《InstructX》

## 1. 30 秒定位

InstructX 是一个统一的图像与视频编辑框架，核心思想是把多模态大语言模型（Multimodal Large Language Model, MLLM）当作“理解器”，把扩散变换器（Diffusion Transformer, DiT）当作“生成器”，通过一组可学习查询（learnable queries）和一个小型多层感知机（Multi-Layer Perceptron, MLP）连接两者。理解器采用 QWen2.5-VL-3B，生成器采用 Wan2.1-14B。论文的关键主张有三点：第一，MLLM 不应只做特征提取器，编辑语义应在 MLLM 内部充分形成，因此对 MLLM 加 LoRA 微调，而不是冻结；第二，训练图像编辑数据可以零样本迁移出视频编辑能力，缓解高质量视频编辑数据稀缺问题；第三，用独立的图像查询与视频查询统一建模两种模态，图像输入使用 256 个可学习查询，视频输入使用 512 个可学习查询。训练分三个阶段：20k 步特征对齐、20k 步全数据混合训练、5k 步高质量微调，全程使用 flow-matching 目标。实验显示 InstructX 在开源方法中总体领先，ImgEdit-Bench 总体得分 3.85，GEdit-Bench 总体得分 6.68，部分视频任务接近甚至略超过 Runway、Kling 等闭源方案，但仍与 GPT-4o 存在差距（Table 1/2/3，§4.3）。

## 2. 为什么这篇论文会出现

近年来，把多模态理解与生成结合是一个明显趋势。文本到图像生成、图像编辑、视频编辑等领域都出现了统一模型，但如何把 MLLM 与扩散模型有效集成仍然没有共识。现有集成范式大致有三类：一是自回归视觉生成，使用离散视觉 tokenizer（如 Janus-Pro、TokenFlow 等）；二是混合自回归-扩散，在同一 Transformer 里同时做文本自回归损失和视觉扩散损失（如 Transfusion、JanusFlow、Show-O、BAGEL 等）；三是使用 MLLM 骨干加外部扩散模型作为视觉解码器（如 DreamLLM、Seed-X、Emu 等）。论文选择了第三种范式，理由是它通常收敛快、改动小、性能有竞争力（§1，Introduction）。

在这个范式下，已有若干工作，如 MetaQuery 引入一组可学习查询作为 MLLM 与扩散模型的接口，但它在 MLLM 与扩散模型之间使用了一个很大的连接器（1.6B 参数），同时冻结 MLLM。论文认为这些设计选择缺乏充分实验论证，具体争议包括：是直接用 MLLM 的所有最后隐藏状态，还是压缩成 meta-query 特征；连接器需要大 Transformer 还是小 MLP；MLLM 是否需要微调（§2.2）。论文通过对比实验验证了一个中心假设：要充分利用 MLLM 的理解能力，编辑语义应主要在 MLLM 内实现，而不是交给后续大连接器。图 3 比较了四种方案：T5+DiT 扩散纯文本、QFormer-based MLLM+DiT、MetaQuery-based MLLM+DiT，以及本文的 MLLM LoRA + 两层 MLP。图 4 左显示特征对齐阶段，仅靠大连接器或 QFormer 收敛慢，加入 MLLM LoRA 后收敛加速；图 4 右显示最终编辑性能同样占优。

另一方面，高质量视频编辑数据一直是瓶颈。早期工作采用零样本策略（如 FateZero、FLATTEN、Tune-A-Video）或首帧编辑后传播（如 AnyV2V、I2VEdit、ReVideo），但往往受限于生成质量、泛化性以及内容漂移。近期有方法通过训练视频专家模型构建数据集（如 UNIC、Señorita-2M），但数据构建管线长、成功率低。论文注意到 GPT-4o 等商业模型在指令式图像编辑上表现很强，因此利用大规模高质量图像编辑数据来支持视频编辑，通过混合图像-视频训练，观察到图像数据训练出的编辑能力能有效迁移到视频，无需显式视频监督（§1）。

## 3. 读懂前需要的最小概念

**MLLM（多模态大语言模型）**：能同时接收文本和图像/视频输入，进行理解与推理的大语言模型。本文使用 QWen2.5-VL-3B。它输出的是基于输入序列的隐藏状态，可以看作对视觉内容的语义编码。论文特别指出 MLLM 的细粒度视觉理解能力远超纯文本 T5 编码器，例如能识别杂乱蔬菜堆中的西兰花、角落书架上的书等（Fig.14，Appendix A.4）。

**DiT（扩散变换器）**：基于 Transformer 的扩散模型，常用作文本到图像或文本到视频的生成骨干。本文使用 Wan2.1-14B。DiT 通常接收文本嵌入（text embeddings）和噪声潜变量（noisy latent），通过去噪或流匹配生成目标潜变量。Wan2.1-14B 是一个预训练视频 DiT，其原生文本嵌入被 InstructX 的 MLLM 条件嵌入替换。

**VAE（变分自编码器）**：将图像/视频从像素空间压缩到潜空间编码，或将潜变量解码回像素。本文用 VAE 编码源图像/视频，并把该编码加到噪声潜变量上，以保持编辑结果与源内容的一致性；有参考图像时则沿序列维度拼接 VAE 特征。这一操作在阶段二引入。

**LoRA（低秩适配）**：一种参数高效微调方法，通过在权重矩阵旁路添加低秩分解矩阵来调整模型行为，不更新原始大参数。本文对 MLLM 加 LoRA，使其参与编辑语义形成，同时保持参数效率。

**Flow Matching（流匹配）**：生成模型训练目标，学习从噪声分布到数据分布的概率路径。本文所有阶段都用 flow-matching 作为训练目标，但论文未给出具体公式。

**Learnable Queries（可学习查询）**：一组可训练向量，加入到 MLLM 输入序列末尾，用来从 MLLM 输出中“抽取”与编辑任务相关的信息。本文为图像设置 256 个查询，视频设置 512 个查询，分别对应不同模态，避免共享查询带来的模态混淆。

**Meta-Query 特征**：MLLM 输出中仅保留 learnable queries 对应的位置特征，其余输出被丢弃，从而压缩为固定长度的编辑表示。与使用全部最后隐藏状态相比，meta-query 方式更高效，且经过实验验证在编辑性能上更有优势（Fig.4）。

**VIE-Bench**：论文自建的指令式视频编辑基准，共 140 个高质量样本，覆盖 8 类任务：局部编辑（对象交换、颜色变化、添加、移除）、全局编辑（风格变化、色调/天气变化）、混合编辑、参考基础编辑（参考基础交换、参考基础添加）。评分使用 GPT-4o 在 1-10 分上评估指令遵循、保持、质量，参考任务另评相似度（§4.2，Appendix A.1）。

## 4. 方法全景：先看数据流

InstructX 的训练和推理数据流一致，核心是“MLLM 理解 + DiT 生成”。下面先给出简化的 ASCII 流程：

```
训练/推理输入：
用户指令文本 + 源图像/视频帧 + (可选参考图像)
          | 
          v
+-----------------------------+
|  MLLM (QWen2.5-VL-3B)       |
|  输入序列 = 系统提示 + 指令 + |
|  视觉 tokens + 图像queries   |
|  (或视频queries)             |
+-----------------------------+
          |
          v
   MLLM 输出 hidden states
          |
          v
仅保留 learnable query 位置特征
(图像256个 / 视频512个)
          |
          v
 两层 MLP connector
          |
          v
  替换 DiT 中的 text embeddings
          |
          v
+-----------------------------+
|  DiT (Wan2.1-14B)           |
|  输入：噪声潜变量 +          |
|  VAE(源图像/视频) +         |
|  (可选)VAE(参考图像)        |
|  条件：MLP后的query特征      |
+-----------------------------+
          |
          v
  流匹配去噪 / 生成潜变量
          |
          v
   VAE decoder -> 编辑后图像/视频
```

**核心组件拆解：**

1. **MLLM 输入构造**：输入包括系统提示、用户编辑指令、源视觉 tokens。视频输入采样 13 帧送入 MLLM（§3.2）。在序列末尾追加独立的两组可学习查询：图像 256 个、视频 512 个。目的是让 MLLM 在理解指令同时输出编辑语义到这些查询位置。假设是编辑语义需要与指令深度绑定，而不能仅从图像特征中提取。图 2 显示 MLLM 输入包含“Src image/video token”“Ref image token”“MLLM context token”，分别对应源视觉、参考视觉和文本上下文。

2. **Meta-Query 保留**：MLLM 输出整个序列的隐藏状态，但只取 learnable queries 对应位置的输出，固定长度。其他视觉/文本 token 的输出被丢弃。这样得到压缩的编辑表示，避免使用所有最后隐藏状态带来的不确定性和计算开销。图像和视频查询的分离也在此处体现，视频使用 512 个查询以承载更多时序信息。

3. **两层 MLP connector**：将 Meta-Query 特征映射到 DiT 的条件空间。输入维度是 MLLM 隐藏维度，输出维度匹配 DiT 文本嵌入维度。论文强调使用简单 MLP 而非大 Transformer，前提是 MLLM 本身经过 LoRA 微调，已经把编辑信息处理好。假设是 MLLM 与 DiT 之间存在表示空间差异，但只需要一个轻量投影即可对齐。与 MetaQuery 的 1.6B 大连接器相比，两层 MLP 的可训练参数量大幅降低。

4. **DiT 生成**：Wan2.1-14B 接收噪声潜变量，并将通过 MLP 的 query 特征作为条件嵌入（替换原生 text embeddings）。为了保持与源内容一致，把 VAE 编码的源图像/视频直接加到噪声潜变量上。如果有参考图像，则把参考图像的 VAE 特征沿序列维度与噪声潜变量拼接。这些操作让 DiT 能参考原始视觉内容，避免漂移。图 2 下方显示了“Condition Embedding +”“Ref image token”与“Noisy latent token”的融合方式。

5. **训练策略**：分三阶段。阶段一只训练 learnable queries、MLLM LoRA、MLP，冻结 DiT；阶段二全数据训练并解冻 DiT；阶段三质量微调。混合图像/视频训练时，采样概率视频 0.6、图像 0.4。图 5 示意了三个阶段的可训练模块变化，图 6 展示了图像数据激发出的视频分割和视频风格迁移能力。

## 5. 核心公式与直觉

论文没有显式写出公式编号，但在方法部分提到使用 flow-matching 作为训练目标，并在图 2 中描述了 VAE 条件注入方式。下面基于论文描述给出两个必要公式化理解，均标注为“基于论文描述的形式化”。

**公式 1：Flow Matching 损失（一般形式）**

Flow matching 训练通常最小化速度场预测与真实条件速度之间的差异。若记数据样本为 \(x\)，噪声样本为 \(z\)，时间步 \(t \in [0,1]\)，概率路径为 \(x_t = (1-t) z + t x\)，速度场为 \(v_\theta(x_t, c)\)，其中 \(c\) 是条件（本文中为经过 MLP 的 meta-query 特征），则损失可写为：

\[
\mathcal{L}(\theta) = \mathbb{E}_{t, x, z} \left\| v_\theta(x_t, c) - (x - z) \right\|^2
\]

变量解释：\(z\) 是从标准正态分布采样的噪声；\(x\) 是 VAE 编码后的目标潜变量；\(c\) 是条件嵌入，在本文中由 MLLM 输出经过查询和 MLP 得到。工程优化动作是让 DiT 学会预测从当前混合态 \(x_t\) 到目标 \(x\) 的速度。论文未明确写出该公式，但提到使用 flow-matching，这是该类目标的标准形式。

**公式 2：源内容注入**

在 DiT 输入层面，噪声潜变量 \(z_t\) 加上源图像的 VAE 编码 \(e_{src}\)，以及可选参考图像的 VAE 编码 \(e_{ref}\)（拼接）：

\[
h_0 = z_t + \lambda e_{src}, \quad h_0' = \text{concat}(h_0, e_{ref}) \ \text{(若有参考)}
\]

变量解释：\(e_{src}\) 是源图像或视频的 VAE 特征；\(\lambda\) 是标量系数（论文未给出具体值，似乎直接相加），用来控制源信息强度；\(e_{ref}\) 沿序列维度拼接，用于参考图像任务。直觉是向扩散模型显式暴露源视觉内容，可以让编辑“知道”要保留什么，从而抑制无关改变。这一操作在阶段二引入，因为阶段一仅靠 MLLM 粗粒度视觉信息会导致一致性差（§3.3）。

论文还提到在图像/视频混合训练中，视频采样 13 帧送入 MLLM，图像查询 256 个、视频查询 512 个，这些数字分别在 Fig.2 和 §3.2/§3.3 中给出。关于 \(t\) 的采样分布、速度场参数化、采样器步数等训练与推理超参，论文未明确披露。

## 6. 训练到底怎么跑

训练分三个阶段，每个阶段有不同的训练对象和数据分布。所有阶段都使用 flow-matching 目标，总学习率 \(1\times10^{-5}\)（§4.1）。

**阶段一：特征对齐训练**。迭代 20,000 步。只用图像指令编辑数据。冻结 DiT 参数，只训练三部分：learnable queries、MLLM 上的 LoRA、两层 MLP connector。目的是把 MLLM 的输出特征空间与 DiT 的生成条件空间对齐。这一阶段结束后，模型具备粗略的指令编辑能力，但因为缺失源视觉条件，编辑结果与原图一致性差（§3.3）。图 4 左显示本阶段不同设计收敛速度，本文设计收敛最快。

**阶段二：全数据训练**。迭代 20,000 步。混合图像和视频数据，采样概率视频 0.6、图像 0.4。这一阶段解冻 DiT，训练 learnable queries、MLLM LoRA、MLP connector 和整个 DiT。同时引入 VAE 编码源图像/视频，加到噪声潜变量上，以提升内容保持能力。阶段二的目标有两个：一是改善编辑结果与原输入的一致性；二是通过混合训练获得统一的图像/视频编辑能力，并利用图像数据激发视频编辑能力。论文特别指出，在纯视频数据中不存在分割和风格迁移任务，但混合训练后模型竟然能做视频风格迁移（图 6），这说明图像数据训练出的能力发生了跨模态迁移。图 5 的阶段二示意中显示了 MLLM LoRA、MLP、DiT 以及 image/video queries 均被训练，VAE 条件也开始加入。

**阶段三：质量微调**。迭代 5,000 步。收集少量高质量训练数据，继续训练上述所有可训练部分。目的是修正阶段二因低质量数据导致的“油腻、塑料感”纹理，使编辑结果更自然美观。图 5 最后一行显示质量微调前后效果差异（“Before SFT” vs “After SFT”）。

全局 batch size 为图像 128、视频 32（§4.1）。论文未披露优化器类型、warmup、梯度裁剪、学习率调度等细节。视频数据合成管线在附录 A.2 有描述：使用 PySceneDetect 分割单场景片段；添加/移除数据先用 GPT-4o 分析视频并选择目标类别，用 Grounding DINO 检测、SAM 分割掩码，再通过视频擦除技术移除目标，经 MLLM 过滤伪影后，将原视频与生成视频角色互换，让 GPT-4o 生成“移除”和“添加”指令，并用 Flux-Kontext 生成跨对参考图像；最终得到 65K 移除对、73K 添加对。交换/变换数据通过光流分析区分静态/动态背景，静态人类视频用 Flux-Kontext 编辑首帧、DW-pose 提取姿态并驱动图像到视频生成，动态背景使用掩码视频修复专家模型生成编辑三元组；最终得到 98K 交换/变换对，合计约 236K 视频编辑样本（Appendix A.2）。

## 7. 推理到底怎么跑

推理时不再有标签或目标，流程与训练前向类似，但只执行一次生成。

**无参考图像任务**：给定源图像或视频、用户指令文本。先对源视频采样 13 帧（如果是源图像则直接编码）。将这 13 帧/图像输入 MLLM，同时在 MLLM 输入序列末尾添加对应的图像查询（256 个）或视频查询（512 个）。MLLM 前向计算，取出查询位置的隐藏状态，送入两层 MLP 得到条件嵌入。源图像/视频通过 VAE 编码器得到潜变量编码，并与从噪声分布采样的初始噪声潜变量相加（视频则逐帧处理，Wan2.1 内部处理时序）。将带有源信息的噪声潜变量和条件嵌入一起送入 DiT，执行 flow-matching 采样。DiT 输出经过 VAE 解码器恢复为像素空间图像或视频。

**有参考图像任务**：流程同上，但额外把参考图像通过 VAE 编码，将其潜变量沿序列维度与含源信息的噪声潜变量拼接。图 2 显示参考图像 token 与源图像/视频 token 均作为 MLLM 输入，同时参考图像 VAE 特征拼接到 DiT 输入端。

**视频帧采样**：论文明确写“for video input, we specifically sample 13 frames to serve as input to the MLLM”（§3.2）。推理时也应如此，这 13 帧从视频中采样，用于 MLLM 理解。DiT 生成整个视频时可能处理全部帧或关键帧后插值，但论文未披露具体帧数对应关系。图 9(b) 的消融显示，如果只用首帧作为 MLLM 输入，当编辑内容出现在视频中段时结果容易崩溃。

**输出**：编辑后的图像/视频，保持原始分辨率和时长。推理成本主要来自 MLLM 前向和 DiT 去噪采样，后者通常需要多次前向。论文未披露采样器类型、去噪步数、CFG 强度或推理延迟。

**最关键消融**：论文做了两个消融（图 9）。第一个是图像/视频独立查询与共享查询的对比，结果显示独立查询在 VIE-Bench 上得分更高，说明分开的查询能更好区分不同模态的特征提取。第二个是 MLLM 输入帧数的消融：如果只用视频第一帧生成编辑指导，在编辑内容出现在视频中段等复杂场景下容易崩溃；使用 13 帧多帧输入则稳定。这证明 MLLM 需要时序上下文来理解需要编辑的视频内容。

**架构选择研究**（图 4）也属于关键消融。左侧展示不同设计在冻结 DiT 的特征对齐阶段的收敛曲线：仅靠大连接器（MetaQuery-based）或 QFormer 收敛慢；加入 MLLM LoRA 后收敛加速。右侧展示对齐完成后解冻 DiT 继续训练的 ImgEdit-Bench 性能，本文设计（MLLM LoRA + 两层 MLP）优于其他。这一结果支持论文的中心假设：编辑语义应该在 MLLM 内形成，而不是靠后续大连接器。附录 A.4 进一步通过可视化（Fig.14）和 ImgEdit-Bench 任务对比（Fig.15）证明 MLLM 相对 T5+DiT 在理解复杂细节上的优势。

**尚未证明的主张**：论文标题和摘要称“图像数据可以涌现视频编辑能力”，并用手动例子（视频分割、视频风格迁移）展示这一能力，但未给出定量对比或消融证明仅图像训练 vs 混合训练的具体差异。VIE-Bench 是自建基准，可能存在作者偏置；论文也承认图像数据激发零样本视频编辑不是直接解决方案（Limitation）。此外，论文对比的闭源模型（GPT-4o、Runway、Kling、Pika）版本和使用条件未完全统一，且评测分数来自 GPT-4o 自身，存在自我评价偏倚风险。用户研究虽然有 30 名专家盲评，但论文只给出图表（Fig.12/13），未披露具体平均分数和方差，难以复现统计检验。

## 9. 与前作怎么选

**与 MetaQuery 相比**：MetaQuery 使用 learnable queries 作为接口，但在 MLLM 与 DiT 之间用 1.6B 参数的大连接器，并冻结 MLLM。InstructX 复用 query 机制，但用两层 MLP 替换大连接器，并对 MLLM 加 LoRA。选择 InstructX 的场景：希望降低连接器参数与训练成本，且需要更强的指令理解和更快的对齐收敛；需要注意 MLLM 微调可能影响其通用理解能力。选择 MetaQuery 的场景：如果 MLLM 不宜微调（如权限、多任务稳定性要求或部署约束），或已经有现成的大连接器预训练权重可以复用。

**与 QFormer-based MLLM+DiT 相比**：QFormer 使用固定长度（256 tokens）的编码器来压缩 MLLM 最后隐藏状态。InstructX 直接使用 learnable queries 从 MLLM 输出中提取信息，避免了 QFormer 的额外编码器和潜在信息损失。当需要更灵活地控制条件长度（图像 256、视频 512）且愿意微调 MLLM 时选 InstructX；如果必须完全冻结 MLLM，且只能依赖后置编码器，QFormer 可能更安全，但收敛速度和最终编辑性能可能不如 InstructX。

**与 T5+DiT 扩散纯文本方法相比**：该方法直接用 T5 编码指令文本，不提视觉理解。InstructX 的核心优势是 MLLM 能看见源图像/视频，理解复杂指令（如“删除杂乱蔬菜堆中的西兰花”）。当任务需要细粒度视觉推理、依赖源内容定位和复杂上下文时选 InstructX；简单文本指令、低延迟要求下 T5+DiT 可能更快，且不需要额外的 MLLM 前向成本。

**何时不选 InstructX**：如果目标是高分辨率（>1080P）编辑，InstructX 受 Wan2.1-14B 预训练限制可能分辨率不足（Conclusion/Limitation 明确指出的约束）；如果需要极低推理延迟或边缘设备部署，14B DiT 加 3B MLLM 权重过大；如果任务只涉及纯文本驱动且不需要源内容强保持，轻量级扩散编辑模型更经济；如果数据场景高度专业化且缺少合成视频数据构建能力，InstructX 的训练管线可能过重。

## 10. 工程判断：可行性、风险与上限

**数据**：图像数据来自 NHR-Edit、X2Edit、GPT-Image-Edit 三个开源集，规模未披露但足够支撑 20k 步训练。视频数据来自自建合成管线，约 236K 个编辑对，覆盖添加、移除、交换、变换（65K 移除、73K 添加、98K 交换/变换）。合成管线依赖多个专家模型：GPT-4o 生成指令、Grounding DINO 检测、SAM 分割、视频擦除、Flux-Kontext 首帧编辑、DW-pose 姿态提取、pose-driven I2V 和 mask-based video inpainting。风险是合成视频的质量依赖于这些专家模型，可能引入伪影或与真实用户分布漂移。论文未披露数据清洗细节、过滤比例和失败率，只提到 MLLM-based filtering mechanism 避免修复伪影（Appendix A.2）。

**算力/延迟**：训练涉及 3B MLLM 加 14B DiT，全局 batch size 128 图像或 32 视频，学习率 1e-5，共 45k 步（20k+20k+5k）。推理需要一次 MLLM 前向（输入 13 帧视频 tokens + 512 查询）和 DiT 多次去噪采样，后者是延迟主要来源。论文未披露推理时延、显存占用或所需 GPU 数量。基于工程推断，训练需要多卡高端 GPU，推理部署需要较大显存，实时性可能不足，尤其是视频任务。

**实现难点**：如何稳定混合图像和视频训练而不互相干扰；如何保证 13 帧采样与 DiT 视频长度对齐；参考图像拼接时如何区分源和参考语义；质量微调数据的筛选标准。论文对这些问题只给出定性描述，没有超参细节。特别是图像/视频查询分离虽有效，但需要额外维护两组查询向量，训练时如何切换和初始化未披露。

**失败环节**：从论文展示的失败案例（图 9b 首帧输入导致编辑内容中段崩溃）和局限章节来看，复杂长视频、高分辨率、遮挡频繁的目标替换可能是弱项。另外，低质量训练数据会导致“油塑感”，需要第三阶段微调修补，说明数据质量是瓶颈。对于动态背景视频，交换/变换数据依赖 mask-based video inpainting 专家模型，背景剧烈变化时可能出现伪影或内容漂移。

**监控信号**：训练时可监控 flow-matching 损失、特征对齐阶段的收敛速度（如图 4 左），以及下游编辑基准分（ImgEdit-Bench、GEdit-Bench、VIE-Bench）。推理时可监控条件一致性（源 VAE 注入强度）和用户评分，但论文未给出自动回归的在线监控方案。用户研究采用 30 名专业创作者盲评，指标为指令遵循、保持、质量 1-5 分。

**指标上限**：在开源方法中总体领先，但仍明显低于 GPT-4o 或 SeedEdit 3.0 在部分图像编辑任务。例如 GEdit-Bench Q_O 上 InstructX 为 6.68，GPT-4o 为 7.83，差距约 1.15 分；ImgEdit-Bench Overall 上 InstructX 为 3.85，GPT-4o 为 4.51，差距 0.66 分。视频 VIE-Bench 上 InstructX 在 Add、Swap、Remove 三项略低于 Runway（Table 3），但差距较小（0.1-0.2 分），在 Style/Tone、Hybrid、Ref-Based Swap 上领先。这说明上限受限于 Wan2.1-14B 基座能力和训练数据质量，且闭源模型在保真度上仍有优势。

**未回答问题**：论文没有定量证明图像数据迁移到视频的具体提升幅度；没有系统比较不同 MLLM 规模（如 7B、13B）的影响；没有探索不冻结 DiT 的其他阶段组合；没有报道训练成本（GPU 卡数、时间）和推理延迟；没有给出模型失效的定量上限或边界条件；没有披露质量微调数据的具体规模和筛选标准。

## 11. 放回研究脉络并收束

InstructX 位于“统一视觉编辑”与“多模态理解-生成集成”两条线的交叉点。从扩散编辑看，它继承了 InstructPix2Pix 的指令编辑思想，但用 MLLM 替换了纯文本编码器；从 MLLM 集成看，它比 MetaQuery 更强调 MLLM 自身微调和轻量连接器。论文的贡献是把架构选择研究做扎实了，并提出了图像数据跨模态激发视频编辑的实用路径。相比 VACE、Omni-Video 等统一理解生成模型，InstructX 聚焦在编辑任务上，并针对 MLLM-DiT 连接方式给出可复用的设计准则。自建 VIE-Bench 弥补了现有指令式视频编辑基准（如 UNICBench、VACE-Benchmark）在指令提示和样本覆盖上的不足。

**读完必须记住的 5 件事**

1. 核心设计：QWen2.5-VL-3B 加 LoRA 做理解，Wan2.1-14B 做生成，通过 learnable queries 和两层 MLP 连接；图像用 256 个查询，视频用 512 个查询，视频 MLLM 输入采样 13 帧。
2. 关键发现：MLLM 不是特征提取器，编辑语义应在 MLLM 内形成；对 MLLM 加 LoRA 比冻结 MLLM 加大连接器收敛更快且最终性能更好（Fig.4）。
3. 训练三阶段：20k 步特征对齐（冻结 DiT）→ 20k 步全数据混合训练（解冻 DiT，引入 VAE 条件）→ 5k 步高质量微调；学习率 1e-5，图像 batch 128、视频 batch 32。
4. 数据策略：图像数据大规模开源可用，视频数据合成约 236K 对（65K 移除 + 73K 添加 + 98K 交换/变换）；混合训练时视频采样概率 0.6、图像 0.4，图像训练可零样本迁移视频能力。
5. 实验结论：在开源图像编辑（ImgEdit-Bench Overall 3.85）和视频编辑（VIE-Bench 多数指标领先开源）中总体占优，但仍低于 GPT-4o 等闭源方案，且受限于 Wan2.1-14B 基座高分辨率能力。

**5 道自测题**

1. InstructX 中 MLLM 与 DiT 之间是如何连接的？为什么作者不用大 Transformer 连接器？
2. 训练三个阶段分别训练哪些参数？为什么阶段一冻结 DiT、阶段二解冻？
3. 图像数据如何“涌现”视频编辑能力？论文提供了哪些证据？证据是否足够定量？
4. VIE-Bench 包含哪些任务类别？评测指标是什么？相比已有视频编辑基准有哪些改进？
5. 如果要用 InstructX 做 4K 视频移除物体编辑，会遇到什么限制？为什么论文把 >1080P 列为局限？

**最终一句话总结**：InstructX 通过“MLLM 理解 + 轻量连接 + DiT 生成”的统一框架，证明了指令编辑中 MLLM 应深度参与语义形成，并用图像数据反哺视频编辑，为开源视频编辑提供了一个实用的强基线，但其高分辨率上限和与闭源模型的差距仍然明显。
