# 大白话深读《HATIE》

## 1. 30 秒定位

HATIE（Human-Aligned benchmark for Text-guided Image Editing）是一个面向文本引导图像编辑任务的基准与评估框架。它要解决的核心问题是：图像编辑没有唯一正确答案，难以自动评测，而用户研究又不可扩展。HATIE 提供一套可替代人工主观评价的自动化流程：基于 GQA 构建了 18,226 张图像、49,840 条编辑查询，覆盖 76 个 COCO 物体类别（Table 1）。评估时，对编辑结果从五个维度打分——图像质量（Image Quality）、对象保真度（Object Fidelity）、背景保真度（Background Fidelity）、对象一致性（Object Consistency）、背景一致性（Background Consistency）。五个分数通过用户研究拟合出的权重线性聚合成总分（Total Score）。Figure 8 报告测试集上自动胜率与用户胜率的 Pearson 拟合；Table 2 另列 Spearman ρ 与 Kendall τ，其中总分分别为 0.7143 与 0.6000，四个分项的 Spearman ρ 为 0.8208–0.9276。它不是编辑模型，而是一把规模化测量编辑模型的“尺子”。

## 2. 为什么这篇论文会出现

文本引导图像编辑近年发展迅速，早期如 Imagic、Prompt-to-Prompt、SDEdit 和近期 InstructPix2Pix、MagicBrush 等模型不断涌现。但论文指出，该领域缺少被广泛接受的标准评估方法（Introduction）。根因在于任务的本质：同一个编辑指令可以有多种正确输出。例如“在客厅场景加一张桌子”，桌子的形状、材质甚至位置可以有无穷多种像素级细节。更模糊的指令更加剧这种不确定性。像素级 L2 距离无法反映语义层面的编辑好坏，必须依赖高层视觉理解。

此前一些工作试图自动评估，但都有明显短板：TEdBench 只有 100 张图像、100 条查询，仍需用户研究；EditBench 有 240 张图像、720 条查询，但也未实现全自动；GIER 有 6,179 张图像、30,895 条查询，但编辑任务局限于灰度化等几乎像素级对齐的任务；EditVal 有 92 张图像、648 条查询、19 类，虽然多样化了一些任务和对象，但评价仍靠用户研究（Table 1 与 §1）。此外，已有自动化尝试往往依赖单一模型指标（如 CLIP similarity 或 LPIPS），牺牲了可复现性和可靠性，因为外部服务（如 ChatGPT）参数不公开会破坏一致性（§3）。编辑质量还需要同时考虑指令执行度、未指定区域保持度、图像整体真实感等多面性，单一分数很容易漏判。HATIE 的出现正是为了把这些维度系统化、规模化、自动化，并通过用户研究学习权重把这些分数校准到与人类感知一致。

## 3. 读懂前需要的最小概念

**文本引导图像编辑**：给定输入图像 \(I_0\) 和自然语言指令或描述 \(C\)，生成编辑后图像 \(I_e = f(I_0, C; p)\)，其中 \(p\) 是控制编辑强度的参数（§2）。根据 \(C\) 的形态，模型分为两类：**描述式（description-based）**，使用两张描述 \(C=\{C_0, C_e\}\) 分别刻画原图和目标图，如“a photo of a dog”变为“a photo of a cat”；**指令式（instruction-based）**，使用单条指令描述差异，如“remove the dog”。两类模型不可直接比较，因为输入接口不同（§2）。HATIE 为两类模型分别提供查询集，但强调同一套指标不能跨类型公平比较。

**保真度与一致性**：保真度（Fidelity）衡量编辑是否正确执行了用户意图；一致性（Consistency）衡量未要求改变的部分是否保持不变。两者往往是权衡关系：编辑强度增大，保真度上升而一致性下降（§3.3）。论文把保真度分为对象与背景，一致性也分为对象与背景，再加上图像质量，构成五个维度。

**常用自动指标**：CLIP 对齐（图像区域与文本的 CLIP 嵌入相似度）、FID（Fréchet Inception Distance，图像集合间的分布距离）、LPIPS（感知距离）、DINO 特征相似度、L2 距离、实例分割模型的检测置信度等。HATIE 不是简单堆砌这些指标，而是按任务类型筛选适用的指标，并通过用户研究学习组合权重。

**人类对齐**：让自动基准的模型排名与人类偏好投票结果相关。论文用 Pearson、Spearman、Kendall 相关系数量化这种对齐程度，并采用留出测试集防止过拟合用户研究训练集。具体而言，用户研究训练集包含 1,350 条查询对应的 2,700 张图，测试集包含 675 条查询对应的 1,350 张图（§3.4）。

## 4. 方法全景：先看数据流

```
GQA 基础数据集
  │  过滤：去掉过小、被裁剪、被遮挡、检测失败、同类别多实例
  ▼
HATIE 图像集 18,226 张 / 19,933 个可编辑对象 / 76 类
  │  查询生成：对象中心 5 类 + 非对象中心 2 类；统计可行性约束；LLM 生成自然语言
  ▼
HATIE 查询集 49,840 条（描述式 + 指令式）
  │  目标模型 f 执行编辑
  ▼
编辑后图像 Ie
  │  评估流水线：实例分割定位对象；按任务选择指标；计算 5 个维度得分
  ▼
σ_IQ, σ_OF, σ_BF, σ_OC, σ_BC
  │  权重拟合自用户研究；线性聚合
  ▼
Total Score σ_Total
```

**核心组件拆解**：

- **数据集构建（§3.1 与 Appendix A）**：以 GQA 数据集为基础，因为其有场景图和丰富标注。过滤对象时，要求包围盒面积不低于整图 0.5%，因为对象太小无法区分或编辑；剔除包围盒贴边的对象，避免对象被裁剪；用预训练 VQA 模型回答六个与遮挡相关的是非题，只保留至少答对四题的对象；并要求对象与 Detectron2 实例分割结果 IoU 大于 0.5，确保评估时能自动定位。此外，剔除同一图像中同类多实例的样本，防止目标混淆。图像被裁剪并缩放至 512×512，同时尽量保留原图且确保可编辑对象未被裁掉。最终保留 18,226 张图像、19,933 个可编辑对象、76 个 COCO 类别。

- **编辑查询生成（§3.2 与 Appendix B）**：分对象中心任务（添加、移除、替换、属性改变、尺寸调整）和非对象中心任务（背景改变、风格改变）。模板化同时用数据驱动统计保证可行性：从 GQA 标注中收集所有对象属性，归纳为颜色（color）、状态（state）、材质（material）、动作（action）四类；从关系标注中归纳为 9 种空间关系 \(R=\{\text{under, above, in, on, left, right, next to, front, behind}\}\)；背景候选有 27 种，风格候选有 10 种（完整列表见 Appendix B.1）。例如对象添加时，只选择与锚点对象在数据集中频繁共现、且位置关系合理的目标对象类，避免“把车放在桌子上”这类不合理查询；属性改变时，颜色/材质/动作属性在同类内替换，状态属性根据统计定义可行替代对（如 wet/dry 配对）。描述式查询由 Llama3 生成原图 caption，GPT-4o 进一步精修属性表述；生成 caption 要求包含确切对象名，并限制在 60 词内；指令式查询则直接套用手工设计的句子模板。最终生成 49,840 条平衡分布的查询。

- **评估指标计算（§3.3 与 Appendix C.1）**：用 Detectron2 实例分割模型提取目标对象区域和背景区域；对每个维度按任务预先指定适用指标。例如对象添加用 CLIP 对齐（分别计算对象类别 \(c_{o'}\) 和关系文本 \(r_{o'}\) 的相似度）、检测置信度；对象尺寸调整用规则化的尺寸分数；属性改变用 CLIP 对齐 + 退化/边缘一致性。目的是让每个任务只被合理指标评判，避免无意义度量（如替换任务的对象一致性）。

- **权重拟合（§3.4）**：通过用户研究收集 6 个描述式模型在 2,025 条查询上产生的 4,050 张编辑图像的成对偏好（2,700 张训练，1,350 张测试）。用户被分为 8 组，每组回答一个整体质量题集和一个特定准则题集；每题由 3 人投票，多数决出胜者。对每个维度和总分，计算用户胜率向量 \(u_k\) 与自动指标胜率 \(v_k\)，用 grid search 选取使 Pearson 相关最大化的权重，搜索步长为 0.01。输出可解释的权重和可复现的总分。

## 5. 核心公式与直觉

**FID 缩放（公式 1）**  
\[
\sigma_{IQ} = 1 - \tanh\left(\frac{\text{FID}}{25}\right)
\]
其中 FID 是输入图像集与输出图像集之间的 Fréchet Inception Distance。tanh 把非负 FID 压缩到 [0,1)，并用 25 做尺度因子，使 SOTA 模型的分数接近 1。直觉是：FID 越低，图像质量越高；缩放后方便与其他维度分数同量纲加权。该公式没有可学习参数，只是单调映射。工程上如果把 FID 换成其他分布距离，需要重调尺度。

**对象保真度（公式 2）**  
\[
\sigma_{OF} = w_{OF}^{clip}\sigma_{OF}^{clip} + w_{OF}^{det}\sigma_{OF}^{det} + w_{OF}^{size}\sigma_{OF}^{size}
\]
其中 \(\sigma_{OF}^{clip}\) 是目标对象区域 \(M_o\) 与目标文本的 CLIP 对齐；\(\sigma_{OF}^{det}\) 是实例分割模型对目标对象的检测置信度；\(\sigma_{OF}^{size}\) 是仅用于尺寸调整任务的规则化分数。权重 \(w_{OF}^{*}\) 通过用户研究 grid search 拟合。直觉是：一个成功的对象编辑，既要在语义上匹配目标描述，也要被检测器认可存在，且在尺寸相关任务中满足尺寸方向。三个信号互补，避免单一 CLIP 的不可靠性。

**一致性的凸组合（公式 3、4）**  
\[
\sigma_{OC} = w_{OC}^{lpips}\sigma_{OC}^{lpips} + w_{OC}^{dino}\sigma_{OC}^{dino} + w_{OC}^{\ell 2}\sigma_{OC}^{\ell 2} + w_{OC}^{pos}\sigma_{OC}^{pos} + w_{OC}^{size}\sigma_{OC}^{size}
\]
\[
\sigma_{BC} = w_{BC}^{lpips}\sigma_{BC}^{lpips} + w_{BC}^{dino}\sigma_{BC}^{dino} + w_{BC}^{\ell 2}\sigma_{BC}^{\ell 2}
\]
LPIPS、DINO、L2 衡量外观和语义保持，位置和尺寸分数衡量几何保持。所有分量先被归一化到 [0,1]，距离指标取倒数转为相似度。权重通过用户研究学习。其假设是：一致性是多属性问题，单一距离无法捕捉语义保持。但注意，位置和尺寸分数是规则化设计（Appendix C.2）。

**总分聚合（公式 5）**  
\[
\sigma_{Total} = \sum_{x \in X} w_x \sigma_x, \quad X = \{IQ, OF, BF, OC, BC\}
\]
权重同样拟合自用户研究。工程上，每个任务只使用预定义的相关维度（如替换任务不考虑对象一致性），这避免误导性平均。这个线性加权是简化的偏好模型，假设五个维度互相独立，但论文并未严格检验该假设。

任务特定变体也值得关注：对象添加的对象保真度被拆成类别 CLIP \(\sigma_{OF}^{clip,c}\) 和关系 CLIP \(\sigma_{OF}^{clip,r}\)，与检测置信度加权（Appendix C.1.1 公式 6）；对象移除则把对象保真度定义为 \(1-\sigma_{OF}^{det}\) 与 \(1-\sigma_{OF}^{clip,c}\) 的加权（公式 7）；属性改变用属性 CLIP 单独作为对象保真度，并用经灰度化、降采样和 Canny 边缘检测的图像段计算退化/边缘一致性（公式 10-12）。这些公式共同说明：HATIE 不是一套固定公式，而是按任务语义选择并重组的模块化指标系统。

## 6. 训练到底怎么跑

需要明确：HATIE 本身不是编辑模型，因此没有传统意义上的“训练 step”。这里的“训练”指的是 HATIE 自身的构建与权重校准过程。可以分解为三个子阶段：

**数据集与查询构建阶段**：这不是优化，而是一次性离线数据处理。流程为：筛选 GQA 对象 → 统计得到属性和关系选项 → 按模板批量生成查询 → 用 LLM 生成自然语言。具体而言，附录 A 显示对象过滤包含多个规则：包围盒面积占图低于 0.5% 者剔除；包围盒贴边者剔除；用 mPLUG 预训练 VQA 模型回答遮挡相关的六个是非题，只保留至少答对四题的对象；再以 Detectron2 分割结果与 GQA 标注包围盒 IoU > 0.5 为自动评估可行性条件。查询生成阶段，对象添加和替换依赖从 GQA 注释中统计出的频繁对象-关系对；属性改变依赖从数据集收集的颜色、状态、材质、动作属性列表；背景改变和风格改变从 27 个背景和 10 个风格候选集中选择，且背景选取时故意从 CLIP 对齐度最低的一半候选中选，以避免把背景改成与原来过近的背景。LLM 方面，Llama3 生成原图 caption，GPT-4o 完成属性插入和语法修正。耗时集中在实例分割检测过滤和 LLM 调用，但论文未披露具体算力和时间成本。该阶段不涉及梯度优化。

**用户研究阶段（§3.4）**：这是权重拟合的监督来源。采样 2,025 条查询，产生 4,050 张编辑图像，由 6 个描述式模型（DiffEdit、DiffuseIT、FreeDiff、P2P、Imagic、MasaCtrl）生成。用户研究只使用描述式模型来拟合权重，指令式模型未参与拟合，这可能导致跨类型泛化风险（论文未直接讨论这一点）。4,050 张图被分入 16 个等大的问卷集：8 个集用于整体编辑质量评估，其余 8 个集用于四个具体准则评估，每个准则 2 个集。24 名参与者被分为 8 组，每组回答一个整体质量集和一个特定准则集。每道题由 3 名参与者投票，多数决出胜者。最终训练集使用 2,700 张图（对应 1,350 条查询），测试集使用 1,350 张图（对应 675 条查询）。用户胜率向量 \(u_k\) 作为优化目标。

**权重拟合 step（§3.4）**：对每个维度 \(k \in \{OF, BF, OC, BC\}\)，对公式 (2)-(4) 中的权重进行 grid search，步长为 0.01，最大化用户胜率 \(u_k\) 与自动指标胜率 \(v_k\) 的 Pearson 相关。总分公式 (5) 的权重也类似拟合。这是一个低维凸组合搜索，计算量小。拟合完成后，固定所有权重，在测试集上评估相关性。论文强调使用了独立的留出测试集，避免了过拟合用户偏好。但 grid search 本身可能有随机性，且权重是在 6 个描述式模型上拟合的，是否适用于任意新模型仍需验证。附录 C.3 展示了训练集相关结果（Table I），其中两个保真度维度拟合得略差，论文解释为 Object Fidelity 和 Background Fidelity 在部分任务中仅由单一指标构成，无法进行权重优化，这从反面说明指标多样性的重要。

## 7. 推理到底怎么跑

推理阶段指的是用 HATIE 评估一个给定的文本引导图像编辑模型 \(f\)。完整顺序如下：

1. **准备查询子集**：根据模型类型（描述式或指令式）选择对应的查询版本。HATIE 为每个查询同时提供两种形式，但模型只能用其原生类型；不可混用后强行比较。描述式模型还需要使用 \(C_0\) 和 \(C_e\) 两个 caption，而指令式模型只需要单条 instruction。

2. **遍历所有查询**：对每个查询 \( (I_0, C) \)，运行模型得到编辑图像 \(I_e\)。如果模型有可调参数 \(p\)（如 Imagic 的插值参数 \(\eta\)、InstructPix2Pix 的文本引导尺度 \(s_T\) 和图像引导尺度 \(s_I\)、Prompt-to-Prompt 的自替换步 \(\tau\)），使用官方默认值或预先调好的值（§5 中说明使用了默认值和 Imagic 的 \(\eta=0.6\)）。全部输出图像集合用于后续统计。

3. **逐图计算维度分数**：对每张 \(I_e\)，用 Detectron2 实例分割模型检测目标对象。按任务类型选择计算规则（如图 5 和附录 C.1）：
   - 对象添加：将新生成对象区域与类别名和关系文本分别做 CLIP 对齐，再加检测置信度，构成对象保真度；背景一致性通过同时遮蔽原图和编辑图中的目标对象区域计算。
   - 对象移除：对象保真度定义为 \(1-\sigma_{OF}^{det}\) 和 \(1-\sigma_{OF}^{clip,c}\) 的加权，衡量“目标对象不再像原类”；背景一致性类似处理。当目标对象未被检测到时，对象保真度直接置 1，背景一致性只用原对象区域遮蔽。
   - 对象替换：对象保真度过类别 CLIP 和检测置信度；对象一致性仅用位置保持一致分数；背景一致性使用两者区域的并集遮蔽。
   - 对象尺寸调整：对象保真度仅由规则化尺寸分数构成；对象一致性包括 LPIPS/DINO/L2 和位置分数；背景一致性使用原对象与调整后对象的区域并集遮蔽。
   - 属性改变：对象保真度用对象段与属性词（如“cream motorcycle”）的 CLIP 对齐；对象一致性通过先对对象段做灰度、降采样和 Canny 边缘检测，再计算退化/边缘一致性，以此忽略颜色等被编辑属性。
   - 背景改变：背景保真度用编辑后背景与目标背景文本的 CLIP 对齐；对象一致性对所有前景对象取平均，每个对象使用 LPIPS/DINO/L2/位置/尺寸。
   - 风格改变：背景保真度仍是背景 CLIP 对齐；背景一致性用全图的退化与边缘化版本计算。

4. **集合级图像质量**：对所有 \(I_0\) 和 \(I_e\) 计算 FID，得到 \(\sigma_{IQ}\) 一次。FID 是集合级指标，不逐图计算。

5. **平均与聚合**：对每个维度，在所有适用测试案例上平均；最后用拟合的权重加权求和得到 Total Score。输出包括五个分项分数、总分以及按任务类型、对象类别的细分统计（Table 5, 6），便于诊断模型强弱项。论文在 Appendix D.2 中提到，评估过程中即使检测置信度极低也收集所有检测结果，以避免检测失败；整体检测失败率为 16.01%，但多数情况是对象确实不存在，而不是模型漏检。

## 8. 实验和消融到底证明了什么

| 证据 | 实验设置 | 主要结果 | 对应锚点 |
|---|---|---|---|
| 与人类偏好高度对齐 | 用户研究测试集：675 条查询、1,350 张图，4 个具体维度 + 总分；计算 Pearson/Spearman/Kendall 相关 | Fig. 8 展示 Pearson 拟合；Table 2 的 Spearman ρ：OF 0.8208、BF 0.8971、OC 0.9276、BC 0.8857、Total 0.7143；对应 Kendall τ：0.7379/0.7857/0.8281/0.7333/0.6000 | Fig. 8, Table 2 |

**最关键证据**：Table 3 显示常规底层指标单独用于整体质量判断时相关有限，例如 CLIP 对齐的 Pearson r=-0.3410、LPIPS 为 0.5468。结合 Figure 8 的 Pearson 拟合和 Table 2 的 Spearman/Kendall 排名相关，论文支持“按任务选择指标并用人类偏好拟合权重”比任取单一常规指标更合理；但不同相关系数类型不可直接拿数值相减，0.7143 是总分的 Spearman ρ，不是 Pearson r。

**尚未证明的主张**：HATIE 的权重在 6 个描述式模型上拟合，虽然指令式模型也能使用同一套权重（因为指标本身不变，只是查询形式不同），但论文并未在指令式模型上专门验证权重拟合的人类对齐；附录 D.4 在 ImageNet 上做了外推验证，但样本规模和数据分布与 GQA 不同，且论文未给出该外推的具体相关系数，只展示了趋势图。另外，实例分割模型的失败率 16.01%（Appendix D.2）被论文解释为“多因对象缺失而非检测器缺陷”，但这个比例仍然可能引入噪声，尤其对一致性分数。论文承认对象移除、移动/旋转、部分属性类型被排除（Limitations），因此 HATIE 不覆盖所有编辑任务。

## 9. 与前作怎么选

| 基准 | 规模 | 自动化 | 任务覆盖 | 何时选它 | 何时不选 HATIE 而选它 |
|---|---|---|---|---|---|
| TEdBench（Kawar et al.） | 100 图像，100 查询 | 否，需用户研究 | 窄，早期编辑任务 | 无 | 当只需快速演示少量案例或预算极低时 |
| EditBench（Wang et al.） | 240 图像，720 查询 | 部分，仍依赖人工 | 图像修复为主 | 无 | 当任务集中在 inpainting 且已有人工标注流程时 |
| GIER（Shi et al.） | 6,179 图像，30,895 查询 | 否 | 适合像素级对齐任务（如灰度化） | 无 | 当编辑结果有明确像素级 ground truth 时 |
| EditVal（Basu et al.） | 92 图像，648 查询，19 类 | 部分自动化 | 中等多样 | 当只关心少数类别且愿意做用户研究时 | 无 |
| **HATIE** | 18,226 图像，49,840 查询，76 类 | 全自动 | 7 大类型，宽覆盖 | 需要大规模、可复现、细粒度、与人类对齐的评估；要对模型做任务级/类别级诊断 | 当需评估移动/旋转、情感/发型属性编辑、或描述式模型的对象移除时，HATIE 未覆盖 |

选择时还要注意：HATIE 的权重和指标基于 Detectron2 等固定模型，如果被评估模型生成的图像风格与这些预训练模型训练分布相差过远，分割或 CLIP 可能失效。EditVal 虽然规模小，但包含部分人工详细标注，可能对极小众对象类更友好。此外，HATIE 的对象移除任务目前只支持指令式模型，描述式模型在对象移除上无法用 HATIE 评估，这一点在选择时也必须考虑。

## 10. 工程判断：可行性、风险与上限

**数据与算力**：HATIE 是一次性构建成本，论文未披露具体 GPU/时长。基于 18,226 张图、49,840 条查询的全模型评估，每张图需运行编辑模型一次，再加分割和指标计算。对已有研究组，9 个模型全量跑的成本可能需数百到数千 GPU 小时，但这是基准评估的标准代价。构建时 LLM 生成 caption 和人工验证也存在成本，但可离线完成。查询生成需要调用 Llama3 和 GPT-4o，其中 caption 生成要求反复生成直到包含确切对象名，这一步可能消耗不少 API 调用；但论文没有给出具体成本数据。

**延迟**：推理延迟主要来自编辑模型前向传播，评估指标的计算是轻量级（CLIP、分割等），可并行化。实时监控不太现实，适合离线 benchmark 或定期回归。如果用于超参数搜索，例如论文中变化 \(\tau\)、\(s_T\)、\(s_I\)、\(\eta\) 得到完整结果（Table II），评估一个 hyperparameter 组合也需要跑完整个查询集，成本会随组合数线性增长。

**实现难点**：权重拟合需要对用户投票胜率做 grid search；用户研究只覆盖描述式模型，若未来新增指令式模型，权重可能需重新校准。实例分割对遮挡、小物体、非自然图像的鲁棒性是系统脆弱点。任务特定的工作流（附录 C.1）手工设计较多，新增任务需重新设计指标组合和权重。例如对象属性改变需要设计退化/边缘一致性，这种规则依赖 Canny 边缘和灰度变换，对强风格化图像可能失效。

**失败环节**：最可能失败的是目标对象未被分割器检测到（论文报告 16.01% 失败率）。在对象移除任务中，目标不存在时 \(\sigma_{OF}\) 会被置 1（Appendix C.1.2），但如果分割器漏检，会错误给满分。背景变化评估中前景对象未检测到时，\(\sigma_{OC}^o\) 设为 0 且背景一致性不用该对象 mask，这也会引入噪声。属性改变任务中，如果目标对象未被检测到，对象保真度和对象一致性都被置 0，背景一致性只用原对象区域遮蔽，这可能高估背景一致性。

**监控信号**：应监控五个维度分数的 bootstrap 误差（论文展示了小误差）、分割失败率、FID 的稳定性、用户留出集上的相关性是否漂移。若某类任务分数方差异常，需检查分割质量或查询可行性。尤其要关注对象移除、替换等依赖检测结果的任务，因为检测失败会直接改变分数分配规则。

**指标上限**：总分是五个分项的线性组合，权重和底层指标都有上限。例如 CLIP 对齐受限于 CLIP 的细粒度理解，FID 又忽略输入输出的配对关系。Table 2 中总分与用户模型胜率的 Spearman ρ 为 0.7143、Kendall τ 为 0.6000，并非完美，所以 HATIE 应被视为相对排序工具，而非绝对正确评分。当未来模型分数接近饱和时，当前指标的区分度也可能下降。

**未回答问题**：权重能不能跨模型类型泛化？指令式模型与描述式模型有同样的任务语义，但用户研究仅用描述式模型拟合，未经指令式测试对齐。基准是否对更强模型饱和？Table 4 中 MagicBrush 总分 0.7329 远低于理论上限 1，尚有区分度，但未来模型接近上限后可能区分不开。另外，HATIE 未覆盖任务范围限制了其全面性。

## 11. 放回研究脉络并收束

HATIE 属于“文本引导图像编辑的自动化基准”这一脉络。此前该领域评估依赖用户研究或小规模、窄任务基准。HATIE 的核心贡献不是提出新的编辑模型，而是建立了一套规模和维度都前所未有的评估协议，并用数据驱动方法让自动分数逼近人类偏好。它把“评估”本身视为一个可学习的系统：从数据筛选、查询生成、多指标计算到权重拟合，形成一个可扩展的闭环。未来可能方向包括扩展到移动/旋转、更细粒度属性编辑，以及跨数据分布的权重泛化。

**读完必须记住的 5 件事**：

1. HATIE 是一个基准与评估框架，不是编辑模型；它包含 18,226 张图像、49,840 条查询、76 个 COCO 类，所有查询同时提供描述式和指令式形式。
2. 评估分五个维度：图像质量（FID 缩放）、对象/背景保真度、对象/背景一致性；各维度由多个底层指标凸组合而成，并根据任务类型选择不同指标组合。
3. 权重通过用户研究成对偏好拟合，目标最大化与用户胜率的 Pearson 相关；测试集 Table 2 的总分 Spearman ρ 为 0.7143，四个分项的 Spearman ρ 均在 0.82 以上。
4. 单一常规指标（如 CLIP 对齐、检测率、LPIPS）与人类偏好相关度远低于 HATIE 的组合分数，说明结构化组合是关键。
5. HATIE 能捕捉编辑强度权衡，并对不同模型提供任务级、对象级的强弱诊断，但未覆盖对象移除（描述式）、移动/旋转、部分属性编辑，且实例分割失败率约 16.01%。

**5 道自测题**：

1. HATIE 的五个评分维度分别是什么？各自主要依赖哪些底层指标？
2. 论文如何证明 HATIE 与人类感知对齐？Figure 8 与 Table 2 分别报告哪种相关证据？为什么不能把 0.7143 写成 Pearson r？
3. 为什么论文认为描述式模型和指令式模型不能直接比较？HATIE 如何支持这两种模型？
4. HATIE 的对象保真度分数由哪几个分量组成？权重如何确定？在对象添加、移除和属性改变任务中，对象保真度的具体定义有何不同？
5. HATIE 的主要局限性有哪些？（至少列出三点）

**一句话总结**：HATIE 用大规模数据、任务特化的指标组合和用户偏好拟合，把图像编辑评估从“主观且不可扩展”推向“自动化且与人类相关”，为后续编辑模型提供了一根更可靠的公共尺子。
