# 大白话深读《read-it-back》

## 1. 30 秒定位

这篇论文提出 **SpectraReward**，一种面向文生图强化学习的免训练奖励函数。核心动作是“把 prompt 读回来”：给定生成图像，冻结一个预训练多模态大模型（Multimodal Large Language Model，MLLM），让它以图像为条件，对原始 prompt 做逐词 teacher-forced 预测，取平均图像条件对数似然作为奖励。它不需要人类偏好标注，不需要奖励模型微调，也不要求 MLLM 打离散分数或回答分解问题。论文进一步提出 **Self-SpectraReward**，用于统一多模态模型：让策略模型自己的理解分支给生成分支打分，形成无外部奖励模型的闭环自改进。实验覆盖两个生成骨干、三个 RL 算法、九个 4B–235B 的奖励 MLLM 骨干、五个分布外基准。结果显示，两种方法都一致提升生成性能，并优于 AlphaGRPO 等先前的 MLLM 衍生奖励方法；同时发现奖励模型规模增益不是单调的，策略自身的理解分支可以媲美甚至超过 235B 外部奖励模型。默认训练配置为 BAGEL 策略 + AWM 算法，512×512 分辨率，每步 32 个 prompt、每组 16 个样本，共 380 步，使用 32 张 A100，默认外部奖励 MLLM 为 Qwen3-VL-30B-A3B（§4.1、Table 1、Table 2）。

## 2. 为什么这篇论文会出现

文生图后训练强化学习已经能稳定提升构图忠实度和指令跟随能力，但论文指出，强化学习配方有两个互补支柱：优化算法决定长期训练稳定性，奖励模型决定策略最终能逼近的上限。奖励模型设计一直是瓶颈。

已有奖励建模有三条路线。第一条用大规模人类偏好标注训练视觉-文本对齐模型，如 ImageReward、Pick-a-Pic、HPSv3、UnifiedReward，它们有效但依赖昂贵标注、数据收集和迭代成本高（§2）。第二条把奖励模型升级为微调后的 MLLM，如 VisionReward、OneReward，能提高上限，但需要大量标注数据和训练开销，还会使奖励模型偏离预训练分布（§2）。第三条绕开偏好训练，直接用预训练 MLLM 做零样本奖励。其中一部分让 MLLM 输出离散标量分或 logit 反馈，对 judge 校准和打分噪声敏感；另一部分如 AlphaGRPO 的 DVReward，把 prompt 分解成可验证的原子问题再逐项问 MLLM，可靠性更好，但引入两阶段流程和问题分解瓶颈，工程复杂度高（§2、Figure 2）。此外，并发工作 PromptEcho 探索了交叉熵形式的相似概念，但其评估只限于特定领域文生图骨干；SRUM 和 GvU 等 UMM 内部自奖励方法也停留在内部评测，没有系统比较外部奖励模型（§2）。

这些路线留下的缺口是：能否设计一种高效、无偏好标签、无需微调、现成可用的奖励模型，直接复用 MLLM 预训练阶段已经学到的图像-文本对齐能力？SpectraReward 的答案是：不去问 MLLM “这张图好不好”，而是问“这张图能不能把原 prompt 读回来”。这个反向问题直接对应 MLLM 预训练最核心的图像到文本语言建模目标，因而有可能成为更干净、更密集的奖励信号。论文在 §3.1 和 Figure 2 中明确对比了这个思路与标量评分、VQA 分解的区别：单次 teacher-forced 前向、密集似然信号、无需分解或强 judge。

## 3. 读懂前需要的最小概念

**MLLM** 指同时处理图像和文本的预训练大模型，通常以图像特征为条件做下一词预测。它在大规模图像-文本对上学到图像与语言之间的对齐。论文使用的 MLLM 包括 Qwen3-VL、Gemma3、InternVL3.5 等家族，跨度从 4B 到 235B 参数（§4.1、Table 2）。

**Teacher forcing** 是训练和评测语言模型时的一种前向方式：不把模型上一步预测的词作为下一步输入，而是把真实目标序列的每一步词作为输入，分别计算模型对下一个真实词的条件概率。SpectraReward 对 prompt 做 teacher-forced forward，实际上是在测试“在图像条件下，模型是否认为这个 prompt 是自然的描述”。这里不需要生成任何新 token，只需前向传播一次，因此计算代价接近一次 MLLM 编码。

**图像条件 prompt 对数似然** 是公式 (1) 的核心量。对 prompt 第 t 个位置，给定前面真实 token 和图像 y，计算模型预测下一个 token x_{t+1} 的对数概率。该值高，说明图像视觉证据对该文本词的支撑强。这些 token 级似然组成了论文所说的 semantic spectrum（语义谱），可看作对每个语义片段的图像支撑度扫描（§3.1）。

**Group-relative RL** 指在同一 prompt 下采样多个生成图像，计算组内相对优势而不是绝对奖励。这种设计让语言先验等跨 prompt 常数抵消，也使奖励只需保证组内排序合理即可。论文在 §3.3 中论证：对固定 prompt，文本先验 log p(x) 对所有组内样本是共享的，因此在组内优势中会抵消，所以不需要显式减去文本先验的 PMI 修正。

**统一多模态模型（UMM）** 是一个网络同时具备视觉理解和图像生成能力，例如 BAGEL、Show-o、Janus-Pro、Emu3 等。BAGEL 内部有理解分支和生成分支，共享 tokenizer 和部分视觉编码，但生成侧还使用 VAE 特征。Self-SpectraReward 正是利用这个“理解分支与生成分支同分布”的性质，让理解分支充当奖励 MLLM（§3.2、Appendix B）。

**优势函数（advantage）** 在 RL 中表示某条轨迹相对于组内均值的相对好坏。论文默认把序列级奖励做组内标准化得到优势，再用 AWM 等算法更新策略。论文还比较了 token-level advantage（把每个 token 位置单独算优势再平均），但默认序列级更稳定，详见 §4.4 和 Table 5。

## 4. 方法全景：先看数据流

SpectraReward 的数据流如下：

```
prompt x (文本)
   │
   ▼
策略 Gθ (生成分支/扩散模型)  ──►  生成图像 y
                                    │
                                    ▼
                        冻结 MLLM M 以 y 为视觉条件
                                    │
                       对 x 做 teacher-forced 前向
                                    │
                    得到每个 token 的对数似然
                      log p_M(x_{t+1} | x_≤t, y)
                                    │
                    平均为标量奖励 R_M(x,y)
                                    │
                    同一 prompt 组内计算优势
                                    │
                    送入 RL 算法更新 Gθ
```

**组件一：策略模型 Gθ。** 输入 prompt x，输出图像 y。在 SpectraReward 主实验中，策略可以是 SD3.5-M 这样的扩散模型，也可以是 BAGEL 这样的统一多模态模型（Table 2）。它的目的是产生候选图像供奖励评估和梯度优化。BAGEL 是原生 AR-Diffusion 统一多模态模型，预训练时同时学习图像理解和图像生成，因此理解分支和生成分支共享基础能力；SD3.5-M 则是单纯生成模型，没有理解分支，只能用外部 MLLM 奖励。假设策略能够通过 RL 被差分更新，并且生成采样可以回传梯度。

**组件二：冻结奖励 MLLM M。** 输入图像 y 和 prompt x，输出每个 prompt token 的图像条件 log-likelihood。论文默认使用 Qwen3-VL-30B-A3B 作为外部奖励骨干（§4.1）。该组件不更新参数，也不需要前缀，只有 InternVL3.5 家族例外，加前缀 “Describe the image” 以获得更稳定奖励值（Appendix B）。它假设 MLLM 预训练已经学到图像到文本的 grounding 能力。在 Self-SpectraReward 中，这个组件被替换为策略自身的理解分支 Gθ^und，其输入额外包含 BAGEL 的 VAE 特征；附录 C 的消融显示加入 VAE 特征能提升 GenEval 和 TIIF-Short（Table 7）。

**组件三：语义谱（semantic spectrum）与聚合。** token 级对数似然构成 semantic spectrum，反映图像证据如何支撑 prompt 的逐词语义。聚合方式是去掉 EOS token 后取均值，得到标量奖励。论文发现 token 级似然对计数错误、物体身份错误等局部语义失配敏感，错误主要落在对应词汇上。Figure 3 给出量化实例：在 “Two cats sitting on a sofa” 的计数错误中，positive 图的 “Two” token 似然为 -5.66，negative 图为 -7.44；在 “A wooden guitar leaning against the wall” 的物体替换中，“guitar” token 从 -1.19 降到 -9.61。序列级奖励也从 -1.932 降到 -2.298、从 -2.822 降到 -3.891。这些数字说明 token 级似然具有局部语义分辨率，均值聚合后仍保留组内排序能力。

**组件四：RL 优势计算与更新。** 在 Self-SpectraReward 中，策略自己的理解分支 Gθ^und 充当 M；外部 SpectraReward 则用单独 M。两种情况下的奖励都送入 AWM（默认）等算法，按 prompt 分组计算优势并更新生成分支。Self 版本还默认把 VAE 特征作为理解分支的额外视觉输入（Appendix B、Table 7）。论文在 §4.4 中比较了 sequence-level advantage 和 token-level advantage：前者先把 token 似然平均成序列奖励再算组内优势，后者对每个 token 位置分别算优势再平均；结果 sequence-level 默认更稳定（Table 5）。

这个方案的关键假设是：图像条件 prompt 似然能可靠地排序同一 prompt 下的不同生成样本，而 group-relative RL 只需要这种排序信号。Figure 4 展示的奖励排序与视觉质量排序一致，支持这一假设。论文还在 Appendix E 的 Figure 6 提供了更多奖励排序示例，覆盖空间关系、计数、属性绑定、相对大小和长 prompt 组合。

## 5. 核心公式与直觉

核心公式只有一个，即 SpectraReward 的奖励定义：

\[
R_M(x,y) = \frac{1}{T-1} \sum_{t=1}^{T-1} \log p_M(x_{t+1} \mid x_{\le t}, y)
\]

其中，x 是 prompt 的 token 序列，长度为 T；y 是生成图像；M 是冻结的预训练 MLLM。p_M 表示在给定 x 的前 t 个 token 和图像 y 的条件下，M 对下一个 token x_{t+1} 的预测概率。求和范围是 t=1 到 T-1，即排除序列最后一个位置对 EOS 的预测。论文在实现中显式屏蔽 EOS token，因为它更像序列终止信号而非语义对齐信号，且对短 prompt 影响过大。附录 C 的消融 Table 6 显示，包含 EOS 时 GenEval 为 88.5，去掉后升到 89.5，而 TIIF-S/L 基本持平。

直觉上，这个公式测量的是：如果让 MLLM 看着图像“读”出原始 prompt，它觉得这些词有多自然。图像忠实于 prompt 时，相关物体、属性、空间关系的词汇都能从视觉证据中得到支撑，似然较高；图像缺少物体、属性错误或关系错误时，对应词汇的条件概率会显著下降。论文的 Figure 3 给出实例：把 “two cats” 的计数从 2 改成 5，主要下降的 token 是 “Two”；把 “wooden guitar” 换成 “wooden chair”，下降集中在 “guitar”。这说明 token 级似然对局部语义失配敏感，而均值奖励能够保留组内排序能力。

公式中有两个实现细节值得展开。第一，Teacher forcing 保证了每个位置都使用真实 prompt 前缀，而不是模型自己生成的前缀，因此奖励是确定性的，同一图像多次计算得到相同数值。第二，平均范围是 T-1 而不是 T，对应屏蔽 EOS。论文在 Appendix B 和 C 中说明，EOS 的似然经常明显低于普通 token，在短 prompt 中会不成比例地拉低平均奖励，因此将其从求和与归一化中排除。

论文还讨论了一个潜在修正：减去文本先验 log p(x) 得到 PMI 风格奖励 \(\log p_M(x|y) - \log p_M(x)\)。但作者认为，在 group-relative RL 中，同一 prompt 的文本先验对所有生成图像相同，会在组内优势计算中抵消，因此 PMI 归一化只影响跨 prompt 的绝对校准，不提供额外优化信号，故默认不采用。这一分析在 §3.3 中明确给出，是理解该方法为何能免去先验校正的关键。同时，这也说明 SpectraReward 的优化信号来自组内相对差异，而不是跨 prompt 的绝对似然大小。要注意的是，如果后续把 SpectraReward 用于非 group-relative 的 RL 或离线排序场景，文本先验就可能重新成为需要处理的因素，论文没有在那些设定下验证该结论。

## 6. 训练到底怎么跑

论文默认使用 **AWM** 作为强化学习算法，因为消融中 AWM 在三个算法里取得最好的下游性能（§4.4、Table 3）。策略模型是 BAGEL，一个原生 AR-Diffusion 统一多模态模型；除非另有说明，外部 SpectraReward 用 Qwen3-VL-30B-A3B 作为奖励 MLLM，Self-SpectraReward 用 BAGEL 自己的理解分支（§4.1）。训练数据为 **AlphaGRPO20k** 数据集的训练分片，论文未披露该数据集的具体提示数量、分布或预处理方式，只说明它来自 AlphaGRPO 工作（§4.1）。

单个训练 step 的流程如下：

1. 采样 32 个 prompt，来自 AlphaGRPO20k 数据集的训练分片。
2. 对每个 prompt，用当前策略生成 G=16 个图像样本。训练分辨率 512×512，采样步数 T=16，随机在前 10 个去噪步中选 6 步做随机截断训练，以减少计算。使用 classifier-free guidance 尺度 4，timestep shift 3。这意味着每个 step 实际处理 32×16=512 张生成图像（§4.1）。
3. 把每个生成图像和它的原始 prompt 送入冻结奖励 MLLM（或 BAGEL 理解分支），做 teacher-forced 前向，得到每个 token 的 log p，屏蔽 EOS 后取均值，得到标量奖励。Self 版本还会加入 BAGEL 的 VAE 特征作为理解分支输入；Appendix B 说明 BAGEL 提供两种视觉输入：语义编码器的 ViT 特征和生成编码器的 VAE 特征，默认同时使用两者；Appendix C 的 Table 7 显示去掉 VAE 输入会使 GenEval 降至 87.8、TIIF-Short 降至 83.6。
4. 在同一 prompt 的 16 个样本内计算组相对优势：默认先做序列级平均奖励，再做组内标准化。论文 §4.4 还测试了 token-level advantage 的三种 std 归一化范围：global std、group std、per-token std，结果见 Table 5，均未明显超过 sequence-level，因此默认使用 sequence-level。
5. 用 AWM 的损失对生成分支做梯度更新。学习率 1e-4，batch size 2，梯度累积 8，共 380 步，使用 32 张 A100 GPU。其余超参数遵循 AWM 官方实现，论文未展开（§4.1）。

训练只做 380 步，规模较小。所有训练在 512 分辨率完成，但下游评估包括 1024 分辨率，以检验奖励信号是否迁移。文中没有披露训练总时长或单步延迟，但从 32 A100、batch size 2、G=16、T=16 的配置看，奖励 MLLM 前向和生成采样占主要开销。外部 SpectraReward 使用 30B-A3B 的 MoE 模型（30B 总参数、3B 激活）可以降低单次前向成本，但每个 prompt 组仍需 16 次生成与 16 次奖励计算；Self 版本省去外部 MLLM 服务，但增加了自理解分支的 VAE 特征输入，计算量未必显著减少。

论文没有提到是否冻结理解分支参数；根据方法描述，Self-SpectraReward 只更新生成分支，理解分支作为奖励来源保持冻结，否则奖励会随训练漂移。但论文未明确说明梯度是否传入理解分支，也未报告该设置。

## 7. 推理到底怎么跑

训练结束后，推理阶段不需要任何奖励模型参与。用户提供 prompt，策略直接生成图像。论文评估时在 512 和 1024 两种分辨率下推理：512 沿用训练分辨率，1024 检验跨分辨率泛化（§4.2）。Self-SpectraReward 在推理时与普通 BAGEL 完全一致，不需要外部 MLLM，不增加推理延迟；SpectraReward 同理，训练时用什么奖励模型与推理无关。论文未披露推理阶段的采样步数、classifier-free guidance 尺度或是否使用与训练相同的 timestep shift，只说明训练设置为 T=16、guidance=4、shift=3（§4.1），因此无法从论文确认推理超参是否与训练完全一致。

论文检验的是真实生成质量的提升，而不是代理奖励的上升。下游用五个分布外基准：**GenEval**、**TIIF-Bench**、**DPG-Bench**、**GenEval2**、**WISE**。GenEval 侧重物体存在、计数、颜色、空间位置和颜色属性绑定；TIIF-Bench 分 short/long 和 Basic/Advanced/Designer 子集，细粒度测指令跟随，其中 text 子类别绝对分较低但提升幅度大；DPG-Bench 分 Global/Entity/Attribute/Relation/Other 五个维度；GenEval2 更强调整体指令跟随和知识；WISE 考察文化、时间、空间、生物、物理、化学等世界知识（§4.2 和 Appendix D）。WISE 还报告了 self-CoT 版本，即推理时先让模型生成思维链再生成图像；Self-SpectraReward 在 self-CoT 下达到 WISE 0.76，SpectraReward 达到 0.74，而 BAGEL 基线为 0.70（Table 11）。这属于推理增强，与奖励机制本身区分，论文没有披露 self-CoT 的具体提示格式。

一个关键点是：训练时策略可能过拟合奖励 MLLM 的偏好，但实验显示外部 SpectraReward 和 Self 版本在五个分布外基准上都有实打实的提升，说明奖励信号具有泛化性，不只是代理分数变高。例如 GenEval2 的 512 分辨率下 Self-SpectraReward 达到 34.3，比 BAGEL 的 23.6 高约 10.7 分；1024 分辨率下 Self 达到 89.8 GenEval，也优于 BAGEL 的 86.6（Table 1）。这些数值来自代理奖励训练后策略在下游基准上的真实表现，不依赖奖励 MLLM 在测试时存在。

| VAE 输入消融 | GenEval / TIIF-Short | 包含 VAE：89.5/85.1；去掉：87.8/83.6 | TIIF-Long 保持 84.3 vs 84.7 | Appendix C Table 7 |

最关键的两项消融：一是奖励函数形式（Table 4）。直接让 MLLM 打 1–5 分不仅没提升，反而让 GenEval 从 84.0 跌到 77.7；问 “Does this figure show {caption}?” 并取 “yes” 概率的 VQA-Score，在 TIIF 上有微小提升但 GenEval 反而下降。只有图像条件 prompt 似然在全部指标上稳定提升。这证明逐 token 的密集似然比离散判断或单点 yes/no 更适合作为文生图 RL 的奖励。Scalar Scoring 的崩塌尤其说明：离散标量在组内排序上噪声过大，可能引入与真实语义无关的偏好信号。

二是奖励 MLLM 骨干与 Self 的对比（Table 2）。同类规模下，Self-SpectraReward 的 BAGEL 理解分支获得 GenEval 89.5，超过所有外部奖励模型，包括 235B 的 Qwen3-VL。具体外部结果：Gemma3-4B 83.6、Gemma3-12B-Pretrain 88.7、Gemma3-12B-Instruct 87.5、InternVL3.5-8B 84.5、InternVL3.5-14B 84.9、Qwen3-VL-8B 87.8、Qwen3-VL-30B-A3B 88.3、Qwen3-VL-235B-A22B 86.8。论文把原因归为 reward-policy alignment：理解分支与生成分支共享 tokenizer、视觉编码器和预训练分布，因而其阅读方式与生成图像的分布天然匹配。这不是说 BAGEL 通用理解能力比 Qwen3-VL 强，而是其奖励信号对策略自身生成样本的排序更准。规模增加并非单调：Qwen3-VL 从 8B 到 30B 提升，再到 235B 下降；Gemma3 从 4B 到 12B 提升 GenEval，但 TIIF 不总提升；Gemma3-12B-Pretrain 甚至优于 Instruct 版本，说明预训练阶段的图像-文本对齐目标与 SpectraReward 更匹配（§4.3）。

第三组值得关注的消融是 RL 算法与基准奖励模型的对比（Table 3）。在 Self-SpectraReward 下，AWM 得到 GenEval 89.5，优于 FlowGRPO 的 85.3 和 DiffusionNFT 的 89.1；即便 DiffisionNFT 接近 AWM，论文仍选 AWM 作为默认。与先前奖励模型对比，AlphaGRPO 搭配 HPSv3 得 83.4、UnifiedReward 83.7、VIEScore 81.7、DVReward 85.0，均低于 Self-SpectraReward 的 89.5。这说明不仅是 RL 算法在起作用，Self-SpectraReward 作为奖励来源本身也显著优于这些人工偏好或分解验证奖励。

附录 D 的类别级结果进一步说明增益来源。在 GenEval 上，SpectraReward 512 的 counting 从 BAGEL 的 74.1 提升到 83.1，Self 提升到 84.4；colors 从 90.4 提升到 93.4/93.6；position 从 71.0 提升到 79.8/81.5；color attribute 从 74.8 提升到 79.0/81.5（Table 8）。这表明提升集中在结构化、组合性类别，而不是单一物体存在。在 DPG-Bench 上，SpectraReward 512 overall 为 88.08（BAGEL 85.07），Self 为 87.73；SpectraReward 的 Global 从 88.94 升至 93.80，Self 的 Attribute 从 91.29 升至 92.12（Table 10）。在 WISE 上，Self-SpectraReward + self-CoT 在 space 达到 0.82、biology 0.73、physics 0.84、chemistry 0.69，均高于 BAGEL + self-CoT 的对应值（Table 11）。这些细粒度数据支撑“奖励信号主要改善显式语义与指令跟随”的结论。

尚未证明的主张：论文明说 SpectraReward 的上限受所选 MLLM 的视觉推理能力约束；隐式物理和常识含义（如 “hot coffee” 隐含蒸汽）可能无法从原始 prompt token 的似然中充分捕捉；美学和安全目标需要额外奖励模型辅助（Appendix A）。文中没有提供与人类偏好评分的直接相关性检验，也没有证明 prompt likelihood 在长尾极端 prompt 上仍保持组内排序可靠。此外，Self-SpectraReward 的优势仅在 BAGEL 一个 UMM 上验证，是否适用于其他 UMM 结构未做实验。论文也未报告多次迭代自奖励或奖励 hacking 的长期稳定性结果。

## 9. 与前作怎么选

**AlphaGRPO / DVReward**：AlphaGRPO 将 prompt 分解为原子验证问题，用 MLLM 的 verifier 置信度构造 DVReward。它的优势是对复杂指令有显式逐项检查，对显式原子需求覆盖完整；缺点是两阶段流程、问题分解可能遗漏隐式约束、工程复杂度高。论文与 AlphaGRPO 同用 BAGEL，SpectraReward 在 TIIF-Bench 和 GenEval 上超过 AlphaGRPO，表明对当前策略任务，单次 likelihood 通读可能比分解验证更有效（§4.2、Table 1）。**何时选 SpectraReward**：prompt 主要是描述性文本，有大量图像-文本对预训练模型可用，希望免标注、免微调、免分解工程。**何时选 DVReward 类**：需要推理型文生图任务或对原子需求的显式可解释检查，且能承担多轮 MLLM 调用成本。

**标量打分 / VQA-Score**：标量打分直接问 MLLM 给 1–5 分，VQA 问 yes/no，都极度简单但信号粗。论文 Table 4 显示标量打分严重损害性能，VQA 增益有限。只要目标是文生图 RL，这两种不推荐。不过如果只是粗略筛选或人工可接受，标量打分成本最低。

**PromptEcho**：并发工作，用交叉熵形式似然，但论文指出其评估限定在特定领域 T2I 骨干，未做跨生成模型、跨 MLLM 家族和 OOD 基准的广泛验证（§2）。SpectraReward 在通用性和规模化实验上更完整。选 PromptEcho 的场景：已有相应领域定制骨干且不需要跨结构泛化。

**SRUM / GvU**：二者都是 UMM 内部自奖励，分别用理解分支的全局-局部信号、token 级 logits。它们与 Self-SpectraReward 直觉一致，但论文指出其未比较外部奖励模型，也不清楚自奖励相对外部奖励的优劣（§2）。SpectraReward 的贡献在于给出统一函数并证明对齐度可以压倒规模。如果研究纯 UMM 自改进，这三者相关；如果关心外部 vs 自奖励的收益边界，选 Self-SpectraReward 的评估设置。

## 10. 工程判断：可行性、风险与上限

**数据维度**：没有偏好标注需求，只需文生图训练集，如 AlphaGRPO20k。这大幅降低门槛，但训练 prompt 的质量和多样性会限制泛化；论文未披露该数据集的规模或来源细节，只给出来源和 20k 名称，无法评估训练集覆盖的提示分布（§4.1）。

**算力/延迟**：训练用 32 A100，batch size 2，梯度累积 8，总 380 步。主要开销来自生成 16 个样本和 reward MLLM 前向。默认外部奖励 30B-A3B（MoE 30B 总参、3B 激活）可以减少单次前向延迟，但每个 prompt 组仍需 16 次生成与 16 次奖励计算。Self 版本免去额外 MLLM 服务，但需要 BAGEL 理解分支前向，且默认使用 VAE 特征，计算可能略增。推理端无奖励开销。论文未报告实际训练墙钟时间或吞吐，无法给出成本估算。

**实现难点**：一是 EOS 屏蔽。论文发现 EOS 对数似然常常异常低，对短 prompt 影响大；Appendix C 表 6 显示去掉 EOS 使 GenEval 从 88.5 升到 89.5。二是 VAE 特征是否输入 BAGEL 理解分支。消融显示加入 VAE 特征提升 GenEval 和 TIIF-Short，具体原因只是经验上更好（Appendix C Table 7）。三是 teacher forcing 与 prompt 前缀：默认不加前缀，InternVL3.5 例外加 “Describe the image”，说明不同 MLLM 家族可能需要微调奖励计算形式（Appendix B）。四是 group std 的标准化范围，论文对比了 sequence-level 和 token-level advantage，最终默认 sequence-level 更稳定（§4.4、Table 5）。附录 B 强调，虽然前缀可以改变绝对似然值，但不显著影响组内相对排序，因此作者对所有奖励 MLLM 保持无前缀，只有 InternVL3.5 家族例外。

**失败环节**：如果 reward MLLM 对某种语义维度不敏感，例如细粒度计数或罕见属性，奖励信号会缺失；如果 MLLM 本身有视觉错觉或语言先验偏向高频词，可能误导策略。论文只在有限正负样本中证明 token 敏感，未穷尽对空间关系、相对大小、遮挡等复杂错误的敏感性。另外，Self 版本完全依赖策略自己理解分支，如果理解分支本身不够强或与生成分支存在系统性盲点，可能形成错误的闭环。Appendix A 指出，SpectraReward 主要捕捉显式语义对齐，对 “hot coffee” 暗示蒸汽这类隐式物理常识覆盖不足；所以如果要处理这类约束，可以用更强的 MLLM 或扩展到推理式文生图，让推理过程把隐式要求显式化。

**监控信号**：训练中可记录 average prompt likelihood 的上升情况、组内 reward 标准差、下游基准代理分；论文建议看重下游 OOD 基准的代理分而非单一代理收益。**指标上限**：论文明确承认 prompt likelihood 主要反映显式语义对齐，隐式常识、美学和安全目标覆盖不足；scaling reward MLLM 到 30B 后出现饱和甚至下降，所以不能靠无限放大解决上限（§4.3、Appendix A）。论文提出可结合专门的奖励模型处理美学和安全，这属于未来工作。

**未回答问题**：文生图 RL 的长期稳定性、奖励 hacking 风险、多次迭代自奖励是否退化、与人类偏好评分的相关性、训练数据规模的影响、非 BAGEL UMM 的 Self 版本是否同样有效，论文均未给出严格证明。这些需要在部署前通过额外实验确认。

## 11. 放回研究脉络并收束

SpectraReward 处于两条研究脉络的交汇点：文生图奖励模型和统一多模态模型自奖励。奖励模型从纯人类偏好学习（ImageReward、Pick-a-Pic、HPS）发展到 MLLM 微调（VisionReward、OneReward），再到零样本 MLLM judge（标量评分、AlphaGRPO/DVReward）和并发工作 PromptEcho。SpectraReward 把“零样本 judge”推到“零样本 likelihood 读回”，进一步去除 judge 的离散决策。Self-SpectraReward 则把这一函数安放进 UMM 的自奖励脉络，与 SRUM、GvU 形成一组自对齐方案。论文的主要经验论点是：奖励模型与策略的分布对齐度可能和奖励模型规模一样重要，这对后续 UMM 自改进方向有直接意义。实验同时证明，奖励函数的微观形式（标量 vs 似然）比奖励模型大小更有决定性：一个 8B 的自奖励可以打败 235B 的外部标量判断。

**读完必须记住的 5 件事**

1. SpectraReward 的定义：图像条件 prompt 平均对数似然，屏蔽 EOS，teacher-forced 单次前向，无偏好评标（§3.1、Equation 1、Appendix C）。
2. Self-SpectraReward 用 UMM 自己的理解分支当奖励，形成无外部模型的闭环；8B 级 Self 奖励在 GenEval 上超过 235B 外部奖励（§3.2、Table 2）。
3. 奖励 MLLM 规模增益非单调：Qwen3-VL 从 8B 到 30B 提升，再到 235B 反而下降；Gemma3 12B-Pretrain 优于同规模 Instruct（§4.3、Table 2）。
4. 训练设置：BAGEL 策略，AWM 算法，512 分辨率，G=16，T=16，随机 6 步截断，380 步，32 A100（§4.1）。
5. 关键消融：prompt likelihood 远优于 1–5 标量打分和 yes/no 概率；sequence-level advantage 默认更稳定；EOS 必须屏蔽；Self 版本加入 VAE 特征更好（§4.4、Table 4、Table 5、Appendix C）。

**5 道自测题**

1. 若把 SpectraReward 的奖励改为减去文本先验 log p(x)，在 group-relative RL 中会产生什么差异？为什么论文不采用？
2. 训练时 T=16 采样步、随机选前 10 步中的 6 步进行截断，这一设计面向什么工程目标？
3. Self-SpectraReward 相比外部 SpectraReward 的“分布对齐”具体体现在哪些组件上？
4. 论文中奖励函数形式的消融里，Scalar Scoring 为什么反而使 GenEval 低于 baseline？
5. 如果要把 SpectraReward 扩展到隐式物理常识约束强的 prompt，论文给出的未来方向是什么？

最终一句话总结：SpectraReward 证明，让冻结 MLLM 从生成图像中“读回”原始 prompt 的平均对数似然，可以作为文生图 RL 的一种免标注、免微调奖励；当把这个函数放进统一多模态模型自身的理解分支时，奖励与策略的分布对齐甚至能替代外部大模型规模，这为后续自奖励视觉生成提供了一个可复用的基准。
