# 大白话深读《Edit-R1-UniWorld-V2》

## 1. 30 秒定位

这篇论文提出一个叫 **Edit-R1** 的图像编辑后训练框架，不是新模型架构。它的目标是把已经被监督微调好的扩散式图像编辑模型继续用“策略优化”方式对齐人类意图：给定一张原图和一句编辑指令，让模型自己生成一组候选结果，用现成的多模态大模型给这些候选打连续分，再用 **DiffusionNFT** 这种免似然、负向感知的流匹配目标更新速度场。报告里最强的 **UniWorld-V2** 在 **ImgEdit** 上得到 **4.49**，在 **GEdit-Bench** 上得到 **7.83**；应用到 **FLUX.1-Kontext [Dev]** 时，ImgEdit 从 **3.71** 提到 **4.02**，超过官方 Pro 的 **4.00**；应用到 Qwen 时也有提升。最大卖点是不训练新奖励模型，只用 MLLM 的 logits 期望，并通过低方差组过滤稳定训练。

论文属于技术报告，实验覆盖三个基座模型：FLUX.1-Kontext [Dev]、Qwen-Image-Edit [2509]、UniWorld-V2。训练数据共 27,572 条指令式编辑样本，只需要原图和编辑指令，不需要编辑后的标准答案。奖励信号来自冻结的多模态大模型（MLLM），对 0～5 评分 token 的 logits 做 softmax 后求期望，得到连续分数。训练时用 DPM-Solver 做 6 步快速 rollout，每组 12 张候选图，共 24 组；对每组计算均值与标准差，丢弃“均值高且方差低”的组后再做 DiffusionNFT 更新。

## 2. 为什么这篇论文会出现

图像编辑模型通常先做监督微调，但这会带来两个问题。论文明确指出：SFT 目标会走“捷径”，让模型忽略复杂指令、只是重建输入图，因为重建原图本身就是低损失解；同时大规模但多样性不足的数据容易导致过拟合，指令忠实度下降。这可以解释为何很多编辑模型在训练分布内不错，但换到开放指令就退化。论文在 Introduction 中引用 UniWorld-V1、Qwen-Image-Edit 等模型为例，指出 SFT 范式这种固有局限会削弱编辑模型的可控性和泛化性。

近两年语言模型的强化学习后训练被认为有效，于是有人把 RL 引入扩散生成。但论文指出现有扩散 RL 方法有硬伤：一类基于似然估计的策略方法会引入系统偏差，并且限制求解器选择；另一类如 Flow-GRPO 依赖一阶 SDE 采样，必须在轨迹多样性与生成质量之间取舍。图像编辑恰好既要求高质量保真，又要求足够探索，所以这些妥协很致命。论文特别提到 DANCEGRPO、FlowGRPO 等基于策略梯度的在线 RL 方法虽然在生成模型上有效，但可能被 reward hacking 利用。

另一个难题是奖励信号。图像编辑任务多样，很难有一个通用奖励模型；训练专属奖励模型又昂贵、有偏差和灾难性遗忘风险。MLLM 虽然可当评委，但采样式评分稀疏、粗糙；加上 CoT 推理会带来曝光偏差和高计算开销。论文提到 UnifiedReward 这类预训练奖励模型虽然可用，但人类对齐准确率不高，也容易引入偏差。于是论文想找一条路：用现成 MLLM 的 logits 直接给连续分数，同时用适合 flow matching 的 DiffusionNFT 做在线策略优化，这两件事拼起来就是 Edit-R1。

## 3. 读懂前需要的最小概念

**Flow Matching / Rectified Flow**：这是一种扩散/生成模型框架。数据样本 \(x_0\) 和噪声 \(x_1\) 通过线性插值 \(x_t=(1-t)x_0+t x_1\) 连接，其中 \(t\in[0,1]\)。模型 \(v_\theta(x_t,t,c)\) 学的是速度场 \(v=x_1-x_0\)，即从数据指向噪声的方向。推理时解确定性 ODE。FLUX.1-Kontext 等模型就是这类骨干。论文的 Equation 1 到 Equation 3 给出了这些定义。与 DDPM 这类 SDE 生成框架相比，流匹配正向过程是确定性 ODE，采样器可以更灵活。

**策略与 rollout**：在 RL 语境下，图像编辑模型本身是策略 \(\pi_\theta\)，生成一张候选编辑图就是采样一次动作。训练时会从当前策略采样一组候选，称 rollout。这里使用 DPM-Solver 作为黑盒求解器，速度快。DiffusionNFT 的训练与采样解耦，因此采样时不必强制使用与训练一致的 SDE 求解器，可以用高阶 ODE solver 快速 rollout。

**MLLM logit-based 奖励**：不给 MLLM 采文本分数，而是让它只输出 0 到 5 的评分 token。对每个评分 token 的 logits 做 softmax，得到概率分布，再求期望值，即为连续奖励。比如概率质量集中在“4”和“5”时，期望可能为 4.7。好处是粒度细、可区分细微差异，且不用生成 CoT。论文 Equation 10 和 Equation 11 定义了该机制，评分 token 集合 \(M=\{0,1,2,3,4,5\}\)。与采样式评分相比，它利用了模型对每个分数的置信度，而不是只取一个离散数字。

**Group filtering**：同一指令采样多张图构成一组。要把组内 raw reward 标准化成 0 到 1 的“最优性概率”，但当组内分数都很接近且很高时，除以很小的标准差会放大噪声。因此要丢弃“均值高且方差低”的组，避免这些无效梯度。论文 Figure 3 给出了一个“把车改成红色”的例子，组内样本都接近成功，概率约 0.96，此时标准化后会把细微噪声放大成伪优劣信号。

**Reward hacking**：训练中模型可能学会刷高奖励但不真正完成编辑，比如输出与输入几乎相同。论文通过奖励模型规模放大和组过滤来缓解。Figure 8 显示 3B 和 7B 奖励模型下模型出现 reward hacking，而 32B 奖励模型能维持高方差探索。

## 4. 方法全景：先看数据流

图 2 的训练管线可以画成如下 ASCII 数据流：

```
原图 I + 编辑指令 T + 当前策略 π_old
        │
        ▼
[DPM-Solver 快速 rollout]  G 张候选编辑图 x^i_0
        │
        ▼
[MLLM 评分]  对每组 (I, x^i_0, base prompt + task prompt)
        │        输出 token logits -> 期望分数 s^i
        ▼
[组内标准化 + 过滤]  组均值 μ, 标准差 σ
        │        若 μ > τμ=0.9 且 σ < τσ=0.05，则丢弃整组
        ▼
[DiffusionNFT 更新]  用 r^i 作为最优性概率
        │      对比 v+θ 与 v-θ 损失，更新速度场 vθ
        ▼
更新后的策略 π_θ 进入下一轮 rollout
```

四块核心组件及它们的输入、输出、目的、假设如下：

**组件 1：快速 rollout 采样器**。输入：原图、编辑指令、当前旧策略 \(\pi_{\text{old}}\)。输出：\(G=12\) 张候选编辑图/每组，共 24 组（Table 5 给出 Number of Images Per Prompt = 12，Number of Groups = 24；论文未完全披露组和 batch 的精确装配方式）。目的：产生在线样本来评估策略表现。假设：DiffusionNFT 允许训练与采样解耦，因此可以使用 DPM-Solver 这类黑盒、高阶 ODE 求解器，不用牺牲质量去换采样多样性。采样推断步数为 6，分辨率 512×512。

**组件 2：MLLM 连续评分器**。输入：三元组 \(X=(I_{\text{original}}, I_{\text{edited}}, T_{\text{instruction}})\)，以及一个 base prompt 和一个按任务类型定制的 task prompt。输出：raw reward \(s(X)\in[0,1]\)，公式是先对评分 token \(r\in\{0,1,2,3,4,5\}\) 的 logits 求 softmax，再算期望 \(\sum_{r} w(r)p(r_n=r|X,R_{<n})\)。目的：给候选编辑图一个与人类偏好对齐的连续奖励。假设：预训练 MLLM 的视觉理解和 token logits 已隐含细粒度偏好，不需要额外微调；不用 CoT 可以避免曝光偏差。MLLM 评分在单独一个节点上用 vLLM 跑，不占训练节点的主显存。

**组件 3：低方差组过滤**。输入：一组 raw reward scores。输出：是否丢弃该组梯度；丢弃条件是组均值超过 \(\tau_\mu=0.9\) 且方差低于 \(\tau_\sigma=0.05\)（Table 5）。目的：避免在图 3 描述的“所有分数都约 0.96”情形下，除以小标准差把噪声放大成伪优劣信号。假设：这些高均值低方差组不含可学习信息，丢弃它们不会损害模型能力。

**组件 4：DiffusionNFT 优化器**。输入：标准化后的最优性概率 \(r^i\)、流插值样本 \(x_t\)、目标速度 \(v\)。输出：对速度预测网络 \(v_\theta\) 的参数梯度。目的：让 \(v_\theta\) 朝高奖励方向走、远离低奖励方向。假设：把 raw reward 归一化为 0 到 1 的概率，可作为不同候选之间的相对好坏判断。此外训练时还加了 KL Loss Weight 为 0.0001 的正则项，避免新策略偏离旧策略太远。优化器学习率 \(3e-4\)，Adam 参数 \(\beta_1=0.9,\beta_2=0.999\)，EMA Decay 0.9。

## 5. 核心公式与直觉

只需要理解四个公式：流匹配插值、MLLM 期望评分、奖励归一化、DiffusionNFT 损失。

**公式 1：流匹配插值（Equation 1）**
\[
x_t=(1-t)x_0+t x_1
\]
\(x_0\) 是数据样本（编辑图），\(x_1\) 是标准高斯噪声，\(t\in[0,1]\)。它告诉我们训练时任意时刻 \(t\) 的状态如何从端点和噪声线性混合而来。目标速度场 \(v=x_1-x_0\)，即真实数据到噪声的移动向量。推理时从 \(x_1\) 一侧积到 \(x_0\) 一侧，沿着 \(v_\theta\) 给出的增量走。

**公式 2：MLLM 期望评分（Equation 10）**
\[
s_{\text{con}}(X)=\sum_{r\in M} w(r)\cdot p(r_n=r|X,R_{<n})
\]
其中 \(M=\{0,1,2,3,4,5\}\)，\(w(r)\) 是 token 数值，\(p\) 是 softmax 后的 token 概率。这个式子的直觉是：与其让模型硬说“4 分”，不如利用它对 0～5 每个分数的置信度做加权平均。脚本里把该连续分数再线性压缩到 \([0,1]\)。这比采样式单个数字更细，且不需要 CoT。如果模型对“4”和“5”各有一定质量，期望可能落在 4.3 和 4.8 之间，这样的连续差异对后续策略优化更友好。

**公式 3：奖励归一化为最优性概率（Equation 7）**
\[
r(x_0,c)=\frac12+\frac12\operatorname{clip}\left(\frac{r_{\text{raw}}(x_0,c)-\mathbb{E}_{\pi_{\text{old}}}r_{\text{raw}}}{Z_c},-1,1\right)
\]
这里 \(r_{\text{raw}}\) 是 MLLM 的连续分数，\(Z_c>0\) 是归一化因子，例如全局标准差。减去均值再裁剪，是为了把任意尺度的奖励映射到 \([0,1]\)，表示“这条候选比当前策略平均好多少”。如果等于均值，则 \(r=0.5\)。这个量被当作最优性概率使用。它不要求奖励本身就是概率，只需要相对排序；减去均值使正负样本对称。

**公式 4：DiffusionNFT 损失（Equation 4）**
\[
L(\theta)=\mathbb{E}_{c,\pi_{\text{old}}(x_0|c),t}\left[
r\|v^+_\theta-v\|_2^2 +(1-r)\|v^-_\theta-v\|_2^2
\right]
\]
其中
\[
v^+_\theta=(1-\beta)v_{\text{old}}+\beta v_\theta,\quad
v^-_\theta=(1+\beta)v_{\text{old}}-\beta v_\theta.
\]
直觉是：当 \(r\) 接近 1，损失主要由 \(v^+_\theta\) 与真实速度 \(v\) 的项决定，而 \(v^+_\theta\) 是当前新策略和旧策略的组合，更新会让模型朝高奖励样本靠近；当 \(r\) 接近 0，则更关注 \(v^-_\theta\)，它把旧策略往反方向推，因此叫“negative-aware”。这个损失不直接做似然估计，与 flow matching 的正向过程一致，所以能支持更高阶采样器。公式中的 \(\beta\) 是控制新旧策略混合幅度的超参数，Table 5 中 Guidance Strength 为 1.0，但论文这里用 \(\beta\) 和 \(1/\beta\) 表示同一件事，细节略含混；可以理解为当 \(\beta=1\) 时，\(v^+_\theta=v_\theta\)，\(v^-_\theta=2v_{\text{old}}-v_\theta\)。

## 6. 训练到底怎么跑

一轮训练 step 的完整顺序如下：

1. 从当前 rollout 策略 \(\pi_{\text{old}}\) 出发，对每条编辑指令采样一批候选。Table 5 写明 Sampling Inference Steps 为 6，Resolution 为 512×512，每 prompt 12 张图，共 24 组；Batch Size 为 3。这意味着一个 step 大约处理 3 条 prompt，共 36 张候选图，但论文未明确说明 24 组如何与 3 条 prompt、12 张图对应。可能的解释是 24 组来自一个 batch 内多条 prompt 的多个子组，但论文没有展开。

2. 把每条 prompt 下的候选组送入 MLLM。原图、编辑图、base prompt 和 task prompt 一起构成输入。MLLM 只输出评分 token 的 logits，不生成 CoT；用 softmax 和期望公式算出 raw reward。为了节省训练 GPU 显存，MLLM 评分在单独一个节点上使用 vLLM 部署，避免与训练进程争抢显存。论文没有给出 MLLM 评分节点的 GPU 型号和并发配置。

3. 在每组内部计算 raw reward 的均值和标准差。如果 \(\mu>0.9\) 且 \(\sigma<0.05\)，该组被整组丢弃，不参与反向传播。这一步发生在奖励归一化之前，防止低方差噪声被标准化放大。论文没有报告实际训练中的组丢弃率。

4. 对保留组的 raw reward 做 Equation 7 的归一化，得到最优性概率 \(r^i\)。归一化使用当前策略 \(\pi_{\text{old}}\) 下的均值 \(\mathbb{E}_{\pi_{\text{old}}}r_{\text{raw}}\) 和全局标准差 \(Z_c\)。因为训练是在线更新，均值也可以按 batch 或滑动窗口估计，论文只写“such as the global std of the rewards”。

5. 对每一张候选图采样时间步 \(t\)，构造 \(x_t=(1-t)x_0+t x_1\)，计算目标速度 \(v=x_1-x_0\)。按 Equation 5、6 由旧策略 \(v_{\text{old}}\) 和当前训练策略 \(v_\theta\) 组合出 \(v^+_\theta\) 与 \(v^-_\theta\)。旧策略 \(v_{\text{old}}\) 是 rollout 时使用的策略，新策略 \(v_\theta\) 是正在训练的策略。

6. 计算 Equation 4 的损失，额外加一个 KL Loss Weight 为 \(0.0001\) 的正则项，反向传播更新速度预测网络。优化器为 Adam 类设置，学习率 \(3e-4\)，\(\beta_1=0.9,\ \beta_2=0.999\)，EMA Decay 0.9（Table 5）。训练时对 text encoder 使用 FSDP，并在 Qwen 和 UniWorld-V2 上开启 gradient checkpointing 节省显存。

7. 训练资源写的是 FLUX 用 3 节点、Qwen 用 6 节点、UniWorld-V2 用 9 节点，每节点 8 张 A100 GPU。论文未披露总训练步数和 wall-clock，Figure 7 只画到 500 步作为 ImgEdit 指标曲线。从 Figure 7 看，DiffusionNFT 在 FLUX.1-Kontext [Dev] 上大约在 500 步内将 ImgEdit 从约 3.71 提到 4.02，但图中基线 Flow-GRPO 和 Flow-GRPO+Local Std 的最终值没有给出数字。

训练数据不需要编辑后的标准答案，只用原图和指令。数据集共 27,572 条，包含 LAION、LexArt、UniWorld-V1 三类来源。LAION 子集利用了 ImgEdit 已有的物体标注和边界框；预处理包括过滤过小或过大的边界框，并用 Qwen2.5-VL-32B 判断指令合理性。Text Edit 任务基于 LexArt 子集随机改字符生成训练样本；Redbox Control 任务从处理后的 LAION 抽子集，在目标物体周围画红框，再生成 Adjust、Remove、Replace 三类指令。Reference 和 Extract 任务使用 UniWorld-V1 的高质量试穿数据，各自只用了 600 条。Figure 5 显示任务分布：Replace 21.1%、Adjust 18.5%、Remove 15.1%、Background 10.9%、Hybrid 9.1%、Action 7.3%、Text Edit 7.3%、Redbox Control 6.5%、Reference 2.2%、Extract 2.2%。论文正文称 9 类，但 Figure 5 显示 10 类，这个不一致论文未解释。

## 7. 推理到底怎么跑

推理阶段不再需要 MLLM 奖励和组过滤，也不做 rollout，只保留训练好的速度预测网络 \(v_\theta\)。论文强调 DiffusionNFT 与采样解耦，推理可以使用黑盒求解器和高阶 ODE solver，所以他们用 DPM-Solver 做 rollout，最终模型推理也可沿用同类型 solver。Flow matching 的生成是按 Equation 3 解 ODE：给定条件 \(c\)（包含原图和指令的编码/上下文），从某个起点积分到终点。论文把这套 ODE 称为 forward process，但文本没有展开推理方向上的实现细节；对编辑模型而言，最终会得到与原图条件一致、且执行了指令的 \(x_0\)。

完整推理顺序大致是：

1. 输入原图和自然语言编辑指令。
2. 将原图/指令编码为模型条件 \(c\)。Qwen、FLUX 和 UniWorld 的编码方式各自不同，论文没有逐一展开。对于 FLUX.1-Kontext，条件可能包括上下文图像和文本；对于 Qwen-Image-Edit，则是其多模态编码器输出。
3. 用 DPM-Solver 或等价 ODE solver，在 6 步或更多步内，从噪声侧积到干净图侧。Table 5 的训练 rollout 用 6 步、512×512；实际部署可用更多步换取质量。论文没有报告推理延迟，但强调了 DiffusionNFT 解耦训练和采样后，可以使用更适合部署的高阶求解器，而不是只能沿用训练时的一阶 SDE。
4. 输出编辑后的图像。过程中不进行采样式评分、不生成 CoT，也不对组内方差做判断。

需要注意，推理时并不直接使用 Equation 4 的 negative-aware 分支；那两个方向只是训练时构造的优化目标。推理仍然是标准 flow matching 解码。论文也没有说明推理时是否需要显式代入原图和指令的额外条件，但从编辑任务性质看，最终 \(x_0\) 必须同时保留原图内容并实现指令语义，这是由训练奖励和条件编码共同保证的。

| Score Logit 奖励更对齐人类 | Table 4, 自建对齐集 | 74.74%，高于 UnifiedReward 65.46%、Yes/No Logit 67.01% | 支持无 CoT、logit 期望比采样式/训练奖励更优；但人类对齐集仅 200 个指令、800 张图，规模有限 |
| 核心组件消融 | Table 3, GEdit-Bench | Qwen 基线 7.54；+NFT(7B) 7.66；+32B 7.74；+Group Filtering 7.76 | 支持奖励模型放大和组过滤带来收益；但过滤增益仅 +0.02，无置信区间，文本与表格存在 7.72/7.74 不一致 |

最关键消融是 **Table 3**：以 Qwen-Image-Edit [2509] 在 GEdit-Bench 上为对象，先加 7B 奖励模型的 NFT，从 7.54 到 7.66；把奖励模型换成 32B，再从 7.66 到 7.74；最后加组过滤到 7.76。收益趋势明确，但组过滤的绝对增益很小，且没有在 FLUX 或 ImgEdit 上重复该消融。图 8 的结果从机制上补充：小奖励模型 3B/7B 的 reward variance 早期快速坍塌，导致模型提前停止有效探索；32B 奖励模型则能维持高方差探索。这说明“奖励模型放大是抗 reward hacking 的主要手段”，组过滤只是辅助。

论文还显示 DiffusionNFT 比 Flow-GRPO 和 Flow-GRPO+Local Std 更好（Figure 7，FLUX.1-Kontext [Dev] 的 ImgEdit 曲线），但该图没有列出最终数值，也没有说明是否公平控制了采样预算。尚未证明的主张包括：低方差组过滤是否能真正降低训练方差而非只是丢弃困难组；框架在非 flow matching 骨干、更大数据规模、其他评测指标上是否仍稳定；Score Logit 奖励是否不会导致对新类型的过拟合；以及训练总步数和多次随机种子下的显著性是未知的。报告中存在一些数字不一致：摘要称 Qwen 在 GEdit 上 7.79，Table 2 为 7.76；正文称 9 类任务但 Figure 5 为 10 类，Table 3 正文写 7.72 但表格为 7.74。这些会削弱对精确复现的信心，但总体方向仍然一致。

人类偏好研究（Figure 6）给出了额外证据：在 FLUX 系列中，UniWorld-FLUX.1-Kontext 的 alignment 得票率 44.3% 对 K-Pro 38.2% 对 K-Dev 17.5%，质量 37.9% 对 39.4% 对 22.7%，总体 41.1% 对 38.8% 对 20.1%。在 Qwen 系列中，UniWorld-Qwen-Image-Edit 的 alignment 得票率最高，但质量维度略低于 Q-2509 或 Q-Base。这说明 Edit-R1 主要提升的是指令忠实度，而非绝对图像质量，甚至可能轻微牺牲质量。这个区分很重要，但论文没有做统计显著性检验。

## 9. 与前作怎么选

**与监督微调相比**：如果任务非常固定、有大量高质量的“原图-指令-目标图”三元组，SFT 实现简单且推理零额外开销，仍是首选。Edit-R1 更适合目标图稀缺、想突破固定标注分布、或需要在线奖励信号继续提升时。论文明确说 Edit-R1 的数据只需原图和指令，省去编辑结果标注。对于 FLUX.1-Kontext [Dev] 这种基座，SFT 也许不现实因为配对编辑结果标注昂贵；Edit-R1 提供了在线探索不依赖 GT 的路径。

**与 Flow-GRPO 相比**：Flow-GRPO 是扩散/流匹配模型的在线 RL 方法，但论文指出它依赖一阶 SDE，会让采样多样性和质量难以兼得。Figure 7 显示 DiffusionNFT 在 FLUX-Kontext Dev 的 ImgEdit 上优于 Flow-GRPO 和其 Local Std 变体。如果基座是 flow matching 模型，且想用高阶 ODE solver 加速 rollout，选择 DiffusionNFT 更自然；如果已有成熟的 GRPO 工程积累、且任务奖励本身噪声很低，可以先用 Flow-GRPO 作为基线。DANCEGRPO 也属于这一类，但论文未与其直接对比。

**与训练专属奖励模型/UnifiedReward 相比**：训练奖励模型可针对特定领域调优，但论文认为这需要精心设计数据，容易引入偏差和灾难性遗忘。Table 4 中 UnifiedReward 的人类两两一致率只有 65.46%，显著低于 Score Logit 的 74.74%。因此，如果希望快速迁移到多种编辑任务、不想维护奖励模型训练流程，选择训练自由的 Score Logit；如果有一个明确的、窄领域的头部交易型任务，可能仍需微调专属奖励，但本论文未验证这种情况。

**何时不选 Edit-R1**：在需要严格可解释的奖励通路、推理必须极致低延迟、或已有大规模成对 GT 数据的简单任务里，Edit-R1 的在线 rollout、MLLM 评分和组过滤是多出来的复杂度；论文也未展示在这些成本边界的收益/开销比。例如，如果只是做固定模板的商品图换背景，已有大量成对数据，直接 SFT 可能更经济。Edit-R1 更适合开放指令、少 GT、多任务的通用编辑能力提升。

## 10. 工程判断：可行性、风险与上限

**数据**：27,572 条样本规模不大，依赖 LAION 自动标注、LexArt 和 UniWorld-V1 现有数据。Reference 和 Extract 各自只有 600 条，仅占 2.2%，但它们又是身份/物体保真要求很高的任务。这种长尾分布意味着模型在这两类能力上的提升上限和稳定性是未验证的；如果实际产品大量依赖换脸/换衣/抠取，这部分训练数据可能不足。数据清洗用了 Qwen2.5-VL-32B 判断指令合理性，但没有披露过滤比例，可能影响数据分布偏移。论文也没有说明训练数据是否去重或与评测集泄漏。

**算力/延迟**：训练需要 3～9 个 8×A100 节点，外加一个 vLLM 节点做 MLLM 评分。采样每 prompt 12 张图、6 步、512×512；之后每张图都要过一次 MLLM，这会成为显存和 wall-clock 的主要开销。推理阶段没有 MLLM，所以部署延迟只取决于编辑模型的 ODE solver 步数；但训练时产生的总吞吐论文没有披露，无法计算每 step 的 GPU-hours。FSDP 和 gradient checkpointing 只用于 Qwen/UniWorld 的 text encoder，说明对更大骨干仍需谨慎管理显存。如果要在 7B 参数模型上跑，训练节点需求可能比报告更低，但论文只给了三个配置。

**实现难点**：DiffusionNFT 需要维护旧策略 \(v_{\text{old}}\) 与当前策略 \(v_\theta\) 的组合，损失中 \(v^+\) 和 \(v^-\) 的构造必须与 \(\beta\) 一致；Flow matching 的正向过程目标速度方向不能写反。MLLM logit 抽取要限制输出 token 集合为 0～5，并正确做 softmax 和归一化；vLLM 下的 logits 接口如果变化会增加工程负担。组过滤阈值 \(\tau_\mu=0.9,\tau_\sigma=0.05\) 可能对任务类型敏感，但论文没有做敏感性分析。旧策略更新频率、EMA 衰减如何与 rollout 策略对齐也没有完全说明。

**失败环节**：最可能的失败来自 reward hacking。Figure 8 已证明 3B 甚至 7B 奖励模型会让策略刷分、偏离源图；如果团队没有更大 MLLM，训练容易崩溃。另一个失败点是把所有低方差组都丢弃，可能把“看似简单但模型还没学会”的任务也丢掉，形成只在简单样本上稳定的假象。DPM-Solver 6 步 rollout 如果质量太差，奖励噪声会被后续标准化进一步放大。此外，base prompt 和 task prompt 的模板如果设计不当，MLLM 分数分布可能扭曲，导致奖励无法对齐。

**监控信号**：应监控 raw reward 均值/标准差、组丢弃率、reward variance 气泡大小、下游 ImgEdit/GEdit 指标、以及人类偏好的抽查。一旦 early training 时 reward variance 快速坍塌，需要换更大的奖励模型；若 discard rate 过高，可能要放宽 \(\tau_\mu\) 或检查任务分类。也要监控 MLLM 分数分布是否与人工标注一致，防止训练奖励上升但下游评测不升。论文没有给出这些曲线，但 Figure 8 已展示奖励方差气泡作为探索强度的代理信号。

**指标上限**：ImgEdit 和 GEdit-Bench 都已接近满分量尺或榜单顶部，尤其 UniWorld-V2 的 ImgEdit 4.49、Qwen 的 ImgEdit 4.48，继续追求绝对分数会面临饱和。评价本身使用 GPT4.1 自动评分，论文没有报告评分器方差、多次运行或人工复评；奖励模型的人类对齐只有 74.74%，意味着仍有约四分之一的成对偏好会判错，这可能直接变成策略训练的上界。后续工作需要在更多样、更困难、更接近真实人机交互的编辑任务中验证。另外，人类偏好研究显示 Edit-R1 提升的是 alignment（指令符合度），质量维度在部分系列中反而略微下降，产品上需要权衡。

**未回答问题**：没有给出不同预算下 DPM 步数、组大小、阈值的影响；没有显示训练后编辑模型在失败案例上的具体错因；没有讨论安全性、版权或误删内容的规则；也没有证明对未包含在新九/十类任务中的开放指令更优。训练总步数、随机种子、±方差都没有报告，导致结果可复现性受限。

## 11. 放回研究脉络并收束

这条工作处于“扩散/流匹配模型的 RL 后训练”和“MLLM-as-a-Judge”两条线的交汇点。此前 InstructPix2Pix、FLUX-Kontext、Qwen-Image-Edit 用 SFT 建立基础编辑能力；DDPO、DPO、Flow-GRPO、DanceGRPO 尝试把 RL 引入生成模型；MLLM-as-a-Judge 则把 VLM 评估转为自动奖励。Edit-R1 的贡献不是发明 DiffusionNFT，也不是发明 logit-based 评分，而是把二者加上一个低方差组过滤，组成一个能直接作用在多个 flow matching 编辑骨干上的在线后训练协议。它强调训练与采样解耦、奖励训练自由、以及用奖励方差监控 reward hacking，这让方案对后来者比较易复用。

在图像编辑这条具体脉络上，早期 SDEdit 和 Prompt-to-Prompt 解决了全局风格迁移和局部控制，但依赖反演和注意力操纵；InstructPix2Pix 开始用指令微调但泛化有限；后续 BAGEL、Qwen-Image、GPT-Image-1 等统一多模态模型把编辑能力卷到接近榜单顶部。Edit-R1 是在这些已经很强的 SFT 基座上再做在线 RL 后训练，它的实验表明即使是很强的 Qwen-Image-Edit [2509]，也能在 GEdit-Bench 上从 7.54 提升到 7.76，说明 SFT 之后仍有可挖掘空间。但要注意提升主要来自指令忠实度，图像质量几乎不变。

**读完必须记住的 5 件事**：

1. Edit-R1 是后训练框架，不生成新架构；输入只有原图 + 指令，不需要编辑后的标准答案。数据共 27,572 条，训练时只用原图和指令。
2. 核心优化是 DiffusionNFT，损失对比 \(v^+_\theta\) 和 \(v^-_\theta\)，分别把速度场拉向高奖励、推离低奖励，避免似然估计。Equation 5 和 6 定义了这两个组合方向。
3. 奖励来自冻结 MLLM 的 token logits 期望，评分 token 为 0～5，不用 CoT、不用采样文本；人类两两一致率 74.74%。Equation 10 和 11 给出计算过程。
4. 低方差组过滤丢弃“均值高且方差低”的组，防止除以小标准差放大噪声；阈值是 \(\tau_\mu=0.9,\tau_\sigma=0.05\)。Figure 3 给出噪声放大示意。
5. 三条基座提升：FLUX 的 ImgEdit 从 3.71 到 4.02，Qwen 从 4.35 到 4.48；GEdit 上 FLUX 从 6.00 到 6.74、Qwen 从 7.54 到 7.76；UniWorld-V2 达到 4.49/7.83。

**5 道自测题**：

1. 为什么监督微调会让编辑模型倾向于重建原图？Edit-R1 用哪种信号防止这种捷径？
2. 写出 DiffusionNFT 损失中的 \(v^+_\theta\) 和 \(v^-_\theta\) 组合公式；当 \(r=0.5\) 和 \(r=1.0\) 时，损失分别侧重什么？
3. MLLM Score Logit 的奖励计算步骤是什么？为什么它比 sampling-based 评分更细？
4. 低 std 组过滤的丢弃条件是什么？如果一组内分数都约 0.96，不丢弃会发生什么？
5. Table 1 中 UniWorld-Qwen-Image-Edit 在哪个子任务提升最大，哪个子任务反而下降？Table 2 中哪个模型得到 7.83？

最终一句话总结：Edit-R1 把图像编辑后训练从“模仿固定标注答案”转成“让模型在 MLLM 连续 logits 奖励下做有正有负的策略搜索”，并用 DiffusionNFT 保持流匹配采样灵活性，代价是必须认真管理奖励模型规模和低方差组噪声。
