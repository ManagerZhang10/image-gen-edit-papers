# 大白话深读《Rich-Text》

## 1. 30 秒定位

《Rich-Text》是 Songwei Ge、Taesung Park、Jun-Yan Zhu 与 Jia-Bin Huang 提出的文生图控制方法，论文题为“Expressive Text-to-Image Generation with Rich Text”，arXiv 编号 2304.06720，2023 年 4 月 13 日首次提交。它要解决的问题是：传统文生图只接受纯文本（plain text），很难准确表达精确 RGB 颜色、局部艺术风格、对象细节或参考图概念。论文提出把富文本编辑器中的字体颜色、字体风格、字号、脚注、嵌入图像和纹理填充等格式信息，作为文生图的额外控制信号。方法分两步：先从纯文本生成过程中提取自注意力与交叉注意力图，构建每个词对应的空间掩码（token map）；再按区域分别执行扩散去噪和属性引导，最后融合成一个全局一致的图像。主比较基座为 Stable Diffusion V1-5，并在 SDXL 上验证泛化。实验覆盖颜色、风格、脚注、纹理、个性化概念和真实图像编辑，定量结果显示在颜色距离、区域 CLIP 分数和 VQA 对齐率上均优于 Prompt-to-Prompt 与 InstructPix2Pix。

## 2. 为什么这篇论文会出现

现有大规模文生图模型几乎都只接受纯文本作为条件。纯文本控制有两个明显缺陷。第一，它不适合描述连续量。比如精确 RGB 值 [178, 34, 34]，通用 CLIP 文本编码器并不理解这种三元组；许多颜色名称如“olive”或“lime”也存在歧义。第二，复杂场景或局部属性很难写。用户想为天空指定梵高风格、为海浪指定浮世绘风格，纯文本却容易让模型表现出全局统一风格；长描述还会超过 CLIP 的 77 token 上限，且文本编码器容易忽略多个对象。论文构造的复杂 prompt 平均词数 46.56、平均 token 数 57.68（Table 1），已经接近单段 CLIP 上限；若再塞入每个对象的细节、颜色、纹理、风格，会进一步加剧编码困难。

论文指出，日常写作中人们很少只用纯文本，富文本编辑器反而更常见。因此，把富文本中的格式信息变成分离于文本内容的额外条件，是一种接近用户习惯的控制接口。相关工作已经发现扩散 UNet 的自注意力和交叉注意力图能表征生成布局，并且已有 Prompt-to-Prompt、Plug-and-Play 等方法利用注意力图做编辑或结构注入。但这些方法没有系统利用富文本属性。Rich-Text 的切入点是把一个富文本提示拆成一个短纯文本提示与多个区域特定提示，通过区域级扩散分别满足属性要求，而不是把富文本粗暴压成一长段纯文本。这样既避开长 prompt 的编码困难，也能保持对象结构和背景细节。与 layout-guided generation 需要用户显式提供框或 mask 不同，本文从纯文本生成路径中自动提取空间布局。

## 3. 读懂前需要的最小概念

**扩散模型（diffusion model）** 从噪声逐步去噪生成图像。本文使用 Stable Diffusion 在潜空间（latent）中执行去噪，UNet 是预测噪声的核心网络。每个时间步 t 有一个噪声样本 x_t，预测噪声后按调度器更新到 x_{t-1}。

**自注意力（self-attention）与交叉注意力（cross-attention）** 是 UNet 中的关键层。自注意力图上第 i 行第 j 列的值表示像素 i 对像素 j 的注意力，能反映图像结构；交叉注意力图上每个文本 token 对应一张空间注意力图，能反映某个词影响哪些区域。论文收集时排除了最浅的 encoder 和最深 decoder 块，因为这些高分辨率层注意力图噪声较强。

**无分类器引导（classifier-free guidance）** 是在条件预测与无条件预测之间做外推，通常为了强化文本条件的匹配程度。本文每个区域默认使用该机制。

**token map** 是本文的核心中间表示。它是一张软掩码，表示某个词或短语控制的图像区域。本文先通过自注意力相似度做谱聚类（spectral clustering）得到分割段，再用交叉注意力为每个分割段标注对应文本片段。

**富文本属性（rich-text attributes）** 在论文中被 JSON 解析成若干“文本片段 e_i + 属性 a_i”的对，例如 e_i=“church”，a_i=“color:#FF9900”。这样每个区域可以携带独立的条件；有些 token 可能没有属性，有些可能携带多个属性。

**区域扩散（region-based diffusion）** 不是单一扩散路径，而是每个区域用各自的提示生成噪声预测，再用 token map 加权融合，使不同区域遵守不同属性。梯度引导（gradient guidance）则在当前预测的干净图 x̂_0 上优化区域颜色或纹理损失，用来弥补文本编码器无法理解的连续量。

另外，真实图像编辑还涉及 diffusion inversion，即把给定图像反演到噪声潜变量。论文使用 edit-friendly DDPM 作为默认 inversion，并可用 Grounded SAM 获取外部 token map，避免手动 caption 与模型期望不一致。

## 4. 方法全景：先看数据流

下面先给出整体数据流，再拆核心组件。本文没有训练 UNet，所有操作发生在一次预训练文本到图像生成的推理路径上。

```
富文本 prompt (JSON)
   │
   ├─解析→ plain text prompt + spans e_i + attributes a_i
   │
plain text → 预训练扩散模型一次前向/生成路径
   │
   ├─ 收集 自注意力 maps、交叉注意力 maps、噪声样本 x_t、残差特征
   │
   ├─ 平均自注意力 → 对称化 → 谱聚类(K 个分割段)
   ├─ 平均交叉注意力 → 归一化 → 标注每个分割段对应 span
   │
   └─ 得到 token maps M_ei
   
对每个 span e_i：
   生成 region prompt f(e_i, a_i)
   例如 footnote 替换、style 追加、closest color name 前置

Region-based diffusion 循环 t=T→1：
   对每个区域 e_i 预测噪声 ε_{t,e_i}=D(x_t, f(e_i,a_i), t)
   融合 ε_t = Σ_i M_ei * ε_{t,e_i}
   若有 color/texture：
        计算预测 x0，求区域颜色损失或 VGG 感知损失
        沿梯度 ∂L/∂x_t 更新 x_t
   若 t > T_pnp：
        注入 plain path 的自注意力与残差特征保持结构
   若 t = T_blend：
        对未格式化 token 区域 M_eU 混合 plain path 的 x^plain_t
   更新到 x_{t-1}
```

**组件 1：token map 构建。** 输入是纯文本生成路径中的注意力图；输出是每个 span 的软掩码 M_ei。目的：自动获得文本对应的空间区域，而不需要用户手动提供掩码。假设：纯文本生成结果已经决定了整体布局；富文本属性只改变局部外观，不应完全改变对象形状和位置。具体做法是自注意力图先平均并转置相加成对称相似度矩阵，再谱聚类得到 K 个 32×32 二值分割段；交叉注意力图按 token 平均、插值到相同 32×32 分辨率，对每个分割段检查 token 的归一化注意力是否超过阈值 ε，公式 2-3；最后把这些匹配的分割段求和并归一化得到 token map（公式 4）。实现中 K=15、ε=0.3；cross-attention 取自所有块但排除第一个 encoder 和最后一个 decoder；T>750 的初始噪声步被丢弃。

**组件 2：region prompt 构建。** 输入是 span 和属性；输出是适合扩散模型读取的文本表示 f(e_i,a_i)。目的：把不能被文本编码器理解的属性（如 RGB 三元组、嵌入式图像）转换为自然语言，或把样式、脚注等直接写成更具体的文本。假设：文本编码器对自然语言短语比对 RGB 三元组更友好；最近颜色名配合梯度引导可以弥补文本表达的不足。论文给出了六步构造过程：初始 f(e_i,a_i)=e_i；若有 embedded image，先用基于梯度的离散优化（Wen et al., 2023）转换为 footnote 文本；若 footnote 存在则替换原 span；若 style 存在则追加“in the style of …”；若 font color 存在，从预定义颜色集合 C 中找最近颜色名的字符串前置；若有纹理描述与纹理图，把纹理描述前置。对于未格式化 token e_U，直接用 plain text prompt，保证非编辑区域语义连贯。

**组件 3：区域去噪与融合。** 输入是当前噪声 x_t、区域 prompt、token map；输出是更新后的噪声 x_t 或下一步 x_{t-1}。目的：让不同区域满足各自的属性，而全局由融合噪声保持一致性。假设：各区域的去噪结果可以在潜空间按软掩码线性融合，边界区域不会产生明显伪影。每个区域调用一次 UNet，按公式 5 加权求和。这与 Mixture-of-Diffusers、MultiDiffusion 的区域融合思想类似，但区域 mask 是自动从 attention 得到的。

**组件 4：梯度引导。** 输入是颜色 RGB 三元组或纹理图；输出是对 x_t 的梯度更新。目的：弥补文本无法精确控制连续外观的缺陷。颜色损失是在预测的干净图 x̂_0 上、用 token map 加权平均颜色后与目标 RGB 比较 MSE（公式 7）；纹理损失用 VGG 特征的 Gram 矩阵感知损失（公式 8），先令目标区域填充纹理图再计算（公式 9）。梯度只按公式 10 乘在 token map 区域内进行更新，避免影响其他区域。默认 λ_color=1、λ_texture=0.2。

**组件 5：保真注入。** 输入是纯文本生成路径的自注意力图、残差特征、噪声样本和未格式化区域掩码；输出是修改后的 x_t 或融合样本。目的：保证没有格式属性或只改颜色的区域尽量与 plain text 生成保持一致。假设：plain text 结果已经包含了良好的结构和内容先验，富文本不应该破坏它。当时间步 t > T_pnp 时注入 self-attention 和 residual features；文中 T_pnp=0.3，表示去噪进程比例。在 t = T_blend 时对 M_eU 覆盖的区域直接混合 plain path 噪声，T_blend=0.3。residual features 取自 decoder 第一层，与 Plug-and-Play 做法一致。

## 5. 核心公式与直觉

本节只保留理解贡献必需的 4 个公式。

**公式 1：交叉注意力归一化**
\[
m_j = \frac{\exp(s_j)}{\sum_k \exp(s_k)}
\]
变量：s_j 是第 j 个 token 在交叉注意力中的分数，m_j 是该 token 归一化后的注意力图。优化动作：无，这是提取过程。工程对应：用于给谱聚类分割段分配文本标签。直觉：一个 token 的注意力图高亮区域，就是该 token 影响图像的位置；归一化后不同 token 之间可以比较阈值。

**公式 4：token map 生成**
\[
M_{e_i} = \frac{\sum_{cM_j \in \mathcal{M}_{e_i}} cM_j}{\sum_i \sum_{cM_j \in \mathcal{M}_{e_i}} cM_j}
\]
变量：cM_j 是被分配给 span e_i 的二值分割段，分子把匹配段相加，分母对全部 span 的匹配段求和，因此 M_{e_i} 是软掩码，且各区域权重和为 1。优化动作：无，这是归一化布局表示。工程对应：在区域去噪融合时作为每个区域噪声的权重；在颜色/纹理梯度更新时决定只改哪些像素。

**公式 5：区域噪声融合**
\[
\epsilon_t = \sum_i M_{e_i} \cdot \epsilon_{t,e_i}
= \sum_i M_{e_i} \cdot D(x_t, f(e_i,a_i), t)
\]
变量：D 是预训练扩散模型，x_t 是当前潜空间噪声，f(e_i,a_i) 是区域特定文本提示，M_{e_i} 是 token map。优化动作：多个区域各自预测噪声后线性融合。工程对应：每个 span 可以有自己的颜色、风格、脚注或嵌入图像，不会强迫整个图像服从同一条 prompt。直觉：这就像把图像分成多个软区域并行生成，再按权重拼接，避免长文本造成属性混淆。

**公式 11：字号重加权注意力**
\[
\tilde{m}_j = \frac{a_j^w \exp(s_j)}{\sum_k a_k^w \exp(s_k)}
\]
变量：a_j^w 是第 j 个 token 的字体大小权重，s_j 是原始注意力分数。优化动作：直接把权重乘进 exp 分数后再归一化，而不是简单乘在原概率上。工程对应：让某些词在生成中更重要，例如增加“mushrooms”的权重来生成更多蘑菇或更明显的主体。直觉：重新归一化保证结果仍是概率分布，避免 Prompt-to-Prompt 中直接乘法导致概率和不为 1，从而产生 OOD 特征和伪影。

颜色和纹理引导没有在上述四个公式中展开，但在方法里非常重要。对颜色：先按公式 6 从 x_t 和噪声估计干净图 x̂_0=(x_t−√(1−ᾱ_t)ε_t)/√ᾱ_t；再在 M_ei 区域内做加权平均颜色与目标 RGB 的 MSE；公式 7 给出对 x_t 的梯度，其中权重和只作用在区域像素上。对纹理：公式 8 定义 VGG 特征 Gram 矩阵的 L2 感知损失；公式 9 把目标区域用纹理图填充后计算损失，避免把区域以外的物体也牵进来。最后公式 10 用 xt←xt−λ·M_ei·∂L/∂xt 做局部更新。文中 λ_color=1、λ_texture=0.2；附录 Figure 31 显示把 λ 从 0 扫到 20 时，颜色距离先降后升，CLIP 相似度单调下降，说明过强的颜色优化会破坏细节并可能发散。

## 6. 训练到底怎么跑

本文没有训练新的扩散模型权重。它是在预训练 Stable Diffusion V1-5 和 SDXL 上进行的推理时方法，即所有参数保持不变，区域属性通过去噪过程中的外部优化和融合实现。因此，传统意义上的“训练一轮 step”不存在。但为了理解方法如何被准备和执行，可以把流程拆成两个层面。

第一层是基座与基准准备。论文使用 Stable Diffusion V1-5 作为主比较模型，因为大多数 baseline 都基于它；还展示了 SDXL 上的泛化，并强调 SDXL 额外通过 pooled CLIP feature 和 adaptive normalization 条件化生成，因此 rich-text 路径需要为每个区域特定 prompt 重新计算 pooled CLIP 特征。基准构建不算训练，但需要准备评估数据。Footnote 任务是让 GPT-4 先产生场景级描述和对象级细节描述，再手动过滤与编辑，共收集 100 个复杂 prompt；平均词数 46.56，平均 token 数 57.68，接近 CLIP 上限（Table 1）。构建阶段先由 GPT-4 按两步生成：第一步生成全局与局部描述，第二步组合成完整段落；使用少量人工 in-context examples 控制格式；随后人工删除幻觉对象和非视觉属性（如食物风味）。之后基于 TIFA 流程生成 2921 对 QA，再经人工修改与过滤，得到 1974 对有效问题，例如把“是否有书”改为“书是否在床头柜上”。Font color 任务将颜色分为 Common 17 种、HTML color names 和 50 个随机 RGB 三元组三类，共 12 个对象、1,200 个 prompt。Font style 任务用 7 种风格和 10 个对象组合，得到 420 个 prompt。所有定量实验均使用三个随机种子平均。

第二层是去噪过程中的“优化 step”。虽然网络参数不更新，但每个时间步 t 会更新潜变量 x_t。具体做法：从 x_T 开始，对每个区域 e_i 用公式 5 预测噪声；若只有文本属性，融合后直接进入下一步；若指定了颜色或纹理，则先按公式 6 从 x_t 与噪声估计干净图像 x̂_0，计算颜色 MSE 或 VGG 感知损失，再用公式 7/9/10 对 x_t 做梯度更新。颜色梯度权重 λ_color=1，纹理权重 λ_texture=0.2。注入与混合时，T_pnp=0.3 与 T_blend=0.3 是去噪进程比例。实现上丢弃 T>750 的初始注意力图，使用 cross-attention 层中除第一个 encoder 和最后一个 decoder 外所有块；token map 聚类 K=15，标签阈值 ε=0.3。运行时间方面，在 RTX A6000 上 plain text 约 5.06 秒，两风格约 8.07 秒，颜色优化约 13.14 秒，batch size 固定为 1。由于无需训练，主要成本是每个区域多一次 UNet 前向和可选的梯度反向传播。

Baseline 设置也值得一提。Prompt-to-Prompt 使用 prompt refinement：从 plain text 基础 prompt 开始，加入颜色或风格 token 形成编辑 prompt。InstructPix2Pix 以 plain text 生成图为输入，用模板如“turn the [object] into the style of [style]”或“make the color of [object] to be [color]”做指令编辑。风格实验中，两条指令采用并行和顺序两种方式；两者均在一个额外的手工 prompt 集合上调参，而本文方法称无需超参数调优。

## 7. 推理到底怎么跑

完整推理顺序如下：

1. 用户在富文本编辑器中输入或编辑提示，例如给“church”加橙色、给“garden”加脚注、给“snowy mountain”嵌入图像。
2. 系统把富文本解析成 plain text 和若干 span-attribute 对（JSON 格式）。
3. 以 plain text 作为输入，用预训练扩散模型跑一次标准生成路径，收集 UNet 中自注意力图、交叉注意力图、每个时间步的噪声潜变量 x_t 以及 residual features。收集时排除第一个 encoder 和最后一个 decoder 的 cross-attention，丢弃 T>750 的噪声早期步；self-attention 图尺寸为 32×32×32×32，表示像素到像素注意力。
4. 构建 token maps：平均所有自注意力图，与转置相加得到对称相似度矩阵；谱聚类得到 K=15 个 32×32 二值分割 mask；平均所有交叉注意力图，插值到相同分辨率；对每个分割段，检查 span 内任何 token 的归一化注意力超过阈值 ε=0.3，若超过则将该分割段分配给该 span；最后把所有属于同一 span 的分割段相加并全局归一化，得到 M_ei。
5. 为每个 span 生成 region prompt f(e_i,a_i)。如果没有格式，则用 plain text prompt；有 embedded image，先用离散优化转换为 footnote；有 footnote，替换 span；有 style，追加“in the style of …”；有 font color，从预定义颜色集合中找最近颜色名前置；有 texture fill，把纹理描述前置，并保留纹理图用于后续感知损失。
6. 从采样得到的初始噪声 x_T 开始按时间步循环：
   - 对每个 span，用 UNet 根据 f(e_i,a_i) 预测噪声；
   - 用 token map 融合所有区域噪声；
   - 若存在颜色或纹理，基于公式 6 估计 x̂_0，在 token map 区域上计算损失并得到梯度，对 x_t 做更新；
   - 若 t > T_pnp，注入 plain path 的 self-attention 图和残差特征；
   - 若 t = T_blend，把未格式化 token 区域 M_eU 对应的 x_t 替换成 plain path 的 x^plain_t；
   - 执行一步去噪得到 x_{t-1}。
7. 最终把 x_0 解码成图像。若基座是 SDXL，还需要对区域特定 prompt 计算 pooled CLIP 特征，因为 SDXL 通过自适应归一化条件化该特征。运行时间随属性数量增加：单个 region prompt 每次多一次 UNet 前向；颜色优化还需反向传播。A6000 上两风格约 8.07 秒，颜色优化约 13.14 秒。
8. 如果是真实图像编辑，则先对输入真实图用 edit-friendly DDPM 做 inversion 得到噪声潜变量；由于源图已知，可用 Grounded SAM 等提供 token maps，代替从 cross-attention 自动提取；之后同样执行区域指导去噪和注入。手动 caption 可能与模型期望不符，因此外部分割通常比 cross-attention 更鲁棒。

## 9. 与前作怎么选

最接近的方案有四个。第一是 **Prompt-to-Prompt**。它用源 prompt 的交叉注意力图控制编辑后图像结构，可以做局部编辑，但不理解 RGB 三元组，不能同时给两个区域不同风格，且字号重加权直接乘法会破坏概率归一化，产生伪影。适合：简单文本替换或注意图控制的结构编辑；不适合：多对象局部属性、精确颜色、长 prompt。

第二是 **InstructPix2Pix**。它是一个指令式图像编辑模型，输入原图和 “make the … orange” 之类的指令。优点是使用自然语言指令；缺点是论文实验显示它容易把颜色和风格全局化，不能精确控制局部区域，顺序执行两条指令会压缩第二区域信息。适合：单条指令的粗粒度编辑；不适合：多区域、精确 RGB 或需要严格保留非编辑区域。

第三是 **Plug-and-Play**。它从源图生成路径注入 self-attention 和残差特征，适合保持结构的图像翻译。本文直接采用其特征注入思想作为保真组件，但没有 rich-text 属性解析和区域融合。若只需结构保持而不需要多属性控制，Plug-and-Play 更简单。

第四是 **Mixture-of-Diffusers / MultiDiffusion** 这类区域融合扩散方法。它们也把不同区域的去噪路径用线性混合合成，但通常需要用户提供区域 mask。Rich-Text 通过 attention 自动从纯文本获得 token map，并额外提供颜色/纹理梯度引导和未格式化区域混合。若用户愿意手动提供 precise mask，这些方法也可以实现类似区域控制；若不想标注 mask，Rich-Text 更方便。

选择建议：需要零样本、无需微调、自动发现区域并同时控制颜色、风格、脚注、纹理或嵌入参考时选 Rich-Text；需要快速简单编辑时 Prompt-to-Prompt 或 InstructPix2Pix 更快；需要强结构保真且属性较少时可直接用 Plug-and-Play。若已有一套精确的 layout 或 mask，且不需要颜色/纹理梯度，MultiDiffusion 类方法可能更容易直接落地。

## 10. 工程判断：可行性、风险与上限

**数据与评估。** 本文没有训练模型，所以不存在训练数据问题。但 rich-text benchmark 依赖 GPT-4 生成初始描述和问题，再人工过滤编辑，这带来了数据构建成本和偏差。颜色和风格的自动指标本身也不完美：CLIP 相似度可能被风格无关的语义相似性影响；VQA 依赖 mplug-large 模型，不能完全代表人类视觉判断。该基准规模较小，且仅覆盖部分富文本应用。附录中人工评价显示颜色和脚注偏好率超过 80%，但风格偏好率仅 65% 左右，说明局部风格的自动指标和用户偏好之间还有距离。

**算力与延迟。** 每张图在 RTX A6000 上约 5–13 秒，batch size 固定为 1。时间随属性数量增加，因为每个区域都要过一次 UNet，颜色和纹理还要反向传播。工程上可以通过批处理区域预测来优化，但论文未明确报告显存占用的扩展性。低资源设备需要考虑内存限制。推理速度对交互式编辑接近可接受，但多属性叠加时会明显变慢。

**实现难点。** 注意力图收集需要丢弃高噪声早期步和部分高低分辨率块，这些经验做法可能换到其他模型需要重新调整。谱聚类 K=15、阈值 ε=0.3、注入时间步 T_pnp=0.3、混合时间步 T_blend=0.3 都是重要超参数，论文称在 SD 上的参数在 SDXL 上基本可用，但没有给出跨任务的敏感性分析；Figure 15 和 Figure 31 只分别展示了 injection 和 λ 的影响。嵌入图像转 footnote 使用离散优化，可能不稳定；纹理填充需要准确 mask 并处理区域与纹理尺寸不一致。简单区域合成方法在附录 Figure 29 出现边界伪影，说明全局融合对边界质量有贡献，但也意味着 token map 边界误差会直接表现为伪影。

**失败环节与监控。** 最可能失败的是 token map 分割错误，导致属性泄漏或覆盖不全。需要监控分割 mask 是否覆盖目标、背景是否被意外着色，以及颜色距离与 CLIP 相似度的权衡曲线。颜色引导权重过大会使优化发散，具体表现是颜色距离反升和图像细节丢失。注入过强会阻碍属性改变，注入过弱则背景漂移。在真实图像编辑中，inversion 误差和自动分割错误会累积，尤其当 caption 与模型期望不一致时；论文承认手动 caption 可能不准确，因此用 Grounded SAM 是更稳的选择。

**指标上限与未回答问题。** 指标只能说明在现有基准上的相对优势，不能证明所有真实场景可用。论文未探索粗体/斜体、超链接、列表等格式；未讨论对象重叠、复杂空间关系、遮挡或不同光照条件下的鲁棒性；未提供自动分割失败时的用户矫正机制。工程上可考虑提供 manual mask override 与交互式修正，以降低 token map 失效风险。

## 11. 放回研究脉络并收束

Rich-Text 处于文本到图像可控生成的脉络中。早期文生图从普通文本开始，后来通过 attention 控制（Prompt-to-Prompt）、指令编辑（InstructPix2Pix）、特征注入（Plug-and-Play）等方式提高局部编辑能力。另一条线是布局引导生成，如 layout-to-image 与 MultiDiffusion，通常要求显式区域或框；同时也有 DALL-E 3、ParaDiffusion、InstanceDiffusion 等工作尝试解决复杂长 prompt 的合成质量。本文的独特位置是：不把富文本当作长文本，而是把格式信息当作分离的局部条件，并自动从注意力图提取布局，再用区域级扩散和梯度引导完成属性渲染。它把文档编辑中的富文本范式嫁接到生成模型控制中，为后续“用户界面即生成条件”这一方向提供了一种框架。

读完必须记住的 5 件事：

1. 富文本 prompt 被解析成 plain text 与多个 span-attribute 对，而不是直接拼接成长文本。
2. token map 通过“自注意力谱聚类 + 交叉注意力标注”获得，负责把每个文本片段映射到图像区域。
3. 区域噪声融合公式 \( \epsilon_t = \sum_i M_{e_i} D(x_t, f(e_i,a_i), t) \) 是多属性局部控制的核心。
4. 颜色和纹理不能靠文本编码，因此引入基于预测干净图的颜色 MSE 和 VGG Gram 感知损失的梯度引导。
5. 保真依赖从 plain path 注入自注意力、残差特征，并对未格式化 token 区域混合噪声，防止无关背景漂移。

5 道自测题：

1. Rich-Text 为什么不把富文本属性直接写成长 plain text 给扩散模型？至少给出两个原因。
2. token map 构建中，如果只用 cross-attention 而不用 self-attention 谱聚类，会出现什么问题？
3. 公式 5 中，M_ei 和 f(e_i,a_i) 分别起到什么作用？
4. 字号权重修改为什么采用公式 11 的重新归一化，而不是直接乘在原始注意力概率上？
5. 在真实图像编辑中，Rich-Text 为什么不再用 cross-attention 自动生成 token map，而改用 Grounded SAM 等分割方法？

最终一句话总结：Rich-Text 用富文本格式作为局部条件，通过注意力提取布局和区域级扩散，把颜色、风格、脚注、纹理与参考图等属性精确地注入预训练文生图模型，提供了一个无需微调、与 SD/SDXL 兼容的灵活控制框架。
