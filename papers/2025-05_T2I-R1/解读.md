# 大白话深读《T2I-R1》

## 1. 30 秒定位

T2I-R1 是一篇 2025 年 5 月发布（arXiv:2505.00703，v2 版本更新于 2025 年 7 月）的论文，研究如何在文本到图像生成（text-to-image generation）中引入类似大语言模型“思维链”（Chain-of-Thought, CoT）的推理过程。作者没有重新设计图像生成架构，而是从一个统一多模态大模型（Unified LMM, ULM）Janus-Pro-7B 出发，用强化学习（Reinforcement Learning, RL）把两种不同粒度的 CoT 同时训练出来：一种是生成前的文字规划，叫语义级 CoT（semantic-level CoT）；另一种是逐 patch 生成图像 token 的过程，叫 token 级 CoT。它们的联合优化框架叫 BiCoT-GRPO。奖励信号不靠单一规则，而是集成了人类偏好模型、物体检测器、视觉问答模型和输出奖励模型四个专家。最终模型在 T2I-CompBench 上平均提升 13%，在 WISE 上提升 19%，部分指标超过了当时的扩散模型 FLUX.1，其中 Spatial 子任务（0.3378）比先前 SOTA 高出超过 5%（Table 1）。这篇工作的核心贡献不是提出新的图像生成 backbone，而是证明：把“先想清楚再画”和“画的过程中一步步画”都纳入强化学习奖励，可以让一个原本理解与生成能力解耦的 ULM 在复杂提示、常识推理和组合生成上明显变强。

## 2. 为什么这篇论文会出现

论文的背景可以拆成三条线。第一条线是大语言模型的推理范式。OpenAI o1 和 DeepSeek-R1 等工作表明，让模型在给出最终答案前先输出一段逐步推理的文字，再配合强化学习优化最终答案的正确性，可以显著提升数学、代码等复杂任务的表现。第二条线是这种范式被迁移到多模态理解任务，例如一些大型多模态模型在视觉问答、数学题、科学推理上也开始生成文字 CoT 并接受规则奖励。第三条线是视觉生成领域刚刚开始尝试类似思路。论文明确提到一个先驱工作“Image Generation with CoT”（对应引用 [19]），它把自回归图像生成中的逐 token 生成过程本身看成一种 CoT，认为每生成一个图像 token 都依赖前面的 token，就像文本 CoT 一样，并尝试优化这个中间过程来提升图像质量。

但论文指出，图像生成和图像理解有本质区别。理解任务里 CoT 是纯文本推理链，最终答案可以用规则判断对错；生成任务不仅要理解提示，还要跨模态对齐（cross-modal alignment）并合成细粒度视觉细节。作者进一步识别出生成任务里其实有两种 CoT：一种是生成前的语义级 CoT，负责把用户提示展开成对场景、物体属性、空间关系的文字规划；另一种是生成过程中的 token 级 CoT，对应从第一个 patch 到最后一个 patch 的像素级决策链。以往工作要么只优化 token 级 CoT，要么依赖额外的 LLM 做提示扩展，没有把两种 CoT 放在同一个模型里联合优化。论文认为，统一多模态模型 Janus-Pro 已经具备基础的文本理解和图像生成能力，缺的是让理解能力真正为生成服务的机制。更具体地说，当前主流生成模型（如 SD、FLUX 等）训练目标只针对生成，缺少显式文本理解；虽然引入外部 LLM 做提示解释在技术上可行，但显著增加计算成本、复杂度和部署挑战。ULM 虽然同时具备理解和生成，但两个能力通常分两个独立阶段预训练，没有证据表明理解能力能直接促进生成。强化学习被选中而不是监督微调（SFT），理由有两个：一是基础模型已经具备两种 CoT 的潜在能力，目标只是通过自探索把它们激发并融合；二是 RL 在推理任务上已被证明有效。这就是论文出现的动机：填补“生成模型没有显式推理”与“理解模型不会直接画图”之间的空白。

## 3. 读懂前需要的最小概念

要理解这篇论文，需要先掌握几个概念。统一多模态大模型（ULM）指的是能同时做图像理解和图像生成的单一模型。Janus-Pro 就是这类模型的代表，它有两个独立的视觉编码器：一个 CLIP 编码器用于理解输入图像，输出语义特征；一个 VQGAN 编码器把图像离散化成 token 用于生成。文本和图像 token 在同一个 Transformer 里预测，但需要人为放入一个特殊 token `<img_start>` 来告诉模型从此时开始输出图像 token 而不是文字。这个概念很重要，因为它决定了论文的两步生成流程为什么必须拆开：模型不能自由交错输出文字和图像，必须用特殊标记手动切换。VQGAN 编码器原本只在图像重建任务上预训练，因此生成的视觉 token 对图像理解不一定最友好；Janus-Pro 用两个编码器分别处理理解和生成，避免了这个问题。

第二个概念是 GRPO（Group Relative Policy Optimization）。它是 DeepSeek 系列提出的一种强化学习算法，核心思想是对同一个提示采样一组 G 个回答，每个回答得到一个奖励，然后在组内做标准化得到优势值。优势值等于“个体奖励减去组内均值再除以标准差”。这样就不需要训练一个独立的 critic 或 value function。GRPO 的损失包括一个 PPO 式的 clip 项和一个 KL 惩罚项，用于防止当前策略偏离参考模型太远。论文公式 (1) 和 (3.1) 给出的就是这个结构。

第三个概念是自回归图像生成。与扩散模型不同，自回归模型把图像看成一串离散 token，像文本一样从左到右、从上到下逐步生成。Janus-Pro 把图像切成 384×384 分辨率下的 patch 网格，每个 patch 对应一个 token，最终这些 token 被 reshape 成 h×w×c 的张量并输入图像解码器得到图像。论文表格 7 显示图像分辨率设为 384×384，因此 M=h×w 代表生成的 token 数量。token 级 CoT 就是指这一串 patch 级生成过程，每个 patch 的生成都以前面所有 patch 为条件。

最后需要理解奖励模型的角色。文本推理任务有规则奖励，例如数学题对错、格式是否符合；图像生成没有标准答案，所以论文用一个专家集合来近似人类评价。它包含四个组件：人类偏好模型（如 HPS 或 ImageReward）评估整体美学和提示对齐，物体检测器（如 GroundingDINO 或 YOLO-world）检查指定物体是否存在、空间关系是否正确，视觉问答模型（如 BLIP、GIT 或 LLaVA）检查物体属性，输出奖励模型（ORM）是一个微调过的 LMM（论文使用 LLaVA-OneVision-7B 微调），整体判断图像和提示是否对齐。这些奖励取平均作为最终标量奖励，然后进入 GRPO 计算优势。训练前需要用 GPT-4o mini 从提示中提取物体和属性，以便检测器和 VQA 使用。

## 4. 方法全景：先看数据流

T2I-R1 的训练和推理都遵循一个两步生成流程。下面是训练时一轮数据流的 ASCII 图：

```
提示文本 p
   |
   v
[步骤1：生成语义级 CoT]
   |  输入：图像提示 + 推理指令
   |  模型：Janus-Pro (策略 πθ)
   |  输出：文本序列 s = {s_1,...,s_|s|}
   |
   v
[拼接：提示 + 语义级 CoT s + <img_start>]
   |
   v
[步骤2：生成 token 级 CoT]
   |  输入：上述拼接序列
   |  模型：同一个 Janus-Pro
   |  输出：图像 token 序列 t = {t_1,...,t_M}
   |
   v
[图像解码]  t --> reshape h×w×c --> 图像解码器 D --> 图像 I
   |
   v
[专家奖励]
   |  人类偏好模型 HPM   -> R_HPM
   |  物体检测器 Det      -> R_Det
   |  视觉问答模型 VQA   -> R_VQA
   |  输出奖励模型 ORM   -> R_ORM
   |  平均得到 R
   |
   v
[GRPO 组内标准化]
   |  对同一提示采 G=8 个样本，得到 {R_1,...,R_G}
   |  优势 A_i = (R_i - mean({R})) / std({R})
   |
   v
[策略更新]
   |  对语义级 token 和图像 token 分别计算概率比 r_i,j
   |  最小化 clip 目标 + KL 惩罚
   |  更新 πθ，两个 CoT 在同一轮中被联合优化
```

核心组件拆解如下。第一个组件是语义级 CoT 生成器。它的输入是用户提示和一句固定的推理指令，输出是一段描述图像规划的文字。论文要求这段文字包含物体属性、空间关系、场景构成等全局信息。它的目的是把“理解提示到底要画什么”和“实际生成像素”解耦。假设是 Janus-Pro 经过预训练已经有文本生成能力，只是没有被激励去为生成服务。论文示例指令大意是“Provide a brief, precise visualization of all elements in the prompt”，即要求模型对提示中所有元素给出简要、精确的可视化描述。

第二个组件是 token 级 CoT 生成器。它的输入是“提示 + 刚才生成的语义级 CoT + `<img_start>`”，输出是 M 个图像 token。这个阶段不再输出文字，而是直接预测 patch 序列。它的目的是处理低层像素细节和 patch 间的视觉一致性。假设是逐 patch 自回归生成时，每个后续 patch 都以前面 patch 为条件，因此强化学习可以像优化文本 CoT 一样优化这个序列。

第三个组件是 BiCoT-GRPO。它把两个阶段都纳入同一个策略轨迹。论文把一条完整响应 o_i 定义为两部分 (s_i, t_i)。概率比 r_i,j 根据 token 位置分段：当 j 在 0 到 |s_i| 范围内时，用语义级 CoT 的条件概率比；当 j 在 |s_i|+1 到 |s_i|+M 范围内时，用图像 token 的条件概率比。这个设计让两个阶段的梯度都能从同一个组内优势 A_i 回流。损失还采用 DAPO（引用 [83]）里的 token 级策略梯度技巧，即损失项在所有生成 token 上归一化，防止过长的语义级 CoT 因为 token 多而获得不均衡的优势。

第四个组件是集成奖励。每个专家接收定制化的输入。例如物体检测器接收“图像 + 从提示中提取的物体名称”，VQA 把“红狗”改写成问题“这是红狗吗？”，ORM 则直接把整个提示送入。具体计算上，物体检测器奖励 R_Det 分三种情况：如果提示中有空间关系，则用 αR_spatial + (1−α)K^{-1}ΣI(obji detected)，其中 R_spatial 在相对距离大于阈值且方向正确时为 IoU，方向错误为 0，α=0.6；如果提示中有数量要求，则比较指定数量 n_obj 和检测数量 \hat n_obj；否则只检测物体是否存在。VQA 奖励 RVQA = K^{-1}Σ P_Yes/(P_Yes+P_No)。最终奖励取平均，目的是从多维度评估质量并防止策略过拟合某一个单一奖励模型。

## 5. 核心公式与直觉

论文的关键公式集中在 GRPO 的定义和如何把两个 CoT 纳入概率比计算。

公式 (1) 给出优势值：

\[
A_i = \frac{R_i - \text{mean}(\{R_i\}_{i=1}^G)}{\text{std}(\{R_i\}_{i=1}^G)}
\]

其中 G 是组大小，论文设置 G=8（Table 7）。R_i 是第 i 个样本经过多个专家平均后得到的标量奖励。这个公式的含义是：不关心一个奖励的绝对值高低，只关心同一个提示下采样出的多个生成结果之间的相对好坏。如果某个生成结果比组内平均好，它的优势为正，策略就会增加生成这类 token 的概率；反之则降低。直觉上，图像没有绝对正确的答案，所以相对比较比绝对奖励更稳定。

公式 (2) 是概率比：

\[
r_{i,j}(\theta) = \frac{\pi_\theta(o_{i,j} \mid q, o_{i,<j})}{\pi_{\theta_{\text{old}}}(o_{i,j} \mid q, o_{i,<j})}
\]

这里 o_{i,j} 是第 i 条响应中的第 j 个 token，q 是提示，o_{i,<j} 是前面已经生成的 token。π_θ 是当前策略，π_θ_old 是采样时的旧策略。概率比衡量更新前后某个 token 的生成概率变化，然后与优势 A_i 相乘再 clip，目的是限制更新幅度。

公式 (3) 把概率比拆成两个阶段。论文写明：

\[
r_{i,j}(\theta) =
\begin{cases}
\frac{\pi_\theta(s_{i,j} \mid q, s_{i,<j})}{\pi_{\theta_{\text{old}}}(s_{i,j} \mid q, s_{i,<j})}, & 0 \le j \le |s_i| \\
\frac{\pi_\theta(t_{i,j} \mid q, s_i, t_{i,<j})}{\pi_{\theta_{\text{old}}}(t_{i,j} \mid q, s_i, t_{i,<j})}, & |s_i| < j \le |s_i| + M
\end{cases}
\]

前半部分是语义级 CoT 的文本 token，条件只依赖提示 q 和之前的语义 token；后半部分是图像 token，条件额外包含完整语义级 CoT s_i 和之前的图像 token。这个公式是整个 BiCoT-GRPO 的核心：它形式化地把语义级和 token 级两个 CoT 放在同一条概率链中，统一计算优势。直觉上，正因为 token 级 CoT 的条件里显式包含 s_i，所以当语义级 CoT 写得好时，图像 token 的生成概率会发生变化；这些变化通过同一优势 A_i 被强化学习捕捉，进而反过来优化语义级 CoT 的生成。联合优化的关键就在这里。

公式 (3.1) 是 GRPO 的总损失：

\[
J_{\text{GRPO}}(\theta) = \mathbb{E}_{(q,a)\sim D, \{o_i\}_{i=1}^G \sim \pi_{\theta_{\text{old}}}(\cdot|q)}
\left[ \frac{1}{\sum_{i=1}^G |o_i|} \sum_{i=1}^G \sum_{t=1}^{|o_i|} \min\left(r_{i,t}(\theta) \hat A_i, \text{clip}(r_{i,t}(\theta), 1-\varepsilon, 1+\varepsilon) \hat A_i\right) - \beta D_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}}) \right]
\]

其中 |o_i| = |s_i| + M。这个损失对组内所有样本的所有 token 求和并做归一化。梯度通过语义级和图像 token 两个路径反向传播，KL 惩罚防止策略偏离参考模型太远。除了这些公式，集成奖励的具体计算方式也很关键。物体检测器奖励中，R_spatial 在方向正确时用 IoU，方向错误时直接置 0；α=0.6 用于鼓励空间关系正确性。VQA 奖励是各物体“是”概率的均值。这些奖励公式没有在正文单独编号，但在 3.4 节详细说明。

## 6. 训练到底怎么跑

训练数据只有文本提示，没有任何真实配对图像。论文 Appendix A.1 写明，训练集来自 T2I-CompBench 训练集和文献 [19] 的提示，总共 6,786 条。训练前用 GPT-4o mini 从这些提示中提取物体及其属性，目的是方便物体检测器和 VQA 奖励模型使用。物体属性提取是离线进行的一次性预处理。

基础模型是 Janus-Pro-7B。训练采用 8 块 H800，总时长约 16 小时，训练 1,600 步，学习率 1e-6，beta=0.01，组大小 G=8，分类器自由引导尺度（CFG scale）为 5，最大梯度范数 1.0，batchsize 为 8，梯度累积步数为 2，图像分辨率 384×384。这些超参数在论文 Table 7 中明确给出。最终奖励模型组合为 HPS + GroundingDINO + GIT，即 H+D+V，不使用 ORM（论文 Table 3 最后一行）。

一轮训练 step 的过程如下。首先从训练集采样一个提示 p。用旧策略 π_θ_old 独立采样 G=8 个响应。但对每个响应，不能一次性生成，因为 Janus-Pro 需要手动切换文本和图像。第一步，把提示和一段推理指令输入模型，要求它输出语义级 CoT s_i。这段指令的具体措辞论文未完全逐字披露，但从图 3 和图 9-12 的示例可以看到，它要求模型提供简要、精确的可视化描述，包含提示中的所有元素。第二步，把原始提示、生成的 s_i 和 `<img_start>` 拼接起来，再次输入同一个模型，让它继续生成 M 个图像 token。图像 token 被 reshape 成 h×w×c 并输入解码器，得到图像 I。

接下来用集成奖励为每个 I 计算 R_i。HPM 使用 HPS，给出整体人类偏好分数；物体检测器使用 GroundingDINO，输入物体名和图像，输出检测结果并计算 R_Det；VQA 使用 GIT，把每个带属性的物体转换成问题“这是[属性]的[物体]吗？”，计算回答“是”的概率。论文没有使用 ORM 在最终模型中，但 ORM 单独训练时是微调 LLaVA-OneVision-7B，输出“是”或“否”的概率，R_ORM 计算方式与 VQA 类似，只是输入完整提示而非拆分对象。平均后得到 R_i，然后用公式 (1) 计算优势 A_i。

参数更新时，论文把整个 (s_i, t_i) 视为轨迹，对语义级 token 和图像 token 分别计算概率比 r_i,j，代入 GRPO 总损失。这个损失对所有 token 归一化，避免长文本影响。更新完成后，π_θ 被用作下一轮的旧策略。训练中没有显式的 SFT 阶段，论文宣称直接通过 RL 激发已有能力。训练步骤总数 1,600，梯度累积 2 步，batchsize 8，意味着每步实际可能使用 16 个提示或 8 个提示累计两次，细节上论文未进一步解释。

## 7. 推理到底怎么跑

推理阶段不需要奖励模型，只需要训练好的 Janus-Pro 策略。给定一个用户提示，模型执行两步生成。第一步，把提示和一段推理指令输入模型，模型自回归地生成语义级 CoT 文本。这段文本是用户可见的，它可能包含对物体的推理、场景想象、空间布局描述等。第二步，把原始提示、生成好的语义级 CoT 和 `<img_start>` 拼接起来，再次输入模型。模型继续自回归地生成 M 个图像 token。这些图像 token 按照训练时的布局被 reshape 成 h×w×c 网格，然后输入图像解码器得到最终图像。

推理时有一些需要注意的细节。论文提到在 WISE 基准上“稍微修改了推理指令”以获得更对齐的结果。这说明语义级 CoT 的指令是一个可以调节的推理策略，而不是完全固定的格式。另外，多样性是一个关键特性：与只优化 token 级 CoT 会显著降低多样性不同，加入语义级 CoT 后，每个提示生成的多张图像在保持细节的前提下有更多变化。这在 Figure 6、7、13、14 中有所体现。论文还比较了 zero-shot 语义级 CoT，也就是直接对未训练的 Janus-Pro 用同样的两步生成流程，发现提升非常微弱，因为 baseline 生成的语义级 CoT 要么遗漏关键物体（Figure 12 中遗漏鸟），要么超出模型实际生成能力（Figure 9-11 中虽然包含所有物体但仍生成失败）。这说明推理阶段两步 pipeline 本身并不足够，必须经过 BiCoT-GRPO 训练才能让语义级 CoT 真正发挥条件作用。

因此，完整推理顺序可以概括为：输入提示 → 生成语义规划文本 → 将规划作为附加条件 → 生成图像 token 序列 → 解码为图像。与训练唯一的区别是不再采样 G 个样本、不计算奖励、不更新参数。推理时只使用单一策略前向计算，但由于 CFG scale=5，内部可能维护条件与无条件两路 logits，计算量增加，论文没有报告具体延迟。

T2I-CompBench 包含 6,000 条组合提示，WISE 有 1,000 条世界知识提示，GenAI-Bench 有 1,600 条真实设计师复杂提示，TIIF-Bench 包含 36 种全新提示组合和 100 条设计师级提示。论文遵循各基准官方评测设置（Appendix A.1）。

最关键的一个消融是两层级 CoT 各自的作用。Table 4 显示，只优化语义级 CoT 时，T2I-CompBench 的 Color↑ 从 baseline 0.6359 升到 0.8082，Shape↑ 从 0.3528 升到 0.5684，Texture↑ 从 0.4936 升到 0.7219；WISE 的 Culture↑ 从 0.3000 升到 0.4900，Science↑ 从 0.3467 升到 0.4367。只优化 token 级 CoT 时，T2I-CompBench 提升也不错（Color↑ 0.7752，Shape↑ 0.5849），但 WISE 的 Culture↑ 只有 0.3500，Science↑ 0.3900，远低于语义级。联合优化达到 Culture↑ 0.5600，Science↑ 0.4633。这证明语义级 CoT 对需要世界知识和常识推理的任务更重要，而 token 级 CoT 对属性绑定、像素细节更有帮助。另一个关键发现是，只优化 token 级 CoT 会显著降低图像多样性，Vendi Score 从 baseline 6.976 降到 6.255；加入语义级 CoT 后升到 8.203，甚至超过 baseline。这说明语义级 CoT 的文本规划会给生成轨迹注入多样性，抵消 RL 对特定模式的过拟合。语义级 CoT 消融在 WISE 上的大幅提升也被 Figure 5 定性展示：模型可以先推理出对象或现象，再生成图像。

奖励函数分析（Table 3）证明集成奖励的作用。单个 HPM 在属性绑定上强（Color 0.8134），但关系弱（Spatial 0.2383）；单个物体检测器在 Spatial 上强（0.3044），但 Color 只有 0.7422。H+D+V 组合在 T2I-CompBench 整体上取得 0.3993 的 Complex↑，视觉质量人评达到 2.063。论文还做了人类研究，让 8 名研究生对四个奖励模型组合的图像按视觉吸引力排序，每个 subtask 随机挑选 30 个提示，共四个候选模型（V、O、H+D、H+D+V），排名 1 给 3 分，排名 2 给 2 分，依此类推。结果 H+D+V 得分最高。但需要注意，Table 3 显示 VQA 单独在 Complex↑ 有 0.4052 最高，但视觉质量只有 0.218，说明单一奖励容易在基准指标上被 hack，人类评分显著偏低。ORM 单独在 Complex↑ 有 0.3959，视觉质量 1.775，也不如集成。尚未完全证明的主张是：论文声称 T2I-R1 是“第一个推理增强的文本到图像模型”，但这是基于对相关工作的梳理而非严格的 benchmark 独特性证明。另外，论文主要在 T2I-CompBench 和 WISE 上优于 FLUX.1，但在 GenAI-Bench 上 FLUX.1 的 Basic 场景是 0.87 对比 T2I-R1 0.87，优势不大；TIIF-Bench 上 T2I-R1 只比 Janus-Pro 提升约 2 分。因此“超过 FLUX.1”需要限定在特定基准和指标上。论文在 T2I-CompBench 的 Spatial 子任务显著领先，但 Chemistry↑ 仍只有 0.30，说明部分常识或科学领域仍有上限。

## 9. 与前作怎么选

与 T2I-R1 最接近的方案有三个。第一个是 PARM/“Image Generation with CoT”（引用 [19]）。它是 T2I-R1 的直接前身，只优化 token 级 CoT，没有语义级 CoT，并且使用可验证奖励（如 ORM）来强化图像生成。Table 1 显示 Show-o + PARM 在 T2I-CompBench 上达到 Color 0.75, Shape 0.56, Texture 0.66，低于 T2I-R1 的 0.8130, 0.5852, 0.7243。选择规则：如果仅需要轻量提升属性绑定且不关心多样性，PARM 就能用；但遇到需要先理解提示再生成的场景（例如 WISE 中的文化常识），就必须用带语义级 CoT 的 T2I-R1。另外 PARM 只针对 token 级 CoT 优化，可能像 Table 4 所示降低多样性。

第二个是 Janus-Pro 的 zero-shot 语义级 CoT。它不是训练方案，而是在推理时直接让 baseline 先输出一段规划文本再生成。论文 Figure 9-12 显示这种方式提升非常有限，因为 baseline 不会生成与自身生成能力匹配的规划，经常遗漏关键物体。如果只是想快速测试语义规划的效果，可以这样操作，但不适合生产。

第三个是使用外部 LLM 做提示扩展的方案（引用 [9]）。这类方法用独立 LLM 把简短提示扩展成详细描述，再喂给图像生成器。T2I-R1 对比它的优势在于不需要额外模型，语义级 CoT 在同一 ULM 内生成且通过 RL 与生成端对齐；劣势是 T2I-R1 的语义级 CoT 受限于 Janus-Pro 的文本生成能力和长度，不像独立 LLM 那样灵活。选择时，如果已经有强扩散模型且只想快速扩写提示，外部 LLM 更简单；如果想要推理能力和生成能力在单一模型中互相促进，且能承担 RL 训练成本，选择 T2I-R1 更合适。

最后还有一个隐含的对照是扩散模型 FLUX.1。它在 T2I-CompBench 的 Spatial 上只有 0.2863，T2I-R1 是 0.3378，但在 GenAI-Bench Basic 上两者接近。因此如果只做通用高质量图像生成、不追求复杂组合推理，FLUX.1 仍是安全选择；若要处理 WISE 这类需要世界知识的常识推理，T2I-R1 更有针对性。

## 10. 工程判断：可行性、风险与上限

从工程角度看，T2I-R1 的可行性较高但有几个门槛。数据方面，训练只需要 6,786 条文本提示，不需要配对图像，数据成本低。但需要额外用 GPT-4o mini 提取物体属性，这引入了外部 API 的依赖和不稳定性。算力方面，8 块 H800 跑 16 小时，对于 7B 模型来说不算大，但需要注意 CFG scale=5 意味着推理时每一步可能要维护两套条件概率，额外增加一倍的计算；论文没有详细讨论推理延迟，但 Janus-Pro 本身就是自回归生成，384×384 分辨率的 token 数并不小。实现难点主要在两处：一是两步生成 pipeline 需要正确拼接提示、语义 CoT 和 `<img_start>`，稍有不慎就会导致模型在错误时刻切换模式；二是集成奖励涉及 HPS、GroundingDINO、GIT 甚至微调 LLaVA-OneVision，每一个都有自己的推理逻辑和显存占用，代码复杂度显著增加。

失败环节最可能出现在奖励模型失效。论文已经证明单个奖励容易被 hack：VQA 单独优化时 T2I-CompBench 的 Complex 指标不错但视觉质量人评很低（0.218）。如果 HPS、检测器、VQA 的权重配比不当，或某个专家对特定布局过拟合，策略会学会生成让专家打高分但人类不喜欢的图像。监控信号应该同时看基准分和 Vendi Score 等多样性指标，以及论文中的人类视觉质量排序。另一个风险是语义级 CoT 可能退化成长篇空话，DAPO 的归一化技巧只能部分缓解，不能保证生成规划一定有效。训练中没有直接约束语义级 CoT 的内容质量，只通过最终生成奖励间接优化，因此可能出现“规划写得华丽但生成脱离规划”的漂移。WISE 上提升明显，但 Chemistry↑ 只有 0.30，说明化学等领域知识仍然不足。

指标上限方面，T2I-CompBench 是规则化 benchmark，性能受限于 reward 模型的判断能力和 ULM 的基础生成能力。论文没有展示在更高分辨率或人类真实偏好数据集上的结果（如 PickScore、HPSv2 基准），也没有提供推理延迟、显存峰值或与扩散模型的效率对比。未回答的问题包括：token 级 CoT 的具体 patch 顺序是否对性能有影响？语义级 CoT 的质量如何自动评估？视频生成能否迁移该框架？论文 Limitations 也承认，视频领域没有统一理解生成的 ULM，GRPO 训练时间太长，奖励设计更是开放问题。因此 T2I-R1 的上限不是“通用高质量图像生成”，而是“在需要常识推理和组合绑定的小型 ULM 上补强推理生成能力”。

## 11. 放回研究脉络并收束

在“推理增强生成”这条新脉络上，T2I-R1 的位置是：它把 DeepSeek-R1 的 GRPO 从纯文本推理迁到图像生成，并把 CoT 从单层扩展为双层级。与理解模型的 R1 变体不同，它的 CoT 不产生最终答案文本，而是作为条件去生成图像；与 PARM 不同，它在 token 级 CoT 之上显式引入语义级规划。它证明了 ULM 可以在一个强化学习 loop 内同时改善它的理解和生成能力，而不是分别训练。

读完必须记住的 5 件事：

1. T2I-R1 识别了图像生成中的两层 CoT：语义级 CoT 是生成前的文字规划，token 级 CoT 是逐 patch 生成图像 token 的过程。
2. BiCoT-GRPO 用同一条 GRPO 轨迹联合优化两个 CoT，概率比分段计算：前半段是文本 token，后半段是图像 token，二者共享同一个组内优势。
3. 奖励不是单一规则，而是 HPS + GroundingDINO + GIT 的平均，目的是多维度评估并防止 hack；最终模型没有采用 ORM。
4. 实验显示语义级 CoT 主要提升 WISE 世界知识和 T2I-CompBench 的空间关系，token 级 CoT 主要帮助属性绑定和图像质量；只优化 token 级 CoT 会显著降低多样性，Vendi Score 从 6.976 降到 6.255。
5. 该方法在特定基准上能超过 FLUX.1，但并不代表通用生成质量全面领先；它更擅长需要推理的提示，且训练成本相对较低，推理 pipeline 是两步生成。

5 道自测题：

1. 解释为什么 T2I-R1 的完整响应 o_i 必须被分成 (s_i, t_i) 两段，而不能像普通 GRPO 那样只处理一段文本。
2. 如果只使用人类偏好模型 HPS 作为奖励，T2I-CompBench 的哪些指标可能虚高？为什么？
3. 如何用 Vendi Score 说明语义级 CoT 对多样性的作用？请说出 Table 4 中的关键数字。
4. 描述训练时从 prompt 到计算优势 A_i 的完整数据流，包括两步生成和四个奖励模块。
5. 为什么 zero-shot 语义级 CoT（直接在 Janus-Pro 上两步生成）提升很微弱？给出至少两个论文中提到的原因。

最终一句话总结：T2I-R1 用双层级 CoT 和集成奖励的强化学习，让统一多模态模型在文本到图像生成中学会“先想清楚再画”，在需要常识推理和组合绑定的 benchmark 上获得显著提升，但它的上限仍受限于基座模型的生成能力和奖励模型的可靠性。
