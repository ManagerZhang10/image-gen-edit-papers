# 大白话深读《Emu3》

## 1. 30 秒定位

Emu3 是北京智源人工智能研究院（BAAI）提出的多模态模型系列，论文标题为《Emu3: Next-Token Prediction is All You Need》（arXiv:2409.18869）。Figure 1 用示意图展示了视频、图像、文本被 token 化后统一送入 Transformer decoder，模型只预测下一个 token。它的核心主张很直接：只用“下一个 token 预测”（next-token prediction）这一种训练目标，用一个 Transformer 解码器同时处理文本、图像和视频的生成与理解，不再需要扩散模型（diffusion model）或 CLIP 加 LLM 的组合式架构。论文把图像和视频离散化成视觉 token，与文本 token 拼成一个序列，从零开始预训练一个约 8B 参数的 decoder-only 模型。在实验部分，Emu3 在文本到图像生成上超过 SDXL 的若干指标，在视觉语言理解上与 LLaVA-1.6 竞争，并在视频生成 VBench 上取得 80.96 的总分，超过多数开源扩散模型。论文还开放了视觉 tokenizer 权重和关键技术，并展示 DPO 可以用于自回归视觉生成。读者读完后应能回答：它如何把多模态问题变成纯 token 序列问题，训练和推理如何运行，实验支持哪些结论，以及它的上限与风险在哪里。

## 2. 为什么这篇论文会出现

语言模型领域里，下一个 token 预测已经推动了 ChatGPT 等系统，并引发关于通用人工智能早期迹象的讨论。但在多模态领域，图像和视频生成仍由扩散模型主导，例如 Stable Diffusion 系列和 DALL-E 系列；视觉语言理解则由 CLIP 视觉编码器加 LLM 的组合式方法主导，例如 LLaVA 系列。这种分工带来两个问题：一是架构复杂，需要分别训练或对齐多个模块，如 CLIP 编码器、扩散去噪网络、文本编码器；二是不同任务之间的训练目标和表征空间并不统一，难以自然地扩展到一个通用模型，也难以像语言模型那样直接通过堆更多数据、更多参数来获得可预测的规模收益。举例来说，SDXL 使用 CLIP ViT-bigG 作为文本编码器（Table 4），PixArt-alpha 使用 Flan-T5-XXL，而视觉理解模型通常需要额外视觉编码器，这些模块的训练目标、输入输出空间各不相同。

早期有一些工作尝试统一生成与理解，例如 Emu 和 Chameleon。Emu 采用自回归目标，但后续版本仍需连接扩散模型来生成图像，即没有完全摆脱组合式架构；Chameleon 虽然用混合 token 训练，但在生成和感知任务上仍未能匹配任务专用方法，例如在 GenEval 上只有 0.39（Table 7）。论文认为，这些工作要么没有彻底摆脱扩散或组合式架构，要么性能不足。Emu3 想验证一个更强的假设：如果视觉信号被充分离散化、文本与视觉共享统一 token 序列，一个纯自回归 Transformer 是否足以在生成和理解任务上同时达到或超过既有专用模型。这个问题的意义在于，它关系到多模态基础模型能否像语言模型一样，依靠统一的“预测下一个 token”目标进行规模化扩展，从而减少系统设计中的手工模块和任务特化，并为未来统一的多模态智能提供一条简化的技术路线。

## 3. 读懂前需要的最小概念

理解 Emu3 需要几个基础概念。首先是“下一个 token 预测”与自回归生成。模型在给定前文 token 序列后，预测下一个离散 token 的概率分布，训练时用交叉熵损失最大化真实 token 的对数概率，推理时从分布中采样或取高概率 token，再把它拼回输入继续预测。

其次是“离散视觉 token 化”。图像和视频原本是连续像素信号，需要编码成码本（codebook）中的离散索引。Emu3 的视觉 tokenizer 基于 SBER-MoVQGAN，它将一个 4×512×512 的视频片段或 512×512 的图像编码为 4096 个离散 token，码本大小为 32,768。压缩发生在时间维度 4 倍、空间维度 8×8 倍。这样视觉内容就变成了和文本 token 一样的离散序列。该 tokenizer 在 MoVQGAN 架构基础上，在编码器和解码器中各加入两个带 3D 卷积核的时间残差层，以增强视频 tokenization 能力；训练目标组合了 L2 损失、LPIPS 感知损失、GAN 损失和 commitment loss。

第三是 decoder-only Transformer 架构。Emu3 保留 Llama-2 风格的 LLM 框架，使用 RMSNorm 归一化、分组查询注意力（GQA）、SwiGLU 激活函数和旋转位置编码（RoPE）。嵌入层被扩展以容纳视觉离散 token。qkv 和线性投影层中的偏置被移除，并设置 dropout 0.1 以提升训练稳定性。模型配置见 Table 3：8B 参数、32 层、隐藏维度 4096、中间维度 14336、32 个注意力头、8 个 KV 头、总词表大小 184622、RoPE base 1,000,000、上下文长度 131,072。

第四是特殊 token 与多模态序列格式。论文用 [BOS]、[SOV]、[SOT]、[EOV]、[EOS] 等特殊 token 来标记文本和视觉的边界，还会在视觉 token 中插入 [EOL] 和 [EOF] 表示行结束和帧结束。文本 tokenizer 采用 QwenTokenizer 处理中英文等多语言文本，[BOS] 和 [EOS] 是文本 tokenizer 原有特殊 token。

第五是后训练方法：质量微调（QFT）只监督视觉 token；DPO 用人类偏好对构造“胜出/落选”三元组来调整模型；视觉语言理解则经过图像到文本训练和指令微调两个阶段。这些概念构成后续阅读的基础。

## 4. 方法全景：先看数据流

Emu3 的核心思想是把所有模态都压成 token，再统一交给一个 Transformer。下面是训练与推理共用的数据流示意图：

```
文本数据 → QwenTokenizer → 文本 token ─┐
                                       ├→ 拼接特殊 token 序列 → 8B Transformer decoder → next-token logits
图像/视频 → 视觉 tokenizer → 视觉 token ┘        │
                                                ▼
                                   训练：交叉熵 loss（视觉 token 权重 0.5）
                                   推理：采样 / top-k / top-p
                                                │
                          文本 token → 文本 detokenizer → 文本
                          视觉 token → 视觉 detokenizer → 图像/视频像素
```

视频数据由一系列帧组成，tokenizer 对每一帧进行空间 token 化并沿时间压缩 4 倍，[EOF] 插入在帧之间，[EOL] 插入在每帧的行之间，从而让一维 token 序列隐式保留二维空间和三维时序结构。

更具体地，输入格式为：

```
[BOS] {caption text} [SOV] {meta text} [SOT] {vision tokens} [EOV] [EOS]
```

其中 [SOV] 表示视觉输入开始，[SOT] 表示视觉 token 开始，[EOV] 表示视觉输入结束。meta text 中写有分辨率、帧率、时长等信息，全部以纯文本格式呈现，例如“resolution 512×512”或“frames 24 per second”，这些文本 token 参与 Transformer 的注意力计算，为条件生成提供显式信号。用于理解任务的数据会把 caption text 移到 [EOV] 之后，从而构造“视觉输入在前、文本回答在后”的序列。这样生成和理解共享同一种序列表示，只是字段位置不同。

核心组件包括：

**视觉 tokenizer**：基于 SBER-MoVQGAN，输入 4×512×512 视频 clip 或 512×512 图像，输出 4096 个离散 token，码本大小 32,768，时间压缩 4 倍，空间压缩 8×8。论文在编码器和解码器中加入两个带 3D 卷积核的时间残差层来增强视频能力。训练目标组合了 L2 损失、LPIPS 感知损失、GAN 损失和 commitment loss。训练数据是 LAION-High-Resolution 图像数据集和 InternVid 视频数据集。在论文报告的评估中，对 Pexels 的 3172 个视频重建 5 秒并统一采样 8 帧，720×720 分辨率下 LPIPS 为 0.110、PSNR 24.30、SSIM 0.771（Table 2），说明压缩后重建仍保留较多高频细节。该 tokenizer 是 Emu3 所有下游任务的基础，其重建质量直接决定生成像素精度的上限。

**文本 tokenizer**：使用 QwenTokenizer 处理中英文等多语言文本。总词表大小 184622 包含了文本 token 和视觉 token 对应的码本索引，因此模型不需要额外的模态适配层，只需扩展嵌入矩阵。视觉离散 token 使用码本索引作为独立词表段，与文本 token 共用嵌入矩阵，因此模型不需要把视觉特征投影到文本空间。

**序列组织与特殊 token**：通过上述格式把文本、元信息和视觉 token 拼成文档式输入。[EOL] 和 [EOF] 分别标记视觉 token 中的行和帧边界，便于模型在离散 token 序列中恢复二维图像或三维视频的空间结构。这种组织方式的假设是：Transformer 能从位置编码和边界 token 中学到布局关系，而不需要显式的二维位置嵌入。

**Transformer 主干**：8B 参数，配置如 Table 3。嵌入层需要同时映射文本 token 和视觉 token。注意力使用 GQA，位置编码用 RoPE，dropout 0.1 用于稳定训练。上下文长度为 131,072，主要用于容纳长视频 token 序列。

**损失与打包**：预训练使用标准交叉熵损失，但对视觉 token 的损失乘以 0.5，防止视觉 token 数量过多主导优化。训练时用张量并行（TP）、上下文并行（CP）和数据并行（DP），将文本-图像数据打包到最大上下文长度，同时保证完整图像不被切分。打包时，文本-图像对会被拼接成多个块填充 131072 上下文，但完整图像不会跨 chunk 切分，这避免了视觉 token 被截断后模型学到不完整图像分布。第二阶段的视频数据可能跨多个 chunk，但论文未明确视频是否允许截断。

## 5. 核心公式与直觉

视觉 tokenizer 自身的训练目标虽然独立于主模型，但同样值得理解。论文写明其组合了 L2 损失、LPIPS 感知损失、GAN 损失和 commitment loss。L2 损失约束像素级保真，LPIPS 损失用深度特征的距离衡量感知相似性，GAN 损失通过判别器推动重建结果接近真实分布，commitment loss 则鼓励编码器输出靠近码本中的离散向量。这些损失共同决定 tokenizer 是否能在高压缩比下保留足够信息。

论文没有给出一个统一的、格式完整的数学公式块，但主模型的训练目标可以从描述中准确还原。预训练阶段的最小化对象是加权的下一个 token 交叉熵损失。可以写成：

\[
\mathcal{L}_{\text{pretrain}} = -\frac{1}{N}\sum_{t=1}^{N} w_t \log p(y_t \mid y_{<t}; \theta)
\]

其中 \(y_t\) 是第 \(t\) 个真实 token，\(p(y_t \mid y_{<t};\theta)\) 是模型对下一个 token 的概率，\(\theta\) 是模型参数。\(w_t\) 是一个权重：当 \(y_t\) 是视觉 token 时 \(w_t=0.5\)，否则 \(w_t=1.0\)。这个公式是论文文本“standard cross-entropy loss”和“apply a weight of 0.5 to the loss associated with vision tokens”的等价表达。直觉上，视觉 token 数量往往远多于文本 token，例如一张 512×512 图像就贡献 4096 个 token，而描述该图像的文本可能只有几十个 token；如果不对视觉损失降权，模型可能把大部分优化容量放在重建视觉细节上，而忽略文本条件和跨模态语义，导致 prompt 跟随能力下降。视觉 token 损失权重 0.5 也间接作用于梯度缩放，使得一个视觉 token 的梯度贡献减半，平衡不同模态 token 数量差异。

质量微调（QFT）阶段仍然使用交叉熵，但监督只施加在视觉 token 上，即对文本 token 的损失权重设为零。形式上可写为 \(\mathcal{L}_{\text{QFT}} = -\frac{1}{|\mathcal{V}|}\sum_{t: y_t \in \mathcal{V}} \log p(y_t \mid y_{<t})\)，其中 \(\mathcal{V}\) 表示视觉 token 集合，文本 token 不参与求梯度。这相当于在预训练之后，把优化目标聚焦于视觉 token 的似然，从而在不干扰语言能力的前提下继续用高质量图像/视频数据提升视觉生成质量。论文写明 QFT 阶段图像分辨率从 512 提升到 720，训练末尾线性退火学习率到零。

DPO 阶段，论文写明 Emu3-DPO 同时最小化 DPO 损失和下一个 token 预测交叉熵损失。论文没有给出 DPO 损失的具体公式，但描述了数据构造过程：对每个用户 prompt，用 QFT 模型进行 8-10 次推理得到候选池；每个候选由三位投票者从视觉吸引力和 prompt 对齐两方面评分；最高分选为 chosen，最低分选为 rejected，形成 \((p, x_{\text{chosen}}, x_{\text{rejected}})\) 三元组。这里的直觉是，交叉熵只能让模型模仿训练数据，而 DPO 直接利用人类偏好信号，使生成结果更符合“好看且贴题”的目标。另一个重要细节是，构造 DPO 数据时直接存储 token，避免重新 tokenize 带来的偏差，这说明 token 化误差在偏好优化中是需要控制的变量。DPO 的训练数据构造中，候选推理的采样参数和评分标准具体化：采样使用 QFT 模型，每个 prompt 采样 8-10 次；三位投票者从视觉吸引力和 prompt 对齐两方面打分；chosen 和 rejected 的 token 在构造时被缓存，后续 DPO 训练直接使用这些 token，消除重新 tokenize 的重建差异。论文没有报告 DPO 数据总量、三元组数量或优化时的参考模型细节。

## 6. 训练到底怎么跑

Emu3 的训练分为视觉 tokenizer 训练、预训练、生成后训练和视觉语言理解后训练几个阶段。

**视觉 tokenizer 训练**：基于 SBER-MoVQGAN 初始化，在 LAION-High-Resolution 和 InternVid 上端到端训练。损失函数组合 L2、LPIPS、GAN 和 commitment loss。论文没有给出该阶段的学习率、批量大小或训练时长，只报告了重建指标。这个 tokenizer 是其他所有阶段的前提，如果它无法稳定重建视频和图像，后续自回归模型的上限会被直接锁死。

**预训练**：分为两个阶段。第一阶段不使用视频数据，从零开始训练，上下文长度 5120，数据为文本和图像。第二阶段引入视频数据，上下文长度扩展到 131,072。两个阶段学习率都是 \(5\times10^{-5}\)，采用余弦退火到零。数据准备上，图像需要过滤分辨率低于 512×512 的样本，用 LAION 美学预测器过滤分数低于 5.5 的样本，并对未通过美学过滤的图像使用文字检测和颜色过滤保留非单色且文字少的样本。视频经过 PySceneDetect 场景切分（ContentDetector 和 ThresholdDetector）、PaddleOCR 文字覆盖过滤、RAFT 光流幅度过滤和 LAION 美学过滤；在文字检测和光流步骤中，帧会按 2 FPS 采样并将短边缩放到 256 以降低计算成本；美学过滤中每个 clip 采样 3 帧取 3 个分数，最低分小于 5 的 clip 被丢弃。图像 caption 由基于 Emu2 微调的图像 captioner 生成，训练集约 1 百万对 GPT-4V 标注；视频 caption 由在 GPT-4V 标注样本上微调图像 captioner 得到视频 captioner，短于 20 秒的 clip 用 12 个均匀采样帧描述，长 clip 拆成 10-20 秒子 clip 分别描述。预训练时，输入被组织为前述特殊 token 格式，并用 TP、CP、DP 并行训练，packing 到最大上下文长度，且完整图像不被切分。

**质量微调（QFT）**：预训练结束后，对生成任务做质量微调。图像数据从多样高质量源选取，参考 HPSv2.1、MPS 和 LAION Aesthetics 三个偏好分数的平均值过滤。视频数据施加严格分辨率和光流过滤。QFT 只监督视觉 token，图像训练分辨率从 512 提升到 720。训练末尾线性退火学习率到零。

**DPO**：在 QFT 模型上再做人类偏好优化。对用户 prompt 生成 8-10 个候选，三位投票者评分，构造 chosen/rejected 对。论文未给出 DPO 的损失系数或训练 epoch，也未给出偏好数据集规模。

**视觉语言理解后训练**：第一阶段是图像到文本训练，把图像理解数据与纯语言数据混合，忽略视觉 token 的损失，只预测文本。每张图像保持长宽比缩放到约 512×512。第二阶段是指令微调，从 LLaVA-OneVision 中采样问答对增强指令跟随。低于 512×512 或高于 1024×1024 的图像会被缩放到相应上下限，中间图像保持原始分辨率。

整个训练流程中，关键超参数如模型配置、学习率、上下文长度、视觉 token 损失权重都有明确说明，但数据规模、GPU 卡数、批量大小、训练 step 数和 wall-clock 时间均未在论文中披露。

## 7. 推理到底怎么跑

推理时，Emu3 根据任务类型走不同的 token 解码路径。

**文本生成**：直接以文本 token 序列为输入，自回归预测下一个文本 token，与标准 LLM 相同。论文未披露文本生成任务的采样温度和 top-k/top-p，因为核心实验聚焦视觉任务。

**图像生成**：给定文本 prompt，模型先处理格式中的文本和元信息，然后自回归地生成视觉 token。根据附录 B.1，所有文本到图像评估中，Top-k 设为 16,384，Top-p 设为 1.0；输出分辨率为 Emu3 512×512，Emu3-DPO 720×720。论文还写明采用 classifier-free guidance，guidance scale 在 MSCOCO 30K 上为 5.0，在 GenEval 上为 5.5，在 DPG-Bench 上为 5.0。但论文没有展开说明这种引导机制如何在离散自回归采样中实现。这一部分事实记录为“论文写明使用 CFG，但未给出实现细节”。生成完视觉 token 后，视觉 detokenizer 将其重建为图像。

**视频生成**：与训练一致，Emu3 原生生成 5 秒、24 FPS 的视频。生成过程同样是自回归预测视觉 token，每个 token 对应时间与空间上的离散块。视频可以被无限扩展：给定 2 秒视频上下文，模型预测后续 2 秒；通过迭代预测，论文观察到可以把 2 秒上下文扩展到 8 秒未来帧。这种扩展不要求重新编码整个视频，而是把已生成的 token 继续拼接到输入中。

**视频理解任务**：图像先经过视觉 tokenizer，保持长宽比缩放到合适尺寸，然后按 [SOT] 视觉 token [EOV] 加问题文本的形式送入模型，模型自回归生成答案文本。推理阶段生成配置论文未给 top-k 或 temperature，但通常可使用 LLM 的常见采样策略；论文未明确披露，应视为未提供。

**后处理**：评估视频时，论文训练了视频稳定化模型和超分辨率模型，对生成视频进行后处理。稳定化模型基于 stable video diffusion 的时间 VAE，训练数据对是 tokenizer 自编码输出与原始视频 clip，维度均为 16×256×256，损失组合为 L1、LPIPS、GAN 和 KL 惩罚。超分辨率是空间-时间 UNet，可放大 4 倍，下采样用 BlurPool，上采样用 sub-pixel，训练随机裁剪 8×256×256 且分辨率大于 1024×1024 的视频。这说明原始 tokenizer 输出的视频还会经过额外的像素级后处理，最终评估指标受益于这些模块。

## 8. 实验和消融到底证明了什么

下面是 5 条关键实验证据的表格：

| 证据 | 任务/指标 | Emu3 结果 | 对照结果 | 锚点 |
|---|---|---|---|---|
| 文本到图像自动指标 | MSCOCO-30K / CLIP-I、CLIP-T、FID | CLIP-I 0.689, CLIP-T 0.313, FID 12.8 | SDXL CLIP-I 0.674, CLIP-T 0.310；Emu3-DPO FID 19.3 | Table 4 |
| 文本到图像人类偏好 | 视觉质量和 prompt 对齐加权总分 | Emu3-DPO 总分 70.0（英文 prompt） | SD-XL 66.9；DALL-E3 73.4；MJ-v5.2 71.1 | Fig.5 |
| 视频生成 | VBench 总分 | Emu3 80.96 | OpenSora V1.2 79.76；CogVideoX-5B 81.61；Kling 81.85；Gen-3 82.32 | Table 5 |
| 视觉语言理解 | OCRBench | Emu3 687 | LLaVA-1.6(HD) 532 | Table 6 |
| 视觉 tokenizer 重建 | 720×720 视频 LPIPS↓/PSNR↑/SSIM↑ | 0.110 / 24.30 / 0.771 | 128×128 为 0.099 / 21.71 / 0.630 | Table 2 |

MSCOCO 的 CLIP-I 0.689 略高于 SDXL 的 0.674，但 FID 12.8 明显差于 SDv1.5 的 9.93 和 DALL-E 2 的 10.93（Table 4），说明 Emu3 生成的图像在语义相似性上不弱，但像素级真实感仍有差距。CLIP-T 0.313 与 SDXL 0.310 基本持平，提示文本对齐能力接近。值得注意的是 Emu3-DPO 的 FID 升至 19.3，说明 DPO 偏好数据可能引入分布偏移。

Fig.5 中英文 prompt 下 Emu3-DPO 总分 70.0，高于 SD-XL 的 66.9，但低于 DALL-E 3 的 73.4、MJ-v5.2 的 71.1 和 FLUX.1-dev 的 74.6，表明人类偏好上已进入第一梯队但未全面领先。视频 VBench 总分 80.96 超过 OpenSora V1.2 的 79.76，与 CogVideoX-5B 的 81.61 相近，低于 Kling 81.85 和 Gen-3 82.32（Table 5）。维度上，Emu3 的 dynamic degree 79.27 显著高于多数模型，但 motion smoothness 98.93 低于 Kling 99.40，scene 20.92 也较低，说明动态幅度大但细节平滑和复杂场景建模仍有短板。

Table 6 中 Emu3 在 OCRBench 上 687 显著高于 LLaVA-1.6(HD) 532，ChartQA 68.6 高于其 54.8*，DocVQA 76.3 高于其 74.4*，说明离散视觉 token 保留了密集文字信息。但 MMMU 31.6 低于 LLaVA-1.5 35.3 和 LLaVA-1.6(HD) 35.1，MMBench 58.5 也低于多个编码器模型，说明复杂推理能力不足。

论文还给出了 DPO 消融：Fig.6 显示，在人类偏好分数上，有 DPO 比无 DPO 在视觉质量和 prompt 对齐两方面都有提升，具体数值为视觉质量从 60.6 到 61.6，prompt 对齐从 52.3 到 57.3。但 Table 4 同时显示，DPO 之后自动指标如 CLIP-I 从 0.689 降至 0.680，FID 从 12.8 升至 19.3，GenEval 从 0.66 降到 0.64（rewriter 后），T2I-CompBench 平均值从 0.7422 降到 0.7164。论文解释这可能是因为 DPO 偏好数据强调整体美学，与自动评价模型的领域不一致，因此自动指标结论有限。这说明 DPO 的真实收益需要人类评估来确认，单纯依赖自动指标可能产生误导。

实验最能支持的主张是：纯 next-token prediction 可以在多个任务上达到与专用模型竞争的水平。在 GenEval 上，Emu3 + rewriter 的 Overall 为 0.66，超过 Chameleon 的 0.39、Show-o 的 0.53、Transfusion 的 0.63，并且超过 SDXL 的 0.55，匹配 DALL-E 3 的 0.67。在 DPG-Bench 上，Emu3-DPO 的 81.60 超过 SDXL 的 74.65 和 PixArt-alpha 的 71.11，接近 DALL-E 3 的 83.50。在 OCRBench 上，Emu3 的 687 显著领先 LLaVA-1.6(HD) 的 532，说明离散视觉 token 并未抹掉文字细节。

但也有一些主张尚未被充分证明。例如，论文声称“简化复杂多模态模型设计，解锁训练和推理的扩展潜力”，但没有给出模型规模、数据规模或训练算力的扩展曲线，因此“扩展潜力”更像方向性判断而非实验结论。视频未来预测只有定性示例，没有定量指标；视觉语言理解中若干基准带星号表示训练数据中出现过相关图像，存在数据泄漏或过拟合风险，例如 VQAv2、GQA、ScienceQA-Img、ChartQA 等，这些结果可能高估模型真实泛化能力；模型在 MMMU 上只有 31.6，低于 LLaVA-1.5 的 35.3 和 LLaVA-1.6(HD) 的 35.1，说明复杂多学科推理仍是短板。此外，classifier-free guidance 在自回归模型中的实现没有说明，导致生成质量的一部分可能来自未公开的推理技巧；视频生成中 dynamic degree 为 79.27，虽然高于多数模型，但部分维度如 scene 只有 20.92，说明复杂场景建模仍弱。论文声称视频可无限扩展，但只展示了 2 秒到 8 秒的定性扩展（Fig.8），没有定量评价长时间扩展的漂移或一致性。此外，视觉语言理解中多次用到的重写器只用于图像生成评估，理解评估没有类似处理，因此跨任务比较需注意评估协议差异。

## 9. 与前作怎么选

与 Emu3 最接近的方案有 Chameleon、Show-o/Transfusion，以及专用模型 SDXL 和 LLaVA-1.6。

Chameleon 也是混合模态的自回归模型，但在图像生成 GenEval 上仅 0.39（Table 4/Table 7），远低于 Emu3 的 0.54（无 rewriter）或 0.66（rewriter）。Emu3 的优势在于更强的视觉 tokenizer 和更系统的后训练流程。如果需求是统一架构且希望生成质量达到可竞争水平，Emu3 明显更合适；但 Chameleon 的论文细节可能对某些研究者仍有参考价值，尤其是早期混合 token 训练经验。Chameleon 的参数规模为 34B（Chameleon-MT-34B，Table 6 中理解结果很少），若目标是快速验证混合 token 训练，Chameleon 的早期经验仍值得参考，但若追求可比性能应选 Emu3。

Show-o 和 Transfusion 是“自回归 + 扩散”的混合方案，Show-o GenEval 0.53，Transfusion 0.63（Table 7），Emu3 的 rewriter 结果 0.66 更高，但无 rewriter 时 0.54 与两者接近。如果团队已有扩散训练基础设施，并且只做图像生成，混合方案可能更容易渐进式迁移；如果目标是彻底统一模态和推理流程，Emu3 的纯自回归方案更简洁，且不需要维护两套采样机制。Show-o 使用 Phi-1.5 作为语言骨干，参数规模约 1.3B（Table 6），模型较小，可能推理延迟和显存开销更低，但生成和理解性能明显弱于 Emu3；Transfusion 规模未披露，但保留了扩散分支，训练和推理需要维护两套采样机制。

与专用模型相比：SDXL 在图像生成上长期是开源标杆，但 Emu3 在人类评估中总分超过 SDXL，并在 DPG-Bench 上 80.60 对 74.65 领先。不过 SDXL 的推理生态更成熟，延迟和显存开销可能更低。LLaVA-1.6-7B 在多个理解基准上与 Emu3 互有胜负，但 Emu3 在 OCRBench、ChartQA、DocVQA 等文档/图表密集任务上明显更强。如果只做单一任务且追求低实现成本，专用模型仍是更稳的选择；如果需要一个模型同时覆盖生成和理解，并且愿意承担较大的训练和推理成本，Emu3 提供了可行路径。如果团队已有成熟的扩散训练推理栈，并且任务以图像生成为核心，SDXL 或后续扩散模型仍是更低风险的选择；但如果需要同时覆盖 OCR 密集型理解、视频生成和未来预测，且能接受自回归生成长序列的延迟，Emu3 提供了一个已验证的统一框架。

## 10. 工程判断：可行性、风险与上限

从工程角度看，Emu3 的可行性建立在两个关键前提上：视觉 tokenizer 的重建质量足够高，以及自回归 Transformer 能稳定学习长视觉序列。论文给出的 720×720 重建 LPIPS 0.110、PSNR 24.30、SSIM 0.771（Table 2）说明 tokenizer 在压缩 4×8×8 后仍保留较多细节，这是可行性证据。但 8B 模型、131K 上下文和 TP/CP/DP 并行训练意味着真实训练资源需求很高，论文未披露 GPU 卡时或显存占用，外部复现成本无法估测。

算力与延迟方面，Emu3 推理时需要逐步生成视觉 token：512×512 图像对应 4096 个 token，720×720 输出因分辨率提升 token 数会更多。与扩散模型的一次或少数几步潜在变量生成相比，自回归视觉生成的延迟可能更高。论文没有给出生成一张图或一段视频的 wall-clock 时间，也没有报告吞吐，因此无法判断是否适合低延迟场景。视觉 tokenizer 本身是卷积编码器，推理开销相对可控，但视频稳定化和超分辨率后处理会额外增加延迟和显存。

实现难点主要有四类。第一，视觉 tokenizer 的训练需要平衡重建精度和码本利用率，码本大小为 32,768 且输出 4096 token，容易出现码本崩塌或模式坍塌；论文没有给出 commitment loss 权重。第二，自回归生成长视觉序列时误差会累积，尤其视频扩展中，前一帧 token 的错误会输入后续预测，论文只在定性示例中展示了 8 秒扩展，未报告更长时域的漂移。第三，DPO 数据构造依赖人工或投票者评分，成本高且偏好标准难以统一；论文的投票者数量只有三位，可靠性有限。第四，classifier-free guidance 如何作用于离散 token 采样没有解释，这可能是生成质量的关键但不透明，复现者可能因此无法达到论文分数。

失败环节的监控信号应包括：训练损失中的视觉 token 分量是否稳定下降；验证集上的重建 LPIPS/PSNR/SSIM；生成样本的 CLIP score 和 FID；VBench 的 motion smoothness 和 dynamic degree；以及人类偏好分数的周期性评估。特别需要监控 DPO 后自动指标和人类指标是否出现背离，因为论文已观察到 DPO 后自动指标下降但人类评分上升，如果只用自动指标筛选 checkpoint 可能错过真正更好的模型。

指标上限方面，Emu3 并非在所有任务上领先。视频 VBench 总分 80.96 低于闭源 Kling 的 81.85 和 Gen-3 的 82.32（Table 5）；图像 DPG-Bench 80.60 低于 DALL-E 3 的 83.50 和 SD3-Medium 的 84.08（Table 8）；MSCOCO FID 12.8 也差于 SDv1.5 的 9.93 和 DALL-E 2 的 10.93，说明像素级真实感仍有差距；视觉语言 MMMU 31.6 远低于许多专用 VLM。因此其上限目前是“与任务专用模型可比，部分任务超过，但尚未达到全面领先”。未回答的问题包括：模型规模扩大到 70B 或更大时，纯自回归视觉生成是否会持续改善？视觉 token 损失权重 0.5 是否最优？训练数据规模和质量对结果贡献多大？以及 CFG 的具体实现和推理延迟。

## 11. 放回研究脉络并收束

Emu3 处于两条研究线路的交叉点。一条是视觉语言理解：从 CLIP 的对比学习，到 Flamingo 连接预训练视觉编码器与 LLM，再到 LLaVA 等组合式 VLM，模型越来越依赖专门预训练模块，但同时也越来越难以统一生成与理解。另一条是视觉生成：扩散模型从 Stable Diffusion 到 SDXL、DALL-E 3 持续主导；自回归图像生成如 DALL-E、Parti、VideoPoet 也曾尝试，但往往需要级联或额外文本编码器，甚至需要生成-细化两阶段框架。早期统一模型 Emu、CM3Leon、Chameleon 试图把两者合并，但性能落后于专用方案。Emu3 的价值在于以纯下一个 token 预测的方式，在图像生成、视频生成和视觉语言理解上同时接近或超过任务专用模型，证明统一 token 化自回归路线是可行的。它也把开放的视觉 tokenizer 作为一项关键资源，因为此前高质量的通用视觉 tokenizer 并不公开，这降低了后续研究的门槛。

读完必须记住的 5 件事：

1. Emu3 是一个 8B decoder-only Transformer，从零训练，只用下一个 token 预测统一文本、图像和视频的生成与理解，没有扩散模型、CLIP 编码器或组合式架构。
2. 视觉 tokenizer 基于 SBER-MoVQGAN，码本 32,768，将 4×512×512 视频 clip 或 512×512 图像编码为 4096 个 token，时间和空间压缩分别为 4 倍和 8×8。
3. 预训练序列格式为 `[BOS] caption [SOV] meta [SOT] vision tokens [EOV] [EOS]`，视觉 token 损失权重 0.5；预训练分两阶段，上下文长度从 5120 扩展到 131,072。
4. 生成后训练包括 QFT（只监督视觉 token，分辨率 512→720）和 DPO（人类偏好三元组，存储 token 避免重 tokenize），DPO 提升人类评分但可能降低自动指标。
5. 实验结果：图像生成超过 SDXL 并在部分指标接近 DALL-E 3；视频 VBench 80.96 超过多数开源扩散但低于 Kling/Gen-3；视觉语言在 OCR/图表类任务强，但 MMMU 和 MMB 较弱。

5 道自测题：

1. Emu3 如何把图像和视频变成离散 token？码本大小、压缩比和输出 token 数分别是多少？
2. 预训练损失中为什么给视觉 token 乘以 0.5？这个权重不乘会有什么潜在后果？
3. QFT 和 DPO 分别优化什么损失？DPO 数据三元组是如何构造的？
4. 在哪些基准上 Emu3 超过 SDXL 或 LLaVA-1.6？哪些指标上 Emu3 仍落后于闭源或专用模型？
5. 论文对 classifier-free guidance 在自回归模型中的实现和训练算力分别披露了什么？还有哪些关键未回答问题？

最终一句话总结：Emu3 用单一 Transformer 和离散 token 证明“下一个 token 预测”可以同时覆盖多模态生成与理解，但目前它更接近“统一路线可行且具备竞争力”，而不是“全面超越所有专用架构”。
