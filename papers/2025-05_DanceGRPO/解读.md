# 大白话深读《DanceGRPO》

## 1. 30 秒定位

这篇论文提出一个叫 **DanceGRPO** 的框架，把大语言模型（LLM）里已经有效的 **Group Relative Policy Optimization（GRPO，群组相对策略优化）** 用于视觉生成模型的对齐。它解决的问题是：扩散模型和 rectified flow 模型预训练后会生成内容，但不一定符合人类审美、文本一致性和运动质量等偏好；而以往的强化学习对齐方法，如 DDPO 和 DPOK，在成千上万个 prompt 上训练容易不稳定，ReFL 又需要可微奖励模型，DPO 提升有限。

DanceGRPO 的核心做法是：把扩散模型和 rectified flow 的采样过程统一写成随机微分方程（SDE），把去噪轨迹构造成马尔可夫决策过程（MDP），然后用 GRPO 做策略优化。它强调同一 prompt 的一组样本共享初始化噪声、从完整去噪轨迹里抽样子集时间步训练、多个奖励模型按各自统计量组合优势函数。论文在文生图、文生视频、图生视频三个任务上，基于 Stable Diffusion、FLUX、HunyuanVideo、SkyReels-I2V 四种基础模型实验，使用 HPS-v2.1、CLIP Score、VideoAlign 等奖励，其中 HunyuanVideo 的视频运动质量相对提升 181%（§3.3、Table 5）。训练阶段使用 SDE 引入随机探索，评估和可视化则回到 ODE 确定性采样；论文认为这统一了扩散与 rectified flow 两种生成范式（§2.1、§2.2）。

## 2. 为什么这篇论文会出现

扩散模型和 rectified flow 已经在图像、视频生成上取得明显进展，但预训练只学习数据分布，并不直接对齐人类偏好。人类偏好包含图像美感、图文对齐、视频运动合理性和视觉质量等，通常需要奖励模型或可微分数来驱动。此前的方法各有瓶颈：

- **ReFL** 这类直接对奖励做可微反向传播的方法，需要奖励模型可微。视频生成里奖励模型和生成链都很庞大，VRAM 消耗很高，工程复杂（§1）。
- **DPO 变体**，包括 Diffusion-DPO、Flow-DPO、OnlineVPO，训练目标直接优化偏好，但论文认为它们往往只带来“边缘性”视觉质量提升，不像 RL 那样能充分利用黑盒奖励（§1）。
- **DDPO 和 DPOK** 把去噪过程当作 MDP，用策略梯度优化黑盒奖励，理论上更通用。但论文指出三个未解决问题：其一，rectified flow 通常用 ODE 确定性采样，这与需要轨迹概率的 MDP 策略梯度不兼容；其二，这些策略梯度方法在超过约 100 个 prompt 的较大规模数据上不稳定；其三，尚未验证视频生成任务（§1）。

更深一层背景来自 LLM。DeepSeek-R1 用大规模 RL 和结果奖励，让模型出现长思维链，展示了 GRPO 在稳定性和扩展性上的能力（§4）。DanceGRPO 的目标是把这种稳定性机制搬进视觉生成。论文把自己的贡献定位为“第一次发现 GRPO 的稳定性机制适合解决视觉生成 RL 的核心优化问题”，并用统一 SDE 形式覆盖扩散模型和 rectified flow，实验上从文生图扩展到视频任务（§1、§2.2）。

另外，从论文的 capability matrix（Table 1）可以看到，之前的 DDPO/DPOK 虽然属于 RL-based 且不需要可微奖励，但不支持视频生成、难以大规模扩展、对 rectified flow 不兼容；ReFL 需要可微奖励，不支持视频生成和大规模扩展；DPO 类方法虽可扩展到视频和 rectified flow，但奖励提升幅度有限。DanceGRPO 试图把五个能力维度同时填满，这也是它出现的直接动机。

## 3. 读懂前需要的最小概念

**扩散模型（diffusion model）**：前向过程逐渐把干净数据 \(x\) 与噪声 \(\epsilon\) 混合，得到 \(z_t = \alpha_t x + \sigma_t \epsilon\)；去噪模型预测噪声 \(\hat\epsilon\)，采样时从高斯噪声逐时间步回到干净样本。论文中 \(\alpha_t\)、\(\sigma_t\) 构成噪声调度，\(z_0\) 接近干净数据，\(z_1\) 接近高斯噪声（Eq. 1）。采样方程 \(z_s = \alpha_s \hat x + \sigma_s \hat\epsilon\) 对应 DDIM 采样器（Eq. 2）。

**Rectified flow**：把前向过程定义为干净数据 \(x\) 与噪声 \(\epsilon\) 的线性插值，\(z_t = (1-t)x + t\epsilon\)；模型预测“速度”或向量场 \(u = \epsilon - x\)，采样时沿 \(z_s = z_t + \hat u \cdot(s-t)\) 前进（Eq. 3、Eq. 4）。它的原生采样是 ODE，确定性强。

**ODE 与 SDE**：ODE 采样是确定性的，给同样的初始噪声和 prompt，输出固定；SDE 采样带有额外随机项，能产生随机探索。DanceGRPO 训练阶段故意加入随机项 \(\epsilon_t dw\)，以便 GRPO 能够探索不同输出；评估和可视化阶段则回到 ODE 采样（§2.2、§3.1）。这里的 \(\epsilon_t\) 既控制随机探索强度，又影响策略梯度的概率分布形态。

**MDP（Markov Decision Process）**：把决策过程定义为状态 \(s_t\)、动作 \(a_t\)、转移 \(P\)、奖励 \(R\)。论文式 (6) 里，状态是 (prompt \(c\), 时间步 \(t\), 当前潜变量 \(z_t\))，动作是去噪到下一时间步 \(z_{t-1}\)，最终时间步的奖励来自奖励模型对 \(z_0\) 和 \(c\) 的打分。转移 \(P\) 是 Dirac delta，只把状态按时间步和潜变量确定地推进。

**GRPO**：对同一个 prompt 生成一组 \(G\) 个输出，用组内奖励的均值与标准差归一化，得到每个输出的优势 \(A_i\)。策略更新时最大化带 clip 的概率比目标。这样做不依赖全局 reward baseline，适合不同 prompt 奖励分布差异大的情况。DanceGRPO 沿用了 DeepSeek-R1 的 GRPO 结构，但把奖励信号复制到所有被优化的时间步上，以缓解奖励稀疏（§2.2）。

**Classifier-Free Guidance（CFG）**：推理时组合条件与无条件去噪输出，加强 prompt 控制。训练 RL 时 CFG 可能带来不稳定，需要特别处理；论文对高保真模型建议关闭训练时 CFG，对依赖 CFG 的模型则联合优化条件与无条件输出（Appendix C）。

**随机插值（stochastic interpolants）**：附录 B 用随机插值框架统一扩散模型和 rectified flow。它构造 \(z_t = \alpha(t) z_0 + \beta(t) z_1 + \gamma(t) \epsilon\)，通过选择 \(\alpha\)、\(\beta\)、\(\gamma\) 恢复 rectified flow 或 score-based diffusion。这个视角解释了为什么两者可以用同一个 SDE 形式表达（Appendix B.1）。

## 4. 方法全景：先看数据流

DanceGRPO 的核心不是新的网络结构，而是把去噪采样、奖励计算和策略更新拼接成一个可扩展的 RL 流程。下面是一个训练迭代的数据流：

```text
prompt batch Db（约 32 个 prompt，Table 6）
        |
        v
更新旧策略：π_old ← π_θ
        |
        v
对每个 prompt c：
   用同一个随机初始化噪声 z_T^c 复制给 G=12 个样本
        |
        v
π_old 执行 SDE 去噪采样 T 步（训练时 ε_t=0.3 引入随机探索）
    Stable Diffusion T=50，FLUX/HunyuanVideo T=25
        |
        v
得到 G 个输出 {o_1, ..., o_G}
        |
        v
K 个奖励模型分别打分 -> {r_i^1, ..., r_i^K}
        |
        v
每个奖励维度组内标准化后相加：
A_i = Σ_k (r_i^k - μ_k) / σ_k
        |
        v
时间步子采样：从 {1..T} 中选 ceil(τT) 个时间步，τ=0.6
        |
        v
对选择的时间步计算 GRPO 目标 J(θ)，clip 范围 ε=1e-4
        |
        v
梯度上升更新 θ <- θ + η ∇J，每 iteration 执行 4 次梯度更新
```

训练时，扩散模型和 rectified flow 都先被写成 SDE。扩散模型的反向 SDE 是论文式 (7)，rectified flow 的反向 SDE 是论文式 (8)。两者共享一个形式：在原有去噪漂移项之外，减去与 score function 相关的项，并加入 \(\epsilon_t dw\) 的随机性。论文认为 \(\epsilon_t\) 是探索噪声的强度，统一了两个生成范式（§2.2、Appendix B）。

接下来是核心组件：

**组件 A：MDP 形式化**。状态 \(s_t=(c,t,z_t)\)，动作 \(a_t=z_{t-1}\)，奖励只在 \(t=0\) 时由奖励模型给出（Eq. 6）。它的输入是采样轨迹，输出是每个时间步的策略概率和最终奖励。作用是让策略梯度有可计算的轨迹分布。对于 rectified flow，原生 ODE 无法提供这种时间步级别的概率，因此必须引入 SDE。论文在式 (6) 中用 Dirac delta 表示转移，轨迹由 \(T\) 个时间步组成，之后 \(P\) 导向终止状态；奖励模型 \(r(z_0,c)\) 通常由视觉-语言模型参数化，如 CLIP 或 Qwen-VL（§2.2）。

**组件 B：共享初始化噪声**。同一 prompt 的 \(G\) 个样本使用相同的初始噪声。这是为了减少视频生成中的 reward hacking 和训练不稳定（Appendix F、Figure 8）。没有它时，奖励模型容易抓住噪声差异带来的视觉伪影，而不是真正改善内容。这个约束显著缩小了探索空间，但论文认为这是防止策略走偏的关键。它也是与 DDPO/DPOK 的一个关键区别：DDPO 对同一 prompt 的样本通常使用不同噪声向量，DanceGRPO 则强制共享（Appendix D）。

**组件 C：多头奖励优势聚合**。不同奖励模型尺度不同，不能直接相加。DanceGRPO 先把每个奖励在自己的组内减去均值、除以标准差，再求和。这样可在 HPS 奖励上提升同时保留 CLIP 自然度。论文在 §2.2 明确说“rather than directly combining rewards, we aggregate advantage functions”。奖励模型种类包括：图像美学（用 HPS-v2.1）、图文对齐（CLIP）、视频美学质量（VideoAlign 的视觉质量 VQ）、视频运动质量（VideoAlign 的 MQ）、以及阈值化二进制奖励（§2.3）。

**组件 D：时间步子采样**。不是每个去噪时间步都回传梯度，而是随机保留约 60% 的时间步，即随机丢弃 40%。这降低计算量，同时保留训练稳定性。其假设是去噪轨迹沿时间高度冗余；消融显示前 30% 时间步对基础生成模式贡献大，但只训练前 30% 会因缺少后期细化而性能下降，因此采用 40% 随机 dropout（§3.6、Figure 4b）。Algorithm 1 中该步骤为 subsample \(\lceil \tau T \rceil\) timesteps，默认 \(\tau=0.6\)（Table 6）。

**组件 E：GRPO 更新目标**。计算每个被采样时间步的概率比，clip 后取 min，乘以优势 \(A_i\)。这个目标使策略朝高优势输出方向更新，同时限制单步更新幅度。论文省略了 KL 正则项，理由是实证上删除后性能差异很小（§2.2）。Clip range \(\epsilon=1e-4\)，远小于通常 PPO 中的 0.2，说明更新非常保守（Table 6）。

这些组件的共同假设是：视觉生成模型的采样轨迹可以被当作有限时间 MDP；同一 prompt 下组内相对奖励可以稳定地给出学习信号；不同奖励模型组内标准化后可以公平组合；时间步之间存在冗余，可以安全子采样。

## 5. 核心公式与直觉

理解 DanceGRPO 的贡献，有四个公式最关键。

**统一采样形式（Eq. 5）**

\[
\tilde z_s = \tilde z_t + \text{Network output} \cdot (\eta_s - \eta_t)
\]

对扩散模型，定义 \(\tilde z_s = z_s/\alpha_s\)，\(\eta_s=\sigma_s/\alpha_s\)；对 rectified flow，定义 \(\tilde z_s=z_s\)，\(\eta_s=s\)。这个式子说明：虽然扩散模型和 rectified flow 理论来源不同，但实践中都能写成“当前状态加上网络输出乘以时间差”的形式。工程上的对应是：DanceGRPO 不需要切换两套策略优化器，而是共用同一 MDP 和 GRPO 目标，只要换算 \(z\) 和 \(\eta\) 的坐标即可。附录 B.2 还通过匹配均值和方差导出了 \(f_t = \partial_t \log(\alpha_t)\)、\(g_t^2 = 2\alpha_t\sigma_t\partial_t(\sigma_t/\alpha_t)\)、\(\eta_t = \epsilon_t / (2\alpha_t\sigma_t\partial_t(\sigma_t/\alpha_t))^{1/2}\)，进一步说明两者是“一枚硬币的两面”（Appendix B.2 Eq. 29）。这一统一形式的推导基于随机插值框架：构造 \(z_t=\alpha(t)z_0+\beta(t)z_1+\gamma(t)\epsilon\)，满足边界条件 \(\alpha(0)=\beta(1)=1\)，\(\alpha(1)=\beta(0)=\gamma(0)=\gamma(1)=0\)，且 \(\gamma(t)\ge0\)；选 \(\gamma=0,\alpha=1-t,\beta=t\) 得 rectified flow，选 \(\alpha=\sqrt{1-t^2},\beta=t\) 可联系 score-based diffusion（Appendix B.1）。

**扩散与 rectified flow 的 SDE 采样（Eq. 7 和 Eq. 8）**

扩散模型反向 SDE：

\[
dz_t = \left( f_t z_t - \frac{1+\epsilon_t^2}{2} g_t^2 \nabla\log p_t(z_t) \right) dt + \epsilon_t g_t dw
\]

Rectified flow 反向 SDE：

\[
dz_t = \left( u_t - \frac{1}{2}\epsilon_t^2 \nabla\log p_t(z_t) \right) dt + \epsilon_t dw
\]

其中 \(\epsilon_t\) 控制采样随机性。没有 \(\epsilon_t\) 时，采样更接近确定性 ODE；加入 \(\epsilon_t\) 后，每个动作 \(a_t\) 对应一个随机分布，使得策略梯度可以计算不同轨迹的概率比。论文的实验显示，降低 \(\epsilon_t\) 会导致性能下降，而 \(\epsilon_t\) 大于 0.3 有时让 RLHF 后图像产生噪点（§3.6、Figure 4c）。这解释了为什么作者把 \(\epsilon_t=0.3\) 设为默认。对于给定正态分布 \(p_t(z_t)=N(z_t|\alpha_t x,\sigma_t^2 I)\)，score function 是 \(-(z_t-\alpha_t x)/\sigma_t^2\)，可以插入上两式得到具体的 \(\pi(a_t|s_t)\)（§2.2）。这种 SDE 构造借鉴了 stochastic interpolants 的 backward SDE：\(dz_t=(u_t-\epsilon(t)s(t,x))dt+\sqrt{2\epsilon(t)}dz\)，当设置 \(\epsilon_t=\sqrt{2\epsilon(t)}\) 时与式 (8) 一致（Appendix B.1 Eq. 15）。

**GRPO 目标函数（Eq. 9）**

\[
J(\theta)=\mathbb{E}_{
\{o_i\}_{i=1}^G\sim\pi_{\theta_{\text{old}}}(\cdot|c),\
a_{t,i}\sim\pi_{\theta_{\text{old}}}(\cdot|s_{t,i})}
\left[\frac{1}{G}\sum_{i=1}^G \frac{1}{T}\sum_{t=1}^T
\min\left(\rho_{t,i}A_i,\ \text{clip}(\rho_{t,i},1-\epsilon,1+\epsilon)A_i\right)
\right]
\]

其中 \(\rho_{t,i} = \pi_\theta(a_{t,i}|s_{t,i})/\pi_{\theta_{\text{old}}}(a_{t,i}|s_{t,i})\)。与 PPO 类似，clip 限制每次策略更新不会偏离旧策略太远。与 LLM 里的 GRPO 不同，这里同一个样本的奖励被复制到所有时间步上，以缓解最终奖励稀疏。论文默认省略 KL 正则项，因为经验上没有明显差异（§2.2）。注意 clip 范围 \(\epsilon=1e-4\)（Table 6），远小于一般 PPO 的 0.2，说明 DanceGRPO 的策略更新幅度被压得很窄，更接近保守的信任域更新，这可能是其稳定性的来源之一。策略 \(\pi_\theta(a_{t,i}|s_{t,i})\) 正是由 SDE 采样式 (7) 或 (8) 定义的分布。

**优势函数（Eq. 10）**

\[
A_i = \frac{r_i - \text{mean}(\{r_1,\dots,r_G\})}{\text{std}(\{r_1,\dots,r_G\})}
\]

这是组内标准化：每个输出的好坏不是看绝对分数，而是看它在同一 prompt 下的一组输出里相对优劣。这样做对 prompt 之间难度差异更鲁棒。多个奖励时，论文先对每个奖励分别标准化，再求和，而不是直接对原始奖励加权（§2.2、Algorithm 1）。例如，对 HPS 和 CLIP 两个奖励，分别计算组内均值 \(\mu_k\) 和标准差 \(\sigma_k\)，然后 \(A_i = (r_i^{\text{HPS}}-\mu_{\text{HPS}})/\sigma_{\text{HPS}} + (r_i^{\text{CLIP}}-\mu_{\text{CLIP}})/\sigma_{\text{CLIP}}\)。这样即使 HPS 分数在 0.2–0.4 而 CLIP 分数在 0.3–0.5，两者也能公平组合。

小结直觉：DanceGRPO 通过 SDE 把两种生成范式变成可探索的轨迹 MDP；通过 GRPO 的组内优势消除不同 prompt 和不同奖励模型之间的尺度差异；通过 clip 和共享噪声抑制 reward hacking 与更新不稳定。

## 6. 训练到底怎么跑

论文没有给出每一个硬件上的绝对训练时间，但给出了超参数和训练循环。默认训练中，如果不用 CFG，一轮迭代大致如下：

1. 从 prompt 数据集采样一个 batch，数量为 32 个 prompt（Table 6）。
2. 把当前策略 \(\theta\) 复制给旧策略 \(\pi_{\text{old}}\)。
3. 对每个 prompt \(c\)，从标准高斯分布采样一个初始噪声 \(z_T\)；这个噪声在同一 prompt 的 12 个样本之间共享（Table 6、§2.2）。每个样本用这个相同的 \(z_T\) 执行独立的 SDE 轨迹；即使初始噪声相同，由于 SDE 中的随机项 \(\epsilon_t dw\)，不同样本仍会有一定差异。
4. 用 \(\pi_{\text{old}}\) 执行 SDE 采样。Stable Diffusion 使用 50 步，FLUX 和 HunyuanVideo 使用 25 步（Appendix A 表格后说明）。训练时 \(\epsilon_t=0.3\)，因此采样中有显式随机探索。
5. 对每个样本用所有奖励模型打分。文生图通常用 HPS-v2.1 和 CLIP Score；文生视频用 VideoAlign 的视觉质量 VQ 和运动质量 MQ；图生视频用 VideoAlign 的 MQ（§3.1、§3.3、§3.4）。论文还试验了 Videoscore 和 VisionReward-Video，但前者奖励分布不稳定，后者 29 个维度语义一致但单维不准确，最终采用 VideoAlign 并增加每秒采样帧数来提高稳定性（§3.3）。
6. 对每个奖励维度 \(k\)，在 12 个样本内计算均值 \(\mu_k\) 和标准差 \(\sigma_k\)，得到标准化后的优势并求和。这是 Algorithm 1 当中“multi-reward advantage”的步骤。
7. 从 \(T\) 个时间步中随机抽取 \(\lceil \tau T \rceil\) 个子集。默认 \(\tau=0.6\)，也就是训练 60% 的时间步，相当于随机丢弃 40% 的时间步（Table 6、§3.6）。对所有被采样子集中的时间步计算 GRPO 目标；即使某时间步不在子集中，策略轨迹仍由完整 SDE 采样得到，只是不贡献本次梯度。
8. 对选中的时间步计算 GRPO 目标，对 \(\theta\) 做梯度上升。默认每个 iteration 做 4 次梯度更新（Table 6）。这 4 次更新共享同一批旧策略采样出的数据和优势，但每次更新后 \(\theta\) 改变，下一次更新使用新的 \(\pi_\theta\) 与旧的 \(\pi_{\text{old}}\) 计算概率比。
9. 学习率为 1e-5，优化器 AdamW，梯度裁剪范数 1.0，clip range \(\epsilon=1e-4\)（Table 6）。
10. 循环进入下一轮，直到奖励曲线不再明显提升。

如果启用 CFG 训练，情况不同。对 SkyReels-I2V 和 Stable Diffusion，CFG 对生成质量很重要。论文观察到只优化条件目标会导致不稳定，所以需要同时计算条件和无条件输出，VRAM 消耗大约翻倍，并且建议把梯度更新频率降到每次 iteration 1 次（Appendix C）。对于 HunyuanVideo 和 FLUX 这样的高保真模型，论文建议在 RL 采样阶段直接关闭 CFG，减少梯度振荡（Appendix C）。

奖励模型方面，Videoscore 被论文评估为奖励分布不稳定，不适合优化；VisionReward-Video 有 29 个维度，语义上一致，但单个维度不够准确；最终文本到视频采用 VideoAlign，并增加每秒采样帧数来提升训练稳定性。文本到视频的 VideoAlign 中“text-video alignment”维度不稳定，被排除在最终奖励之外（§3.3）。视频训练还采用渐进策略：先文生图，再低分辨率视频，最后高分辨率视频；实际训练视频样本分辨率是 480×480，可视化时可以用更大像素（§3.3）。所有奖励曲线采用移动平均平滑后绘制（§3.1）。

## 7. 推理到底怎么跑

训练完成后，推理流程去掉随机探索和奖励回传，回到标准生成。具体顺序如下：

1. 给定文本 prompt；如果是图像到视频任务，再给参考图像作为条件输入。
2. 从高斯噪声采样初始潜变量 \(z_T\)。
3. 按照对应模型的 ODE 采样器逐步去噪。论文明确说“使用 ODE-based sampler 做评估和可视化”，不再使用训练时的 SDE 随机项（§3.1）。因此推理是确定性的，同一 prompt 和初始噪声产生固定输出。例如，扩散模型使用类似 DDIM 的确定性采样；rectified flow 使用其原生 ODE 采样，沿向量场逐步推进。
4. 去噪结束后得到 \(z_0\)，解码到像素空间，形成图像或视频帧。解码器由各个基础模型自带，DanceGRPO 不改变。
5. 如果使用 CFG，在采样时对条件和无条件去噪输出做引导加权。这是模型原有机制，不是 DanceGRPO 新引入。对 SkyReels-I2V，CFG 在训练和推理中均必要；对 FLUX 和 HunyuanVideo，训练时关闭 CFG 不影响推理阶段使用 CFG（Appendix C）。
6. 用奖励模型或人工评估输出质量。论文在评测时用 HPS-v2.1、CLIP Score、GenEval、Pick-a-Pic、VideoAlign、VisionReward 等指标，并做人类偏好评估（§3.1、§3.5）。文生图测试集为 1,000 个 prompt，用来计算 CLIP 和 Pick-a-Pic；HPS-v2.1 和 GenEval 使用官方 prompt；文生视频和图生视频各另有 1,000 个测试 prompt，用于 VideoAlign 打分（§3.1）。

推理时不需要生成 12 个样本，也不需要组内优势和时间步子采样。这也说明 DanceGRPO 的 RL 成本集中在训练阶段，推理只增加模型权重优化后的行为变化，不会引入额外 RL 计算。

Best-of-N 推理扩展是另一个可选方案。论文在训练时从每个 prompt 的 16 个采样池中选奖励最高 8 个和最低 8 个作为训练样本，试探过池大小 16、64、256，发现能加速训练收敛（Figure 4a、§3.2）。但这不是推理时必需的；推理时如果要做 Best-of-N，可以采样 \(N\) 个候选，用奖励模型选最高分的一个。论文把 Best-of-N 视为可选扩展，因为它会降低采样效率，并明确把 tree search 或 greedy search 留作未来工作（§2.2、§3.6）。

## 8. 实验和消融到底证明了什么

下面表格给出论文中部分关键证据，均来自正文或附录明确引用的图表。

| 证据 | 任务 / 模型 | 指标 | 结果 | 来源 |
|---|---|---|---|---|
| SD v1.4 并用 HPS+CLIP 训练后 | 文生图 / Stable Diffusion v1.4 | HPS-v2.1、CLIP Score、GenEval | HPS 0.239→0.335；CLIP 0.363→0.395；GenEval 0.421→0.522 | Table 2 |
| FLUX 并用 HPS+CLIP 训练后 | 文生图 / FLUX.1-dev | HPS-v2.1、CLIP Score、GenEval | HPS 0.304→0.343；CLIP 0.405→0.427；GenEval 0.659→0.687 | Table 3 |

| HunyuanVideo 用 VideoAlign VQ+MQ 训练 | 文生视频 / HunyuanVideo | VideoAlign 视觉质量 VQ、运动质量 MQ | VQ 4.51→7.03 (+56%)；MQ 1.37→3.85 (+181%) | Table 5、Figure 2 |
| SkyReels-I2V 用 VideoAlign MQ 训练 | 图生视频 / SkyReels-I2V | VideoAlign 运动质量 MQ | MQ 相对提升 118% | §3.4、Figure 2(c) |

这些实验支持论文的核心主张：DanceGRPO 能在不同生成范式、不同任务和不同基础模型上有效提高奖励指标，而且提升幅度在部分指标上很大。例如 HunyuanVideo 的运动质量从 1.37 提升到 3.85，相对提升 181%，是论文“up to 181%”的来源。由于这是相对提升，而不是说所有任务都能有同样幅度，因此解读时要避免过度泛化。

值得注意的是，Table 5 中还给出了文本-视频对齐 TA 从 1.75 降到 1.59，VisionReward 从 0.124 微升到 0.128。这说明 DanceGRPO 并不是在所有评估维度上都单调提升，某些指标会下降或几乎不变。这提示多奖励组合的平衡来自优势函数聚合，而非每个单一奖励都同时被最大化。论文也强调，只用 HPS-v2.1 训练时 HPS 会更高（0.365），加入 CLIP Score 后 HPS 降到 0.335，但 CLIP Score 提升到 0.395，图像更自然（Table 2、Figure 9）。在 FLUX 上也有类似趋势：仅 HPS 训练时 HPS 0.372，但 CLIP 下降到 0.376，GenEval 下降到 0.561；加入 CLIP 后 HPS 略降至 0.343，但 CLIP 升至 0.427，GenEval 升至 0.687（Table 3）。这表明多奖励聚合可以在保持甚至提升综合指标的同时，避免单一奖励导致的质量偏差。

**最关键的消融**：

- **共享初始噪声**：附录 Figure 8 显示，如果同一 prompt 的不同样本使用不同初始噪声，HunyuanVideo 会出现 reward hacking 和训练不稳定；改成共享初始噪声后，模型学到更合理的内容变化。这说明“探索”必须受到约束，否则奖励模型会利用噪声差异制造假阳性。该消融没有给出数值曲线，但从视觉上直接展示了不同初始化噪声导致的伪影（Appendix F）。
- **时间步选择**：Figure 4(b) 比较了只训练前 30% 时间步、随机 30%、最后 40%、随机 60% 和全时间步。前 30% 时间步对基础生成模式很关键，但只训练前 30% 会因缺少后期细化而性能下降。论文最终采用 40% 随机时间步 dropout，即训练 60% 的时间步（§3.6）。具体条件为：(1) first 30% timesteps from noise；(2) randomly sampled 30%；(3) final 40% timesteps before outputs；(4) randomly sampled 60%；(5) sampled 100%。结果显示初始 30% 有 disproportionate contribution，但单独训练此区间不如全序列训练。
- **噪声级别 \(\epsilon_t\)**：Figure 4(c) 显示降低 \(\epsilon_t\) 会导致性能明显退化；\(\epsilon_t\) 大于 0.3 有时会生成带噪点的图像；DDPM 型噪声衰减计划与默认配置没有统计显著差异。这说明随机探索强度必须落在一个较窄范围内。消融使用 FLUX 模型进行，明确显示 \(\epsilon_t\) 的重要性。
- **多奖励组合**：Figure 9 和正文 §2.2 强调，只用 HPS-v2.1 训练会产生不自然的“油腻”风格，加入 CLIP Score 可以保持更自然图像。即使 HPS 分数下降（从 0.365 到 0.335），CLIP Score 和 GenEval 变得更均衡，人眼也更可接受。该消融也体现在 Table 2、3 中。

**尚未证明的主张**：论文把 DanceGRPO 称为“第一个 RL-based unified application framework”覆盖多种任务、模型和奖励，但对比实验主要在 Stable Diffusion 上与 DDPO/ReFL/DPO 进行（Table 4）。对于视频任务，没有给出同一基础模型上 DDPO/DPOK 的直接数值对比，只说明 DDPO 在 rectified flow SDE 中总是发散（Appendix E、Figure 5）。人类评估只呈现艺术家更偏好 RLHF 结果，但没有给出显著性检验或具体偏好率（§3.5、Figure 3b）。二进制奖励只是初步阈值实验，还不能证明在真实规则型视觉奖励下稳定。Best-of-N 的 tree search 或 greedy search 被明确留作未来工作（§2.2）。

## 9. 与前作怎么选

与 DanceGRPO 最接近的方案有三类：

**DDPO / DPOK**。它们也是策略梯度 RL，但 DanceGRPO 指出其在大规模 prompt 集和 rectified flow 上不稳定。适合：小型文生图扩散模型、少量 prompt 上的快速实验、需要黑盒奖励。不适合：数十万 prompt 数据、视频生成、需要稳定训练的生产级设置。DanceGRPO 与 DDPO/DPOK 的关键差异在 Appendix D 中被归纳为四点：使用 GRPO-style 目标函数、在 prompt 级别组内计算优势而不是全局、同一 prompt 样本共享噪声、以及把方法推广到 rectified flow 和视频生成。这些差异正是 DanceGRPO 在 Table 4 中 HPS 0.365 对 DDPO 0.297 的来源之一。附录 E 还显示将 DDPO 目标插入 rectified flow SDE 后总是发散，进一步说明原生 DDPO 不适合 rectified flow。

**ReFL**。它直接通过可微奖励模型回传梯度，更新去噪模型。优点是不需要采样轨迹的策略梯度估计；缺点是视频奖励模型往往不可微，显存占用高，工程量大。适合：有可微奖励、图像任务、对显存不敏感的研究设置。不适合：黑盒奖励、视频生成、大模型或多模型统一优化。论文 Table 1 将 ReFL 标记为不支持视频生成、不扩展大规模 prompt、不适用于 rectified flow，且需要可微奖励；但它在 HPS-v2.1 上比 DDPO 高（0.357 对比 0.297），见 Table 4。

**DPO / Flow-DPO / OnlineVPO**。它们把偏好对数据转成直接优化目标，无需 RL 采样。实现简单、训练成本较低，但论文认为其视觉质量提升只有边缘性（§1）。适合：预算低、只有成对偏好数据、需要快速验证的团队。不适合：奖励模型只有单一样本打分而非成对偏好、期望大幅提升视觉偏好指标的任务。Table 4 中 DPO 在 SD 上 HPS 仅 0.241，CLIP 0.367，均低于 DanceGRPO 的 0.365 和 0.421。

DanceGRPO 适合：同时覆盖扩散和 rectified flow、需要视频生成、有多个黑盒奖励模型、希望用统一框架扩展到超过 10,000 个 prompt。不适合：只是想快速微调一个图像模型且没有足够 GPU；或者奖励模型不可靠、没有合适的多奖励组合，因为 RL 容易把单一奖励的偏见放大（§2.2、§3.3）。

## 10. 工程判断：可行性、风险与上限

**数据规模**：论文说“always use more than 10,000 prompts”来优化模型（§3.1）。测试集另有 1,000 个过滤 prompt。具体 prompt 分布、过滤规则、多样性指标没有完整披露。VidProM 和 ConsisID 被用作来源之一（§3.1），但数据集的污染、与测试集的分布关系未说明。工程上要复现，需要自己构建足够大的 prompt 集，并避免与评测基准重合。

**算力与延迟**：训练资源非常重。Flow-based 文生图模型使用 32 块 H800 GPU，视频生成系统用 64 块 H800，图生视频用 32 块 H800，Stable Diffusion 变体用 8 块（§3.1）。每个 prompt 生成 12 个样本，视频模型采样 25 步，单步成本和显存都很高。CFG 训练会双倍 VRAM（Appendix C）。对于没有多卡高速互连的团队，这不是一个低成本方案。推理侧没有额外 RL 开销，但训练时多奖励模型打分也增加时间。框架基于 FastVideo 实现，需兼容高效视频注意力（§3.1）。

**实现难点**：需要把 SDE 采样正确接入现有生成框架；SDE 还要和 FastVideo 等高效视频注意力方案兼容（§3.1）；不同奖励模型得分尺度和分布差异大，如果标准化计算在 batch 内不稳定，优势函数会失真；CFG 训练切换条件和无条件输出会产生大量显存与梯度缓冲；多奖励模型推理本身也是一笔额外开销。此外，不同任务需要不同奖励模型组合：文生图用 HPS+CLIP，文生视频用 VideoAlign VQ+MQ，图生视频只用 MQ，这要求对不同任务分别验证奖励信号稳定性。

**失败环节与监控信号**：最容易失败的是 reward hacking。信号包括：单一奖励不断上升但图像变得油腻或不自然；视频里出现明显伪影；训练曲线剧烈振荡或直接发散。监控时不能只看 HPS 或 CLIP 的均值，要同时看图像质量、多样性、图文一致性和人类抽检结果。论文明确提到 Videoscore 奖励分布不稳定，VideoAlign 的 text-video alignment 维度不稳定，这些都应作为负面信号提前排除（§3.3）。同时，如果使用不同初始噪声，视频训练会 reward hacking，这也是一个早期失败信号（Appendix F、Figure 8）。所有奖励曲线用移动平均绘制，可辅助观察趋势（§3.1）。此外，只用 HPS 训练会产出油腻图像，需要加入 CLIP 等第二奖励缓解；仅优化条件目标在 CFG 下会导致发散，需要联合条件与无条件输出。

**方法上限与未回答问题**：DanceGRPO 的优化目标受奖励模型能力限制。HPS-v2.1 偏好高分不等于人类高度满意；CLIP Score 也不能捕捉空间关系、文本计数等细节。论文没有证明 DanceGRPO 能让模型获得超越奖励模型蒸馏上限的新能力，也没有回答在更大规模 prompt 集上的泛化边界。多奖励组合里每个奖励的权重来自标准化求和，但没有讨论如何自动选择奖励模型或处理冲突。Best-of-N 的 tree search 被搁置。跨模态生成和更一般的生成式 AI 统一优化也只是未来工作（§5）。理论上，SDE 到 MDP 的转换采用 score 近似，并未证明这种构造下的策略梯度是无偏且收敛的。二进制奖励实验仅以固定阈值处理 HPS/CLIP，尚未推广到真实规则型视觉奖励。

## 11. 放回研究脉络并收束

这项研究位于两条脉络的交汇处：一条是 LLM 的 RLHF，从 PPO 到 DPO 再到 DeepSeek-R1 的 GRPO；另一条是视觉生成模型的对齐，从 ReFL、Diffusion-DPO 到 DDPO/DPOK。视觉生成模型的对齐长期落后于 LLM，原因是采样轨迹长、显存大、奖励模型维度高且不稳定，以及 diffusion 和 rectified flow 的不同数学形式。DanceGRPO 的价值在于把 GRPO 的组内相对归一化思路引入视觉生成，并用 SDE 统一两种生成范式，验证了从图像到视频的扩展可行性。

**读完必须记住的 5 件事**：

1. DanceGRPO 不是新的去噪网络，而是把 GRPO 策略优化套在现有扩散模型和 rectified flow 之上的 RL 对齐框架。
2. 训练时用 SDE 采样制造随机探索，推理时回到 ODE 采样；SDE 噪声 \(\epsilon_t=0.3\) 是重要稳定性参数（Table 6、§3.6）。
3. 同一 prompt 的 \(G\) 个样本必须共享初始噪声，否则视频生成会 reward hacking（Appendix F、Figure 8）。
4. 多奖励模型不能直接相加，要先在各组内标准化优势，再把标准化后的优势求和（§2.2、Algorithm 1）。
5. HunyuanVideo 运动质量相对提升 181% 来自 VideoAlign MQ 指标，不是所有任务统一提升 181%（Table 5）。

**5 道自测题**：

1. 为什么不能直接用 rectified flow 的原生 ODE 做 GRPO 策略探索？
   - 参考答案：ODE 确定性采样使得每个状态只有固定下一个动作，无法形成有概率比意义的随机策略；需要引入 SDE 噪声。

2. DanceGRPO 对同一 prompt 下多个样本的优势怎么计算？
   - 参考答案：用组内奖励减去均值、除以标准差，得到 \(A_i\)；多奖励时对每个奖励维度分别标准化再求和。

3. 只用 HPS-v2.1 训练会出现什么问题？论文怎么缓解？
   - 参考答案：产出偏“油腻”的图像；加入 CLIP Score 作为第二个奖励，并在优势层面组合，可以保持自然度，但 HPS 可能略有下降（Figure 9、Table 2）。

4. 训练阶段和评估/可视化阶段采样方式分别是什么？
   - 参考答案：训练用 SDE，\(\epsilon_t=0.3\)；评估和可视化用 ODE-based sampler（§3.1）。

5. 论文对 DDPO/DPOK 大规模不稳定、rectified flow 不兼容、视频未验证这三个问题的直接证据是否充分？
   - 参考答案：部分充分。正文和附录给出了 DDPO 在小规模 SD 对比以及 DDPO 在 rectified flow SDE 发散的图示，但缺少 DDPO 在同一视频模型上的对照数值（Table 4、Appendix E）。

最终一句话总结：DanceGRPO 用 SDE 统一了扩散模型与 rectified flow 的 RL 探索，用 GRPO 组内优势和多奖励聚合给出了一种更稳定的视觉生成对齐框架，它证明了跨图像与视频任务的可行性，但真正的泛化上限仍受奖励模型质量与大规模训练成本限制。
