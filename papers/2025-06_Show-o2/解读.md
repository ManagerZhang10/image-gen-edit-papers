# 大白话深读《Show-o2》

## 1. 30 秒定位

Show-o2 是一个原生统一多模态模型（native unified multimodal model），目标是用单一模型同时完成多模态理解（看图、看视频回答问题）和多模态生成（文生图、文生视频、图生视频、图文交错生成）。它把自回归建模（autoregressive modeling）和流匹配（flow matching）接在同一个语言模型上：文本 token 走语言头做下一 token 预测，图像/视频潜在表示走流头做速度预测。视觉侧采用 Wan2.1 提出的 3D 因果 VAE（3D causal VAE），对图像做 8 倍空间压缩，对视频额外做 4 倍时间压缩。Show-o2 的关键设计是“双路空间（-时间）融合”：一路语义层从带噪视觉潜在中提取高层语义，一路投影器保留低层细节，两者拼接融合成统一视觉表示，再送入基础语言模型。训练分两阶段：先只训投影器、融合模块和流头，再全模型微调，从而无需海量纯文本语料也能保留语言能力。论文给出 1.5B 和 7B 两个版本，在多个多模态理解、图像/视频生成基准上取得有竞争力的结果，并用 66M 图文对达到接近 Janus-Pro 144M 数据的效果（Table 5、Table 6）。

## 2. 为什么这篇论文会出现

大规模语言模型（LLM）在文本任务上很强，多模态大模型（LMM）也能做视觉问答，视觉生成模型能生成图像和视频。一个自然的问题是：能否用一个模型同时完成理解和生成，而不是分别接 CLIP 做理解、接 VAE 和扩散模型做生成？这引出了统一多模态模型（UMM）。现有 UMM 大体分两条路线：一是用统一视觉表示，同时做理解和生成，如 Chameleon、Transfusion、Show-o；二是解耦表示，理解用 CLIP、生成用 VAE，再通过适配器或可学习 token 把现成模型拼起来，如 NExT-GPT、SEED-X、TokenFlow。Show-o2 把自己归为前者，即“原生统一”，强调输出序列可以直接解码成文本、图像和视频，而不是作为条件送给外部 Stable Diffusion 这类预训练解码器（Table 1、Appendix Table 15）。

已有原生统一模型存在几个问题。第一，视觉表示难以同时服务理解和生成：理解需要高层语义，生成需要保留低层纹理、结构和文本细节，单一路径往往顾此失彼。第二，大多数统一模型主要覆盖文本和图像，对视频的可扩展性不足。第三，训练统一模型通常会破坏 LLM 原有的语言能力，为了避免这一点往往需要网页级高质量文本语料，成本很高。Show-o2 试图用同一个 3D 因果 VAE 空间统一图像和视频，再用双路融合同时保留语义和低层特征；训练上提出两阶段配方，在不使用大规模纯文本语料的情况下尽可能保留 Qwen2.5-Instruct 的语言能力。这三点分别对应论文贡献中的“可扩展视觉表示”“原生统一建模”和“有效训练配方”。论文在 Table 13 明确指出，一阶段全参数联合训练并加入 RefinedWeb 后，1.5B 模型的 GSM8K 从 51.86 掉到 4.55，HumanEval 从 35.37 掉到 3.05，而两阶段训练能把 GSM8K 保持在 49.43、HumanEval 35.54，这为两阶段设计提供了直接动机。

## 3. 读懂前需要的最小概念

**3D 因果 VAE**：一种视频/图像压缩自编码器。Show-o2 使用 Wan2.1 的 3D 因果 VAE，对图像进行 8 倍空间压缩，对视频再额外做 4 倍时间压缩。因果（causal）意味着编码时当前帧不依赖未来帧，适合序列建模。视觉输入被编码为连续潜在变量 x。

**流匹配**：一种生成范式。给定从噪声 x0（标准高斯）到数据 x1 的线性插值 xt = t·x1 + (1−t)·x0，其中 t∈[0,1]，定义速度场 vt = dxt/dt = x1 − x0。网络学习预测速度 vt，推理时从噪声 x0 出发，按学到的速度逐步积分得到生成样本。相比扩散模型预测噪声或分数，流匹配更直接地回归插值轨迹的斜率。

**自回归建模**：对文本 token 逐个预测，用因果注意力保证当前 token 只看之前的 token。Show-o2 的语言头沿用 LLM 的下一 token 预测（next token prediction，NTP）。

**全注意力与因果注意力的混合**：Show-o2 采用 omni-attention，即在整条多模态序列上保持因果注意力，但在一个视觉组内部使用全注意力。这样文本生成仍自回归，而图像/视频内部 token 可以互相看到，适合生成任务。

**SigLIP 蒸馏**：Semantic layers S(·) 复用 SigLIP 视觉 Transformer 块并换上新的 2×2 patch embedding，通过最小化与原始 SigLIP 特征之间的负对数余弦相似度来蒸馏，使 S(·) 能从干净和带噪视觉潜在中提取类似 SigLIP 的语义特征。论文 §4.1 给出了蒸馏的具体设置：从 SigLIP-so400m-patch14-384 加载权重，输入 432×432 分辨率得到 729 个 patch，蒸馏 200K 迭代，batch size 512，余弦学习率峰值 2e-5，最后 20K 迭代以 0.3 概率对潜在加噪。完成后，干净潜在经 S(·) 的特征与原始 SigLIP 特征的平均余弦相似度约 0.9。

## 4. 方法全景：先看数据流

Show-o2 的完整前向数据流可以用下面的 ASCII 图表示：

```
输入：交错文本/图像/视频
        |
        v
+-------+--------+    +------------+
| Text tokenizer |    | 3D Causal  |
| + Embedding    |    | VAE Encoder|
+-------+--------+    +------+-----+
        |                   |
  文本连续嵌入      视觉潜在表示 x_t
        |                   |
        |          +--------v---------+
        |          | 双路提取          |
        |          |  /          \     |
        |          | S(x_t)    P(x_t)  |
        |          | 语义层    投影器  |
        |          +--------+---------+
        |                   |
        |          空间(-时间)融合 STF
        |                   |
        |          统一视觉表示 u
        +-------------------+
                    |
            构造多模态序列
        [BOS] Text [BOI/BOV] u [EOI/EOV] Text ... [EOS]
                    |
                    v
          基础语言模型（冻结/训练）
                    |
        +-----------+-----------+
        |                       |
   语言头 LM Head         流头 Flow Head
   自回归 NTP            流匹配 LFM
        |                       |
        v                       v
 文本 token 序列          预测速度 v_t
        |                       |
  Text de-tokenizer      3D Causal VAE Decoder
        |                       |
        v                       v
      文本输出              图像/视频输出
```

核心组件及其输入、输出、目的和假设如下：

**文本 tokenizer 与嵌入层**：输入文本，输出连续文本嵌入。它复用 Qwen2.5-Instruct 的 tokenizer，文本模态完全走语言模型原有路径。

**3D 因果 VAE 编码器**：输入图像或视频，输出连续视觉潜在 x_t。论文 §4.1 设定输入图像分辨率为 432×432，经过 2×2 patch embedding 后得到 729 = 27×27 个视觉潜在，与 SigLIP 在 384 分辨率下的 patch 特征数量对齐。视频随机采样 2 秒、17 帧、帧间隔 3 帧，分辨率 432×432 或 480p；视频上下文长度设为 7006。该组件冻结，不参与训练。

**语义层 S(·)**：输入视觉潜在 x_t，输出高层语义特征。它由 SigLIP 的 ViT 块加新的 2×2 patch embedding 组成，通过预蒸馏逼近原始 SigLIP 特征。蒸馏损失见公式 2。假设是：即使视觉潜在被加噪，S(·) 也能提取出稳定语义，支撑理解和生成条件。蒸馏完成后 S(·) 固定，不再参与两阶段训练。

**投影器 P(·)**：输入视觉潜在 x_t，输出低层特征。它是一个简单的 2D patch embedding 层，目的是保留视觉潜在中的低层结构、纹理和文本细节，避免语义层过度压缩。在 Stage1 中 P(·) 可训练。

**空间（-时间）融合 STF**：输入 S(x_t) 和 P(x_t)，将它们沿特征维度拼接，再经 RMSNorm 和两层 MLP，输出统一视觉表示 u。公式为 u = STF(S(x_t), P(x_t))。视频时，由于潜在在时间维对齐，融合过程包含时间维的完整帧信息。此外，在 u 前额外加时间步 t 嵌入；对于干净图像，t 设为 1.0。STF 在 Stage1 和 Stage2 均可训练，7B 扩展时需重新初始化并配合 MLP 对齐隐藏维度。

**基础语言模型**：输入多模态序列，输出隐藏状态，分别供语言头和流头使用。1.5B 和 7B 版本均基于 Qwen2.5-Instruct。在 Stage1 中这部分不训练；Stage2 中除 VAE 和已蒸馏的 S(·) 外，全模型训练（§3.2、Table 2）。

**语言头与流头**：语言头做自回归 NTP，对应文本 token 的交叉熵损失；流头由若干带 adaLN-Zero 时间调制和全注意力的 Transformer 层组成（类似 DiT），预测速度 vt。流头与语言头共享同一个基础 LLM 的输出，但参数独立。流头在 Stage1 中预训练，7B 扩展时复用 1.5B 流头并通过 MLP 变换对齐维度。

**序列格式**：[BOS] {Text} [BOI/BOV] {Image/Video} [EOI/EOV] {Text} ... [EOS]。BOI 表示图像开始，BOV 表示视频开始，EOI/EOV 表示结束。推理时，一旦预测出 [BOI]，就在其后追加噪声潜在，由流头逐步生成图像；生成结果再作为上下文继续生成后续内容，支持图文交错生成。训练时对交错序列所有图像以 0.3 概率加噪，否则随机保留前面图像、只对后面的图像加噪（§4.4），以训练条件生成。

## 5. 核心公式与直觉

Show-o2 需要理解的公式主要有四个，分别对应视觉潜在加噪、语义蒸馏、视觉融合和总损失。

**公式 1：流匹配插值轨迹**

\[
x_t = t \cdot x_1 + (1-t) \cdot x_0
\]

其中 \(x_0 \sim \mathcal{N}(0,1)\) 是标准高斯噪声，\(x_1\) 是真实数据潜在（来自 VAE 编码），\(t\in[0,1]\) 是时间步。这个线性插值定义了一个简单轨迹：t=0 时是纯噪声，t=1 时是干净潜在。在这个轨迹上，速度（导数）恒为 \(v_t = x_1 - x_0\)。流头的任务就是输入 \(x_t\) 和时间步 t，预测这个速度向量。工程上，训练时对每个样本随机采样 t，按照公式混合噪声和数据，再喂给流头，用回归损失拟合 \(x_1-x_0\)。相比直接预测 x1 或噪声，速度预测在低噪声区间更稳定，是 rectified flow 的常见选择。

**公式 2：语义层蒸馏损失**

\[
L_{\text{distill}} = -\frac{1}{n} \sum_i \log \text{sim}(S(x_t), \text{SigLIP}(X))
\]

其中 \(X\) 是输入图像，\(\text{SigLIP}(X)\) 是原始 SigLIP 提取的图像 patch 特征，\(\text{sim}(\cdot)\) 是余弦相似度，\(n\) 是特征数量。这个损失鼓励 \(S(x_t)\) 的特征与 SigLIP 特征方向一致，即最大化余弦相似度。直观上，这是让语义层无论输入是干净潜在还是带噪潜在，都能输出接近 SigLIP 的语义空间。论文 §4.1 提到在 66M 图文对上，干净视觉潜在经过 S(·) 的特征与 SigLIP 原始特征的平均余弦相似度约 0.9。蒸馏过程中，前 180K 步基本用干净潜在，最后 20K 步以 0.3 概率应用公式 1 加噪，让语义层逐渐适应带噪输入。

**公式 3：统一视觉表示**

\[
u = \text{STF}(S(x_t), P(x_t))
\]

STF 是空间（-时间）融合机制。具体操作是把 S(x_t) 和 P(x_t) 沿特征维拼接，然后过 RMSNorm 和两层 MLP。直觉是：S 提供强语义，P 保留低层细节；拼接后融合网络可以自适应地组合两者，避免单一特征对理解和生成的偏科。对于视频，拼接和融合在时间维对齐，因此得到的是时空统一表示。

**公式 4：总训练损失**

\[
L = \alpha L_{\text{NTP}} + L_{\text{FM}}
\]

其中 \(L_{\text{NTP}}\) 是语言头的下一 token 预测损失（交叉熵），\(L_{\text{FM}}\) 是流头的流匹配损失。α 在 Stage1 设为 0.2，Stage2 设为 1.0。这样做的直觉是：Stage1 重点是生成能力，所以给文本损失较小权重；Stage2 要平衡理解和生成，权重升为 1。论文没有明确写 \(L_{\text{FM}}\) 的具体函数形式，只写了“predict the defined velocity vt via flow matching”（§3.1），从上下文推断是速度回归损失，但论文未给出显式公式。工程实现时通常采用 MSE 或加权 MSE，这一点论文未明确披露。

## 6. 训练到底怎么跑

Show-o2 采用两阶段训练。先说数据与资源，再讲一轮 step 细节。

**训练前准备**：语义层 S(·) 先进行预蒸馏。从 SigLIP-so400m-patch14-384 加载权重，换上新的 2×2 patch embedding，输入图像分辨率 432×432 得到 729 个 patch。蒸馏 200K 迭代，batch size 512，余弦学习率峰值 2e-5。最后 20K 迭代以 0.3 概率对视觉潜在加噪。蒸馏完成后，S(·) 被固定，不再参与后续两阶段训练。论文 §4.1 指出，干净潜在经 S(·) 的特征与原始 SigLIP 特征的平均余弦相似度约 0.9。

**Stage1：冻结基础 LLM，只训投影器、STF 和流头**。可训练组件和数据见 Table 2：Stage1 训练 Projector、Spatial(-Temporal) Fusion、Flow Head；数据集包括约 66M 图文对、WebVid、Pandas 视频字幕和 OmniCorpus 交错数据。1.5B 模型先在 66M 图文对上训练 150K 迭代，上下文长度 1024，分辨率 432×432；多模态理解和生成的总 batch size 分别为 128 和 384，AdamW 优化器，恒定学习率 1e-4，α=0.2。视觉生成数据以 0.1 概率丢弃字幕，用于分类器自由引导（CFG）。这段用 64 H100 约 1.5 天。随后替换为从 66M 中过滤出的 16M 高质量生成数据，继续训练 40K 迭代。需要视频和交错生成能力时，在 Stage1 逐步加入视频-文本和交错数据；视频上下文长度设为 7006。视频采样 2 秒、17 帧、帧间隔 3 帧，分辨率为 432×432 或 480p。Stage1 的一个训练 step 大致是：从图文/视频/交错数据中采样一个 batch；文本 tokenizer 得到嵌入，VAE 编码器得到视觉潜在；对生成样本采样 t 并构造 x_t；P(·) 和 S(·) 分别提取低层和语义特征，STF 融合得到 u；构造序列，基础 LLM 前向；语言头算 NTP，流头算 FM；总损失 L=0.2 NTP + FM 反传，只更新 P、STF、Flow Head。

**Stage2：全模型微调（除 VAE 和预蒸馏好的 S(·) 不更新外，所有可训练参数参与）**。数据是 9M 高质量多模态理解指令（来自 Densefusion-1M 和 LLaVA-OneVision）、16M 高质量生成数据（从 66M 过滤）以及 1.6M 视频理解数据。1.5B 模型总共训练约 35K 迭代，α=1.0，约 15 小时（论文未披露 GPU 数，但相比 Stage1 时间显著短）。这个阶段学习率等超参未完全披露，只提到跟随 LLaVA-OneVision 的训练策略（§4.1）。视频理解增强是在图像级模型基础上，用 1.6M 视频样本和 1.1M 图像样本进一步微调，采用与 LLaVA-OneVision 相同的视频训练和推理设置。

**7B 扩展**：先基于 1.5B 模型预训练好的流头，加入一个轻量 MLP 变换对齐隐藏维度。新初始化的 STF、投影器和 MLP 先用 3K 步、2K warm-up 进行对齐训练，再联合训练这些新模块和流头；然后按 1.5B 相同方式跑 Stage1 和 Stage2。整个 7B 训练约 2.5 天，使用 128 H100。由于计算成本，7B 模型没有加入交错和视频数据训练（§4.1）。Table 2 显示 7B 模型在 Stage2 的数据量仍为 9M 理解指令、16M 生成数据、1.6M 视频理解数据，但 Stage1 的图像数据同样使用 66M 图文对，视频和交错数据未加入。

**关键监控信号**：Stage1 的生成损失是否下降、文本损失是否稳定；蒸馏平均余弦相似度是否接近 0.9；Stage2 后 GenEval/DPG-Bench 是否提升；文本指标是否不掉太多。论文通过 Table 13 验证两阶段训练保留了 MMLU、GSM8K、HumanEval 等文本 benchmark。在 1.5B 模型上，两阶段训练后 MMLU 56.75、GSM8K 49.43、HumanEval 35.54，接近原始 Qwen2.5-Instruct 的 60.20、51.86、35.37；7B 模型上 MMLU 70.73、GSM8K 75.28、HumanEval 70.73，相比原始 71.75、82.49、65.24 有轻微波动但总体保留。

## 7. 推理到底怎么跑

推理分为理解和生成两类。

**多模态理解推理**：输入图像或视频，先由 3D 因果 VAE 编码为潜在；因为 t=1.0，得到干净潜在后生成时间步嵌入。S(·) 和 P(·) 提取特征，STF 融合为 u。文本嵌入和 u 按序列格式拼接，过基础语言模型，语言头依次自回归生成文本 token。视觉部分内部使用全注意力，文本部分遵循因果注意力。视频理解时，潜在在时间维对齐，融合时考虑完整帧信息；1.5B 视频模型最多 32 帧训练和推理，7B 视频模型训练时 16 帧、推理时 32 帧（Table 4）。理解任务不需要流头。另外，Table 14 显示理解推理可以使用 AnyRes 策略增加图像 token 数：默认 729 token 增加到 5×729 后，ChartQA 从 48.00 提升到 66.92，DocVQA 从 59.34 提升到 77.26，InfoVQA 从 42.31 提升到 45.80，TextVQA 从 62.92 提升到 71.54。

**视觉生成推理**：以文本为条件，给定文本提示，tokenizer 得到嵌入，构造含 [BOI] 或 [BOV] 的序列。基础 LLM 在 [BOI] 后需要填充视觉潜在。具体做法论文描述为：一旦检测到 [BOI] token，就在序列后追加噪声，流头逐步生成图像（§4.4）。由于流匹配是连续过程，需要多步积分；论文 Table 11 显示推理步数 25、50、100 的结果，默认可能用 50 步（论文未明确默认值，但表 11 比较了 25/50/100，CFG 7.5 时 50 步 GenEval 0.71、100 步 0.73，25 步 0.71）。同时使用分类器自由引导（classifier-free guidance，CFG），训练时以 0.1 概率丢字幕；推理时 CFG 尺度建议在 5.0-7.5，更高收益有限。Table 11 显示 1.5B 模型在 CFG 2.5 时 GenEval 0.65、DPG-Bench 81.6；CFG 5.0 时 0.71、83.9；CFG 7.5 时 0.71、84.8；CFG 10 时 0.71、85.0。生成视频时，输入文本或图像，由 VAE 解码器将预测的潜在解码为视频帧。

**混合模态生成推理**：给定交错图文序列，模型自回归生成文本，当需要图像时输出 [BOI]，随后用流头从噪声逐步生成图像潜在，经 VAE 解码得到图像，该图像和文本再一起作为上下文继续生成下文。训练时对交错序列中的所有图像以 0.3 概率加噪，否则保留前面的图像、只对后面的图像加噪，迫使模型学会在给定历史图文上下文中继续生成（§4.4）。推理时生成的图像必须被重新编码为潜在，作为后续生成的上下文。Fig. 2 展示了视觉故事讲述（visual storytelling）任务中模型能生成连贯的文本和图像，例如“cemetery”“mountains”等场景的交替叙述。

**潜在解码**：流头输出的视觉潜在由冻结的 3D 因果 VAE 解码器还原为图像或视频。文本 token 由 text de-tokenizer 转回文本。整个推理流水线不依赖任何外部 Stable Diffusion 或 CLIP 解码器。

**最关键消融**：Table 12 显示 Stage2 的重要性。只看 Stage1 时，1.5B 模型在 GenEval 上为 0.63、DPG-Bench 83.28；加上 Stage2 后，提升到 0.73 和 84.70。这说明仅靠大规模图文对训练生成流头不够，少量高质量理解/生成混合数据能显著提升生成质量和指令跟随。另一个关键消融是 Table 10，空间融合对 MME-p（1164.7→1187.8）、GQA（56.2→57.6）和 FID-5K（21.8→20.5）都有提升，但幅度有限；POPE 持平。该表使用 LLaMA-3.2-1B 和 1M 理解数据 + ImageNet-1K 生成数据，属于小规模试点，不能直接外推到最终模型，但验证了融合机制方向有效。

Table 11 的消融进一步显示，CFG 尺度从 2.5 增至 5.0 时 GenEval 从 0.65 增至 0.71，DPG-Bench 从 81.6 增至 83.9；CFG 大于 5.0 后 GenEval 不再显著提升，但 DPG-Bench 仍从 83.9 增至 85.0。推理步数从 25 增至 100 时，GenEval 在 CFG 7.5 下从 0.71 提升到 0.73，DPG-Bench 从 84.6 提升到 84.7，收益有限。这说明默认 CFG 约 5.0-7.5、推理步数约 50 是成本与质量之间的合理选择。

Table 14 还表明，尽管模型训练时固定 432×432 分辨率，但在推理时通过 AnyRes 把图像 token 数从 729 增加到 5×729，可以大幅提升 ChartQA、DocVQA、InfoVQA、TextVQA，但也暴露了图表理解短板：默认 token 下 ChartQA 48.00，远低于 LLaVA-OV-7B 的 56.24；论文将原因归结为语义层蒸馏时图表相关数据有限，限制了图表信息捕捉。

**尚未证明的主张**：论文声称 Show-o2 “state-of-the-art” 在多模态理解和生成基准上，但并非所有指标都领先。例如在 GenEval 上 7B 的 Overall 0.76 低于 Janus-Pro 7B 的 0.80，也低于 Mogao 和 BAGEL；在 OneIG-Bench 上 1.5B 和 7B 的 Text 指标仅为 0.002，远低于 OmniGen2 的 0.680，说明文本渲染仍然是短板（论文自身也承认，§5 Limitations）。视频理解上，Show-o2 7B 在多数基准上打不过开源理解专用模型 LLaVA-OV-7B（如 NExT-QA 79.0 vs 72.1，PerceptionTest 61.9 vs 57.1），更不用说闭源模型。因此“state-of-the-art” 应理解为整体均衡、同时具备理解和生成的原生统一模型中具有竞争力，而不是全面碾压所有任务。论文对大一统模型的训练 scaling 上限也没有给出更大规模或更多数据的实验支持。

## 9. 与前作怎么选

**Show-o vs Show-o2**：Show-o 是前作，同样用统一 Transformer 做理解和生成，但 Show-o2 的改进在于三点：一是视觉表示从单一路径变为双路融合，二是 VAE 从 2D 换成 3D causal VAE 以支持视频，三是训练从一阶段改为两阶段以保护语言能力。如果只做 256/512 图像级别的研究，Show-o 足够；但如果需要视频、更好的语义保真、更低的语言退化，选择 Show-o2。

**Janus-Pro vs Show-o2**：Janus-Pro 用解耦表示，理解走 SigLIP、生成走 VAE，训练数据规模和生成性能更强（GenEval 7B 0.80 vs Show-o2 0.76，DPG 84.19 vs 86.14，两者各有所长）。但 Janus-Pro 理解与生成使用不同视觉路径，不是原生统一表示；Show-o2 在少 2 倍数据下达到接近效果，说明表示融合有效。如果重点在图像生成和文本渲染，Janus-Pro 可能更稳；如果研究目标是原生统一表示和视频扩展，Show-o2 更合适。

**Transfusion vs Show-o2**：Transfusion 也是 AR+Diffusion 混合，但 Show-o2 用流匹配而非扩散损失，并额外做了双路视觉融合和两阶段训练。Transfusion 的 GenEval 只有 0.63，明显低于 Show-o2，但 Transfusion 的模型规模和训练细节不同，不宜直接归因。若关注单一 LLM 内同时做下一 token 预测和连续生成，Show-o2 是更近期、更完整的参考实现。

**TokenFlow / 组装类模型 vs Show-o2**：组装类模型如 TokenFlow、NExT-GPT 用两个模型或适配器，灵活且易于替换组件，但需要维护多个模型和推理管线。Show-o2 的优势是端到端一个模型、一次前向即可切换任务，概念上更简洁，适合部署在对管线复杂度敏感的场景。如果已有的 LMM 和扩散模型非常强，且希望快速验证交错生成，组装类可能更快；Show-o2 更适合原生统一研究。

**选择建议**：做原生统一多模态研究，尤其是想把图像/视频统一进一个 VAE 空间并保留语言能力，选 Show-o2；如果只要图像生成且数据很多，Janus-Pro 或专用扩散模型可能表现更好；如果只需要理解，专用 LMM 如 LLaVA-OV 仍是最优。

## 10. 工程判断：可行性、风险与上限

**数据**：论文表露 66M 图文对来自 CC12M、COYO、LAION-Aesthetic-12M 和 AI 合成数据，分辨率至少 512，用 LMM 重写字幕（合成数据除外）。9M 理解指令来自 Densefusion-1M 和 LLaVA-OneVision。视频数据使用 WebVid、Pandas、OpenVid-1M 等。没有公开数据清洗比例、去重规则和版权筛查细节，只在 §5 提到数据包含名人和版权材料，存在知识产权风险。复现时需要自行整合这些来源，且 LMM 重写字幕本身消耗大量推理算力。视频生成数据仅训练在 2 秒 17 帧的小片段上，分辨率 432×432 或 480p，长视频和复杂运动的上限未验证。

**算力/延迟**：1.5B 模型 Stage1 150K+40K 需要 64 H100 约 1.5 天；Stage2 约 15 小时。7B 全程约 2.5 天，128 H100。推理时流匹配需要多步积分，CFG 尺度 5.0-7.5，步数 50 左右，生成成本大约是普通 VAE 解码的 50 倍以上。视频生成上下文长 7006，潜在维度大，显存需求高。论文没有提供 7B 的推理延迟、吞吐或显存占用曲线，工程落地前必须做 profiling。7B 模型没有加入交错和视频数据训练，因此其视频生成和交错生成能力主要继承自 1.5B 流头的迁移，未在 7B 上验证视频相关能力。

**实现难点**：一是 3D causal VAE 的使用和 patch embedding 对齐，要求输入 432×432 产生 729 个潜在，不同分辨率需要 bicubic 插值位置编码。二是语义蒸馏需要同时处理干净和带噪潜在，最后 20K 步加噪概率 0.3，这个节奏对生成稳定性很敏感。三是流头与语言模型隐藏维度对齐，7B 复用 1.5B 流头时需要 MLP 变换，显式对齐步骤 3K 步不可跳过。四是交错生成中噪声调度与序列因果关系的耦合：训练以 0.3 概率对所有图像加噪，否则只加后面的，实现细节需要精确匹配。

**失败环节**：语义蒸馏若余弦相似度无法收敛到 0.9 附近，理解指标可能整体下滑；Stage1 冻结 LLM 训练流头时，如果生成损失震荡，后续 Stage2 难以挽救；Stage2 混合数据比例不当可能再次损害语言能力；视频训练时，若时间压缩或帧采样不匹配，生成会出现闪烁或主体不一致；文本渲染在 66M 数据中比例低，生成的文字几乎不可用（OneIG Text 得分 0.002 在 1.5B/7B 模型上得到印证）。论文在 §5 还指出小物体细节受限于分辨率，后续通过加入 TextAtlas 子集和 512/1024 高分辨率数据改善，但正文实验主要基于 432×432 模型，高分辨率版本只出现在 Table 7 的 Show-o2-1024×1024 一行（Text 指标提升到 0.125）。

**监控信号**：训练中应监控语义层平均余弦相似度、NTP 和 FM 损失的分项收敛、生成 CFG 不同尺度下的 FID/GenEval、Stage2 后 MMLU/GSM8K 是否明显下降、视频的 VBench 主体一致性和时序连续性。推理侧需要监控流匹配步数对质量的边际收益，如表 11 中 GenEval 从 0.71 到 0.73 增益有限，可据此裁剪步数。

**指标上限与未回答问题**：该架构在原生统一模型里上限受限于 VAE 压缩质量和流匹配步数，文本渲染能力很难仅靠当前数据改善；理解能力受限于 SigLIP 蒸馏的语义空间，对图表、文档等需要 OCR 的任务存在短板（Table 14 ChartQA 48.0 vs LLaVA-OV 56.24）。论文没有回答：更大 LLM 底座（如 32B）是否能继续保留语言能力；视频生成扩展到长视频时时空一致性能否保持；更强语义编码器（如 SigLIP2、InternViT）会带来多少提升；交错生成中更长序列是否会出现文本/图像遗忘。附录 Table 15 列出了大量统一模型，但并未给出它们之间的系统性对比或 scaling 曲线，所以这类问题仍需要后续工作验证。

## 11. 放回研究脉络并收束

Show-o2 处在“统一多模态模型”的研究脉络中。它沿袭了 Show-o、Transfusion 的原生统一路线，同时吸收了 Janus 系列的解耦思想——但把它压缩到单个视觉表示内部：用语义层仿照 CLIP 编码思路，用投影器保留 VAE 细节，再空间融合。与 Emu3、VILA-U 等纯自回归路线不同，Show-o2 明确采用流匹配处理连续视觉潜在，避免了离散 token 的信息损失。与 TokenFlow、NExT-GPT 等组装式方案不同，它坚持单个 LLM 内同时完成理解和生成，这使它的训练和推理管线更简洁，但也更依赖精心设计的视觉表示和训练配方。

从证据看，Show-o2 的核心贡献是“如何在一个 3D VAE 空间内，让语义与细节共存，并用两阶段训练在不破坏 LLM 的前提下学会生成”。它的实验结果证明：只用 66M 图文对，图像生成就能接近 144M 数据的 Janus-Pro；且文本能力几乎没有退化。这是对原生统一模型可行性的一次有效论证。但论文也暴露了上限：文本渲染弱、图表理解不足、视频生成离专用模型仍有差距。

**读完必须记住的 5 件事**：

1. Show-o2 用 3D causal VAE 统一图像和视频，视觉潜在经过双路语义/低层提取与空间（-时间）融合后送入基础 LLM。
2. 文本走语言头做自回归 NTP，视觉走流头做流匹配速度预测，损失为 \(L=\alpha L_{\text{NTP}}+L_{\text{FM}}\)。
3. 两阶段训练是保护语言知识的关键：Stage1 只训投影器、STF 和流头，Stage2 全模型微调；一阶段联合训练会让 MMLU/GSM8K 大幅下降。
4. 1.5B/7B 模型在 GenEval、DPG-Bench、VBench 等基准上与更大的统一模型有竞争力，且只用 66M 图文对；但文本渲染和图表 VQA 是弱项。
5. 推理生成需多步流匹配加 CFG，CFG 约 5.0-7.5、步数 50 左右，收益在更高尺度/步数上趋于饱和。

**5 道自测题**：

1. Show-o2 的 3D causal VAE 对图像和视频分别做了多少倍空间/时间压缩？输入 432×432 图像得到多少个视觉潜在？
2. 双路空间融合中，S(·) 和 P(·) 分别负责什么？它们各自的输入是什么？
3. 公式 \(L=\alpha L_{\text{NTP}}+L_{\text{FM}}\) 中，α 在 Stage1 和 Stage2 分别取多少？为什么 Stage1 用较小 α？
4. 请描述一个 Stage1 训练 step 的数据流，并指出哪些参数被更新。
5. 论文 Table 13 对比了一阶段训练和两阶段训练的语言能力，一阶段训练为何会导致 GSM8K 从 51.86 掉到 4.55？

最终一句话总结：Show-o2 通过“3D 因果 VAE + 双路特征融合 + 流匹配 + 两阶段训练”，在保留 LLM 语言知识的前提下，实现了图像、视频和交错图文的原生统一理解与生成，为后续扩展视觉编码和长视频生成提供了可复用的架构基线。
