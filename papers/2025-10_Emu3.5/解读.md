# 大白话深读《Emu3.5》

## 1. 30 秒定位

Emu3.5 是北京智源人工智能研究院（BAAI）提出的大规模多模态世界模型，核心是用统一的“下一个 token 预测”（Next-Token Prediction, NTP）目标同时学习视觉和语言。它进行了两个阶段预训练：第一阶段约 10T token，第二阶段约 3T token，总计超过 13 万亿个多模态 token，主要来自互联网视频的顺序关键帧和自动语音识别（ASR）转录文本（§3.1, §3.2）。模型有 34.1B 参数，其中 Transformer 层 31.2B、嵌入层 2.9B，上下文长度 32,768，视觉词汇表 131,072，文本词汇表 151,854（Table 1）。后训练包括约 150B token 的监督微调（SFT）和大规模混合任务强化学习（RL），并提出离散扩散适配（Discrete Diffusion Adaptation, DiDA），把逐 token 自回归解码改成图像内并行离散扩散，每张图像推理加速约 20 倍，DiDA 生成 4,096 个视觉 token 只需 10 秒（Table 16）。论文显示，Emu3.5 在图像生成和编辑基准上与 Gemini 2.5 Flash Image 相当甚至部分超越，在视觉叙事、视觉引导、世界探索和具身操作四类交错生成任务上自动胜率更高，其中世界探索胜率 65.5%、具身操作胜率 67.1%（Table 14）。模型与训练流水线开源，代码在 github.com/baaivision/Emu3.5。

## 2. 为什么这篇论文会出现

论文认为，仅靠文本训练的语言模型只看到了世界的狭窄切片。人类的知识大量来自视觉和环境交互，尤其是长视频里交织的语言、因果和时序一致性。但此前多模态模型大多用短时、独立的图像-文本对训练，难以捕捉长时程的时空连续性和跨模态对齐。Emu 系列早期工作（Emu、Emu2、Emu3）已经证明可以用一个简单生成目标统一多模态任务，但这些工作主要局限于短格式或小规模数据，没有回答三个问题：如何有效学习长视频与文本交织的数据；如何实现通用多模态交互；如何高效预测数万个视觉 token。这三个问题分别对预训练、后训练和推理提出了苛刻要求（§1）。Emu3.5 的出发点就是直接面对这些挑战，构建一个“原生”预测交错视觉-语言下一状态的世界模型。

所谓“世界模型”，在本文中不是显式的物理模拟器，而是能够生成长时程一致观察序列、进行步骤化操作规划和交互式环境探索的生成式模型。论文把这一思路进一步落到视觉叙事、视觉引导、世界探索和具身操作等新任务上。为了支撑长时程学习，数据端需要从互联网视频中提取自然交织的关键帧与 ASR 文本，并配合两阶段过滤和第二阶段额外标注；训练端需要统一 SFT 和 RL 建立多任务接口；推理端需要 DiDA 把自回归图像生成改成并行离散扩散，否则数万视觉 token 的串行解码会使得实时交互不可行。这三个环节共同构成了 Emu3.5 的贡献主线。

## 3. 读懂前需要的最小概念

**原生多模态序列**：把图像离散化成 token 后，直接和文本 token 拼成一个文档式序列，模型用同一个 Transformer 同时处理。与之相对的是“组合式”多模态系统，例如用单独的图像编码器把图像嵌入后喂给语言模型。Emu3.5 的视觉和文本 token 共享同一个词汇表（总大小 282,926，其中视觉 131,072，文本 151,854），模型在同一个嵌入空间中学习。

**视觉 token 化**：图像被下采样 16 倍（f=16），每个离散 token 对应一个 256 维码本向量。码本大小 131,072，视觉 tokenizer 本身有 455M 参数，通过宽度缩放增强对复杂图像结构的表达能力。模型用 IBQ 框架训练视觉 tokenizer，并加入 SigLIP 特征蒸馏，提升离散图像 token 的语义信息（§2.3）。推理时图像从离散 token 重建，可选普通解码器或扩散解码器；扩散解码器可输出 2 倍分辨率，并用 LoRA 蒸馏把 50 步去噪降到 4 步。

**下一个 token 预测（NTP）**：给定前缀序列，模型输出下一个 token 的概率分布，训练用交叉熵损失。这是所有阶段（预训练、SFT、RL）的统一目标。训练时对视觉 token 和文本 token 的损失采用不同权重，防止视觉 token 数量过大压迫文本学习。预训练阶段视觉损失权重 0.5、文本 1.0；SFT 第一阶段视觉权重 1.0，第二阶段降回 0.5，因为第二阶段分辨率提高后视觉 token 更多，需要重新平衡。

**交错生成任务**：输入和输出都包含图像与文本的交替序列。例如视觉叙事（Visual Narrative）是生成连续故事线，每段文字配一张图；视觉引导（Visual Guidance）是生成步骤化教程；世界探索（World Exploration）是用户交互式或自由漫游地生成观察帧和叙述；具身操作（Embodied Manipulation）是把长时程机器人操作分解为子任务指令和关键帧状态。这些任务要求模型同时维护文本逻辑和视觉一致性，是原生多模态序列建模的直接体现。

**离散扩散适配（DiDA）**：把训练好的自回归模型适配为离散扩散模型。训练时给每个图像 token 序列复制一个加噪副本，噪声 token 可以并行双向关注同一图像内的其他噪声 token，但仍因果关注前面干净的文本/图像 token。这样推理时图像 token 不再是逐个生成，而是一次初始化全部噪声 token，再经过若干步离散去噪并行精炼。这使每张图像推理从 4,096 个串行步骤压缩到少量并行步骤，实现约 20 倍加速且质量几乎不变。

**强化学习**：论文使用 GRPO（Group Relative Policy Optimization），一种无需额外价值模型的策略优化算法。多任务多模态奖励被归一化到 [1,10] 后联合优化，避免单一奖励被“黑客”，并促进跨任务迁移。奖励系统由通用组件（CLIP 相似度、VLM 对齐、美学评分）和任务特定组件（OCR 文本保真、人脸身份保持、一致性指标）构成。

## 4. 方法全景：先看数据流

**训练数据流（预训练与后训练）**

```
原始互联网视频（约63M个，平均6.5分钟，约790年连续画面）
  -> PySceneDetect 场景分割
  -> 每个场景较短则取中间帧，否则按 t 秒采样关键帧（平均0.27帧/秒）
  -> 音频用 Whisper-large-v2 + Faster-Whisper 做 ASR
  -> spaCy 按时间停顿和句法规则切分转录文本
  -> 按时间戳交替排列关键帧和文本，形成视频交错序列
  -> 基础过滤：时长/分辨率、谈话头、语言与静音平衡
  -> 高级过滤：DeQA 感知清晰度、DINO/FG-CLIP 冗余、LLM 文本评分
  -> 第一阶段预训练：不额外标注，直接用于 NTP 损失，约10T token
  -> 第二阶段预训练：加入 LLM 语义分割/摘要、Qwen2.5-VL 视觉描述、多模态总结，约3T token
  -> SFT：把任务格式化成“指令+交错上下文 -> 交错输出”，约150B token
  -> RL：用奖励系统对生成结果打分，GRPO 更新策略，混合多任务
  -> DiDA 适配：用 SFT 和自蒸馏数据修改注意力掩码，训练并行离散去噪
```

采集的视频时长分布为：<5 分钟占 62%，5–10 分钟 24%，10–15 分钟 8%，15–30 分钟 4%，>30 分钟 2%（Figure 5）。平均每秒提取 0.27 个关键帧，说明场景分割不是每帧都取，而是显著降低冗余帧。第一阶段预训练的数据采样比例为：文本 0.2、图像-文本对 0.2、视频-文本对 0.05、X2I 数据 0.0、视频交错数据 0.55；第二阶段调整为：文本 0.18、图像-文本对 0.16、视频-文本对 0.08、X2I 数据 0.03、视频交错数据仍 0.55（Table 2）。视频交错数据始终占主导，体现世界模型对长时程时序的依赖。

**推理数据流**

```
用户输入（文本/图像/交错序列）
  -> 文本用 QwenTokenizer 编码，图像离散化为视觉 token
  -> 拼接为统一 token 序列，长度为不超过 32,768
  -> 模型自回归生成文本 token（逐 token）
  -> 遇到图像生成阶段，切换到 DiDA：初始化全部噪声视觉 token，并行去噪若干步
  -> 输出干净视觉 token 序列
  -> 可选：扩散图像解码器（2倍分辨率，4步 LoRA 蒸馏）重建像素
  -> 输出交错文本和图像
```

**核心组件拆解**

1. **统一 Transformer 架构**：输入是离散 token 序列，输出是下一个 token 概率。64 层，隐藏维度 5,120，中间层 25,600，注意力头 Q=64，KV=8（GQA），RMSNorm 前置归一化，QK-Norm，SwiGLU 激活，RoPE 位置编码，dropout 0.1，上下文 32,768。总参数 34.1B，其中嵌入层 2.9B（§2.2, Table 1）。假设：一个 decoder-only 架构能同时学会视觉结构、文本语法和跨模态因果。

2. **视觉 tokenizer**：IBQ 框架，下采样 16，码本 131,072，维度 256，tokenizer 模型规模 455M。训练数据包括通用、美学、文本密集、人脸密集四类。损失包含重构、量化、感知（LPIPS）、对抗（PatchGAN）、熵和 SigLIP 语义蒸馏（§5.1-5.2）。输出是离散 token，能够被解码器重建。假设：更小的下采样倍率和更大的码本可以提高压缩率而不牺牲语义。

3. **预训练数据**：13T token，采样比例：文本 0.2/0.18、图像-文本对 0.2/0.16、视频-文本对 0.05/0.08、X2I 数据 0.0/0.03、视频交错数据 0.55/0.55（Table 2）。视频交错是核心，占半采样权重，提供长时程时序和跨模态对齐。假设：互联网视频天然包含因果链和丰富世界知识，足以替代大量人工标注。

4. **后训练任务定义**：SFT 将多个任务（通用任务、X2I、视觉叙事、视觉引导、世界探索、具身操作）统一为“输入交错序列 -> 输出交错序列”的格式。RL 使用奖励系统（通用美学、CLIP 相似度、VLM 对齐、任务特定 OCR/人脸/一致性等）归一化到 [1,10]，GRPO 更新（§4.2）。假设：多任务统一 RL 可以实现跨任务迁移，例如 T2I 的高保真度转移到视觉叙事。

5. **DiDA 注意力掩码**：训练时，每个图像有一份干净 token 和一份噪声 token。噪声 token 因果关注前面的干净 token，同时双向关注同一图像内其他噪声 token；干净 token 保持因果（§4.3，Figure 9）。假设：这种掩码能让模型学会从噪声并行恢复干净图像，同时不破坏文本生成的因果性。

## 5. 核心公式与直觉

论文没有给出大量显式公式，最核心的训练目标就是加权 NTP 交叉熵损失。对于一条交织序列 \(x=(x_1,\dots,x_T)\)，损失可写作：

\[
\mathcal{L} = -\sum_{i=1}^{T} w_{m(i)}\ \log P_\theta(x_i \mid x_{<i})
\]

其中 \(m(i)\) 表示第 \(i\) 个 token 的模态，\(w_{m(i)}\) 为视觉 token 时取 0.5，文本 token 时取 1.0（§3.2 Table 2 中“Loss weight (visual : text) 0.5 : 1.0”）。这个权重的直觉是：视觉 token 数量远大于文本 token。例如一张 1024×1024 图像在 16 倍下采样时对应约 4,096 个视觉 token，而一段普通文本可能只有几十到几百 token。若等权会淹没文本信号，降权视觉损失可维持模态平衡。在 SFT 第一阶段视觉权重为 1.0，第二阶段又降回 0.5，因为第二阶段分辨率提高、视觉 token 增多，需要重新平衡（§4.1.3）。值得注意的是，预训练的交叉熵损失专门针对所有 token，包括视觉 token 和文本 token，视觉 token 的 loss 权重 0.5 是全局设置，意味着每个视觉 token 的梯度贡献减半。

视觉 tokenizer 训练目标由多个损失项组成，虽然论文未给出统一公式，但明确列出：重构损失、量化损失、LPIPS 感知损失、PatchGAN 对抗损失、熵损失和 SigLIP 语义蒸馏损失（§5.2）。这些损失协同工作：重构和量化保证离散 token 可恢复图像；感知和对抗损失提升视觉保真度；熵损失防止码本使用不均；SigLIP 蒸馏使离散 token 携带更高层语义，从而改善下游交错的语义连贯性。

DiDA 的核心不是新公式，而是对概率图模型的重新组织。原始自回归生成图像时：

\[
P(x^{\text{img}}_1,\dots,x^{\text{img}}_N) = \prod_{j=1}^{N} P(x^{\text{img}}_j \mid x^{\text{img}}_{<j}, \text{context})
\]

这是严格的从左到右因果。DiDA 把生成过程改为离散扩散：先对整张图像的 token 序列加噪成一个完全随机的初始状态，然后经过 \(T\) 步去噪，每一步对整条图像 token 序列同时更新：

\[
x^{t-1} \sim q(x^{t-1} \mid x^t, \text{context}), \quad t=T,\dots,1
\]

其中 \(x^T\) 是纯噪声离散 token，\(x^0\) 是干净图像 token。由于每一步所有 token 同时更新，推理从 \(N\) 次串行变成 \(T\) 次并行，而 \(T \ll N\)，所以有约 20 倍加速。为了训练这个并行去噪过程，注意力掩码变为：噪声 token 看前面干净 token（保持跨模态因果），同时看同图所有噪声 token（允许并行双向）。这种设计让模型学会从上下文和噪声中一次性恢复整图，而不是逐 token 猜测下一像素块。论文没有给出 DiDA 的损失函数或具体步数 \(T\)，但 Table 16 显示 DiDA 在 4,096 token 图像上的推理时间为 10 秒，质量与 AR 基线几乎持平（GenEval 0.86 vs 0.86，DPG-Bench 88.26 vs 87.46，GEdit-Bench 7.59 vs 7.56）。这个“不牺牲性能”的结论是 DiDA 方法的关键实验支撑。

## 6. 训练到底怎么跑

训练分四个阶段，每阶段配置明确。

**Tokenizer 训练**：独立于主模型。训练迭代 500K 次，batch size 256，Adam 优化器 \(\beta_1=0.5,\beta_2=0.9\)，学习率 1e-4，前 15K 步 warmup。损失包括重构、量化、LPIPS 感知、PatchGAN 对抗、熵和 SigLIP 蒸馏（§5.2）。图像语料包含 ImageNet、OpenImage、CC3M、CC12M、电影/游戏/ vlog 等；美学数据来自开源网站；文本密集数据含 TextAtlas5M、PosterCraft、LAION；人脸数据由 RetinaNet 从 Midjourney、COYO-700M、DataComp、JourneyDB 中提取。所有图像过滤掉分辨率低于 512×512 或质量分低于 0.4 的样本，并移除水印（§5.1）。视频语料用于视频解码器训练：Koala、Sekai、Agibot 以及高质量内部 stock 视频，使用 PySceneDetect 分割场景、光流去除运动过小或过大的片段、VTSS 过滤 Koala 数据（§5.1）。

**预训练**：分两个阶段。Stage 1 在 10T token 上训练 700K 步，最大序列长度 32,768，batch size 448，学习率 5e-4，余弦调度，AdamW \(\beta_1=0.9,\beta_2=0.95\)，权重衰减 0.1，梯度裁剪 5.0，warmup 700 步，TP=8，CP=2，图像限制为 1,024 个视觉 token（即最多 512×512）。Stage 2 继续在约 3T token 上训练 240K 步，学习率 1e-5，动态视觉 token 数 1,024-4,096，分辨率范围 [512,512] 到 [1024,1024]，CP 仍为 2，但 Stage 2 数据离线预打包并填充到最大长度（§3.2，Table 2）。Stage 1 数据以视频交错为主，不增加人工标注；Stage 2 加入更多交错标注和更高分辨率。初始化自 Qwen3 模型。第一阶段训练损失平滑下降，9 个验证集（T2I、I2T、视频交错、ISG-Bench、OpenING、MMIE、视觉叙事、视觉引导、世界探索）均稳定下降，说明 OOD 泛化持续改善（Figure 7）。

**监督微调（SFT）**：两阶段。总数据约 150B token（Table 3 各任务 token 数之和：通用 29.7B、X2I 56.2B、视觉叙事 10.1B、视觉引导 22.5B、世界探索 17.5B、具身操作 14.1B）。第一阶段标准分辨率，X2I 768px，视觉引导/叙事/具身操作 512px，世界探索 720px，视觉损失权重 1.0，序列长度 16,384，batch size 1024，学习率 6e-6，TP=8，CP=1，训练 3000 步。第二阶段高分辨率，X2I 1024px，其他交错任务 720px，视觉损失权重 0.5，序列长度 32,768，TP=8，CP=2，训练 3000 步（§4.1.3）。通用任务（T2I、语言、VL）在两个阶段都预打包并填充到最大长度。SFT 数据规模：视觉叙事 430K 样本（中英双语），视觉引导 960K 样本，世界探索 200K 样本，具身操作 973K 样本（其中 920K 来自 OXE、40K 来自 Agi-world Alpha、13K 来自 Songling Aloha），X2I 数据集约 27.35M 样本（预训练数据章节），SFT 的 T2I 约 5M 高质样本，语言 8.9M Infinity-Instruct，VL 约 3.7M LLaV A-OV（§4.1.2）。

**强化学习（RL）**：混合多任务。对每个任务筛选约 10K 高质量 prompt，外加 1K 人类反馈样本；另有 58K X2I 指令和 50K T2I 样本用于 X2I 专项 RL。使用 GRPO，全局 batch size 640，学习率 1e-6，rollout 数 8。采样引擎基于 vLLM 集成进 VeRL。统一多任务 RL 完整过一遍所有 prompt，随后再做一个 X2I/T2I 专项 RL 阶段（§4.2.2-4.2.3）。平均奖励从约 4.5 升到 7.1 以上（Figure 8）。奖励系统的每个信号都被归一化到 [1,10]，以便不同任务的奖励尺度一致，避免单一任务主导梯度。

**DiDA 适配**：在主模型 RL 之后，用“few billions tokens”的自蒸馏数据训练。数据来自 SFT 和模型自身生成。训练时修改注意力掩码，引入噪声图像副本。优化细节未明确披露迭代数、学习率等，但论文说明基于 FlagScale 框架，引入 PyTorch FlexAttention 逐行块掩码，混合并行含 TP、PP、SP、ZeRO-1 DP，并启用激活重计算（§4.3.2）。DiDA 推理部署使用 FlagScale 的混合异步引擎，支持文本和图像相位切换，FP8 量化，在 4 卡上获得至少 50% 吞吐提升。

## 7. 推理到底怎么跑

推理按模态分两套路径，由 FlagScale 的有限状态机（FSM）调度器动态切换。

**输入阶段**：用户提供文本、图像或交错序列。文本用 QwenTokenizer 编码成文本 token；图像用视觉 tokenizer 编码成离散视觉 token，1024×1024 图像约 4,096 个视觉 token。序列拼成一条上下文，长度不超过 32,768。

**文本生成阶段**：模型自回归逐 token 解码文本。每步从词汇表（文本+视觉）采一个 token，只生成文本时可以连续进行。这个阶段保持标准因果注意力。

**图像生成阶段**：当模型决定输出一张图像时，切换为 DiDA。先对该图像的视觉 token 位置全部初始化为噪声离散 token，然后经过 \(T\) 步离散去噪（论文未明确给出 \(T\)，但说明每张 4,096 token 图像总推理时间 10 秒）。在每一步，噪声视觉 token 同时并行更新，模型计算条件分布 \(q(x^{t-1}|x^t,\text{context})\)。上下文包括前面所有干净 token 和当前图像内的噪声 token。经过若干步后得到干净视觉 token。

**图像重建阶段**：干净视觉 token 送入图像解码器。普通解码器直接重建，分辨率等同编码；可选的扩散解码器以这些 token 为条件，生成 2 倍分辨率的像素图像，并通过 LoRA 蒸馏将 50 步降为 4 步（§2.3）。视频生成则使用扩散视频解码器，基于生成的 keyframe token 和可选的帧间文本信息，用 4 通道掩码指示哪些帧的 token 已提供，支持任意数量中间帧（§2.3）。视频解码器初始化自 Wan2.2 5B，先用 720px/480px 1 秒片段预训练约 80K 步，再在 2–5 秒片段上混合训练 80K 步，最后在 1080px 数据上微调（§5.2）。

**速度证据**：Table 16 显示，DiDA 生成 4,096 个视觉 token 的 T2I 推理时间只需 10 秒，约为 AR 基线推理时间的 1/20。GenEval 0.86、DPG-Bench 87.46 与 AR 的 88.26 基本持平，GEdit-Bench 7.56 vs 7.59 略降但不显著。同时 FlagScale 混合推理框架配合 FP8 量化，在 4 卡上相较朴素方案至少 50% 吞吐提升（§4.3.2）。这意味着单张图像的延迟从 AR 模式的数分钟级压缩到 10 秒级，使得交互式视觉生成在工程上可行。

## 8. 实验和消融到底证明了什么

论文实验分为文本到图像（T2I）、任意到图像（X2I）、交错生成（视觉叙事/引导/世界探索/具身操作）、tokenizer 重建和 DiDA 消融。

**实验支持了什么结论**

- **文本渲染强**：LeX-Bench 和 CVTG-2K 上 Emu3.5 超过所有对照，说明视觉 tokenizer 和第二阶段高分辨率训练有效。LeX-Bench Hard 类别的 pned 从 Gemini 的 7.61 降到 4.39，recall 从 0.74 升到 0.87；CVTG-2K 平均 Word Accuracy 0.9123 大幅领先 GPT-Image-1 的 0.8569。TIIF-Bench 上 Emu3.5 平均分最高，OneIG-Bench 英文轨总分 0.564 也第一，中文轨 0.529 排第二，说明英文和中文文本渲染均很强但中文略弱（Table 4, 5, 6）。LongText-Bench 英文 0.976 第一，中文 0.928 第二，落后 Qwen-Image 的 0.946（Table 8），证实中文长文本渲染仍是相对短板。

- **X2I 综合能力突出**：ImgEdit 4.41（最高）、GEdit-Bench 7.59（最高）、OmniContext 8.82（最高），但 ICE-Bench 上 Task 2 Face Reference 0.573、Task 3 Style Reference 0.522、Task 31 Face Swap 0.528 弱于 Gemini 2.5 Flash Image（0.617/0.596/0.595），说明人脸身份、风格参考和换脸仍是短板（Table 13）。ICE-Bench 的 Task 1-31 总体 0.637 仍为最高，说明综合能力占优但局部子任务不足。ImgEdit 的 9 个子任务中，Emu3.5 在 Replace 子任务（4.84）显著强于所有基线，但在 Style 子任务（4.79）略低于 Qwen-Image-Edit-2509 的 4.84，Extract 子任务（3.96）低于 Gemini 2.5 Flash Image 的 3.69？实际上表 10 中 Emu3.5 Extract 为 3.96，高于 Gemini 的 3.69，因此并非弱项。但 Action 子任务 4.57 低于 Qwen-Image-Edit-2509 的 4.71，说明动作类编辑略弱。GEdit-Bench 的 G_SC 8.11 略低于 Qwen-Image-Edit-2509 的 8.15，但 G_O 最高，说明综合质量胜出。这些细粒度结果帮助定位具体缺陷。

- **世界建模任务有优势**：四项交错任务对 Gemini 2.5 Flash Image 的胜率在 49.2% 到 67.1% 之间，其中世界探索和具身操作明显高于 50%，视觉叙事胜率 49.2% 略低于 50%，但输率仅为 40.5%，说明整体可比或占优（Table 14）。视觉引导 51.5% 胜率也略高。这些评估使用 ChatGPT 作为自动裁判，覆盖多重一致性、任务完成、物理规律等维度。具身操作评估集包含 331 个样本（10 张真实拍摄、109 张采样、192 张合成），初始帧由 Gemini 生成以制造 OOD 扰动，Emu3.5 仍能在衣物折叠等任务中识别语义部件并执行到位（§6.6）。世界探索评估包含 8 个维度：路径合理性、空间一致性、全局连贯性、环境丰富度、视觉-文本对齐、图像质量、文本质量、任务完成（§6.5）。

- **DiDA 消融最关键**：Table 16 直接对比同一模型 AR 和 DiDA 推理。T2I 基准 GenEval 和 DPG-Bench 几乎不变（0.86 vs 0.86；88.26 vs 87.46），GEdit-Bench 7.59 vs 7.56，差异很小。这证明离散扩散适配没有牺牲性能，却把 4,096 token 图像推理时间压缩到 10 秒，与扩散模型快速采样相当（§6.8）。同时，Emu3.5 相比 Emu3 用约一半视觉 token（8,100 → 4,096）实现了更高分辨率和更好质量，且模型参数增至 4 倍但同分辨率推理效率可接受。Table 16 还显示 Emu3 的 AR 推理时间约为 260 秒，而 Emu3.5 AR 更慢（论文未给确切秒数，但文本说明 DiDA 加速约 20×），进一步凸显 DiDA 对实用化的必要性。

- **RL 有帮助**：平均奖励从 4.5 升到 7.1，且论文声称多任务 RL 能跨任务迁移，例如 T2I 高保真度迁移到视觉叙事。但这一迁移更多是定性展示，定量证据不足。Figure 8 的奖励曲线平滑上升，说明多任务联合优化没有出现明显互相干扰。

**尚未证明的主张**

论文承认“comprehensive evaluation”不足（§7）。视觉叙事、视觉引导、世界探索和具身操作均使用 ChatGPT 作为自动裁判，缺乏严格的人类评估或多轮一致性测试。此外，“世界模型”是否真正理解物理法则和因果，目前只有定性生成样例，没有系统化的物理一致性或轨迹可执行性验证。DiDA 的离散扩散步数 \(T\)、训练成本和是否对文本生成有潜在影响也未见详细消融。长视频预训练中哪些因素（帧率、ASR 质量、场景分割参数）对下游性能贡献最大，论文也没有做消融实验。RL 的奖励系统虽然设计为多维，但各奖励的权重分配和最终组合方式没有公开，无法判断是否存在偏置。

## 9. 与前作怎么选

**Emu3（前作）**：8B 参数，720×720 需 8,100 个视觉 token，AR 推理慢（Table 16 中约 260 秒量级），生成分辨率和质量都低于 Emu3.5。Emu3.5 用 4 倍参数但一半视觉 token 实现更高分辨率、更强文本渲染和更多交错任务。如果资源受限且只需简单 T2I 或 X2I，Emu3 可能仍可用；但若要世界模型能力、高分辨率、文本密集图像，应选 Emu3.5。Emu3.5 的 GenEval 0.86 相比 Emu3 的 0.66 有显著提升，DPG-Bench 从 80.60 提升到 88.26，显示模型规模和训练数据带来的收益（Table 16）。

**扩散模型（FLUX.1、Qwen-Image、GPT-Image-1 等）**：在单一图像生成和编辑上，扩散模型仍是强基线。Qwen-Image 在 LongText-Bench 中文指标 0.946 高于 Emu3.5 的 0.928，在 GEdit-Bench 的 G_SC 8.15 略高于 Emu3.5 的 8.11，G_PQ 7.86 对 7.70 也略胜。如果任务纯粹是中文长文本渲染或局部图像编辑，且不需要多模态交错长序列生成，扩散模型可能是更成熟、延迟更低的选择。但 Emu3.5 是“第一个自回归模型在推理速度与生成质量上匹敌闭源扩散模型”（§1 声称），并且天然支持多图输入和可交互步骤生成。另外，在英文文本渲染（LeX-Bench、CVTG-2K）和多区域文本生成上，Emu3.5 已经超过 GPT-Image-1 和 Qwen-Image。

**Gemini 2.5 Flash Image（Nano Banana）**：闭源，图像编辑较强，但 Emu3.5 在 X2I 基准多数胜过或打平，且在交错生成任务上世界探索和具身操作显著占优。若需要开源可复现、可微调、可部署，选 Emu3.5；若只调用 API 且不在意长序列交互，Nano Banana 也是可行选择。需要注意，Nano Banana 在 ICE-Bench 的 Face Reference、Style Reference、Face Swap 子任务上强于 Emu3.5，若应用恰好是这些任务，Nano Banana 可能更合适。

**何时不选 Emu3.5**：需要人脸参考生成、风格参考、换脸等特定 X2I 子任务且对质量要求极高时，Emu3.5 目前弱于 Gemini；需要极低延迟且单张图像生成时，扩散模型快速采样可能更稳定；没有足够 GPU 资源（34B 模型训练和推理都需要多卡），不适用。此外，如果任务只有中文长文本渲染，Qwen-Image 的中文指标更高，Emu3.5 不占优。

## 10. 工程判断：可行性、风险与上限

**数据可行性**：预训练需要 13T token，视频数量约 63M，总时长约 790 年。这样的数据收集、ASR、场景分割、过滤和标注流水线极其庞大。论文声称开源模型和数据流水线，但实际复现成本很高。数据来源包括第三方合作伙伴视频，版权和隐私风险未讨论。视频时长分布显示 62% 小于 5 分钟，长视频占比低，但总时长仍巨大。ASR 使用 Whisper-large-v2 + Faster-Whisper，后处理用 spaCy 按时间停顿和句法规则切分，这套流水线需要大量计算。显式过滤包括 DeQA 感知质量、DINO/FG-CLIP 冗余度量和 LLM 文本评分，每一步都依赖外部模型，进一步增加成本。

**算力/延迟**：34.1B 参数训练需 TP=8、CP=2，推理也需多卡。DiDA 将图像生成延迟降到 10 秒/张，但仍比 4 步扩散模型可能更高（论文说“与扩散模型快速采样相当”）。文本生成仍需逐 token，与任何 LLM 相同。若要支持多用户并发，需要 FlagScale 的混合推理引擎和 FP8 量化，否则吞吐不足。SFT 阶段 batch size 1024、序列长度 16K 到 32K，RL 阶段全局 batch 640、rollout 8，这些配置对 GPU 内存要求高，需要大规模分布式训练经验。

**实现难点**：DiDA 训练需要修改注意力掩码为“噪声-干净”混合因果/双向模式，普通框架不支持，需 FlexAttention 逐行块掩码和自定义调度。FlagScale 的 FSM 调度器需要处理文本/图像相位切换，工程复杂度高。扩散解码器用 LoRA 蒸馏到 4 步，需要额外训练稳定性控制。视觉 tokenizer 的熵损失和码本使用监测需在训练中持续调整，防止码本坍塌或利用不均。

**失败环节与监控信号**：训练中监控验证损失（9 个验证集，覆盖 T2I、I2T、视频交错和下游任务）可及时发现模态失衡或发散。RL 阶段监控平均奖励，避免奖励黑客。推理时若 DiDA 掩码实现有误，会导致文本生成质量下降或图像噪声残留，应监控文本困惑度和图像重建指标。视觉 tokenizer 若码本使用不均，会导致熵损失上升和码本利用不足。长视频预训练中，如果 ASR 质量差或场景分割碎片化，可能导致文本-视觉对齐错误，应监控交错序列验证损失。世界探索和具身操作的评估目前依赖 ChatGPT，缺乏可重复的定量指标，因此风险在于模型可能在自动评价上得分高但实际交互表现不佳。

**指标上限与未回答问题**：现有 X2I 基准（ImgEdit、GEdit-Bench、ICE-Bench）已接近或超过部分闭源模型，但指标仍主要由 GPT-4o/4.1 自动评分，可能存在偏好偏差。世界模型能力缺乏标准指标，论文依赖 ChatGPT 胜率，难以连续度量时空一致性和物理因果。Token 压缩率仍为 1024 token/512²，相比连续潜在扩散模型效率低。未回答：DiDA 的离散扩散步数 \(T\) 与生成质量的关系；长视频预训练中哪些因素（帧率、ASR 质量、场景分割）对下游性能贡献最大；RL 对不同任务的迁移机制是否可量化；模型是否能在真实机器人闭环中执行生成的规划。此外，论文未报告训练总 GPU 时数或碳排放，使得资源评估困难。

## 11. 放回研究脉络并收束

Emu3.5 处于多模态基础模型从“专用生成器”向“统一世界模型”演进的关键位置。此前 Emu 系列验证了统一 NTP 目标可以融合多任务，但受限于短时数据和低效推理。Emu3.5 的三个主要贡献正好推进了这三个维度：数据上用约 63M 长视频构造交错语料，模型上扩展到 34B 并引入大规模 RL，推理上用 DiDA 把自回归图像生成改造成并行扩散，从而在自回归框架内逼近扩散模型的延迟。

**读完必须记住的 5 件事**

1. Emu3.5 的训练目标始终是带模态权重的下一个 token 预测：视觉损失权重 0.5，文本权重 1.0，所有阶段统一；SFT 第一阶段视觉权重 1.0，第二阶段降回 0.5 以平衡分辨率提升后更多的视觉 token。
2. 预训练数据核心是视频交错序列：从 63M 视频中按场景分割取关键帧，Whisper 做 ASR，按时间戳拼成“帧-文本-帧-文本”序列，占 55% 的采样权重；第二阶段加入 LLM 语义摘要和 Qwen2.5-VL 视觉描述。
3. DiDA 的关键是注意力掩码改造：噪声图像 token 可双向看同图噪声 token，同时因果看前面干净 token；干净 token 保持因果。这样图像从逐 token 生成变成并行离散扩散，10 秒生成 4,096 token，质量几乎不降。
4. Emu3.5 不仅做图像生成，还支持交错式长序列任务：视觉叙事、视觉引导、世界探索、具身操作，其中后两者的自动胜率对 Nano Banana 分别为 65.5% 和 67.1%。
5. 论文明确承认不足：新任务还缺乏系统化评估，Token 压缩率仍高，某些 X2I 子任务（人脸参考、风格参考、换脸）弱于 Gemini。

**5 道自测题**

1. Emu3.5 预训练的两个阶段在数据、分辨率、视觉 token 数和学习率上有何差异？为什么第二阶段要加入额外标注？
2. 画出 DiDA 训练时的注意力掩码示意图，并解释为什么噪声 token 可以并行更新而干净 token 不行？
3. 若你只有四张 A100，想部署 Emu3.5 做 T2I，用 AR 和 DiDA 的延迟大约差距多少？需要哪些基础设施支持？
4. 论文中哪一张表能说明 DiDA“不牺牲性能”？请说明指标和对照。
5. 在 ICE-Bench 上，Emu3.5 哪些子任务较弱？这对实际应用意味着什么？

最终一句话总结：Emu3.5 通过大规模视频交错预训练、统一多模态 RL 和离散扩散适配，把自回归原生多模态世界模型推进到能与扩散模型在延迟和质量上竞争，同时开辟了长时程视觉-语言生成与交互式世界建模的新方向。
