# 大白话深读《DreamOmni2》

## 1. 30 秒定位

DreamOmni2 是一篇 2025 年 10 月的工作论文，提出两个新任务：**多模态指令编辑**和**多模态指令生成**。传统指令编辑只用文字，难以描述纹理、姿势、风格等抽象属性；传统主体驱动生成只关注具体物体或人物，忽略抽象概念。DreamOmni2 允许用户同时输入文本指令和多张参考图像，让模型从参考图中提取“具体物体”或“抽象属性”（如材质、构图、光照、姿势），并据此编辑源图或生成新图。

方法上，论文提出三阶段数据合成管线（特征混合生成配对数据、训练提取模型、构造编辑/生成数据），并在框架上引入**索引编码（index encoding）**与**位置编码偏移（position encoding shift）**，使 DiT 模型能区分多张输入图像，减少复制粘贴伪影。此外，联合训练视觉语言模型（VLM）与生成/编辑模型，让 VLM 把非结构化用户指令转成模型易理解的标准格式。实验在自定义 DreamOmni2 基准上，用 Gemini、Doubao 和人工评测对比 GPT-4o、Nano Banana 等，DreamOmni2 在编辑和生成任务上均取得最高或接近最高的成功率（Table 2、Table 3）。代码和模型承诺开源。

## 2. 为什么这篇论文会出现

论文开头点出当前统一生成和编辑模型的两大局限：**语言描述不足以表达复杂视觉意图**，以及**参考图像只支持具体物体，不支持抽象属性**。

在指令编辑中，用户说“把包的花纹改成和那条裙子一样”，但裙子花纹很难用文字精确描述。现有方法（InstructP2P、DreamVE 等）只能根据文本修改，无法把参考图中的纹理、材质、姿势等转移到源图。在主体驱动生成中，主流方法如 Dreambooth、IP-Adapter、Omincontrol 和最新的统一模型（如 Flux Kontext、OmniGen2），大多把参考图编码为视觉 token，但训练数据依赖分割或检测模型提取具体对象，难以处理抽象属性（如光照、设计风格）或遮挡物体。

论文把这两类问题合并为一个更通用的范式：**多模态指令编辑与生成**——参考图可以是具体物体，也可以是抽象属性；任务可以是修改源图，也可以是从参考图直接生成新图。这更贴近真实用户需求：用户经常说“把第一个人的姿势改成第二个人的姿势”“生成一张和参考图同样风格的图”，而不是只给文字。

但挑战在于训练数据。现有数据管线无法合成“带参考图像条件”的编辑三元组，也无法合成抽象属性参考。因此论文提出三阶段数据管线：先用特征混合生成具有相同属性或物体的配对图，训练一个“提取模型”来抽取任意概念并生成参考图；再利用提取模型和编辑模型构造编辑数据；最后用提取模型从源图反向生成参考图，构造生成数据。框架上还需要解决多图输入的索引混淆和位置冲突问题，以及复杂自然语言指令的理解问题。论文由此完整定义了任务、数据、模型和基准。

## 3. 读懂前需要的最小概念

**多模态指令编辑/生成**：输入包含文本指令和一张或多张参考图像（reference images）。编辑任务还需一张源图（source image），输出是修改后的目标图（target image）；生成任务不需要源图，从参考图和指令直接合成目标图。核心是让目标图中的某些元素与参考图中的“概念”（物体或属性）一致。

**DiT（Diffusion Transformer）**：用 Transformer 替代 U-Net 的扩散模型主干。输入通常包括噪声潜变量（noise tokens）、文本嵌入（text embeddings）和图像 token（视觉嵌入）。注意力机制在 token 之间计算相关性，模型通过逐步去噪生成图像。

**特征混合（Feature Mixing）**：在注意力层中手动拼接来自不同分支的 query、key、value，迫使两个分支生成的图像共享某些视觉特征。论文用此方法生成具有相同物体或属性的图像对，作为训练提取模型的监督数据。

**提取模型（Extraction Model）**：一个经过训练的生成/编辑模型，输入一张图和一条描述性指令，能从图中“提取”指定概念（如“这个包的材质”）并生成一张仅体现该概念的参考图。它不依赖分割掩码，因此可处理抽象属性和遮挡物体。

**索引编码与位置编码偏移**：DiT 中每张输入图像的 token 需要位置信息。索引编码告诉模型每个 token 属于第几张图（如 Image 1、Image 2）。位置编码偏移则让不同图像的 token 使用不同区段的位置坐标，避免多图 token 在空间上重叠，减少输出中的复制粘贴效应。

**VLM 联合训练**：视觉语言模型（如 Qwen2.5-VL 7B）先理解用户原始指令，输出标准格式的指令或描述，再交给生成/编辑模型执行。目的是弥合真实用户指令的随意性与训练时固定格式之间的差距。

**LoRA**：低秩适配，只训练少量参数来微调大模型。论文在 Flux Kontext 上分别训练编辑 LoRA 和生成 LoRA，保留原模型能力并减少计算开销。

## 4. 方法全景：先看数据流

DreamOmni2 整体分为**数据构造**和**模型框架**两部分。数据构造是三阶段流水线，模型框架是在 Flux Kontext 基础上增加多图编码和 VLM 联合推理。

### 数据流全景（ASCII）

```
阶段1: 创建提取模型的训练数据
  基础T2I模型（双分支特征混合）
  输入: 两条文本提示（描述相同物体/属性）
  输出: 图像对（目标图+源图，共享同一概念）
        │
        ▼
  训练提取模型（微调后的生成/编辑模型）
  输入: 一张图 + 描述概念的关键词
  输出: 一张仅包含该概念的参考图

阶段2: 创建多模态指令编辑数据
  目标图来源: T2I模型生成 或 真实图像数据库
  对目标图选定一个关键词（物体/属性）
        │
        ├──> 提取模型：输入目标图+关键词 → 参考图
        ├──> 编辑模型：输入目标图+关键词的反义/变换指令 → 源图（与目标图在关键词处不同）
        └──> LLM：根据关键词生成编辑指令
  组合成四元组: (源图, 指令, 参考图, 目标图)

阶段3: 创建多模态指令生成数据
  取阶段2中的源图（或目标图）
  用提取模型从源图提取多个关键词 → 生成多张参考图
  结合阶段2已有的参考图
  组合成三元组: (多张参考图, 指令, 目标图)

模型训练与推理:
  VLM（Qwen2.5-VL 7B）理解用户原始指令 → 输出标准格式指令/描述
  DreamOmni2 编辑LoRA / 生成LoRA（基于Flux Kontext）
  输入: 文本指令 + 多张参考图像（+源图，仅编辑任务）
  经过索引编码和位置编码偏移后输入DiT
  输出: 编辑后的目标图或生成的目标图
```

### 核心组件拆解

**阶段1：特征混合双分支生成**
- 输入：两个分支，目标分支有文本 token 和噪声 token；源分支只有噪声 token（无文本）。
- 组件：在 DiT 注意力层中，目标分支的 query 仅来自目标分支，但 key 和 value 拼接了源分支的噪声特征。
- 输出：两张图像，共享同一视觉概念但内容不同。
- 目的：利用基础 T2I 模型生成高质量配对数据，训练提取模型。
- 假设：注意力特征混合能替代分割/检测，隐式地让两图共享抽象属性。

**阶段2：编辑数据构造**
- 输入：目标图（从 T2I 或真实图库选）和选定的关键词。
- 提取模型：生成参考图，体现该关键词的视觉内容。
- 编辑模型（基础指令编辑模型）：将目标图中该关键词的内容改成不同内容，生成源图。
- 输出：四元组（源图、参考图、指令、目标图）。
- 目的：构造“带参考图条件”的编辑训练对。

**阶段3：生成数据构造**
- 输入：阶段2的源图或目标图，以及多个关键词。
- 提取模型：针对每个关键词生成一张参考图。
- 输出：多张参考图 + 指令 + 目标图的三元组。
- 目的：构造多参考图驱动的生成训练对。

**模型框架：索引与位置编码**
- 索引编码：为每个图像的 token 添加可学习的索引嵌入，区分 Image 1、Image 2 等。
- 位置编码偏移：根据前面输入图像占用的 token 数量，对当前图像的位置编码加上偏移量。
- 目的：避免不同图像之间的像素混淆，减少复制粘贴伪影。

**VLM 联合训练**
- VLM 负责把用户指令改写成标准格式：编辑任务输出“用户指令+细化的图像描述”，生成任务输出“细化的图像描述”。
- 生成/编辑模型接收标准格式，执行图像合成。
- 目的：让模型能处理不规则、逻辑复杂的真实指令。

## 5. 核心公式与直觉

论文中只明确给出一个公式，即阶段1的**特征混合注意力**（Equation 1）：

\[
\text{Attn}_{\text{tar}}(Q,K,V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right)V
\]

其中：
- \(Q = [Q^n_{\text{tar}}; Q^t_{\text{tar}}]\)：目标分支的 query 由目标噪声 token \(Q^n_{\text{tar}}\) 和目标文本 token \(Q^t_{\text{tar}}\) 拼接。
- \(K = [K^n_{\text{tar}}; K^t_{\text{tar}}; K^n_{\text{src}}]\)：key 额外拼接了源分支的噪声 token \(K^n_{\text{src}}\)。
- \(V = [V^n_{\text{tar}}; V^t_{\text{tar}}; V^n_{\text{src}}]\)：value 同样拼接源分支噪声 token。
- \(d\) 是注意力头维度，\([;]\) 表示在 token 维度上的拼接。

**直觉**：目标分支的文本 token 通过 query 与 key 计算注意力权重，但 key 和 value 中混入了源分支的噪声特征。这意味着目标分支在生成过程中会“参考”源分支的视觉特征，但又保留自己的 query 和文本引导。因为源分支没有文本，它只能被动提供视觉上下文，而目标分支的文本决定了最终生成内容。于是两张图会共享某些视觉属性（如物体的颜色、纹理、风格），但整体内容不同。这类似于在注意力层做隐式的信息交换，不需要显式拼接两图（如 diptych 方法），从而避免了分辨率减半和边缘混合问题。

**优化动作对应**：训练提取模型时，使用这些共享属性的图像对作为监督；提取模型学会根据指令和输入图，生成一张把指定概念“单独呈现”的参考图。后续阶段依赖该能力来生成参考图，无需分割或检测模型。

论文没有给出索引编码、位置编码偏移或 VLM 联合训练的具体公式，仅用文字描述其设计。因此第 5 节只保留这一个核心公式足够。

## 6. 训练到底怎么跑

DreamOmni2 的训练分两个独立阶段：**VLM 微调**和**生成/编辑模型 LoRA 训练**。两者联合训练指的是推理时 VLM 输出作为生成/编辑模型的输入，并非同时更新参数。

### VLM 微调
- 模型：Qwen2.5-VL 7B。
- 目标：学习将用户原始指令改写成预定义标准输出格式。编辑任务：输出“用户指令 + 细化图像描述”；生成任务：输出“细化图像描述”。
- 学习率：\(1 \times 10^{-5}\)（论文 §3.2）。
- 计算量：约 10 A100 小时（论文 §3.2）。
- 数据：来自本文构造的数据（未明确披露具体条数，但应包含真实和合成样本）。

### 生成/编辑模型 LoRA 训练
- 基座：Flux Kontext（一个统一的生成/编辑模型，本身支持单图上下文）。
- 方法：使用 LoRA 微调，保留 Kontext 原有的指令编辑能力。
- 分别训练两个 LoRA：一个用于**编辑**任务，一个用于**生成**任务。原因：编辑需要保持源图一致性，生成不需要；指令中常不明确用户意图，分开训练让用户自行选择。
- 训练数据：阶段2产生的编辑四元组（源图、指令、参考图、目标图）用于编辑 LoRA；阶段3产生的生成三元组（多参考图、指令、目标图）用于生成 LoRA。
- 学习率：\(5 \times 10^{-6}\)。
- 批次大小：16。
- 计算量：两个 LoRA 合计约 384 A100 小时（论文 §3.2）。
- 输入格式：多张参考图 + 文本指令 +（编辑时）源图。文本指令来自 VLM 输出的标准格式。
- 多图编码：在输入 DiT 前，对所有图像的视觉 token 加上索引编码和位置编码偏移。

### 训练数据分布
- 覆盖具体物体、全局属性（光照、风格、色调）和局部属性（姿势、发型、材质等），见 Figure 3。
- 参考图数量从 1 到 5 张不等（论文 §3.1）。
- 目标图来源混合：T2I 生成图更灵活，真实图更符合自然分布。

### 关键训练细节
- 没有端到端联合优化 VLM 和 DiT；VLM 先训练好，推理时作为前处理模块。
- 编辑和生成 LoRA 是独立的，推理时根据用户选择激活其中一个。

## 7. 推理到底怎么跑

完整推理顺序如下：

1. **用户输入**：一段自然语言指令、一张源图（仅编辑任务）、一张或多张参考图。
2. **VLM 处理**：Qwen2.5-VL 理解用户指令，输出标准格式文本。编辑任务：输出“用户指令 + 细化图像描述”；生成任务：输出“细化图像描述”。
3. **编码输入图像**：将源图（若有）和所有参考图编码为视觉 token。每张图分配一个索引嵌入（如 Image 1、Image 2、Image 3），表示其在指令中的编号。
4. **位置编码偏移**：根据每张图之前的 token 总数，对其位置编码加上相应偏移。例如第一张图的位置编码从 0 开始，第二张图从 \(L_1\) 开始（\(L_1\) 为第一张图的 token 数），依此类推。
5. **拼接 token**：将文本 token（来自 VLM 输出）、噪声 token（生成任务的初始噪声；编辑任务的待去噪潜变量）和所有图像 token 拼接成一个序列，送入 DiT。
6. **扩散/流匹配去噪**：使用训练好的编辑 LoRA 或生成 LoRA 权重，在 Flux Kontext 基座上运行去噪过程，逐步生成目标潜变量。
7. **解码**：将潜变量解码为最终图像。编辑任务输出编辑后的源图（保持源图结构，修改指定属性）；生成任务输出全新合成图。

**关键设计**：
- 编辑和生成 LoRA 在推理时二选一。论文指出用户指令不总是明确意图，因此由用户自行选择模式。
- 当未检测到参考图时（纯文本指令），LoRA 不激活，回退到 Kontext 原有能力。
- VLM 只在推理前执行一次，不参与迭代去噪。

**注意**：论文未说明推理延迟、显存占用或去噪步数等具体数字。这些需根据 Flux Kontext 和 Qwen2.5-VL 的公开信息做工程推断，但论文本身未披露。

## 8. 实验和消融到底证明了什么

论文在自定义 DreamOmni2 基准上评测，包括 205 个编辑测试用例和 114 个生成测试用例（附录 A.1），参考图 1-5 张，覆盖具体物体、全局属性和局部属性。评测使用 Gemini 2.5、Doubao 1.6 两个 VLM 打分，以及专业工程师人工评估。成功率指标（Success Rate）为编辑/生成结果是否符合指令与参考图一致性。

### 关键证据表

| 证据 | 任务 | 对比方法 | 指标与数值（人类评估） | 结论锚点 |
|------|------|----------|------------------------|----------|
| 编辑任务全面领先 | 多模态指令编辑 | GPT-4o, Nano Banana, UNO, DreamO, OmniGen2, Qwen-Image-Edit, Kontext, Qwen-Image-Edit-2509 | DreamOmni2 人工评估：具体物体 0.6098，抽象属性 0.6829；均高于 GPT-4o（0.5610 / 0.5793）和 Nano Banana（0.5366 / 0.3293） | Table 2 |
| 生成任务超越商业模型 | 多模态指令生成 | 同上 | DreamOmni2 人工评估：具体物体 0.6098，抽象属性 0.6829；Nano Banana 为 0.5366 / 0.3293；GPT-4o 为 0.5610 / 0.5793 | Table 3 |
| VLM 联合训练有效性 | 消融：VLM 与生成/编辑模型训练方案 | Scheme 1（基座 Kontext） vs Scheme 2（仅训练 Gen/Edit） vs Scheme 3（仅 VLM） vs Scheme 4（联合） | 编辑抽象属性：Scheme 4 0.6280 vs Scheme 3 0.3415 vs Scheme 2 0.3171；生成具体物体：0.6667 vs 0.5417 vs 0.4583 | Table 4 |
| 索引与位置编码贡献 | 消融：多图编码方案 | Scheme 1（无索引无偏移） vs Scheme 2（无索引有偏移） vs Scheme 3（有索引无偏移） vs Scheme 4（两者皆有） | 编辑具体物体：0.6585 vs 0.2439 / 0.4634 / 0.3415；生成抽象属性：0.6333 vs 0.2222 / 0.5111 / 0.4556 | Table 5 |

### 最关键消融解读

**Table 4 的 VLM 联合训练消融**最值得关注。Scheme 1 是 Kontext 基座，几乎没有多图编辑和抽象属性生成能力（编辑具体物体 0.1220，抽象 0.0122）。Scheme 2 只训练生成/编辑模型，编辑抽象属性提升到 0.3171，说明本文数据确实教会了模型处理多参考图和抽象概念，但生成具体物体只从 0.3750 升到 0.4583，提升有限。Scheme 3 只训练 VLM 并将其输出给 Kontext，生成具体物体达到 0.5417，高于 Scheme 2 的 0.4583，说明 VLM 的指令重写对生成任务帮助很大，但编辑任务几乎没变（0.2439 vs Scheme 2 的 0.3659？注意 Table 4 中 Scheme 3 编辑具体物体为 0.2439，Scheme 2 为 0.3659，反而下降，可能是数据或评测噪声）。Scheme 4 联合训练两者，所有任务都大幅领先，证明 VLM 和生成/编辑模型分别解决了不同问题：VLM 处理复杂指令，LoRA 处理多图条件生成，两者互补。

**Table 5 的索引/位置编码消融**显示：单独使用位置编码偏移（Scheme 2）比单独使用索引编码（Scheme 3）提升更明显，尤其在编辑具体物体上（0.4634 vs 0.3415）。但两者结合（Scheme 4）仍是最优，说明位置偏移解决空间对齐，索引解决语义归属，二者缺一不可。

### 尚未证明的主张

- **泛化到未见领域**：基准全部由真实图像构成，但测试数量较少（编辑 205，生成 114），未报告在更大规模或跨域数据上的稳定性。
- **VLM 与 LoRA 联合训练的具体机制**：论文未给出联合训练时梯度如何传递，或 VLM 输出是否参与反向传播。从描述看更像级联推理而非端到端训练，但“joint training”一词可能误导。
- **评测一致性**：VLM 打分（Gemini、Doubao）与人工评估存在一定偏差（如编辑抽象属性 Doubao 给 DreamOmni2 0.6280，人工 0.6829；GPT-4o 人工 0.5793，Gemini 0.7195），论文承认 VLM 难以检测引用不一致和意外修改。
- **图像质量与多样性**：只报告成功率，未报告 FID、LPIPS 等生成质量指标，也未评估多样性或文字渲染精度。
- **参考图数量影响**：未单独分析参考图数量增加时性能变化。

## 9. 与前作怎么选

**最接近方案**：

1. **Flux Kontext（Batifol et al., 2025）**
   - 单图上下文生成/编辑模型，支持以图生图和指令编辑，但不支持多图输入。
   - 何时选：只有一张参考图，任务为简单替换或风格迁移，且不需要 VLM 重写复杂指令。
   - 何时不选：需要多张参考图组合（如多主体、多属性），或指令口语化、逻辑模糊。

2. **OmniGen2（Wu et al., 2025b）**
   - 多图生成模型，支持具体物体组合，但不支持抽象属性参考，也不支持带源图的编辑任务。
   - 何时选：任务明确是多个具体物体的组合生成，且不需要保持源图一致性。
   - 何时不选：涉及抽象属性（光照、风格、纹理）或多模态编辑。

3. **Qwen-Image-Edit-2509（Wu et al., 2025a）**
   - 多图编辑/生成模型，但论文显示其抽象属性成功率极低（编辑抽象属性人工 0.0427），主要局限于具体物体。
   - 何时选：编辑具体物体且对抽象属性要求不高时可以考虑，但即使具体物体其人类评估也仅 0.2195，远低于 DreamOmni2 的 0.6098。
   - 何时不选：任何涉及抽象属性或多图一致性要求较高的场景。

4. **GPT-4o / Nano Banana（闭源商业模型）**
   - 支持文本+图像输入，但论文评测显示它们常引入意外修改或参考不一致，且人工评估低于 DreamOmni2 的抽象属性部分。
   - 何时选：无法部署开源模型、需要闭源 API、且任务简单时。
   - 何时不选：追求抽象属性精度、需要离线部署或数据隐私敏感时。

**综合建议**：如果任务需要**从参考图中提取抽象属性进行编辑或生成**，当前开源方案中 DreamOmni2 是唯一明确支持此任务的模型。如果只需单图具体物体替换，Kontext 基座已足够，但 DreamOmni2 的编辑 LoRA 在不激活时仍保留 Kontext 能力，因此不存在兼容性问题。部署成本上，DreamOmni2 需要额外加载 Qwen2.5-VL 7B，显存和延迟高于单独使用 Kontext 或 OmniGen2。

## 10. 工程判断：可行性、风险与上限

### 可行性

- **数据**：三阶段管线可自动化生成大规模训练数据，不依赖昂贵的人工标注或分割模型。特征混合利用已有 T2I 模型，理论上成本可控。但论文未披露数据总量、清洗流程和失败率。
- **算力**：VLM 微调约 10 A100 小时，两个 LoRA 训练约 384 A100 小时，总计约 394 A100 小时。对于研究团队可承受，但复现需注意 LoRA 训练批次 16 和学习率 \(5 \times 10^{-6}\) 的调参。
- **实现难点**：索引编码和位置编码偏移需要在 DiT 的输入阶段精确控制 token 顺序和偏移量。如果参考图数量可变，需要动态计算偏移。此外，VLM 与 DiT 的级联推理增加了系统复杂度，需额外处理 VLM 输出解析和异常指令。

### 风险与失败环节

- **VLM 理解偏差**：VLM 重写指令可能丢失关键信息或引入错误描述，导致生成/编辑模型执行错误。
- **提取模型性能**：整个数据管线依赖提取模型的质量。若提取模型无法正确分离概念（如将局部材质误当整体风格），会生成低质量参考图，污染后续训练。
- **多图 token 长度爆炸**：多张图像 token 拼接到序列中，可能超过 DiT 的位置编码范围或显存限制。论文未提及最大参考图数量限制，但附录显示最多 5 张。
- **评估不一致**：VLM 打分与人类评估存在偏差，且论文承认 VLM 难以捕捉“未经同意的修改”或“参考一致性”的细微问题。若只依赖 VLM 评估，可能高估模型性能。
- **任务歧义**：用户指令未明确“编辑”还是“生成”时，模型必须由用户选择模式，这可能导致产品体验不顺畅。

### 监控信号与指标上限

- **监控**：训练阶段应监控 LoRA 损失、参考图重建误差（如 CLIP 相似度）、编辑前后差异；推理阶段可记录 VLM 输出格式正确率、多图索引识别准确率、去噪步数等。
- **指标上限**：论文只报告成功率，没有图像质量、多样性和文字渲染指标。实际应用需补充 CLIP-I/CLIP-T、LPIPS、FID 等。从消融看，编辑抽象属性人工成功率 0.6829 已接近实用上限（人类评委可能对抽象属性存在主观差异），若要进一步提升可能需要更大规模数据或更强的基座模型。论文未报告失败案例的失败模式分布，只能推测为参考图混淆、属性提取错误和指令理解失败。

- 数据管线中的 T2I 模型和编辑模型是否会引入系统性偏差？

## 11. 放回研究脉络并收束

DreamOmni2 站在三条研究脉络的交汇点：指令编辑、主体驱动生成、统一多模态生成模型。指令编辑从 InstructP2P 以来一直靠语言三元组，DreamOmni2 把参考图像引入编辑循环，弥补语言粒度不足。主体驱动生成从 Dreambooth 的微调范式演进到 IP-Adapter 的免微调，再到 OmniGen2 等基于 DiT 的多图生成，DreamOmni2 进一步把参考概念从具体物体扩展到抽象属性。统一模型如 Flux Kontext 已将生成和编辑合入单一骨干，但只支持单图；DreamOmni2 通过轻量 LoRA 和编码方案扩展为多图，同时保留原能力。

### 读完必须记住的 5 件事

1. **任务定义**：多模态指令编辑和生成要求模型根据文本指令和多张参考图，编辑源图或生成新图，参考概念包括具体物体和抽象属性（如材质、姿势、风格、光照）。
2. **数据管线**：三阶段构造——特征混合生成配对数据训练提取模型；提取模型+编辑模型合成编辑四元组；提取模型反向生成参考图合成生成三元组。整个过程不依赖分割/检测。
3. **框架创新**：索引编码告诉模型每个 token 属于第几张图；位置编码偏移避免多图 token 空间重叠，减少复制粘贴伪影。两者结合使 DiT 能处理多图输入。
4. **VLM 联合训练**：Qwen2.5-VL 将非结构化用户指令改写为标准格式，生成/编辑模型只接收标准指令。这是级联推理而非端到端优化，但显著提升复杂指令下的成功率。
5. **实验结论**：在 205 个编辑和 114 个生成测试上，DreamOmni2 的人工评估成功率全面领先开源模型，并超过或接近 GPT-4o、Nano Banana。消融证明联合训练和编码方案均有效。
