# 大白话深读《Flow-GRPO》

## 1. 30 秒定位

Flow-GRPO 是本论文提出的方法，首次把在线策略梯度强化学习（online policy gradient RL）中的 GRPO（Group Relative Policy Optimization，组相对策略优化）引入流匹配（Flow Matching）文生图模型训练。它的核心问题是：流匹配模型本身采用确定性 ODE 采样，而在线 RL 需要随机采样来探索环境，二者存在结构性冲突；同时在线 RL 要反复生成样本计算奖励，若沿用完整去噪步数，数据收集成本极高。论文给出两个关键策略：一是 ODE 到 SDE 的等价转换，在保持边缘分布不变的前提下给采样注入高斯噪声，使流匹配模型能像扩散模型一样进行随机 rollout；二是 Denoising Reduction，训练时只用 10 步去噪采样，推理时仍用原模型默认的 40 步 ODE，从而在不明显牺牲最终质量的情况下把数据收集加速约 4 倍。实验以 SD3.5-M 为基座，GenEval 综合准确率从 0.63 提升到 0.95，超过 GPT-4o 的 0.84；视觉文本渲染准确率从 0.59 提升到 0.92；PickScore 偏好任务也有提升。论文强调加入 KL 正则后，DrawBench 上的图像质量和偏好分数基本保持，reward hacking 很轻微。该工作在 NeurIPS 2025 发表，实验覆盖组合生成、文本渲染和人类偏好对齐三类任务。

## 2. 为什么这篇论文会出现

流匹配模型已经成为图像和视频生成的主流骨干之一，因为它在理论上有良好的连续归一化流基础，并且在使用较少去噪步数时就能取得有竞争力的 FID。但这类模型在组合场景生成上仍存在明显短板，例如物体计数、空间关系、属性绑定和文字渲染等任务容易出错。论文引用 GenEval 与 TextDiffuser 相关工作，说明这是公开的难题：GenEval 基准显示许多模型在 counting、position、attribute binding 维度得分不高；TextDiffuser 等工作揭示文字渲染是 T2I 系统的薄弱环节。与此同时，在线 RL 在 LLM 推理能力上的成功让研究者开始把它迁移到生成模型。早期工作如 DDPO 已经用策略梯度优化扩散模型，但扩散模型的得分匹配天然带随机性，而流匹配模型常用确定性 ODE 采样，没有逐步条件分布的方差。更重要的是，在线 RL 要求策略在相同 prompt 下能产生多条不同轨迹来估计 advantage，并形成有效的探索；确定性采样只有初始噪声带来随机，后续映射是一一对应，这会使训练效率大幅下降。论文在 Section 4 明确指出，确定性动力学下计算 \(p(x_{t-1}|x_t,c)\) 还涉及散度估计，计算昂贵，这也阻碍了直接使用 GRPO。另一个现实问题是采样成本。大模型生成一张图通常要 40 步甚至更多，若每一步训练都要从当前策略采样一批图像，GPU 时间会不可接受。因此需要一种既保留流匹配结构、又能便宜采样的在线 RL 方案。Flow-GRPO 的动机就是把 LLM 中 GRPO 的 group-relative advantage 机制与流匹配的可微生成过程结合，同时用 SDE 转换和降步训练解决确定性与效率两个障碍。论文在 Related Work 中梳理了五类 T2I 对齐方法，指出 Offline DPO 缺少在线探索，而 Online DPO 对超参数敏感；这些都在为 Flow-GRPO 的必要性铺路。

## 3. 读懂前需要的最小概念

**流匹配（Flow Matching / Rectified Flow）**：给定数据样本 \(x_0\) 和噪声 \(x_1\)，用线性插值 \(x_t = (1-t)x_0 + t x_1\) 定义从数据到噪声的路径，\(t\) 从 0 到 1。模型 \(v_\theta(x_t,t)\) 学习真实速度场 \(v = x_1 - x_0\)。采样时用 ODE \(dx_t = v_t dt\) 从噪声回到数据。SD3.5-M 等模型采用这一框架，其特点是可以直接回归速度向量，无需预测噪声或得分。

**马尔可夫决策过程（MDP）**：论文把去噪过程看作 MDP。状态 \(s_t = (c, t, x_t)\)，动作 \(a_t\) 是模型预测的去噪后样本 \(x_{t-1}\)，策略 \(\pi(a_t|s_t) = p_\theta(x_{t-1}|x_t,c)\)，转移是确定性的。奖励只在最终步 \(t=0\) 给出，即 \(r(x_0,c)\)。这种建模使去噪链可以用策略梯度方法优化，但要求条件分布 \(p_\theta(x_{t-1}|x_t,c)\) 可计算。

**GRPO（Group Relative Policy Optimization）**：一种不维护 value 网络的策略梯度方法。对同一 prompt 采样一组 \(G\) 个样本，利用组内奖励的均值与标准差归一化得到 advantage，然后做 clipped policy gradient。相比 PPO 更省显存，因为无需训练价值网络。本文采用 GRPO 作为 RL 优化器，与流匹配采样结合。

**ODE 到 SDE 的等价转换**：给定一个确定性 ODE，可以构造一个具有相同边缘分布 \(p_t(x)\) 的随机微分方程。具体做法是给漂移项加入 \(\sigma_t^2/2 \nabla \log p_t(x)\)，再配一个扩散项 \(\sigma_t dw\)。反向 SDE 则对应减去 \(\sigma_t^2 \nabla \log p_t(x)\)。对 Rectified Flow，分数函数可以用速度场闭式表示，因此不需要额外训练 score 网络。这个转换是 Flow-GRPO 引入随机性的基础，详细推导见 Appendix A。

**KL 正则**：RL 目标中加入 \(-\beta D_{KL}(\pi_\theta \|\pi_{ref})\)，防止策略远离参考模型，从而抑制 reward hacking。本文发现它不等价于 early stopping：加 KL 后训练更慢，但能达到同样的高 reward 同时保持图像质量。对 SDE 离散化后的高斯策略，KL 有闭式解，可由两步速度差直接计算。

## 4. 方法全景：先看数据流

先画出一轮训练 rollout 和优化的数据流。

```
Prompt c
   │
   ▼
初始噪声 x_T ~ N(0, I)   （T=10，训练时）
   │
   ▼
SDE 采样器（从 ODE 等价而来）
   │  d x_t = [vθ(x_t,t) + σ_t²/(2t)(x_t+(1-t)vθ(...))] dt + σ_t dw
   │  Euler-Maruyama 离散化，10 步
   ▼
G 张图像 x0^(1), ..., x0^(G)  （G=24）
   │
   ▼
Reward 函数 r(x0, c)     （GenEval/OCR 规则奖励 或 PickScore 模型奖励）
   │
   ▼
组内归一化 advantage A^i
   │  A^i = (R^i - mean(R)) / std(R)
   ▼
GRPO loss：
   J = E[ (1/G) Σ_i (1/T) Σ_t min(r_i,t A^i, clip(r_i,t,1-ε,1+ε)A^i) - β D_KL ]
   │
   ▼
反向传播，更新 LoRA 参数 θ
```

核心组件拆解如下。

**组件 1：SDE 采样器**。输入：当前策略模型 \(v_\theta\)、初始噪声 \(x_T\)、prompt \(c\)、时间步数 \(T=10\)。输出：一组图像 \(x_0\) 及其反向轨迹。目的：为 RL 探索提供随机性，同时保持与原始 ODE 模型相同的边缘分布。假设：SDE 的漂移项与扩散项构造正确，且分数函数可以从 Rectified Flow 速度场闭式得到。离散化采用 Euler-Maruyama 格式，\(\sigma_t = a \sqrt{\frac{t}{1-t}}\)，超参数 \(a=0.7\)。

**组件 2：Denoising Reduction**。输入：训练时去噪步数 \(T=10\)，而非推理时的 40。输出：较低质量但仍包含有效偏好信号的图像样本。目的：显著降低 wall-clock 时间。假设：GRPO 只依赖组内相对奖励，不需要高质量样本；10 步 SDE 样本虽有伪影，但相对正确/错误仍可区分。论文在 Appendix D 展示 10 步 SDE 采样图像存在颜色漂移和细节模糊，但仍能提供有用的相对奖励信号。

**组件 3：组内 advantage 估计**。输入：同一 prompt 下的 \(G\) 个奖励。输出：归一化后的 advantage \(\hat A^i\)。目的：减少奖励尺度漂移和方差，替代 value 网络。假设：组内奖励分布近似反映样本质量差异，适合标准化。Group size \(G=24\)，论文通过 Figure 5 表明 \(G=12\) 和 \(G=6\) 会导致 advantage 方差过大，训练不稳定甚至崩溃。

**组件 4：GRPO 更新策略**。输入：轨迹样本、advantage、旧策略与当前策略的对数概率比 \(r_{i,t}\)。输出：策略梯度损失。目的：提升高 advantage 样本的概率。假设：clip 操作可以限制更新幅度，KL 惩罚防止偏离参考模型过远。更新只作用于 LoRA 参数，LoRA 的 rank \(r=32\)，\(\alpha=64\)，分辨率 512。

**组件 5：KL 正则项**。输入：当前策略与参考策略的预测速度。输出：闭式 KL 损失。目的：保持生成多样性与图像质量。假设：\(\pi_\theta\) 在 SDE 离散化后的条件分布是各向同性高斯，因此 KL 可由两步速度差的加权平方给出。该假设在 Euler-Maruyama 离散下成立。

这些组件的总体假设是：SDE 采样器是 ODE 的统计等价版本；低步数采样不破坏训练所需的相对偏好信号；KL 正则足以抑制 reward hacking。为验证这些假设，论文做了消融：噪声水平 \(a\)、组大小 \(G\)、去噪步数 \(T\)、有无 KL 以及初始噪声差异均通过实验进行了检验。

## 5. 核心公式与直觉

这里只保留理解贡献必需的 4 个公式。

**公式 1：Rectified Flow 插值路径**

\[
x_t = (1-t)x_0 + t x_1, \quad t\in[0,1]
\]

其中 \(x_0\) 是数据样本，\(x_1\) 是标准高斯噪声。时间 \(t=0\) 对应数据，\(t=1\) 对应纯噪声。训练目标是让模型学会沿这条直线路径的速度场 \(v = x_1 - x_0\)。这个公式的意义在于把生成过程变成一个可微的路径积分，为后续从 ODE 推导 SDE 提供闭式关系。它也是流匹配目标（公式 2）和 SDE 分数函数表达的基础。

**公式 2：Flow Matching 损失**

\[
L(\theta)=\mathbb{E}_{t,x_0,x_1}\|v - v_\theta(x_t,t)\|^2
\]

这是预训练时的目标，直接回归速度向量。Flow-GRPO 不是替代这个损失，而是在预训练模型基础上做在线微调。工程对应：\(v_\theta\) 通常是 Transformer 输出，可以是 latent space 或 pixel space，本文在 SD3.5-M 上训练，具体是 latent 空间，但论文未展开说明架构细节。该公式的意义在于提供速度场与模型输出的直接回归监督，后续 SDE 转换用到的正是这个速度场。

**公式 3：SDE 采样更新（离散形式）**

\[
x_{t+\Delta t}=x_t+\left[v_\theta(x_t,t)+\frac{\sigma_t^2}{2t}(x_t+(1-t)v_\theta(x_t,t))\right]\Delta t+\sigma_t\sqrt{\Delta t}\,\epsilon
\]

其中 \(\epsilon\sim N(0,I)\)，\(\sigma_t=a\sqrt{\frac{t}{1-t}}\)，\(a\) 是噪声水平超参数，默认 0.7。这个式子由 ODE 等价 SDE 推导而来，关键点是把分数函数替换成速度场的表达式：对 Rectified Flow，\(\nabla\log p_t(x) = -\frac{x}{t} - \frac{1-t}{t}v_t(x)\)。代入反向 SDE 得到式 8，然后 Euler-Maruyama 离散化得到式 9。直观上，前两项是原来的确定性流加一个校正项，最后一项是注入的随机噪声。工程上，用 10 步即可，且每一步的条件分布 \(p_\theta(x_{t-1}|x_t,c)\) 是各向同性高斯，因此概率比和 KL 都可以简单计算。

**公式 4：GRPO 目标与 advantage**

\[
\hat{A}_t^i=\frac{R(x_0^i,c)-\text{mean}(\{R(x_0^i,c)\}_{i=1}^G)}{\text{std}(\{R(x_0^i,c)\}_{i=1}^G)}
\]

\[
J_{\text{Flow-GRPO}}(\theta)=\mathbb{E}_{c,\{x^i\}\sim\pi_{\theta_{old}}}\left[\frac1G\sum_{i=1}^G\frac1T\sum_{t=0}^{T-1}\min(r_i^t \hat{A}^i,\text{clip}(r_i^t,1-\varepsilon,1+\varepsilon)\hat{A}^i)-\beta D_{KL}\right]
\]

其中 \(r_i^t(\theta)=p_\theta(x_{t-1}|x_t,c)/p_{\theta_{old}}(x_{t-1}|x_t,c)\)。Advantage 是组内标准化的奖励，用于衡量第 \(i\) 个样本相对同组其他样本的好坏。GRPO 通过 min 来限制每次更新的幅度，KL 项防止策略偏离参考模型。工程上 \(G=24\)，\(\beta\) 对 GenEval 和文本渲染设为 0.04，对 PickScore 设为 0.01；\(\varepsilon\) 未在正文中单独给出数值，但属于 GRPO 标准超参数，论文指出除 \(\beta\) 外其他 GRPO 超参数跨任务固定。KL 项在 SDE 离散化下可闭式计算为 \(D_{KL}(\pi_\theta\|\pi_{ref})=\frac{\Delta t}{2}\left(\frac{\sigma_t(1-t)}{2t}+\frac{1}{\sigma_t}\right)^2\|v_\theta(x_t,t)-v_{ref}(x_t,t)\|^2\)，这意味着 KL 约束等价于对当前策略与参考策略速度预测的加权 L2 距离施加惩罚。

## 6. 训练到底怎么跑

以一轮训练 step 为例说明完整流程。

1. **构建 prompt 批次**：从任务对应训练分布中采样 prompt。GenEval 使用官方脚本模板随机组合，训练集与测试集严格去重，即把仅对象顺序不同的 prompt 视为相同并移除训练集中与测试集重复的变体。初始各子任务比例根据基座模型在六类任务上的初始准确率设定：Position:Counting:Attribute Binding:Colors:Two Objects:Single Object = 7:5:3:1:1:0。视觉文本渲染任务用 GPT-4o 生成 20K 训练 prompt 和 1K 测试 prompt，每个 prompt 模板为“A sign that says ‘text’”，其中 text 是必须出现在图像中的确切字符串。人类偏好对齐任务使用 PickScore 作为奖励模型，训练 prompt 来源未明确给出具体数量，但属于 DrawBench 或 Pick-a-Pic 相关数据。所有任务共享同一套 Flow-GRPO 流程，只是奖励函数不同。

2. **生成 rollout**：对每个 prompt，从标准高斯噪声 \(x_T\) 出发，使用当前策略模型（带 LoRA）按式 9 的 SDE 更新进行 \(T=10\) 步采样，得到 \(G=24\) 张图像。初始噪声每个 rollout 使用不同的随机噪声，以增加探索多样性。LoRA 超参数为 \(r=32\)，\(\alpha=64\)，图像分辨率 512。论文附录 B.3 明确写出 \(T=10\)，评价时 \(T=40\)，\(G=24\)，\(a=0.7\)，\(\beta\) 任务相关。训练时用 SDE 采样，不是 ODE。

3. **计算奖励**：GenEval 奖励由检测模型判断物体数量、颜色、位置关系。计数奖励公式为 \(r = 1 - |N_{gen} - N_{ref}|/N_{ref}\)；位置或颜色任务在物体计数正确时先给部分奖励，其余部分在预测位置或颜色正确时给足。视觉文本渲染奖励为 \(r = \max(1 - N_e/N_{ref}, 0)\)，其中 \(N_e\) 是渲染文本与目标文本之间的最小编辑距离，\(N_{ref}\) 是引号内字符数。人类偏好任务直接用 PickScore 输出分数。奖励只给最终样本，中间步无奖励。

4. **计算 advantage**：同一 prompt 的 \(G\) 个奖励进行标准化，得到该组每个样本的 advantage。标准化使用组内均值和标准差，公式见第 5 节式 4。若某组标准差为零，advantage 可能无法定义，但论文未讨论此边界情况。

5. **计算 GRPO loss**：取每条轨迹的时间步平均。在每个时间步，计算新旧策略在给定 \(x_t\) 下产生 \(x_{t-1}\) 的对数概率比。由于 SDE 离散后 \(\pi_\theta\) 为高斯分布，该比值可由两步预测速度直接得到。将 min 项乘上 advantage，再对 \(G\) 和 \(T\) 求平均。减去 \(\beta D_{KL}(\pi_\theta\|\pi_{ref})\)。论文未给出 \(\varepsilon\) 具体数值，但 GRPO 标准 clip 范围通常为 \([1-\varepsilon,1+\varepsilon]\)，此处 \(1-\varepsilon\) 和 \(1+\varepsilon\) 是超参，具体取值论文未披露。

6. **反向传播和优化器更新**：对 LoRA 参数做梯度更新。论文未明确写出学习率、优化器类型和 batch size，只说明除 \(\beta\) 外 GRPO 超参数固定。训练用 24 张 NVIDIA A800 GPU，GPU 小时见 Appendix C.5 的曲线，但论文未给出总训练步数或总 GPU 小时的确切数值，学习曲线横轴是 training step 或 GPU hours，从 Figure 7a 可以看到 GenEval 任务横轴到 4000 GPU hours，因此可以推断训练成本在该量级。关键点是：采样使用的模型是 \(\pi_{\theta_{old}}\)，也就是更新前的旧策略；在线训练中，数据收集模型随训练不断更新。论文在 Section 5.2 与 Appendix C.1 中比较的在线 DPO 变体也采用类似定期更新策略（every 40 steps），但 Flow-GRPO 每次 step 都使用当前旧策略采样。

## 7. 推理到底怎么跑

推理与训练采样有明确区别。

推理时，模型回到原始确定性 ODE 采样流程，不再使用 SDE。论文在 Section 4 的 Denoising Reduction 部分写明：“we set the timestep T as 10 in training, while the inference timestep T is set as the original default setting (T=40) for SD3.5-M。” 这意味着最终评估用 40 步 ODE，恢复一个确定性的高质量采样路径。

具体顺序为：给定 prompt \(c\)，从高斯噪声 \(x_T\) 出发；按照 SD3.5-M 原始 ODE 调度器，逐步预测速度场 \(v_\theta\)，然后按确定性公式 \(x_{t-\Delta t} = x_t - v_\theta(x_t,t)\Delta t\)（时间方向从 1 到 0）更新 \(x_t\)；重复 40 步直到 \(x_0\)；解码得到图像。这里没有额外的随机注入，因为推理目标是稳定生成高质量样本。推理时也可以选择使用 SDE 采样，但论文默认评估采用原始 40 步 ODE，以便与基座模型公平对比，并保持输出质量。附录 D 的 Figure 19 显示 40 步 ODE 和 40 步 SDE 采样结果视觉上几乎无法区分，说明 SDE 转换本身不会损害质量，但推理仍用 ODE 以确保确定性和与 SD3.5-M 基线一致。

这个设计的关键逻辑是：训练时我们用低步数 SDE 获得便宜但粗糙的轨迹，让 RL 从这些轨迹中提取相对偏好信号；推理时回归完整 ODE 步数，使学到的策略能够以原始精度表达。因此训练开销低，但评估结果不因低步数而明显受损。论文在多个基准上报告的结果（Table 1、2、3、4）都是使用 40 步 ODE 推理得到的，这说明训练中的 low-step 采样没有削弱策略迁移到完整步数的能力。

最重要的消融有两组。

**Denoising Reduction**：论文在 GenEval 上对比训练采样步数 5、10、40，并以 GPU 小时为横轴。T=10 和 T=40 最终 GenEval 分数接近，但 T=10 用约 1/4 时间达到；T=5 有时更快有时更慢，没有一致优势，因此选择 T=10。在 OCR 和 PickScore 上也有类似结果（Figure 9）。这证明短轨迹虽然图像质量下降，但 RL 依赖的组内相对偏好仍然存在，因此能同时加速训练和不牺牲最终推理性能。论文 Appendix D 可视化显示 10 步 SDE 生成图像有颜色漂移和细节模糊，但这些低质样本仍能提供有效的相对偏好信号。

**KL 正则**：GenEval 和 OCR 任务中，去掉 KL 后任务准确率未降低，但 DrawBench 上的 Aesthetic、DeQA、ImageReward 等质量分数显著下降；PickScore 任务中去掉 KL 质量分数不降，但视觉多样性崩塌，不同 seed 生成几乎相同风格（Figure 6）。学习曲线显示 KL 不是 early stopping，加了 KL 后需要更多训练步，但达到高 reward 且保持质量。具体数值可见 Table 2：GenEval w/o KL 的 Aesthetic 从 5.39 降到 4.93，DeQA 从 4.07 降到 2.77，ImageReward 从 0.87 降到 0.44；而 w/ KL 保持 5.25、4.01、1.03。这直接支撑“KL 有效防止 reward hacking”。

尚未被证明的主张包括：视频生成的可扩展性只是推测，论文明确列为 future work；多奖励平衡只在视频场景下提及，未在 T2I 中系统验证；没有展示在更大规模模型（如 8B 或视频生成模型）上的资源成本；也没有证明在所有 prompt 上完全避免 reward hacking，论文在结论中承认“occasional reward hacking occurs for certain prompts”。此外，ORW 对比仅在人偏好任务上做了小规模实验（Table 5, Table 6），DDPO 和 ReFL 的对比也在附录中，不是多任务全面对比。

## 9. 与前作怎么选

比较四个最接近的方案。

**DDPO（Adapted）**：论文在 Appendix C.1 将 DDPO 适配到 flow matching，用同一 SDE 采样和 PickScore 奖励。结果显示 Flow-GRPO 奖励上升更快，后期 DDPO 出现 collapse，而 Flow-GRPO 稳定上升（Figure 8）。选择 Flow-GRPO 当奖励不可微、且需要稳定在线训练时更合适；若希望沿用成熟的 diffusion DDPO 代码，可能需要额外适配，且 DDPO 可能需要价值网络或奖励归一化技巧。

**ReFL**：直接可微奖励梯度反传，但要求 reward 可微。论文指出 GRPO 在可微奖励下也优于 ReFL，但更关键的是 GRPO 不需要可微奖励，可以直接用 VLM 给出不可微分数。如果 reward 是可微视觉模型的输出，ReFL 实现更简单；若要用任意 VLM 或规则检测器，Flow-GRPO 更通用。论文还强调 GRPO 支持未来 VLM 升级而无需重新训练 reward model，而 ReFL 需要固定 reward 网络并回传梯度。

**Flow-DPO / Online DPO**：离线或在线偏好方法只用最高和最低奖励样本构造对比对。论文 Figure 4 显示 Flow-GRPO 在 GenEval 组合生成任务上优于所有 DPO 变体。在线 DPO 比离线更好，但对 β 敏感，过小会训练崩塌。适合样本难以成对或组内偏好明显的情况；但 Flow-GRPO 利用整组奖励，信息利用更充分。报告中在线 DPO 是第二强基线，但需要调 β，过小会 collapse。

**ORW（Online Reward-weighted Regression）**：在 PickScore 任务上，Flow-GRPO 在最终 reward、CLIP 与 Diversity 分数均优于 ORW（Table 5、Table 6）。ORW 使用 Wasserstein-2 正则而非 KL，实现不同。如果偏好避免 KL 估计或不想用 SDE 高斯假设，可以考虑 ORW，但论文结果表明 Flow-GRPO 更稳定。ORW 的 β 和 α 需要仔细调整，且 steps_per_epoch 对性能有影响。

总体选 Flow-GRPO：目标是借助不可微奖励、规则奖励或 VLM 奖励，在流匹配 T2I 上做在线 RL 微调，且希望避免训练崩塌并抑制 reward hacking。不选 Flow-GRPO：只有很少算力，或需要快速离线偏好对齐，或 reward 模型本身就是可微网络且没有 VLM 调用需求。此外，如果希望完全避免 SDE 采样器的实现复杂度，可以考虑离线 DPO 或 ORW。

## 10. 工程判断：可行性、风险与上限

**数据**：训练依赖任务 prompt 与奖励来源。GenEval 用官方生成脚本，训练集与测试集做对象顺序去重；OCR prompt 由 GPT-4o 生成 20K train / 1K test；PickScore 需要人类偏好奖励模型。生成式任务的训练数据规模不大，但需要维护去重与任务比例。风险在于规则奖励可能被对抗性利用：文本渲染奖励基于编辑距离，可能忽略语义位置错误，例如文字出现在错误位置但拼写正确仍得高分；GenEval 计数奖励对物体数量做归一化，可能鼓励生成过多物体来骗过检测器。论文未公开详细的 prompt 分布和数据集规模上限，训练 prompt 数量可能只有数千至数万，因此依赖奖励模型的鲁棒性和检测器的准确性。

**算力与延迟**：训练需要 24 张 NVIDIA A800 GPU，分辨率 512。单是 SDE 采样 10 步、G=24、500 步以上训练，成本很高。Table 1 的最终模型训练 step 未见明确数字，但 Figure 4 显示 GenEval 任务在 1400 步时仍在评估，可能训练 1500 步以上；Figure 7a 横轴到 4000 GPU hours，因此一次训练可能消耗数千 GPU hours。按 24 卡 A800，4000 GPU hours 约合 7 天（100% 利用率）。实际成本需看论文附录曲线，此处为基于图表的推断。推理仍用 40 步 ODE，与原 SD3.5-M 相同，延迟无额外增加；若用户强行用 SDE 推理，会引入随机性和额外计算，不推荐。

**实现难点**：SDE 采样器需要仔细处理时间方向和 \(\sigma_t\) 的 \(t\) 定义。论文中 Eq. 9 更新形式表明时间可能从噪声到数据，但数学推导中 \(t=0\) 是数据，若直接实现需对齐符号。\(\sigma_t\) 若设得过大，注入噪声过多会导致低质量奖励和训练失败；过小则探索不足。KL 闭式依赖 \(\pi_\theta\) 为高斯假设，只适用于 Euler-Maruyama 离散化，若换用高阶 SDE solver，则该近似不成立。低步数 SDE 样本可能出现色彩漂移和细节模糊，如 Appendix D 所示，但这是可接受的，因为 GRPO 只依赖相对偏好。此外，LoRA 微调只作用于部分参数，可能限制对深层特征的重塑能力，但论文未讨论此限制。

**失败环节**：噪声水平 \(a\) 是关键超参数，默认 0.7；超过 1.0 增加噪声没有收益，甚至可能使训练失败（zero reward and failed training，Figure 7b 旁注）。组大小 \(G\) 太小时 advantage 方差大，\(G=12\) 和 \(G=6\) 会崩溃。KL β 设置不当会导致质量下降（β 过大训练慢，过小 reward hacking）。去重不当会让测试 prompt 泄漏，高估泛化能力；论文在 GenEval 中做过对象顺序去重，但未提及完全 hold-out 的 unseen prompt 去重。附录 C.3 初始噪声消融显示，不同 rollout 使用不同初始噪声比使用相同初始噪声更能稳定训练；如果实现时固定了种子，探索多样性会下降。

**监控信号**：训练时应同时监控任务奖励、DrawBench 图像质量分数（Aesthetic、DeQA、ImageReward、UnifiedReward）、PickScore/human preference 分数，以及生成多样性。KL 应保持小且近似常数；论文 Appendix C.5 学习曲线显示有 KL 的训练 KL 值保持稳定。如果质量指标在 reward 上升时下降，说明 KL 不足或更新幅度过大。还应监控 group std，过小说明多样性丧失；监控 advantage 分布异常尖峰；监控不同 seed 生成图的相似度以检测多样性崩塌。

**指标上限**：GenEval overall 达到 0.95，已接近满分，未来提升空间有限；但 unseen counting 12 objects 只从 0.02 到 0.12，说明对大量物体的计数仍有困难。文本渲染 0.92 虽然高，但仍可能对长文本或罕见字体失败。T2I-CompBench++ 的 Non-Spatial 只有 0.3195，基本没有提升（从 0.3146 到 0.3195），说明非空间组合能力未被该方法覆盖。未回答的核心问题：是否能在不增加更多显存的前提下扩展到视频生成；如何设计多奖励平衡；如何根除偶然 reward hacking；对超大模型（如 FLUX.1-Pro 或视频模型）的可行性和成本是否可接受。

## 11. 放回研究脉络并收束

Flow-GRPO 处在三条线的交叉点：流匹配生成模型、在线 RL for LLM 向图像生成的迁移、T2I 对齐。在它之前，DDPO 已在扩散模型证明策略梯度可优化图像质量，但扩散模型天然有反向随机性；DPO 类方法离线对齐简单但缺少在线探索；在线 DPO 有提升但对 β 敏感。Flow-GRPO 的贡献在于把 GRPO 与流匹配模型结构结合，证明 ODE 主干可以通过 SDE 转换获得 RL 所需的随机采样，并通过 Denoising Reduction 使训练成本可接受。同期工作如 F5R-TTS 在语音流模型上通过预测速度的均值方差来引入随机性，但需要重新训练速度预测头；而 Flow-GRPO 不需要重新训练，直接通过 SDE 转换利用已有的速度场，保持模型架构不变。论文还展示了较强的泛化能力：在 GenEval 风格训练数据上，模型在 T2I-CompBench++ 上也有提升，并且在 unseen object classes 上从 0.64 提升到 0.90，在 unseen counting 5-6 objects 上从 0.13 提升到 0.48，说明学习到的组合能力不是死记硬背。但 Non-Spatial 指标几乎无变化，提示该方法对某些关系类型仍有限制。

**读完必须记住的 5 件事**

1. Flow-GRPO 首次把 GRPO 集成进流匹配模型，核心改动不是损失函数本身，而是采样器：将确定性 ODE 等价转换为 SDE，保持边缘分布的同时注入高斯噪声。
2. Denoising Reduction 是效率关键：训练用 10 步 SDE，推理用 40 步 ODE，在 GenEval、OCR、PickScore 三个任务上都获得约 4 倍采样加速而不损失最终奖励。
3. SDE 离散化后的策略条件分布是各向同性高斯，因此 KL 正则可以直接由两步速度差闭式计算，使策略更新稳定。
4. KL 正则不等于 early stopping：去掉 KL 在 GenEval/OCR 上降低图像质量，在 PickScore 上导致多样性崩塌；加 KL 后训练更长但质量保持。
5. 实验显示 SD3.5-M 在 GenEval 从 0.63 到 0.95，文本渲染从 0.59 到 0.92，并在 unseen 物体和计数上也有一定泛化，但 Non-Spatial 等开放组合任务提升很小。

**5 道自测题**

1. Flow-GRPO 为什么不能直接在原 flow matching 模型上用 GRPO？如果强行用确定性 ODE 采样，会遇到哪些具体问题？（提示：条件分布计算与散度估计、探索不足）
2. 写出式 9 中每一项的含义。\(\sigma_t\) 的设定为什么用 \(a\sqrt{t/(1-t)}\)？噪声水平 \(a\) 过大或过小分别会导致什么结果？
3. 训练时 \(T=10\)、推理时 \(T=40\)，为什么低步数轨迹反而不会降低 RL 训练的最终质量？请从组内相对偏好角度解释。
4. 如果观察到训练中 reward 上升但 DrawBench Aesthetic 分数下降，你应该调整哪个超参数？为什么调整它能抑制 reward hacking？
5. 用 GRPO 微调 SD3.5-M 时，为什么组大小 \(G=12\) 或 \(G=6\) 会导致训练崩溃？advantage 估计的方差如何受 \(G\) 影响？

最终一句话总结：Flow-GRPO 将流匹配的确定性 ODE 采样改造成等价 SDE 采样，以 10 步低质轨迹和 GRPO 组内比较完成在线 RL，在组合生成、文本渲染和偏好对齐上以较小质量代价取得显著提升，为流式生成模型的在线对齐提供了一个可复用的工程路径。
