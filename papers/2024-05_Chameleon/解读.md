# 大白话深读《Chameleon》

## 1. 30 秒定位

Chameleon 是 Meta FAIR 提出的“早融合、基于 token 的混合模态基础模型”家族，论文于 2024 年 5 月发布（arXiv:2405.09818）。它包含 7B 与 34B 两个尺寸，把图像与文本统一离散化为 token，经由同一个自回归 Transformer 从零开始训练，不依赖独立的视觉编码器、文本编码器或领域专用解码器。模型能够理解并生成任意交错的图文序列，例如“看图写菜谱并附成品图”“根据描述生成多张示意图并逐张解释”。早期版本将这类能力视为多个系统的拼接结果，而 Chameleon 用单一稠密模型直接输出完整多模态文档。技术上，Chameleon 最关键的工作在于解决了一个此前制约早融合模型规模化训练的痛点：softmax 的平移不变性在多模态熵差异下会导致 logits 范数漂移，最终使 loss 发散。论文用三种稳定化手段——QK-Norm、规范层重排（norm reordering）、z-loss——让 34B 模型在约 9.2 万亿 token 上稳定训练 2.1 个 epoch。实验方面，Chameleon-34B 在 COCO 图像描述上以 2-shot 达到 CIDEr 120.2，超过 Flamingo-80B 的 32-shot 113.8（§5.2, Table 7）；文本基准 MMLU 上 65.8 超过 Llama-2 34B 的 62.6（§5.1, Table 6）；在新设计的含 1048 条 prompt 的混合模态人类评估中，对加图像增强的 GPT-4V+ 与 Gemini+ 的胜率分别为 51.6% 和 60.4%（§4.2.2, Figure 9b）。这是一篇将“全模态文档统一建模”从概念推进到可稳定训练规模的工作，量化上限与风险同样被论文如实标注。

## 2. 为什么这篇论文会出现

此前的主流多模态基础模型大多采用“晚融合”：图像先经过一个独立的视觉编码器变成连续特征，再通过交叉注意力或投影层注入文本 LLM；生成图像时则通常要额外挂载扩散解码器或独立图像生成模块。Flamingo、LLaVA、IDEFICS、VisualGPT 属于前者；DALL-E、CM3Leon 等在不同程度上属于后者。这种设计的优势是可以分别继承已经训练好的文本与视觉骨干，工程上容易落地，但它存在结构性限制：模型难以在“同一套参数”里自然处理任意顺序的图文交错文档。例如“先给两张图、再要求比较差异、接着生成示意图”，晚融合模型通常只能在文本侧输出比较内容，无法直接产出图像 token，必须借助外部图像生成器补齐。这一限制不是单纯的能力不足，而是架构图层面缺少图像输出的路径：视觉编码器只负责把图像压缩为连续表示，反向生成能力属于另一套模型。

Chameleon 的出发点是早融合：图像与文本在输入端就被映射到同一个离散 token 空间，之后共享一个 Transformer。这带来两个直接好处：跨模态信息从第一层开始融合，以及一个模型同时具备理解与生成图像的能力。论文在 §1 中明确说，这一设计是“直接泛化标准多模态任务”——图像理解、图像生成和纯文本 LLM 都可以视为同一个 mixed-modal 建模问题的特例。相关工作脉络里，BEiT 首先探索了用离散 token 做自监督视觉表示；DALL-E 首次用自回归方式生成图像 token；CM3 把交错图文文档作为训练目标；CM3Leon 进一步把 token 自回归扩展到 text-to-image。Chameleon 是在这条线上第一次把模型规模稳定推到 34B 并在多类基准上同时评测理解与生成。

训练稳定性是这类模型一直难以规模化的核心阻碍。论文在 §2.3 写到，当模型超过 8B 参数、训练超过 1T token 时，非常晚的阶段会出现 loss 发散，而发散前困惑度往往没有明显异常。作者把根源定位在 softmax 的平移不变性：因为 softmax(z) = softmax(z+c)，不同模态熵差异很大，各模态会通过轻微抬升自己的 logits 范数来“竞争”，在共享权重的 Transformer 中表现为范数缓慢但不受控地增长，最终超出 bf16 的有效表示范围。论文引用 Wortsman et al. (2023)，指出在单模态设置中这个问题被称为 logit drift 问题。作者进一步发现，最后一层输出范数的失控增长是未来 loss 发散的强预测指标（Figure 5a），即使在训练进度 20%–30% 后仍可能出现发散。这一诊断把“多模态训练为何会崩”从模糊经验推进为可监控、可消融的具体机制。因此 Chameleon 的核心贡献不只是提出新任务，而是“证明早融合在适当架构与正则化配合下可以稳定扩展到 34B，并在大量基准上不输晚融合模型，同时解锁原生混合模态生成能力”。

## 3. 读懂前需要的最小概念

**离散图像 token 与 image tokenizer**。图像的本质是连续像素矩阵，无法直接送入文本自回归模型。Chameleon 训练了一个基于 Make-A-Scene（Gafni et al. 2022）的图像分词器，把 512×512 图像编码为 1024 个离散 token，每个 token 从大小为 8192 的 codebook 中取值。这相当于用 1024 个“视觉词”表达一张图，反 tokenize 时再还原为图像。该 tokenizer 训练只用授权图像，并对含人脸图像做了 2 倍上采样以改善人脸生成质量。论文明确披露这个 tokenizer 的一个核心弱点：对含有大量文字的图像重建质量差，因而给 OCR 相关任务设定了能力上限（§2.1）。这意味着处理图像内文字时，模型的输入表示本身就携带了瓶颈，不是简单的注意力或对齐问题。

**BPE tokenizer 与混合词表**。文本侧用 SentencePiece 库训练了一个 BPE tokenizer，词表大小为 65,536，其中显式包含 8192 个图像 codebook token（§2.1）。这样图像 token 和文本 token 在同一个词表里，理论上可以无缝拼接为一个序列。这里的“混合词表”不是把图像 token 也变成可解释的子词，而是在离散索引空间里预留一段专用区段，让模型在预测时可以直接输出图像 token。这是早融合得以实现的词汇表基础，也是推理时区分“当前输出是文本还是图像”的判定依据。

**自回归 Transformer 与早融合**。自回归指每一步基于前文预测下一个 token，训练目标是标准的 next-token prediction。早融合指图像与文本从一开始就经过同一个 Transformer 处理，没有模态特定的编码器或解码器；晚融合则相反，图像先走视觉塔、文本走语言塔，在较高层才交互。Chameleon 的 Transformer 是 decoder-only，与 Llama 系列一致。早融合的好处是任意交错序列天然可行，每一层都可以看到完整的文本与图像 token 历史；代价是所有模态共享同一套参数，彼此在表示空间内竞争。

**稳定化工具**。RMSNorm 是 Llama 系列常用的归一化；QK-Norm（query-key normalization）是对注意力中的 query 与 key 向量分别做 LayerNorm；z-loss 是对预测 logits 的 softmax 分母即配分函数 Z 做正则化，抑制 logits 整体幅度增长；norm reordering 则改变 Transformer block 内部 LayerNorm 的位置，从残差输入侧移到残差分支之后，以约束前馈块输出的范数增长。这些工具对应的数学形式在 §5 中展开。其中 QK-Norm 与 z-loss 是两个独立的稳定机制，分别管住注意力内部 softmax 与输出层 softmax；norm reordering 则额外约束 SwiGLU 前馈块的乘性范数增长。

## 4. 方法全景：先看数据流

Chameleon 的训练管线可以画成下面的 ASCII 数据流：

```
                 ┌──────────────────────────────────────────────┐
                 │           预训练混合数据池                     │
                 │ text-only 2.9T tokens + text-image 1.5T       │
                 │ + interleaved 400B tokens                      │
                 │ （第一阶段约前80%，第二阶段后20%：              │
                 │   第一阶段数据权重降50%，混入高质量数据与        │
                 │   指令微调集过滤子集）                          │
                 └──────────────────────┬───────────────────────┘
                                        ▼
                 ┌──────────────────────────────────────────────┐
                 │ 分词：文本 BPE 65536 词表；图像 512×512 →      │
                 │ 1024 离散 token (codebook 8192)               │
                 │ 图文对旋转：50% 时图像在文本之前               │
                 └──────────────────────┬───────────────────────┘
                                        ▼
                 ┌──────────────────────────────────────────────┐
                 │ 任意交错 token 序列： [<img> token set, text,  │
                 │ <img> token set, ...]                          │
                 └──────────────────────┬───────────────────────┘
                                        ▼
                 ┌──────────────────────────────────────────────┐
                 │ 统一自回归 Transformer (Dec-Only)             │
                 │ 架构类似 Llama-2：RMSNorm、SwiGLU、RoPE       │
                 │ 改动：QK-Norm + norm reordering + z-loss      │
                 │ 训练目标：next-token prediction + z-loss       │
                 └──────────────────────┬───────────────────────┘
                                        ▼
                 ┌──────────────────────────────────────────────┐
                 │ 输出：预测下一个 token（可能是文本或图像 token）│
                 └──────────────────────┬───────────────────────┘
                                        ▼
                 ┌──────────────────────────────────────────────┐
                 │ 若预测到图像 token 块，送入 image de-tokenizer │
                 │ 生成 512×512 图像；否则 decode 文本             │
                 └──────────────────────────────────────────────┘
```

核心组件如下：

**图像分词器**：输入 512×512 图像，输出 1024 个离散 token，codebook 8192。目的是把视觉信息离散化，使其能被语言模型直接处理。假设是图像可以压缩进有限离散码本，并且重建质量足够支撑下游任务。论文只使用授权图像训练 tokenizer，且对含人脸图像上采样 2 倍。该 tokenizer 对含大量文字的图像重建弱，构成 OCR 任务的上限（§2.1）。这一弱点的全文措辞是“A core weakness of our tokenizer is in reconstructing images with a large amount of text, therefore upper bounding the capability of our models, when it comes to heavy OCR-related tasks.”

**BPE 文本分词器**：输入文本，输出子词 token；词表 65,536 并包含图像 codebook 的 8192 个 token。训练方式是用 SentencePiece 库在训练数据子集上学习（§2.1）。目的是让文本与图像共享同一个离散空间。假设是训练语料统计足够训练一个稳定词表，且把图像 token 纳入词表不会给 BPE 建模带来干扰。

**混合模态数据集**：第一阶段为无监督数据，文本 2.9 万亿 token（来自 Llama-2 与 CodeLlama 预训练数据）、图文对 1.5 万亿 token（来自 14 亿 text-image pairs，图像经 resize + center crop 到 512×512）、交错图文 4000 亿 token（来自公开网页，不含 Meta 产品或服务数据，过滤方式与 Text-To-Image 相同）（§2.2.1）。第二阶段把第一阶段数据权重降低 50%，并混入更高质量数据集和指令微调集的过滤子集，同时保持图文 token 比例大致相同（§2.2.2）。图文对训练时旋转 50%，让图像在文本之前出现，以模拟图像描述任务。总共 4.4T token 的数据集（Table 1 的 Tokens 列），训练 2.1 epoch 得到 9.2T token 的总训练量。

**统一 Transformer**：大体沿用 Llama-2，采用 RMSNorm、SwiGLU 激活、RoPE 位置编码，但新增 QK-Norm，并对 34B 重排了 layer norm 位置。输入为任意交错 token 序列，输出为下一 token 分布。目的是学习跨模态联合概率，并避免训练发散。7B 与 34B 的架构与优化决策对照见 Table 1，其中 7B 使用 dropout 0.1，34B 不使用；两者都使用 QK-Norm 与 z-loss；上下文长度都是 4k；学习率 1e-4；训练总 token 4.4T（指数据集规模，训练 2.1 遍得到 9.2T）。

**SFT 对齐阶段**：预训练后加轻量监督微调，数据共六类——文本 1.6M 样本（940M token）、代码 14.1K 样本（1.1M token）、视觉对话 15.6K 样本（19.4M token，含 16.7K 图像）、图像生成 64.3K 样本（68.0M token）、交错生成 16.9K 样本（35.8M token，含 30.7K 图像）、安全 95.3K 样本（38.6M token，含 1.6K 图像）（§3.1, Table 3）。目的是激活指令跟随与混合模态生成能力，并增强安全性。关键假设是不同模态配比的平衡可以避免模型学到无条件生成某一模态的先验，即如果某一模态样本占压倒性多数，模型会倾向于总是输出该模态，造成“沉默”或“过度生成”。

## 5. 核心公式与直觉

**第一个关键机制：QK-Norm**。Chameleon 在注意力中对 query 和 key 做层归一化：

\[
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{(\text{LN}(Q))(\text{LN}(K))^\top}{\sqrt{d}}\right)V
\]

其中 LN 是 LayerNorm，d 是注意力头维度。直觉上，softmax 对输入整体加常数不敏感。如果 query 和 key 的范数同时缩放一个常数，softmax 输出不变，但 logits 本身可以持续变大而不影响局部概率分布。在纯文本模型中，模型可能学会某种范数平衡；但混合模态下，文本与图像的熵差异显著，各模态会通过轻微抬升自己在该层表示范数来竞争共享权重的表示空间。由于所有 token 经过同一组参数，这种竞争表现为全局范数缓慢漂移，最终超出 bf16 的表示范围，导致 loss 发散。QK-Norm 直接对每个 token 的 query 和 key 向量做归一化，消除了它们共同缩放的自由度。论文 Figure 5b 显示 7B 模型去掉 QK-Norm 后约 20% epoch 处发散；而加入 QK-Norm 的对照保持稳定。这一改动借鉴自 Dehghani et al. (2023) 和 Wortsman et al. (2023)。注意 QK-Norm 只限制注意力内部 softmax 的输入，不直接约束输出 logits。

**第二个关键机制：z-loss**。设置在预测 logits 的 softmax 配分函数上：

\[
L_{\text{z}} = 10^{-5} (\log Z)^2,\quad Z = \sum_i e^{z_i}
\]

其中 z_i 是 logits。softmax 为 \(\sigma(x)_i = \frac{e^{z_i}}{Z}\)。当 \(Z=1\) 时，logits 的对数和为零，即 \(\log Z=0\)。z-loss 惩罚 \(\log Z\) 偏离零，推动 logits 整体幅度不要过大。直觉上，最终输出 softmax 也有平移不变性：所有 logits 同时加上常数 c，概率分布不变。如果 logits 在训练中缓慢整体抬升，配分函数 Z 会指数级增大，可能超出 bf16 的数值范围。z-loss 把 \(\log Z\) 拉回 0，相当于固定了 logits 的“零水平”。论文明确指出，QK-Norm 只解决内部注意力 softmax，最终输出 softmax 仍需要 z-loss；Chameleon-7B 需要 dropout 与 z-loss 共同作用才稳定，Chameleon-34B 只需 z-loss 而不需要 dropout（§2.3, Figure 6c）。系数 \(10^{-5}\) 很小，所以对正常语言建模损失影响微弱。

**第三个关键机制：norm reordering**。Chameleon-34B 的 block 更新为：

\[
h = x + \text{attention\_norm}(\text{attention}(x))
\]
\[
\text{output} = h + \text{ffn\_norm}(\text{feed\_forward}(h))
\]

而 Llama-2 是：

\[
h = x + \text{attention}(\text{attention\_norm}(x))
\]
\[
\text{output} = h + \text{feed\_forward}(\text{ffn\_norm}(h))
\]

区别在于 LayerNorm 从残差输入流移动到残差分支之后。这是 Swin Transformer 所用的归一化策略（Liu et al., 2021, 2022）。在 Llama-2 中，注意力输入和 FFN 输入被归一化，但输出分支未被直接约束；如果注意力输出或 FFN 输出本身很大，残差结果可能持续膨胀。在 Swin-style 顺序里，注意力输出和 FFN 输出分别经过 attention_norm 和 ffn_norm 再与残差相加，直接约束分支输出的范数。论文解释这尤其重要，因为 SwiGLU 是乘性激活，FFN 输出的范数在 Llama 参数化下可能不受控增长。论文说这种重排与 dropout 不太兼容，因此 34B 训练时不使用 dropout；7B 在采用该重排后也可以不用 dropout 稳定训练，但 QK-Norm 两者都必需。论文还说明：在发散发生前，是否做 norm reordering 对困惑度没有差异，直到 Llama-2 参数化开始发散（§2.3）。这暗示 norm reordering 本身不是表示质量的关键，而是数值稳定性的关键。

## 6. 训练到底怎么跑

**预训练一轮 step 的流程**：

1. 从混合数据池采样一批 token 序列。第一阶段（约前 80% 训练）用无监督大规模数据；第二阶段（约后 20%）把第一阶段数据权重减半，并混入高质量数据集与指令微调集的过滤子集（§2.2）。第一阶段内部，文本、图文对、交错图文的比例并非均匀，而是由数据规模决定：文本 2.9T、图文 1.5T、交错 400B，因此一个随机 token 大约有 60% 来自纯文本、31% 来自图文对、8% 来自交错文档。
2. 对每个样本分词：文本走 BPE；图像先 resize + center crop 到 512×512，再过图像 tokenizer 得到 1024 个图像 token。对于图文对，有 50% 的样本将图像放在文本之前，以模拟 captioning；另外 50% 是将文本放在图像之前（§2.2）。
3. 拼接成 token 序列，送入统一 Transformer。解码目标是 next-token prediction：给定前 t 个 token，预测第 t+1 个 token 的概率分布，损失为交叉熵。图像 token 在这里与文本 token 完全等价，没有特殊损失分支。
4. 加上 z-loss 正则项 \(10^{-5}(\log Z)^2\) 得到总损失。Z 为每一步输出 softmax 的配分函数。
5. 反向传播，AdamW 优化器更新。优化器超参：β1=0.9，β2=0.95，ε=10⁻⁵，线性 warmup 4000 步，之后学习率指数衰减到 0；weight decay 0.1；全局梯度裁剪阈值 1.0（§2.3 Optimization）。
6. 7B 使用 dropout 0.1，34B 不使用；两者都使用 z-loss 与 QK-Norm。批次大小：7B 为 \(2^{23} \approx 8M\) tokens，34B 为 \(3 \times 2^{22} \approx 12M\) tokens（§2.3）。
7. 整个预训练约 9.2 万亿 token，即 2.1 个 epoch（等效完整数据集大小约 4.4T token）。7B 训练 600k 步覆盖约 55% 总训练，34B 600k 步覆盖约 80% 总训练（Figure 6a）。资源：7B 用 1024 张 A100 80GB（856,481 GPU hours），34B 用 3072 张（4,282,407 GPU hours），都在 Meta RSC 集群上，用 NVIDIA Quantum InfiniBand 互联（§2.3, Table 2）。对齐阶段使用内部集群，A100 80GB，Elastic Fabric 互联。

**SFT 一轮 step 的流程**：

1. 从 SFT 数据中采样，批次大小 128 个样本，序列最大长度 4096 token。数据集包含文本、代码、视觉对话、图像生成、交错生成、安全六类，具体样本数与 token 数见 Table 3。
2. 将 prompt 和 answer 打包进同一序列，用特殊 token 分隔 prompt 结束与 answer 开始。为了提高效率，一个序列内尽可能塞入多个 prompt-answer 对（§3.2）。这一点类似文本 LLM 的序列打包，但需要额外注意图像 token 块不能跨样本截断。
3. 对 answer 部分计算自回归交叉熵损失，prompt 部分的损失被 mask 掉。论文说明这种 targeted approach 能带来小幅整体提升（§3.2）。
4. 加与预训练相同的 z-loss。
5. 优化器：初始学习率 1e-5，余弦退火；weight decay 0.1；dropout 0.05（§3.2）。
6. 关键点：SFT 阶段必须平衡不同模态配比。若模态配对严重不平衡，模型会学到“无条件生成某一模态”的先验，表现为过度生成或沉默某模态（§3.2）。为此论文在图像生成 SFT 中特别用美学分类器筛选，选取评分至少 6 且尺寸接近 512×512 的前 64K 张授权图像（§3.1）。
7. SFT 中 prompt 里的图像用 border padding 保留全部信息，answer 里的图像用 center crop 保证视觉生成质量（§3.2）。原因：prompt 图像用于理解，不能丢失边缘信息；answer 图像用于生成监督，center crop 去掉边界噪声，使生成目标更干净。

## 7. 推理到底怎么跑

Chameleon 的自回归推理不是简单逐 token 解码，因为必须在文本与图像之间切换控制流。论文 §2.4 列出了三个特有挑战：

**每步数据依赖**：当前 token 决定下一步生成文本还是图像，因此每个生成步都必须检查输出 token 类型。实现上是阻塞式的：token 从 GPU 拷贝到 CPU 才能判断是否出现图像开始标记。这比纯文本 LLM 推理多了大量主机同步。即使非流式生成文本时，每个输出 token 也必须检查是否为图像开始 token，以决定是否切换到图像专用解码增强（§2.4）。

**模态约束 masking**：当用户只需图像输出，或需要约束生成特定模态时，不属于目标模态的 token 会被 mask 掉并忽略。这使 GPU 端不需要复杂分支，避免无效 token 进入 de-tokenizer。例如纯图像生成模式下，模型输出的文本 token 会被遮住，只保留图像 token 块。

**固定尺寸图像块**：文本是变长 token 序列，图像则是固定 1024 个 token 一块。非流式推理时，图像 token 块可以融合执行而无需逐步条件判断；流式推理则仍需逐步判断，因为需要检测图像结束和文本恢复的信号。论文说在流式设置下，每一步都需要 token 依赖的条件逻辑，因为生成模式会据前一步 token 变化。

推理实现基于 PyTorch，GPU kernel 来自 xformers（Lefaudeux et al., 2022），支持文本和图像的流式生成（§2.4）。最终若输出图像 token，则送入 image de-tokenizer 重建 512×512 图像。因此推理瓶颈不仅来自 Transformer 前向，还来自 token 类型检查与模态切换带来的 GPU-CPU 同步和分支。论文没有披露具体吞吐量或延迟数字，因此实际部署效率无法从论文中精确估算。论文指出“the tokens must be inspected at each step (i.e. copied from the GPU to the CPU in a blocking fashion) to guide control flow”，这直接说明每次生成都引入了数据拷贝与阻塞等待，推理延迟会比同尺寸纯文本模型高。

**最关键消融**：34B 的 norm reordering。论文 Figure 6c 显示，Chameleon-34B 在 Llama-2 原参数化下，无论是否加 dropout，loss 都会在后期急剧上升并发散；改成 Swin-style norm reordering 后，不使用 dropout 也能稳定训练。另一个关键证据是 Figure 6b：当去掉图像生成任务后，训练不再出现不稳定。这直接支持了“多模态熵差异导致 logit drift”的诊断，而不是普通 LLM 的训崩。z-loss 对两者都必需，因为 QK-Norm 只约束注意力内部 softmax，最终输出 softmax 的配分函数漂移需要单独正则化。Figure 5a 还显示，输出范数失控增长是未来 loss 发散的强预测指标，可作为训练监控信号。

论文还给出了逐步递进的稳定化消融：Figure 5b 对比 7B 有/无 QK-Norm，无 QK-Norm 约 20% epoch 发散；Figure 5c 对比 7B 有/无 dropout，无 dropout 在更早阶段开始 loss 上升。Figure 6c 说明 34B 即使有 dropout 也不能稳定，必须 norm reordering。Table 1 总结了 Chameleon 与 Llama-1/2 的关键差异：学习率从 Llama-1/2 的 3e-4/1.5e-4 降到 1e-4，训练 epoch 从 1.0 变为 2.1，7B 增加 dropout 0.1，34B dropout 0.0，两者均增加 z-loss 与 QK-Norm。

人类评估方面，相对评估中 Chameleon 对 Gemini+ 的胜率 58.8%（按 win+tie/2 计算，论文报告 60.4% 是另一口径，Section 4.2.2 写“overall win rates 60.4% vs Gemini+ and 51.6% vs GPT-4V+”，而 Table 11-14 列出的 Overall Win rate 分别是 58.8% 与 51.6%，两者可能因口径不同略有差异，但这里保持论文主文本数字）。绝对评估中，Chameleon 完全满足任务率 55.2%，明显高于增强基线。按类别看，Chameleon 在 Advice、Comparison、Brainstorming 上完全满足率较高，在 Reasoning 与 Story 上较低（Table 9）。论文指出人类评估的一组脆弱点：prompt 来自众包而非真实用户，且不包含 OCR 或 Infographics 类视觉理解任务；GPT-4V、Gemini 的 API 只能输出文本，虽然用 DALL-E 3 增强，但无法实现原生混合输出（§4.5）。

**尚未证明的主张**：第一，论文没有在 34B 以上继续验证稳定边界，34B 的稳定配方能否推广到 70B+ 仍然未知。第二，人类评估的 prompt 来自众包而非真实用户，并且不包含 OCR 或 Infographics 类视觉理解任务（§4.5），因此“混合模态生成优于 GPT-4V”的结论不能外推到需要读图内文字的场景。第三，tokenizer 的重建弱点给 OCR 上限提供了定性陈述，但论文没有给出量化 OCR 基准；同时该弱点意味着某些要求细粒度文字理解的评测可能低估模型中后期能力。第四，安全方面，red team 对 34B 的 445 轮对抗交互中仍有 1.6% 不安全、4.5% 不确定（Table 5）；论文承认 RLHF/RLAIF 可进一步加固，但本文未做。第五，图像生成质量没有用 FID、IS 等常规指标在标准基准上量化比对，图 2-4 只是定性展示；因此“高质量图像生成”的声称在定量层面没有被充分证明。第六，在 VQAv2 上 Chameleon-34B 66.0 落后于 Flamingo-80B-FT 82.0、GPT-4V 77.2 以及 LLaVA-1.5 的更高值，说明其视觉问答方面并未达到 SOTA，与论文摘要中“state-of-the-art in image captioning”的表述形成对比，视觉问答属于“competitive”而非最强。

## 9. 与前作怎么选

**Chameleon vs Flamingo / LLaVA / IDEFICS（晚融合理解模型）**。晚融合模型在少样本图像理解上很强：Flamingo-80B 在 VQAv2 32-shot 得 67.6，Chameleon-34B 2-shot 得 66.0；IDEFICS-80B 在 COCO 32-shot 得 116.6，而 Chameleon-34B 2-shot 得 120.2。若任务是纯“看图问答/描述”，且算力预算有限，LLaVA-1.5 或 IDEFICS-Instruct 经过额外指令微调后可能更省资源；尤其 LLaVA-1.5 在 VQAv2 上使用了 GPT-4 对话、ShareGPT、GQA、区域级 VQA 等额外数据，得分超过 Chameleon-34B（Table 7 下有说明）。但晚融合模型无法原生输出任意图文交错序列，必须外接图像生成器，这在需要“看图分析→生成示例图”的闭环任务中会产生两套系统的衔接成本，并且两张图的语义一致性很难保证：外部 generator 无法直接利用视觉理解模型的中间表示。

**Chameleon vs CM3Leon / Gemini**。CM3Leon 也是 token-based 自回归模型，但论文把它的定位更偏向 text-to-image 生成；Gemini 也是 early-fusion token-based 方案，但关键区别是 Gemini 使用独立的图像解码器，而 Chameleon 是端到端稠密模型，没有任何 routing 组件（§6 Related Work）。如果业务需要一个跨理解与生成的单一稠密模型，且不希望维护独立图像解码器，Chameleon 的设计更统一；但 Gemini 等闭源模型在更大规模、安全对齐和产品成熟度上可能更具优势。论文没有提供与 Gemini Ultra 同尺寸的对比，因此不能宣称在同一体量下超越。值得注意的是，论文把 Chameleon 与 Perceiver 类比，因为两者都追求统一模态与任务的通用架构，但 Chameleon 是更直接的 token-based 自回归方案，而 Perceiver 使用非自回归的注意力瓶颈。

**何时不选 Chameleon**。需要重度 OCR 或对图表、长文档内文字做理解时，Chameleon 的图像 tokenizer 明确构成上限（§2.1）。数据规模小于 1T token 时，从头训练早融合模型未必比晚融合模型更划算，因为晚融合可以复用已经训练好的单模态骨干，数据效率和迁移成本更低。如果完全没有图像生成需求，仅做视觉问答，用 Llama 加视觉投影器的微调方案在算力上通常更经济，因为不需要图像 tokenizer 重建能力，也不需要为图像生成做稳定化与平衡。只有在“需要原生输出交错图文文档”或“希望一个模型同时覆盖理解与生成”的目标下，Chameleon 的优势才会超过其额外的预训练成本和稳定性调优难度。

## 10. 工程判断：可行性、风险与上限

**数据**。预训练数据规模约 9.2 万亿 token，其中第一阶段文本 2.9T（来自 Llama-2 和 CodeLlama 数据）、图文对 1.5T（来自 14 亿 pairs）、交错图文 400B。第二阶段把第一阶段数据权重减半并混入高质量数据和指令子集。SFT 仅约 1.9M 样本（Table 3）。交错图文数据远小于文本数据，这可能限制模型在长程多模态推理和整文档理解上的上限。论文未披露交错文档的具体来源分布、语言构成、代码占比、以及质量过滤的完整细节；只说明来自公开网页且不含 Meta 产品数据，并采用与 Text-To-Image 相同的图像过滤。SFT 中文本类别样本数 1.6M 远大于其他类别，但 token 数与其他类别相比绝对量仍大；视觉聊天只有 15.6K 样本，意味着视觉指令跟随能力可能欠拟合。数据方面最大的未知是交错文档的质量和规模，因为 400B token 相对于文本 2.9T 很小，可能不足以让模型学到足够强的多图推理与文档生成能力。

**算力 / 延迟**。34B 预训练用 3072 张 A100 80GB，总 4,282,407 GPU hours（约相当于 178,000 个 A100 天）；7B 用 1024 张，856,481 GPU hours（Table 2）。这是很高的固定训练成本，仅 GPU 时间就使复现门槛达到百万美元量级。推理端，每张 512×512 图像变成 1024 个离散 token，若一次对话涉及 3 张图则额外增加 3072 个 token 的自回归步骤；每步还需检查是否为图像开始 token，GPU 到 CPU 的阻塞拷贝限制吞吐。论文给出了定性描述，但没有具体的 tokens/s 或延迟数字，因此部署成本无法精确估算。可以合理推断：在单张 A100 上，34B 模型的每 token 生成时间在几十毫秒量级，加上图像生成要额外生成长达 1024 步的图像块，响应延迟会比纯文本高出一个数量级。

**实现难点**。一是稳定训练要求同时启用 QK-Norm 与 z-loss；34B 还要求 norm reordering 且不能使用 dropout。任何一项配置缺失都可能导致很晚阶段的发散，而发散发生前困惑度可能没有预警，这要求训练监控必须盯紧输出范数而非 loss。二是 SFT 的模态平衡非常关键：若文本与图像生成数据配比失衡，模型会学到无条件生成某一模态的先验，导致沉默或过度生成（§3.2）。例如若交错生成数据中图像块比例过高，模型可能在纯文本对话中无缘无故插入图像开始 token。三是图像 tokenizer 的 8192 codebook、每图 1024 token 的参数化带来固定自回归长度，既增加训练计算量，也限制生成图像的细粒度细节。四是推理时模态切换逻辑的工程复杂度：流式生成需要每步条件判断，非流式可以融合图像块，但文本仍须逐 token 检查；masking 需要确保只对目标模态 token 进行 de-tokenize，否则容易产生格式错误。

**失败环节与监控信号**。论文给出了明确的预警指标：最后一层输出范数失控增长是未来 loss 发散的强预测因子（Figure 5a, §2.3）。工程上应监控输出范数、logits 配分函数 Z、以及 loss 尖峰。若输出范数持续加速上升，应立刻检查 QK-Norm 与 z-loss 是否被正确启用。此外，Figure 6b 的消融说明“图像生成能力存在”本身会增加稳定性风险，因此监控应在训练早期就建立。另一个失败模式是 text-to-image 时模型可能只输出文本描述而不输出图像 token，或者相反，只输出图像块而不产生文本说明；论文把这一问题归因于 SFT 模态配比失衡，需要以平衡采样和有针对性的对比数据纠正。

**指标上限与未回答问题**。已公开的上限是 OCR 受 tokenizer 重建能力限制（§2.1），这是硬约束：如果 tokenizer 不能重建含文字图像，模型学到的视觉表示就缺乏可靠文字信息，后续无论怎么训练都无法恢复。未回答的问题包括：34B 稳定配方是否能推广到 70B 以上；更长的图文文档上下文如何扩展；是否必须从零开始训练，还是可以用已有 Llama 权重初始化；SFT 后没有 RLHF，red team 仍发现 1.6% 不安全响应；图像生成的定量质量指标缺失；人类评估中相对 GPT-4V+ 的胜率是 51.6%，说明优势并不悬殊，且该评估排除了 OCR 类任务。此外，论文未披露推理阶段的内存占用与量化可行性，也未说明如何在不牺牲图像质量的前提下减少 1024 token 的图像块生成成本。

## 11. 放回研究脉络并收束

Chameleon 承接的脉络是“离散 token 统一建模”：BEiT 用图块 tokenizer 做自监督视觉表示；DALL-E 首次以自回归方式生成图像 token；CM3 把交错图文文档作为训练目标；CM3Leon 将 token 自回归扩展到 text-to-image 生成任务。Chameleon 的直接贡献是把这一路线从“小规模不稳定”推进到 34B 规模的稳定训练，并在多个视觉语言与文本基准上完成评测。同时，它与 Gemini 形成同期对照：两者都采用 early-fusion token-based，但 Gemini 使用独立图像解码器，Chameleon 是端到端稠密模型，无路由组件（§6）。Chameleon 还第一次做了一定规模的人类混合模态开放生成评估（1048 条 prompt），尽管这一评估面仍不够宽。

**读完必须记住的 5 件事**：

1. Chameleon 是“一个 Transformer 处理所有模态”的早融合架构，图像被切成 1024 个离散 token（codebook 8192），与文本共享一个 65,536 词表的统一词汇空间。这个统一空间是理解与生成图像在同一模型内发生的唯一基础。
2. 训练不稳定的根因是 softmax 平移不变性在跨模态熵竞争下造成的 logits 范数漂移；QK-Norm 管内部注意力，z-loss 管最终 softmax，34B 还要 Swin-style norm reordering 且不用 dropout。三者缺一在某些配置下会导致训练后期发散。
3. 预训练约 9.2T token（4.4T 数据集训练 2.1 遍）；SFT 仅约 1.9M 样本，但必须平衡文本、视觉对话、图像生成、交错生成等六类模态配比，否则模型会学到无条件生成单一模态的先验。
4. Chameleon-34B 在 COCO 描述上以 2-shot 超过 Flamingo-80B 的 32-shot，在 MMLU 上超过同尺寸 Llama-2，但在 VQAv2 上不敌加了大量指令数据的 LLaVA-1.5 和更大参数量的微调模型；其核心差异能力是原生输出图文交错文档，而非每个子任务都达到 SOTA。
5. 推理的复杂度不仅在 Transformer 前向，更在每步 token 类型检查、模态 mask、固定 1024 token 图像块生成，以及 GPU-CPU 的阻塞式同步；这些因素限制了部署吞吐，并意味着每生成一张图都要付出额外的自回归 step 成本。

**5 道自测题**：

1. 解释“早融合”与晚融合在计算图上的根本不同，并说明为什么晚融合模型难以原生生成任意交错图文序列。  
2. 写出 z-loss 的数学形式，解释为什么它和 QK-Norm 分别作用于 softmax 的两个不同位置，以及为什么 34B 不需要 dropout 但 7B 需要（在特定配置下）。  
3. Chameleon-34B 的 Transformer block 归一化顺序与 Llama-2 有何不同？为什么 34B 用这种顺序就不能用 dropout？  
4. 如果部署 Chameleon 只做纯文本聊天，哪些推理特殊逻辑可以省略？哪些检查仍然不可避免？  
5. 论文声称 Chameleon 在混合模态生成上优于 GPT-4V 和 Gemini，这个结论依赖了什么实验设计，以及它的脆弱点在哪里？

最终一句话总结：Chameleon 用“把图像变成 token”这条较老的思路，解决了早融合模型规模化训练的新问题，从而在单一稠密 Transformer 中同时获得文本推理、图像理解和图像生成；但它不是全方面最强，其实际价值被限制于图像 tokenizer 的 OCR 上限、巨大的从头训练成本，以及只在 34B 规模验证过的稳定配方，且混合模态能力仍需要更宽的评测和更细致的工程优化才能兑现。
