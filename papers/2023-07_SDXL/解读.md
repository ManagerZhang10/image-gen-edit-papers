# 大白话深读《SDXL》

## 1. 30 秒定位

这篇论文解决的是 Stable Diffusion 在高分辨率、多宽高比文本生成中质量不足、物体被意外裁剪、局部细节差的问题。核心做法是把 UNet 放大到 2.6B 参数，使用双文本编码器得到 2048 维条件上下文，并加入原始尺寸条件、裁剪条件、多宽高比桶训练；再用独立 refiner 模型对 latent 做 SDEdit 去噪。代价是显存与采样成本上升，且需要加载两个大模型。证据上，用户研究显示 SDXL 加 refiner 在四模型投票中胜率为 48.44%，并在 PartiPrompts 上对 Midjourney v5.1 获得 54.9% 偏好；但论文同时承认 FID 与 CLIP 分数不能反映这些提升。

## 2. 为什么这篇论文会出现

Stable Diffusion 作为开放权重 latent 文本到图像扩散模型，已成为很多下游应用的基础，但上一代模型在分辨率、构图和细节上仍明显落后于闭源黑盒系统。与此同时，黑盒模型的架构与数据不透明，使社区难以复现、评估和改进。论文的目标是给开放模型补上高分辨率生成能力，同时保持良好的条件可控性。

三个直接痛点驱动了本文设计。第一，潜在扩散模型训练通常要求最小图像尺寸。直接丢弃小图会损失数据，论文展示其预训练数据中如果丢弃小于 256² 的样本，会损失 39% 的数据；而把小图放大又会引入模糊伪影。第二，随机裁剪是数据增强，但裁剪信息会泄漏到生成过程，造成猫头被切掉等典型失败。第三，常见的 512² 或 1024² 方形输出不符合真实屏幕和照片的自然宽高比分布。最后，论文还指出 FID 和 CLIP 这类自动指标与人类偏好不一致，因此评价方式本身也需要转向用户研究。这些背景共同促成了一套模块化改进：大 UNet、双文本编码器、微条件、多宽高比训练、改进自动编码器和 refiner。

## 3. 方法全景：先看数据流

训练数据流可概括为：

```
原始图像 (h_orig, w_orig)
   -> resize 到目标短边
   -> 采样裁剪参数并裁剪
   -> 冻结的 autoencoder 编码为 latent
   -> 加噪到某离散噪声级
   -> 送入 UNet
      输入: 噪声 latent
      条件: 文本上下文 2048 维 + pooled text 嵌入
           + Fourier(c_size) + Fourier(c_crop) + Fourier(c_ar)
   -> 输出: 对干净 latent 的去噪预测
   -> 与真实 clean latent 计算 denoising score matching 损失
```

推理数据流为：

```
随机噪声 latent
   -> base UNet 多步 DDIM/CFG 去噪
   -> base latent
   -> 可选: refiner 在 latent 空间做 SDEdit
      先加噪到前 200 个噪声尺度之一，再用同一 prompt 去噪
   -> 同一个 autoencoder decoder 解码为图像
```

核心组件拆解如下：

第一，双文本编码器。论文用 CLIP ViT-L 与 OpenCLIP ViT-bigG 两个预训练文本编码器。取二者倒数第二层文本编码器输出，沿通道轴拼接，得到 2048 维上下文张量，喂给 UNet 的 cross-attention。同时，OpenCLIP ViT-bigG 的 pooled text embedding 作为全局文本条件，与其它微条件拼接后注入 timestep embedding。这部分不替换 prompt 文本，而是把同一 prompt 表达成两种上下文。

第二，UNet 骨干。参数量为 2.6B，相比 SD1.x/2.x 的约 860M 明显增大。与旧版不同，SDXL 采用异构 Transformer block 分布：最高特征层不放 Transformer block，低层放 2 个和 10 个，并完全移除 8× 下采样最低层；通道倍率从 [1,2,4,4] 变为 [1,2,4]。输入张量是噪声 latent 与 noise level 条件；输出是同形状的去噪预测。它依赖 cross-attention 读取 2048 维文本上下文。

第三，微条件嵌入。原始图像尺寸 c_size、训练裁剪坐标 c_crop、多宽高比目标尺寸 c_ar 都被独立做 Fourier 特征编码。它们与 pooled text embedding 沿通道拼成一个大向量，再映射到和 noise level 条件相同的通道数，加到 timestep embedding 上。这样 UNet 知道“这张训练图原来是多大、被裁了多少、目标桶是多大”，推理时可反向控制构图和分辨率效果。

第四，自动编码器。论文沿用原始 Stable Diffusion 的自动编码器结构，但用更大 batch size 256 训练并加 EMA，且在 COCO 验证集上重建指标优于旧版。SDXL 和 refiner 均使用这个固定 latent space。对 1024² 输出，base latent 空间尺寸在论文图 1 中写为 128×128。

第五，refiner。它是一个独立 LDM，与 base 共享同一 latent space 和 autoencoder，但只针对高质量、高分辨率数据训练，并专门作用于前 200 个离散噪声尺度。推理时拿到 base latent 后，先加噪到这些低噪声尺度，再用同一 prompt 去噪，目标是改善背景细节和人脸。

## 4. 核心公式与直觉

论文附录给出连续时间扩散模型表述，理解 SDXL 训练和推理只需要两个公式。

第一个是训练目标，即 denoising score matching：

\[
\mathbb{E}_{(x_0,c)\sim p_{\text{data}},\ (\sigma,n)\sim p(\sigma,n)}
\left[ \lambda_\sigma \| D_\theta(x_0+n;\sigma,c)-x_0 \|_2^2 \right]
\]

这里 \(x_0\) 是干净 latent，\(c\) 是条件信号，在本工作中包括文本、c_size、c_crop、c_ar。\(n\) 是方差为 \(\sigma^2\) 的高斯噪声，\(D_\theta\) 是 UNet 去噪网络，输入是加噪 latent 和噪声级，输出预测干净 latent。\(\lambda_\sigma\) 是权重，论文固定为 \(\sigma^{-2}\)；\(p(\sigma)\) 是 1000 个离散噪声级上的分布。直觉是：无论噪声多大，网络都要学会把混噪输入里的干净成分“挖”出来。这个公式直接对应 UNet 的训练步骤和参数更新。

第二个是 classifier-free guidance：

\[
D_w(x;\sigma,c) = (1+w)D(x;\sigma,c) - wD(x;\sigma)
\]

其中 \(w\) 是引导强度，\(D(x;\sigma)\) 是无条件预测。实现上，训练时以一定概率把条件 \(c\) 替换成空嵌入来联合学习条件与无条件模型；SDXL 与常见做法一致，按约 10% 概率替换。推理时，通过放大条件与无条件的差异来增强 prompt 跟随，代价是多样性和某些高频细节的偏移。论文在用户对比中常使用 cfg-scale 8.0，ImageNet 消融用 5.0。两个公式合起来解释了 SDXL 的全部优化动作：训练是回归干净 latent，采样是用外推后的去噪预测沿 ODE 或 DDIM 逐步走回图像。

## 5. 训练与推理怎么跑

训练 step 如下。先从内部数据集取一张图，记录原始高度和宽度作为 c_size。将短边 resize 到目标尺寸 s；根据原图是横图还是竖图，从离散均匀分布采样 crop 上游标 c_top 或左游标 c_left，并裁出固定尺寸。进入多宽高比阶段时，从论文附录 I 的 40 个桶中取一个目标宽高，作为 c_ar，且一个 batch 只使用同一桶，随后交替桶。冻结的 autoencoder 把裁剪后图像编码成 latent；按 1000 步离散 schedule 采样噪声级并加噪。随后把噪声 latent、噪声级条件、pooled text embedding 与 Fourier 编码后的 c_size、c_crop、c_ar 拼接条件一起送入 UNet；cross-attention 读取双文本编码器拼接出的 2048 维上下文。UNet 输出去噪预测，按公式与干净 latent 计算损失，只更新 UNet 参数。自动编码器固定；文本编码器在 SDXL 阶段是否更新，论文未明确披露。refiner 作为独立 LDM 单独训练，限制在前 200 个噪声尺度。

训练阶段安排：先在 256² 固定分辨率下预训练 600,000 步，batch size 2048；再在 512² 继续训练 200,000 步；最后做多宽高比微调，目标面积约 1024²，同时使用 offset-noise 水平 0.05。论文未披露具体训练卡数、总 GPU 时数、数据集规模和文本过滤细节。

推理顺序分两段。base 推理：用户设定目标宽高比、c_size、c_crop=(0,0) 以获得物体居中构图；从随机噪声 latent 开始，反复运行 UNet，配合 classifier-free guidance 和 DDIM 采样器。论文多数评估用 50 步 DDIM、cfg-scale 8.0；ImageNet 消融用 50 步 DDIM、cfg 5.0。base latent 可以直接解码。可选 refiner 推理：将 base latent 用 SDEdit 过程加噪到前 200 个离散噪声尺度中的某一步，再用 refiner 按同一 prompt 去噪，最后解码。这一阶段顺序不能颠倒，且 refiner 只改善细节，不替代 base 的构图生成。

## 6. 实验和消融证明了什么

关键证据如下表：

| 证据 | 任务/数据集 | 指标 | 结果 | 出处 |
|---|---:|---:|---:|---:|
| 尺寸条件消融 | ImageNet 512² 3 个 LDM | FID-5k / IS-5k | CIN-size-cond 36.53/215.34；CIN-nocond 39.76/211.50；CIN-512-only 43.84/110.64 | §2.2 Table 2 |
| 自动编码器重建 | COCO2017 验证集 256² | PSNR/SSIM/LPIPS/rFID | SDXL-V AE 24.7/0.73/0.88/4.4；优于 SD-V AE 1.x 与 2.x | §2.4 Table 3 |
| 四模型用户偏好 | 文本到图像用户研究 | win rate | SDXL w/ refiner 48.44%；SDXL base 36.93%；SD1.5 7.91%；SD2.1 6.71% | §2.5 Fig.1 |
| 与 Midjourney v5.1 对比 | PartiPrompts 用户研究 | prompt adherence 偏好 | 17,153 次比较中 SDXL v0.9 获 54.9% 偏好 | App.E Fig.9 |
| FID/CLIP 与人类偏好背离 | COCO 10k 生成 | FID/CLIP score | SDXL 的 FID 差于 SD1.5 和 SD2.1，CLIP 仅略升 | App.F Fig.12 |

最关键的消融是尺寸条件在 ImageNet 512² 上的结果：它同时优于丢弃小图的 CIN-512-only 和使用全部数据但无条件的 CIN-nocond，直接证明 c_size 能恢复因数据丢弃或放大伪影造成的性能损失。但要注意，这只是类条件 ImageNet，不是文本到图像任务；SDXL 的主要质量结论依赖用户研究，而不是自动指标。

尚未被充分证明的主张包括：c_crop 条件只有定性图，没有定量消融；多宽高比训练没有单独对照训练步骤的定量收益；refiner 的贡献只体现在用户研究的整体 win rate 和定性放大图中，缺少控制变量式的自动指标比较。论文也承认 FID/CLIP 不适合用于此类基础文本生成模型，因此“优于旧版 Stable Diffusion”主要建立在人类偏好而非经典生成指标上。

## 7. 与前作怎么选

| 方案 | 条件与参数量 | 何时选 | 何时不选 |
|---|---|---|---|
| Stable Diffusion 1.5 | 860M UNet，CLIP ViT-L 768 维 | 显存有限、需要大量既有微调生态、只需 512² 方形图 | 需要 1024² 多宽高比、更强 prompt 跟随和更少裁剪伪影 |
| Stable Diffusion 2.1 | 865M UNet，OpenCLIP ViT-H 1024 维 | 需要比 SD1.5 稍强的文本编码且算力仍有限 | 对构图稳定性和局部细节要求高 |
| SDXL base 或 SDXL+refiner | 2.6B UNet，双编码器 2048 维 | 需要高分辨率、多宽高比、开放权重，且能接受更大 VRAM | 只能加载单模型、显存或延迟预算极小、只做低清快速生成 |

SDXL base 已能处理 1024² 级多宽高比输出，并在用户研究中胜率高于旧版。只有在对人脸、背景细节要求更高的场景下，才值得额外加载 refiner。refiner 是可选后缀，不是独立替代品；它不能修复 base 阶段的构图错误或 prompt 丢失。工程上，如果部署环境只允许一个模型，应优先考虑 SDXL base 或后续蒸馏单阶段方案，而不是强行同时挂两个大模型。

## 8. 工程判断与收束

数据方面，论文只展示内部数据集的高度-宽度分布，未披露数据总量、来源配比、去重策略和文本过滤细节。训练步数和 batch size 明确，但总图像量无法直接推算，因为重复采样与数据加载顺序未给出。

算力和延迟方面，论文明确指出两阶段推理需要同时加载两个大模型，影响显存和采样速度，但未披露具体 GPU 类型、训练卡数、单卡显存峰值、端到端延迟或吞吐。基于论文的工程推断，SDXL 的主要推广阻力是消费级显存难以同时容纳 base 与 refiner，以及多步采样在 1024² latent 下带来的时延。

实现难点主要有：多条件嵌入的通道对齐和映射必须严格匹配 noise level 条件维度；多宽高比训练需要按桶组织 batch，并保证不同宽高比下裁剪条件只在桶边界内工作；refiner 的前 200 个噪声尺度选择让 SDEdit 加噪程度不能太大，否则会破坏 base 构图。

最可能失败的环节包括：复杂空间关系与多个对象绑定、人手结构、长文本渲染、概念出血。论文在 Appendix B 明确列出这些失败案例。自动指标上限也不可靠：FID 会惩罚美学偏好，CLIP 评分只与人类判断弱相关，因此后续迭代若只报 FID/CLIP，可能掩盖真实质量变化。

未回答的问题：单阶段模型是否能替代 base+refiner；字节级 tokenizer 是否真正解决长文本；更大 transformer 主导架构是否可行；蒸馏能否在不损失质量下降低推理成本；连续时间 EDM 是否优于当前离散时间加 offset-noise 的设计。

读完必须记住的 5 件事：

1. SDXL 的核心是 2.6B 异构 UNet、双文本编码器的 2048 维条件，以及尺寸、裁剪、宽高比三种微条件。

2. 尺寸条件在 ImageNet 512² 上同时改善 FID 和 IS，是最扎实的消融证据。

3. refiner 是同一 latent space 中的独立 SDEdit 去噪模型，只处理前 200 个噪声尺度，用于细节润色，不是必须环节。

4. SDXL 对旧版的优势主要来自用户研究，FID 反而更差，CLIP 仅略升，经典自动指标不可作为质量判断。

5. 论文未披露训练卡数、数据规模和显存延迟数字，因此开源权重之外的训练可复现性仍受限制。
