# 大白话深读《beyond-accuracy》

## 1. 30 秒定位

这篇论文不训练新模型，而是提出一个评测基准 XTC-Bench，用来检查“统一多模态模型”（Unified Multimodal Models, uMM）在“看图说话/回答”和“文生图”这两件事之间，是否共享同一套语义理解。核心问题是：模型可能生成一张正确图片，却答错关于同一张图片的事实问题；或者反过来，看图答对，但生成时画错。论文把这种底层不一致称为跨任务视觉语义一致性（cross-task visual semantic consistency）。作者用场景图（scene graph）作为统一锚点，同时派生生成提示和 VQA 问题，再比较生成结果解析出的场景图与理解答案。指标叫 CCTA（连续跨任务一致度）和 AW-CCTA（准确率加权版）。实验覆盖 8 个开源 uMM 和 2 个商用系统，结论是：生成/理解分数高不等于一致性好；一致性更多取决于训练目标是否耦合，而不是架构是否统一（§4.2、Table 4/5）。数据集包含 2,000 张手工挑选的图像，提取出超过 31,000 个原子事实，平均每张图 8–10 个对象、11–17 条关系，属性查询与关系查询各占约 40%，对象检索占 16%（Table 1）。这一规模足以在事实粒度上暴露当前 uMM 的系统性语义不对称。

## 2. 为什么这篇论文会出现

现有评测大多把视觉理解与视觉生成拆成两个孤立赛道。理解侧用 VQA 或选择题（MME、MMBench、SEED-Bench），生成侧用文本-图像对齐或感知指标（GenEval、T2I-CompBench++、FID、CLIPScore）。即使像 MME-Unify、UniEval、RealUnify 这些“统一评测”，也只是把两边的分数放在一张表里，没有要求同一个视觉概念在两个方向上的语义必须对齐（§2.2）。换句话说，一个模型可以“生成时知道车是白色和银色”，但“看图时却回答蓝色”，两边都拿到不错的单任务分，内部表示却矛盾。

Fig.1 给出两个直观例子：OmniGen 生成图里车颜色正确（白+银），算生成分 0.85，但对“右前方车的颜色？”却答“blue”，理解分只有 0.45；BAGEL 生成远角视角错误，却能在理解问题中正确回答视角是“从背面”。这说明生成与理解的能力可能来自不同的表示或不同的解码路径，共享架构不保证共享语义。论文认为，真正的统一模型应该让“把概念写出来”和“把概念读进去”得到同一组原子事实。否则，所谓“统一”只是工程层的功能拼接，不是表示级的语义一致。

从研究脉络看，统一多模态模型（Chameleon、Emu3、Janus-Pro、Show-o、BLIP3-o、BAGEL 等）在架构上不断探索共享表示，但评测始终停留在“各自考各自的”。GAPEval 引入了双向性能差距，但它测量的是“理解分和生成分之间的差值”，而不是同一事实在两个方向上的逐点对齐。RealUnify 追问“统一是否真的让一个能力增强另一个”，但也不关心两者是否从同一个结构化语义中派生。XModBench 覆盖跨模态一致性，但局限在单一任务推理格式内。XTC-Bench 的空白正是：没有人把生成提示和 VQA 问题锚定在同一个场景图的事实节点上，因此无法在对象、属性、关系三个粒度上直接比较“你生成的”和“你理解的”是否一致。

## 3. 读懂前需要的最小概念

**场景图（scene graph）**：把一张图拆成节点（物体）和边（关系）。每个节点有类别标签，如 person、car；节点可带属性键值，如颜色=白+银、材质=金属。边是两个物体间的谓词，如 on、in front of、wearing。相比 CLIP 那种整图相似度，场景图能在“事实”粒度做比较：哪辆车、什么颜色、与谁有什么关系。本文的参考场景图来自 COCO 和 Visual Genome，使用 Fair-PSG 预测 57 种谓词，其中包含一个特殊谓词 NR（No Relation），用于表示两个对象之间不存在有效关系（§3.2）。

**统一多模态模型（uMM）**：能在同一架构或共享表示中同时做视觉理解（看图回答）和视觉生成（文生图）的模型。论文把参评模型分为三类：纯自回归（Pure AR，如 OmniGen-2、BLIP3-o、Janus-Pro、Tar）、扩散（Pure Diffusion，如 MMaDA）、自回归+扩散混合（AR+Diffusion，如 Show-o、Show-o2、BAGEL）（§4.2）。这些模型的共同点是声称共享表示，但训练目标耦合程度不同：纯 AR 用同一个 next-token prediction 同时监督文本和图像 token；扩散模型可能在扩散目标与理解目标之间切换；混合模型则同时维护两种生成机制。

**原子事实（atomic fact）**：场景图中一个不可再分的事实，比如“person 的上衣颜色是红、白、黑”，或者“person 站在 skiers 旁边”。生成和理解的比较单位就是这个事实。论文的 VQA 生成保证每个问题只对应一个原子事实；当多个同类别对象同时存在时，使用组合搜索从属性中寻找最短无歧义标识（§3.2 VQA Generation）。

**Hungarian 算法**：一种求解二分图最优匹配的组合优化方法，用于把参考场景图的节点和生成图解析出的节点按相同类别一一对齐，避免直接比较时计数或顺序错位。本文只在相同类别的节点间做匹配，如果两边数量不等，剩余节点被直接丢弃，不参与评分（Algorithm 1）。

**LLM-as-Judge**：用大语言模型给生成/理解答案打 0–5 分，而不是精确字符串匹配，因为“深红”和“暗红”语义相近应得部分分。论文采用 Qwen3-235B 作为主 judge，给每个事实构造一个验证问题（例如：“生成描述是否正确说明这个人穿着红衬衫？”），允许部分语义得分，然后归一化到 [0,1]。

## 4. 方法全景：先看数据流

论文的评测不是一个训练过程，而是一条离线构建 + 在线评估的流水线。数据流如下：

```
参考图像 I
  │
  ├── 分割(kMaX-DeepLab) → 对象mask + 类别
  ├── 关系预测(Fair-PSG) → 候选谓词
  ├── 过滤 + Qwen3-VL验证 → 参考场景图 G
  │
  ├── 从 G 线性化 → 生成提示 P_G ──→ uMM 生成 ──→ 生成图像 I_hat
  │                                                    │
  │                                                    └─ 同一提取管线 → 预测场景图 G_hat
  │
  └── 从 G 派生 VQA 问题 Q = {(q_k, y_k)} ──→ uMM 理解 ──→ 答案 y_hat
                                                          │
                                                          ▼
                                          图匹配(G, G_hat) → 对齐的原子事实
                                                          │
                                                          ▼
                                    LLM Judge 评分 → G, U, CCTA, AW-CCTA
```

**核心组件拆解**：

1. **场景图构建（输入：参考图像；输出：G=(V,E)）**。目的：提供高精度的语义锚点。假设：场景图能忠实表示图像中可视觉验证的物体、属性和关系。实现分三阶段：kMaX-DeepLab 做全景分割得到 mask 和标签；Fair-PSG 预测 57 种谓词；Qwen3-VL-235B 对候选关系做 Yes/No 验证；再用 dual-view（语义聚光灯 + 局部裁剪）让 Qwen3-VL-235B 生成属性。重叠同类别实例≥3 时合并为 meta-node，丢弃内部关系（§3.2）。具体地，分割模型选择 kMaX-DeepLab 是因为它在 COCO val2017 上 Stuff PQ 48.8 最高，而背景区域（如道路、天空、草地）对关系推理至关重要（Appendix Table 9）。Fair-PSG 复现训练后 PredCls 平均准确率 0.77（Appendix Table 10）。

2. **生成提示构造（输入：G；输出：自然语言 P_G）**。目的：把 G 的所有原子事实无损转成可读提示。假设：线性化 + LLM 精炼不会引入幻觉或跨对象属性纠缠。实际采用两阶段：先逐对象精炼，再句子级润色，避免一次性自然化稠密图时属性错绑（§3.2 Prompt Generation）。人类验证表明提示保真度达到 97.15%，对象覆盖 100%，属性覆盖 99.40%（Table 7）。

3. **VQA 生成（输入：G；输出：问题-答案对）**。目的：为每个原子事实生成唯一识别的问题。假设：问题能准确定位目标对象，不被同类别其他对象干扰。对多实例场景使用组合搜索，从属性组合中找最短无歧义标识；关系查询把同对节点间的多条平行边合并成一个综合问题（§3.2 VQA Generation）。组合搜索会先按 k=1,2,... 逐渐增加属性数量，直到找到不与竞争实例重叠的最小属性子集；属性值被小写分词并检测交集或子串匹配（§3.2）。

4. **图匹配（输入：G 与预测 G_hat；输出：对齐的节点/边配对）**。目的：让参考事实和生成事实对应。假设：相同标签的节点在语义上可比。节点按标签分组，用 Hungarian 算法最小化代价矩阵 C = α(1−sim_attr)+β(1−sim_edge)，α=0.7、β=0.3。sim_attr 用 Sentence Transformer（all-MiniLM-L6-v2）嵌入属性值；sim_edge 用边文本及邻居属性做子层 Hungarian。未匹配节点被丢弃，匹配率即 matched nodes（§3.2 Graph Matching、Algorithm 1）。边相似度 sim_val(e, ē) 内部混合了关系文本嵌入和邻居属性相似度，其中关系文本嵌入权重 0.4，邻居属性相似度权重 0.6（Equation 3）。

5. **评分（输入：对齐事实对；输出：G、U、CCTA、AW-CCTA）**。目的：把生成/理解表现和一致性拆开。假设：LLM Judge 给出 0–5 分并归一化到[0,1]。生成分 G 对每个生成事实取平均，理解分 U 对每个 VQA 问题取平均，CCTA 是两边分数差的连续一致度，AW-CCTA 用平均精度加权惩罚一致幻觉（§3.3）。

## 5. 核心公式与直觉

论文的核心公式并不多，最需要理解的是图匹配代价、CCTA 和 AW-CCTA。此外，边相似度内部的加权公式也直接决定图匹配质量。

**图匹配代价（Equation 2）**：

\[
C_{ij} = \alpha (1 - \text{sim}_{\text{attr}}(v_i,\hat v_j)) + \beta (1 - \text{sim}_{\text{edge}}(v_i,\hat v_j))
\]

- \(v_i\) 是参考节点，\(\hat v_j\) 是生成解析出的同标签节点。
- \(\text{sim}_{\text{attr}}\) 是属性相似度：每个属性键的值串接成字符串，用 Sentence Transformer 编码，对键并集求余弦均分；缺失键按 0 处理。
- \(\text{sim}_{\text{edge}}\) 是边结构相似度：对入射边做子层 Hungarian，边相似度又混合关系文本嵌入和邻居属性。论文设定 \(\alpha=0.7\)、\(\beta=0.3\)，原因是消融比较发现 attribute dominance 的节点对齐正确率最高，不同设置影响约 5% 的节点对齐（§3.2）。
- 直觉：先按属性把“同一个东西”对上，再参考局部关系。如果只看关系，可能把两个不同颜色的同类别物体错配；如果只看属性，可能忽略空间上下文。

边相似度内部进一步定义为：

\[
\text{sim}_{\text{val}}(e,\hat e) = 0.4\cdot\cos(z_e,z_{\hat e}) + 0.6\cdot \frac{\text{sim}_{\text{attr}}(u,\hat u)+\text{sim}_{\text{attr}}(v_i,\hat v_j)}{2}
\]

（Equation 3），其中 \(z_e\) 是关系文本“[source_label] [relation] [target_label]”的空间句嵌入。这个 0.4/0.6 权重意味着邻居物体的属性一致性比关系文本本身的嵌入更重要，因为属性往往是精确匹配的关键。

**CCTA（Equation 6）**：

\[
\mathrm{CCTA} = \frac{\sum_{f\in F} w_f \left(1 - |\tilde g_f - \tilde u_f|\right)}{\sum_{f\in F} w_f}
\]

- \(\tilde g_f\) 是生成侧对事实 \(f\) 的归一化 LLM 评分，\(\tilde u_f\) 是理解侧。
- 权重 \(w_f=1\)，表示所有事实等权。
- 如果生成和理解都对或都错，差值小，CCTA 高；一边对一边错，差值大，CCTA 低。它只衡量对称性，不关心正确性，所以可以出现“一致地错”得高分。

**AW-CCTA（Equation 7）**：

\[
\mathrm{AW\text{-}CCTA} = \frac{\sum_{f\in F} w_f \left(1 - |\tilde g_f - \tilde u_f|\right) \cdot \frac{\tilde g_f+\tilde u_f}{2}}{\sum_{f\in F} w_f}
\]

- 在 CCTA 项上乘了联合准确率 \((\tilde g_f+\tilde u_f)/2\)。
- 如果两边都错到 0，AW-CCTA 趋近 0；如果两边都正确趋近 1，AW-CCTA 趋近 CCTA。论文用它暴露“一致幻觉”（consistent hallucination）。
- 工程对应：当你需要部署价值时，只看 CCTA 可能被一个稳定但错误的模型骗到；AW-CCTA 是更实用的排序指标。人类研究显示 raw CCTA 与人类“一致性”轴 Spearman 相关 0.79，但与“可靠性”轴只 0.39；AW-CCTA 则把可靠性相关提升到 0.86（Table 8），证明这个加权公式确实校准到了“有用的一致”而非“稳定地错”。

## 6. 训练到底怎么跑

需要先明确：**这篇论文没有训练任何待评估的 uMM**。如果问“训练流程”，只有两个地方涉及训练或离线拟合：

**一是公平场景图生成器的复现训练**。论文采用两阶段 Fair-PSG 框架，需要训练 Decoupled SceneFormer（DSFormer）。原文没有公开权重，作者复现训练，在 COCO val2017 上 PredCls 平均准确率 0.77（Appendix Table 10）。Fair-PSG 本身包含 57 个谓词类，包括一个特殊 NR（No Relation）谓词。训练数据是 Microsoft COCO，评估遵循 Fair-PSGG 原协议。具体训练超参数论文未披露，只说明与原始 Fair-PSGG 一致，偏差可能来自随机初始化和优化差异（Appendix）。

**二是离线基准构建的“训练/准备”阶段**，可以类比成训练流程：

- 选图：从 COCO 2017 验证集和 Visual Genome 各取 1,000 张，共 2,000 张（Table 1）。这批图是人工挑选的，目的是保证场景语义密度足够高。
- 全景分割：kMaX-DeepLab 对每张图生成对象/背景掩码和标签；该模型在 COCO val2017 上的 PQ 为 58.1，Stuff PQ 48.8（Appendix Table 9）。选择它的理由是 Stuff 类别（背景）对关系推理最重要。
- 关系预测：对每对对象，Fair-PSG 输出 57 个谓词分数；过滤规则是 No-Relation 分数 \(s^{NR}_{ij} > 0.5\) 丢弃，非 NR 谓词分数 \(s^r_{ij} \ge 0.4\) 保留；互斥谓词只保留最高分主体-客体对；同类别重叠实例≥3 才合并 meta-node（§3.2）。互斥谓词指的是 eating/driving 这类一个主体不能同时与多个客体存在的动作；如果多个 subject 对同一 object 具有同一互斥谓词，只保留分数最高的那个 subject-object 对。
- LLM 验证：Qwen3-VL-235B 对候选关系给出 Yes/No，红色框标主体，蓝色框标客体，只保留 Yes 关系。验证提示要求模型只返回 JSON 的 Yes/No，降低解析不确定性（Appendix 6.2）。
- 属性生成：每个对象按 meta-class 对应预定义属性键集，输入 dual-view（语义聚光灯模糊非目标区域+目标 bbox，局部裁剪放在灰色背景），用 CoT 结构化提示生成属性值；Qwen3-VL-235B 为主 judge（§3.2、Appendix 6.2）。属性 meta-class 共 30 个，例如 person、vehicle、animal、furniture 等；每个 meta-class 预定义了可视觉验证的属性键，如 primary color、material type、screen on/off、door open/closed 等（Table 11）。
- 提示与 VQA 生成：用两阶段 LLM 精炼，VQA 组合搜索保证唯一指代。
- 该阶段没有反向传播，也没有学习 uMM 参数；所谓“训练 step”理解为流水线的每次执行。为了可复现，论文比较了 Qwen3-VL-235B、32B、7B 三个 judge 规模，全量开源模型聚合分数在 32B 下 G=0.436、U=0.542、CCTA=0.623、AW-CCTA=0.301，235B 下为 G=0.447、U=0.603、CCTA=0.594、AW-CCTA=0.331（Table 6）。7B 下数值进一步下降，但模型相对排序基本不变。

## 7. 推理到底怎么跑

在线评估时，每一个被评估的 uMM 会经历如下推理顺序：

1. **生成分支**：给模型输入从参考场景图线性化得到的 \(P_G\)，让它生成一张图像 \(\hat I = M_{\mathrm{gen}}(P_G)\)。不同模型可能有不同推理协议，但论文用的是各模型的公开生成接口，未披露额外温度或采样参数。

2. **生成图解析**：把 \(\hat I\) 送入与参考图相同的提取管线：kMaX-DeepLab 分割 → Fair-PSG 关系预测 → LLM 验证 → 属性生成，得到预测场景图 \(\hat G\)。这里注意：属性生成对生成图也使用 Qwen3-VL teacher，而不是让被评估模型自己回答。这意味着生成图解析质量也受 teacher 模型能力限制，如果被评估模型生成的图过于抽象或非自然，teacher 可能提取失败。

3. **理解分支**：给模型输入参考图像 \(I\) 和从 \(G\) 派生的每个问题 \(q_k\)，得到答案 \(\hat y_k\)。理解分支不依赖生成图像，只依赖参考图像。VQA 问题分为三类：对象检索、属性查询、关系查询；分布大致为属性 39.5%、关系 44.6%、对象检索 15.9%（Table 1）。关系查询会把同一对节点间的多条平行边合并为一个综合问题，避免重复。

4. **图匹配**：用 Algorithm 1 把 \(\hat G\) 的节点与 \(G\) 的节点对齐；之后若参考边两端都匹配且 \(\hat G\) 中存在对应边，才认为边匹配。未对齐节点不计入匹配评分。对齐只发生在完全相同的类别标签内；如果生成图没有生成某个对象，或者解析失败，该对象及其所有关联关系的事实就不会进入一致性计算，这可能导致样本选择偏差。

5. **LLM 评分**：对每个原子事实，根据图匹配找到生成侧描述，构造验证问题，让 Qwen3-VL-235B 给 0–5 分；理解侧每个 VQA 答案同样由 LLM Judge 与 ground-truth 比较。分数归一化后计算 G、U，再在共享事实集合 F 上计算 CCTA 和 AW-CCTA（§3.3）。评分模板要求比较 ground-truth 答案和预测答案，0 表示完全错误，5 表示完全正确，允许语义等价的部分分。对人类验证，LLM judge 与人类 0–5 分的 Pearson 相关整体达 0.892（Table 7）。

推理顺序中最重要的解耦是：生成正确性只看生成图解析出的语义，不理解答案；理解正确性只看 VQA，不看生成图；一致性则在事实对齐后比较双方分数。

**最关键消融**：论文没有主实验表格式消融，但描述了三处方法选择。其一是图匹配权重 \(\alpha/\beta\)：比较 attribute dominance、equality、relation dominance 三种配置，发现节点对齐约 5% 不一致，人工检查认为 attribute dominance 最准确，因此设 0.7/0.3（§3.2）。其二是关系过滤阈值：No-Relation 0.5、正谓词 0.4，目的是精度优先，便于 LLM 验证处理高质量候选（§3.2）。其三是属性生成 dual-view：早期简单 crop 或 bbox 会造成目标混淆，比如小物体或分散物体被前景主导；dual-view 显著改善身份消歧和属性识别（§3.2 Attribute Generation）。这些消融属于工程调优，不是主实验对模型架构的消融。另一个重要的稳健性检验是 human study 中五名注释者的 Krippendorff’s alpha：场景图质量 0.78、提示保真 0.75、LLM judge 可靠性 0.84（Appendix Table 12），说明自动管道噪声有限但确实存在。

**尚未证明的主张**：论文明确指出 XTC-Bench 是黑盒评估，不能定位表示在哪一层分叉；没有提出训练或架构修复方案；均匀权重假设未经证实，某些事实在视觉上可能更重要；空间坐标未显式建模，关系比较只是松散语义等价（§5 Limitations and Future Work）。另外，论文只测了 2,000 张自然图像，商用模型只报 G/U，AW-CCTA 未覆盖商用，结论对非自然图像或符号视觉概念的泛化性未知。商用 GPT 模型虽然 Table 2/3 给出了生成和理解分数，但 Table 4 中并未给出 CCTA 或 AW-CCTA，因为作者只把 GPT 作为单任务参考（§4.1 脚注）。这一处理限制了“商用最强但一致性未必最高”结论的直接比较范围。

## 9. 与前作怎么选

**最接近的前作比较**：

- **GAPEval**：也用双向考察理解/生成差距，但测量的是“差距”而非事实级对齐。XTC-Bench 更细，能定位到某个对象的某个属性是否双边一致。若只想看宏观 gap，不关心事实粒度，可选 GAPEval。GAPEval 的不足在于无法区分“两边都错但一致”和“一边对一边错”，因此会对一致幻觉视而不见。
- **RealUnify**：研究一个能力是否增强另一个能力，而不是二者是否从同一语义结构派生。若关注互促关系，选 RealUnify；若关注表示一致性，选 XTC-Bench。RealUnify 的问题是它只能看到能力之间的相关或迁移，不能把同一视觉概念拉到同一事实网格上比较。
- **MME-Unify / UniEval**：统一报单任务成绩，不测量方向间一致性。若只想要一张覆盖多任务的分数表，选 MME-Unify；若要诊断内部语义不对称，选 XTC-Bench。它们适合快速横向对比模型“什么任务强”，但无法回答“模型心里想的是不是同一件事”。
- **XModBench**：考察跨模态一致性，但局限在单一任务推理格式，没有用场景图锚定视觉概念。若跨模态但非视觉事实粒度需求，可考虑 XModBench。不过 XModBench 无法把图像生成内容解析回结构化事实，因此不适合本论文要解决的视觉语义对齐问题。

**何时选 XTC-Bench**：当模型研究目标是“真正共享表示”，需要知道生成和理解是否同构；当你想暴露一致幻觉、衡量事实级对齐；当你有可用的场景图 teacher 和 LLM judge，并能接受 2,000 规模的数据覆盖。如果你主要做统一多模态模型的架构探索，XTC-Bench 能提供传统单任务榜单看不到的诊断信号：例如你的模型 G 和 U 都很高，但 AW-CCTA 很低，说明你的训练目标虽然都拟合了，但感知和生成的内部语义并不同步。

**何时不选**：只做单任务排行榜、需要大规模多样图像、没有算力跑 Qwen3-VL-235B、或任务包含抽象概念/非自然图像等 teacher 不稳定场景；以及需要快速定位架构内部瓶颈时，XTC-Bench 提供不了白盒归因。此外，如果你关心的是生成图像的主观美学或风格多样性，XTC-Bench 的原子事实评分可能过于严苛，会把“艺术化偏差”误判为语义不一致。

## 10. 工程判断：可行性、风险与上限

**可行性**：基准构建流程清晰，依赖公开模型（kMaX-DeepLab、Fair-PSG、Qwen3-VL 系列）。可替换为 32B/7B judge，实验显示排序基本不变，说明资源受限可复现。但初始构建仍需要训练 Fair-PSG 的 DSFormer，且主 judge 是 235B，单次全量评估的推理成本偏高（§4.3）。如果你只是想复现排序，可以用 7B judge 把成本降低一个量级，但要接受 AW-CCTA 均值从 0.331 降到 0.273 的绝对分数下降。

**数据**：2,000 张来自 COCO/VG 的自然图像，场景语义密度高（平均 8–10 对象、11–17 关系）。但覆盖类别有限，30 个 meta-class，属性键比较粗，没有年龄、性别表现等细节（§5）。扩展需要更多标注与 teacher 能力。当前数据源均为自然照片，对于医疗影像、工业缺陷、抽象艺术或符号推理场景，teacher 模型可能无法给出可靠场景图，因此不能直接迁移。

**算力/延迟**：每张参考图要跑分割、关系预测、属性生成、VQA 生成；每个模型要跑生成、再跑生成图解析；最后 LLM Judge 对每个事实评分。若按 31,000 事实、多个模型、235B judge 计算，总推理 token 量巨大。实际部署建议先用 32B/7B 复现，确认排序趋势后再用 235B 精算。注意生成图解析也需要对每一张生成图重新走完整提取管线，这意味着被评估模型的推理成本之外，还叠加了固定的 teacher 成本。

**实现难点**：场景图精度是核心瓶颈；关系预测容易召回虚高，需要阈值+LLM 验证；属性生成易受目标混淆影响，需要 dual-view；图匹配的超参数和相似度计算会直接影响结果；LLM-as-Judge 偏向可能系统性高估或低估某些谓词。论文在附录中展示了谓词级别的 PredCls 性能（Table 10），许多罕见关系（如 kissing、picking、opening）的 F1 接近 0，说明这些关系即使经过 LLM 验证，也容易在 teacher 层面产生缺失或误判。

**失败环节**：高抽象或非自然图像；多个同类别物体高度重叠；罕见关系和复杂属性；teacher model 对不确定属性（如材质）不稳定；生成图解析时如果模型没生成参考图中的对象，连接率下降，可能高估“已生成部分”的语义准确率。论文明确提到，材质属性会出现跨运行不一致（同一张床一次被描述为“粗糙”，另一次为“光滑织物”；金属物体被标为“木质”），因此他们把属性限制在可高置信度视觉接地的键集内（§3.2 Attribute Generation）。

**监控信号**：应同时监控 CCTA 与 AW-CCTA 的差值。如果差值大，可能正在经历一致幻觉；监控 matched nodes 比例，若过低则 G/U 比较的样本有偏；监控 G-U gap 和架构族均值，判断是否生成侧系统性偏弱；监控 LLM judge 的相关系数或人工抽检，防止 judge 漂移。具体而言，MMaDA 的 CCTA 0.630 与 AW-CCTA 0.144 的差值就是一致幻觉的红色警报；如果某个新模型的这个差值超过 0.3，就应该怀疑它只是稳定地错。

**指标上限**：CCTA 和 AW-CCTA 理论上限都是 1，但受限于 teacher 场景图提取质量、LLM judge 评分噪声、生成图解析与参考图解析的不对称，实际可及上限可能低于理想值。论文中最佳 AW-CCTA 只有 0.623，说明即使最强的 Gemini，仍存在明显语义不对齐。这个上限本身也是问题：如果 teacher 的原子事实有 5–6% 的错误，那么一致性的天花板就被压低了。场景图人类评估的准确率是 94.02%，提示保真度 97.15%，这意味着即使被评估模型完美，自动管道也会引入约 6% 的噪声事实，从而把理论 AW-CCTA 压低到 0.94 左右的上限（基于地面事实噪声的估算，论文未给出这一推算，属工程推断）。

**未回答问题**：内部机制归因缺失；没有提出任何提高一致性的训练约束、双向损失或推理自检；事实权重均匀假设未验证；空间坐标未显式表示；静态图像限制；商用模型未参与 AW-CCTA 完整评估；规模仅 2,000 图像的泛化性未证明。此外，虽然论文说“目标耦合比架构统一更重要”，但并未给出可操作的训练目标修改方案，也没有验证哪一类具体损失项能提高 AW-CCTA。

## 11. 放回研究脉络并收束

这篇论文站在“统一多模态模型”评估的交叉点：过去理解与生成各打各的，之后出现统一排行榜但只做并列，再到本文用场景图把两边绑在同一组事实网格上。方法上它借用了场景图生成、词嵌入相似度、LLM-as-Judge 等成熟工具，把它们组合成对一致性敏感的探针。从研究趋势看，统一模型正从“能同时做多件事”走向“做的是不是同一件事”。XTC-Bench 把“语义一致性”从哲学口号变成可计算的指标，并且通过 AW-CCTA 把“一致但错”的伪一致性也纳入诊断。

**读完必须记住的 5 件事**：

1. **一致性是独立于单任务精度的第三维**：G 和 U 高不能推出 CCTA 或 AW-CCTA 高，实验里 BAGEL 开源双第一但 AW-CCTA 仅 0.569，而 Gemini G/U 都不是最高却拥有最高的 AW-CCTA 0.623。这说明优化单任务指标可能不会自动带来表示级对齐。
2. **场景图提供事实级对齐**：它把“生成是否正确”和“理解是否正确”都归约到同一组对象、属性、关系上，从而能计算逐事实的 |g−u| 差值。没有场景图，你只能比较两个整体分数，无法定位到底是哪个对象、哪个属性、哪条关系发生了分裂。
3. **CCTA 与 AW-CCTA 是互补诊断**：raw CCTA 查对称性，AW-CCTA 罚一致错误；MMaDA 的 0.630 vs 0.144 是最佳例证。如果只看 CCTA，MMaDA 会排到开源第三，但它的实际效用接近零。
4. **目标耦合比架构统一更重要**：纯 AR 组的平均 AW-CCTA 最高，纯扩散虽然 gap 小但一致错误严重，AR+Diffusion 的组内跨度最大，说明混合目标很难调好。架构“看起来统一”并不自动让表示同步，真正起作用的是训练时多模态目标是否互相约束。
5. **当前 uMM 存在系统性的生成-理解不对称**：几乎所有模型理解分高于生成分，说明了训练目标偏向感知接地，生成忠实度不足。Fig.4 中绝大多数模型位于 G=U 对角线之上，表明理解比生成更成熟，这种不对称会直接拉低 AW-CCTA。

**5 道自测题**：

1. 为什么一个模型可以生成正确颜色但理解时答错颜色？从“共享表示”角度看，这个现象意味着什么？
2. XTC-Bench 从哪里同时得到生成提示和 VQA 问题？使用场景图作为锚点解决了什么比较难题？
3. 图匹配代价 C_{ij} 中 α=0.7、β=0.3 的选取依据是什么？如果 α 降到 0.3，可能会发生什么对齐错误？
4. MMaDA-8B 的 raw CCTA 是 0.630，但 AW-CCTA 只有 0.144。这两个数字共同说明了什么，为什么单独看 CCTA 会被误导？
5. 论文说“一致性由目标耦合而不是架构统一决定”，表格中哪一项证据直接支持这句话？请指出具体数字和模型族。

**最终一句话总结**：XTC-Bench 用场景图把视觉生成与理解钉在同一组事实上，证明了当前统一多模态模型普遍存在“功能统一、语义分裂”，并且给出 CCTA/AW-CCTA 两把尺子把这种分裂量化为可监控、可诊断的指标。
