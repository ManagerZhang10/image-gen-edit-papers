# 大白话深读《Transfusion》

## 1. 30 秒定位

《Transfusion》提出一种训练单个 Transformer 同时处理离散文本与连续图像的方法。文本部分沿用语言模型的标准“下一 token 预测”（next token prediction），图像部分沿用扩散模型（diffusion）的去噪目标，两者共享同一个 Transformer 主体。图像不经过离散量化，而是通过变分自编码器（VAE，Variational Autoencoder）编码成连续隐向量，再切成 patch 向量进入序列；文本与图像序列用特殊标记 BOI/EOI 分隔。注意力方面，文本 token 使用因果注意力（causal attention），同一图像内部的 patch 之间使用双向注意力（bidirectional attention）。论文在控制条件下与离散图像 token 的 Chameleon 方法比较，显示 Transfusion 在文本和图像生成任务上以更低计算量达到同等或更好表现。论文训练了 0.16B、0.37B、0.76B、1.4B 和 7B 五种规模的模型（Table 2），其中最大的 7B 模型在 2T 多模态 token 上训练后，文本能力与 Llama 1 相当，图像生成质量接近部分扩散模型，同时具备图像编辑等混合模态能力。

## 2. 为什么这篇论文会出现

多模态生成模型需要同时处理离散元素（文本、代码）和连续元素（图像、音频、视频）。语言模型在离散模态上占据主导，扩散模型则在连续模态生成上表现最优。已有融合方案大致分两类：一类是让语言模型调用扩散模型，或把预训练扩散模型接到语言模型上，例如 GILL、DreamLLM 等；另一类是把连续模态量化成离散 token，再用标准语言模型统一训练，例如 Chameleon 和 DALL-E。量化方法简化了架构，但引入了信息瓶颈，会损失连续信号的细节。论文认为这种信息损失并不必要，提出直接在一个 Transformer 里对文本做分类式预测、对图像做回归式去噪，让两种模态共享参数与数据流，同时保留各自最合适的训练目标。作者希望证明这种“混合损失”方法不仅能工作，而且在计算效率上优于量化路线。论文中特别强调，Transfusion 不是为了替代单模态模型，而是提供一个端到端的多模态统一方案，使文本生成与图像生成不再割裂。

论文通过受控对比（controlled comparison）来支撑这一主张：Chameleon 和 Transfusion 使用完全相同的 VAE 训练数据、计算和架构，唯一区别是 Chameleon 的 VQ-VAE 含有量化层和 codebook loss（§4.1 Baseline）。Chameleon 还引入了 query-key normalization、post-normalization、denominator loss 和更低的 1e-4 学习率来管理训练不稳定性，这些稳定性修改本身也带来了效率代价（§4.1，Table 4）。Transfusion 在这样的公平设定下，以明显更少的计算达到同等或更好的多模态表现，这是论文的核心卖点。

## 3. 读懂前需要的最小概念

**下一 token 预测（LM 目标）**：给定前文 token，预测下一个 token 的概率分布，用交叉熵训练。文本的每个位置都以分类方式计算损失。语言模型将序列概率分解为条件概率的乘积，即 P(y) = ∏ᵢ P_θ(yᵢ|y_{<i})（§2.1，式 1）。

**扩散模型（Diffusion）**：训练时对干净样本逐步加高斯噪声，模型学习从带噪版本预测噪声；推理时从纯噪声开始迭代去噪。论文采用 DDPM 形式，噪声调度用 cosine（§2.2）。扩散的前向过程定义了一个马尔可夫链，逐步添加高斯噪声，但通过重参数化技巧可以直接从 x₀ 采样 x_t，无需逐步迭代。

**重参数化（Reparameterization）**：公式 `x_t = sqrt(α_bar_t) x_0 + sqrt(1-α_bar_t) ε` 允许一步从干净样本和噪声得到任意时间步的带噪样本，这是扩散训练高效实现的关键。α_bar_t = ∏_{s=1}^{t} (1-β_s)，β_s 按 cosine schedule 随 s 递增（§2.2）。

**潜空间图像表示（Latent Image Representation）**：用预训练 VAE 将 256×256 像素图像编码为 32×32×8 的张量，每个 8 维向量概念上对应 8×8 像素块，避免直接在像素空间做扩散。论文的 VAE 有 86M 参数，训练 1M 步（§4.1），使用 L1 + LPIPS + 0.5 GAN + 0.2 ID + 0.000001 KL 的组合损失（Appendix A）。GAN 训练延迟到 50,000 步开始，以先保证重建质量。

**Patch 化（Patchification）**：将 32×32 的潜空间网格按 k×k 窗口分组，每组通过线性层或 U-Net 下采样块压缩为一个向量，作为 Transformer 的输入元素。例如 2×2 patch 得到 256 个 patch 向量，8×8 patch 得到 16 个 patch 向量（§3，Table 6）。1×1 即不压缩时为 1024 个元素。

**BOI/EOI token**：离散的特殊标记，分别表示图像序列的开始与结束，让模型知道何时切换到扩散模式或文本模式。图像 patch 序列被 BOI 和 EOI 包围后插入文本序列中（§3 Data Representation）。

**因果注意力与双向注意力**：文本生成必须只看左侧，因此是因果掩码；但图像内部像素/patch 没有自然顺序，应允许多方向信息流。Transfusion 对每个图像内部使用双向注意力，对跨模态和文本仍保持因果（§3 Transfusion Attention，Figure 4）。

**U-Net down/up blocks**：论文比较的第二种 patch 编码/解码方式。U-Net down 将 k×k 局部窗口的潜向量压缩为单个 Transformer 向量，U-Net up 执行反向操作。论文将 U-Net 中的 AdaLayerNorm 替换为普通的 layer norm（§3 脚注 7）。U-Net 层内部含有自己的双向注意力，独立于 Transformer 的注意力掩码。

## 4. 方法全景：先看数据流

论文方法围绕一个主干 Transformer、两个模态特异的轻量编码/解码器，以及混合损失。下图给出训练时的一条混合序列数据流：

```
文本: "A cute cat ." -> tokenizer -> [text embeddings]
                                                    \
                                                     +--> [Transformer] --> 输出向量
图像: raw pixels -> VAE encoder -> latent x0 -> noise -> xt -> patchify -> [线性/U-Net down] -> 输入向量
                                                     /
序列构成为: [text tokens] BOI [image patch vectors] EOI [text tokens] ...
        
输出侧:
  文本位置输出 -> text head -> 词表 logits -> LM loss (交叉熵)
  图像位置输出 -> 线性/U-Net up -> 噪声预测 ε_hat -> diffusion loss (MSE)
```

**核心组件**：

- **VAE 编码器/解码器**：预训练，参数 86M，将 256×256 图像变成 32×32×8 潜张量。它本身不是 Transfusion 训练的一部分，只用于准备连续图像表示。假设：低维潜空间能保留足够信息，且比像素空间节约计算。训练损失为 L1 + LPIPS + 0.5 GAN + 0.2 ID + 0.000001 KL，GAN 从 50k 步开始（Appendix A）。

- **Patch 编码器**：把 k×k 个 8 维潜向量压缩成 Transformer 的 d 维输入。论文比较了两种：简单线性层，以及 U-Net 下采样块（U-Net down）。线性层参数极少（<0.5% 总参数）；U-Net down 带有内部双向注意力，参数量大。输入中还会加入时间步 t 的嵌入（§3 脚注 6），加在 patchify 之前。目的：把图像变成与文本 token 相同维度的向量序列，并控制序列长度。

- **Transformer 主体**：Llama 风格，含 SwiGLU 激活和 RoPE（§3 脚注 4）。处理整个混合序列，输出同样维度的向量。文本 token 产生离散分布，图像 patch 产生噪声预测。假设：一个共享 Transformer 能同时学习两种模态的表征。论文用五种配置：0.16B（16 层，768 维，12 头）、0.37B（24 层，1024 维，16 头）、0.76B（24 层，1536 维，24 头）、1.4B（24 层，2048 维，16 头）、7B（32 层，4096 维，32 头）（Table 2）。

- **注意力掩码**：整个序列采用因果注意力，但同一图像内部的 patch 之间不受因果限制，可以互相看到。因此图像 patch 可以依赖同图中任意位置，文本和后续图像只能看到之前的元素（Figure 4）。表 5 显示这个设计至关重要。

- **文本头**：将 Transformer 输出映射到词表概率分布。用于 LM 损失。文本的 embedding 矩阵同时负责输入向量化和输出词表映射（§3 Model Architecture）。

- **Patch 解码器**：线性或 U-Net up，将 Transformer 输出映射回潜空间 patch，预测该时间步的噪声。U-Net up 同样有参数和归纳偏置。U-Net 的 AdaLayerNorm 被替换为普通 layer norm（§3 脚注 7）。

- **损失组合**：`L_Transfusion = L_LM + λ·L_DDPM`，其中 λ 论文设为 5（§3 式 4，§4.1 Optimization）。LM 损失逐文本 token 计算，BOI 不计算损失（§3 脚注 8）；扩散损失按整个图像计算，对所有 patch 的 MSE 汇总（§3 脚注 9 "per image"）。

**训练时的假设**：文本与图像可以共享同一序列和 Transformer；不同模态使用不同损失不会互相干扰到无法训练；图像 patch 的双向注意力能提供图像生成所需的空间一致性；扩散噪声加在 patchify 之前意味着下游 token 会看到带噪图像，这在噪声受限实验中（Table 8）被验证有助于提升图像理解的条件表示。

## 5. 核心公式与直觉

论文的贡献可以压缩为四个公式。我们逐一解释变量和工程对应。

**公式 1：语言模型损失（式 1）**

`L_LM = E_{y_i}[-log P_θ(y_i | y_{<i})]`

`y_i` 是词表中一个离散 token，`P_θ` 是模型对下一个 token 的条件概率分布。优化动作是最大化真实 token 的对数概率，即最小化交叉熵。工程上，文本位置的 Transformer 输出向量经过一个线性层做词表 softmax，损失只在文本 token 且不是 BOI 的位置上计算。这个损失让模型保持文本生成和文本理解能力。

**公式 2：扩散噪声重参数化（式 2）**

`x_t = sqrt(α_bar_t) x_0 + sqrt(1-α_bar_t) ε`

`x_0` 是干净的图像潜向量，`ε` 是从标准高斯采样的噪声，`α_bar_t` 是时间步 t 的累积噪声系数，由 cosine scheduler 决定（§2.2）。`α_bar_t = ∏_{s=1}^t (1-β_s)`，其中 β_s 按 cosine 曲线随 s 增大。这个公式让训练时不需要逐步加噪，直接用随机 t 和 ε 构造带噪输入。工程上，每个图像在进入 patch 编码器前先根据 sampled t 加噪；模型输入是 `x_t`，要预测的是 `ε`。这是扩散训练的常用技巧。

**公式 3：扩散损失（式 3）**

`L_DDPM = E_{x_0, t, ε}[||ε - ε_θ(x_t, t, c)||^2]`

`ε_θ` 是模型预测的噪声，函数输入为带噪潜向量 `x_t`、时间步 `t` 和上下文 `c`（如文本条件）。优化动作是最小化预测噪声与真实噪声之间的均方误差。工程上，图像位置的 Transformer 输出通过 patch 解码器映射回潜空间，与真实噪声计算 MSE。损失按图像汇总，而不是按 patch 逐个计算（§3 脚注 9），目的是让模型在图像级别学习去噪。时间步 t 的嵌入被加到每个 patch 向量上（§3 脚注 6）。

**公式 4：总损失（式 4）**

`L_Transfusion = L_LM + λ·L_DDPM`

λ 是两种损失的平衡系数，论文设为 5（§4.1），但明确说明这是初步实验的选择，未做系统调优。工程上，每个训练 step 的 batch 同时包含文本和图像，两种损失相加后反向传播。这个公式是整个方法的核心：让同一个模型同时优化离散分类和连续回归两种目标，共享参数但没有互相蒸馏或量化。论文将其视为一个更广泛想法的具体实例：把离散分布损失与连续分布损失结合，用同一模型优化（§3）。

**直觉**：LM 损失在离散分布空间工作，扩散损失在连续向量空间工作；Transfusion 不做统一，而是把两件事放在一个序列、一个 Transformer 里同时做。图像 patch 的连续向量直接影响文本 token 的注意力上下文，文本 token 也直接影响图像去噪条件，双向信息流贯穿整个训练过程。

## 6. 训练到底怎么跑

以下是一个标准训练 step 的流程，以论文主实验配置（batch 2M tokens，序列长度 4096）为例。小实验训练 250k 步总 0.5T tokens，大实验 batch 4M tokens 训练 500k 步总 2T tokens（§4.1 Optimization）。

1. **采样数据**：从训练集中采样文本和图像对。文本用 Llama 2 tokenizer 转成整数 token；图像先中心裁剪并缩放到 256×256，再通过预训练 VAE 编码得到 32×32×8 潜张量。图像与文本按 1:1 token 比例混合（§4.1 Data），80% 的时候 caption 在图像前，20% 时图像在 caption 前。小实验用 380M 授权的 Shutterstock 图片及其 caption（§4.1 Data）；大实验混合 692M 图片/epoch，包含 Shutterstock、220M 公开图片（预过滤不含人物）、CC12M，并升采样 80M 含人物的 Shutterstock 图片以重新平衡分布，最后 1% 训练步升权重高美学图片（§4.1 Data）。

2. **构造混合序列**：把文本 token 嵌入成向量，图像潜张量按 patch size（如 2×2 latent pixels）切成 patch 向量。每个图像 patch 向量经过线性层或 U-Net down 压缩到 Transformer 的隐藏维度。序列中在图像前插入 BOI，图像后插入 EOI。序列长度控制为 4096。patch size 决定每张图像的序列元素数：1×1 为 1024 个，2×2 为 256 个，4×4 为 64 个，8×8 为 16 个（Table 6）。

3. **前向传播**：整个序列输入 Llama 风格 Transformer。注意力掩码遵守因果规则，但同一图像内部的 patch 可以互相看到（§3，Figure 4）。Transformer 输出：文本位置进入文本头得到词表 logits；图像位置进入 patch 解码器（线性或 U-Net up）得到噪声预测。

4. **计算损失**：对文本 token（不包括 BOI，§3 脚注 8）计算交叉熵 LM loss；对每组图像 patch 计算 MSE 扩散损失。两者加权相加，λ=5。特别地，如果图像在文本前（20% 情况），该图像对应的扩散噪声在部分实验中被限制到 t≤500（Table 8），以降低后续文本条件受到的噪声污染。

5. **反向传播与优化**：梯度裁剪范数 1.0，AdamW 优化器（β1=0.9, β2=0.95, ε=1e-8），学习率 3e-4，前 4000 步 warmup，之后余弦衰减到 1.5e-5。权重衰减 0.1（§4.1 Optimization）。所有参数随机初始化（无预训练）。

6. **多规模训练**：小实验训练 250k 步，batch 2M tokens，总数据 0.5T tokens。大模型实验 batch 4M tokens，训练 500k 步，总数据 2T tokens，其中文本 1T，图像约 3.5B 张并含 caption，接近 1T 个 patch/token（§4.4）。大实验的 U-Net up/down 层增加了约 0.27B 参数，相对于 7B 主干的增幅为 3.8%，与文本 embedding 参数相当（§4.1 Model Configuration）。

**重要点**：扩散噪声是在 patchify 之前加到潜图像上，这意味着下游 token 在训练时看到的是带噪图像，而不是干净图像（§3 脚注 9）。论文通过 noise limit 实验（Table 8）发现，图像在文本前时限制最大 t≤500 能显著提高 image-to-text 的 CIDEr（0.76B 模型从 25.4 增到 29.4；7B 从 33.7 增到 35.2），说明过度噪声会损害图像作为文本条件时的表示质量，而其它 benchmark 受影响小于 1%。

## 7. 推理到底怎么跑

推理阶段根据输入提示自回归生成文本，并在需要时切换到扩散模式生成图像。论文的 decoding 算法（§3 Inference）如下：

1. **文本模式初始化**：输入 prompt 经 tokenizer 和 embedding 后进入 Transformer。每次从模型输出的词表分布中采样一个 token。论文在文本基准上使用贪婪解码；对于 Llama 2 评估套件使用排序分类（ranked classification）（§4.1 Inference）。

2. **检测到 BOI**：当模型采到 BOI token，表示接下来要生成图像。此时停止文本 token 采样，切换到扩散模式。

3. **图像生成初始化**：决定生成图像的 patch 数量 n（由设想的图像尺寸决定，例如 256×256 且 patch size 2×2 时为 256 个 patch）。生成 n 个纯高斯噪声向量 `x_T`，追加到序列中 BOI 之后（§3 Inference）。

4. **迭代去噪**：从 t=T 到 t=1 循环。每个时间步，将当前序列（其中图像部分为 `x_t`）输入 Transformer，取图像位置的输出通过 patch 解码器得到噪声预测 `ε_θ`。根据噪声调度将预测噪声从 `x_t` 中按比例移除，产生 `x_{t-1}`，并用它覆盖序列中的图像 patch。模型始终只看到最后时间步的带噪图像，不能看到过去时间步（§3 Inference）。推理时使用 250 步去噪，训练时是 1000 时间步（§4.1 Inference），也就是说训练和推理的时间步数不一致，这在扩散模型中是常见实践。

5. **使用 CFG**：分类器自由引导（classifier-free guidance，Ho & Salimans）通过同时计算条件预测和无条件预测来增强图像质量。论文在 controlled 实验用 CFG 系数 w=5（与 Chameleon 相同），ablation 实验用 w=3，大规模实验对每个 benchmark 单独调 w（§4.1 Inference）。CFG 需要每步前向两次 Transformer（一次条件、一次无条件），因此计算翻倍。

6. **结束图像生成**：去噪完成后，追加 EOI token 到序列，切回文本模式，继续自回归生成后续内容。整个过程可以生成任意交错的文本和图像（§3 Inference）。

7. **文本生成细节**：LM 模式下使用 temperature 和 top-p 截断（论文提及标准做法，但具体数值未明确除 greedy 外）。图像生成从 1000 个训练 timesteps 中抽取 250 步推理，显著减少计算量。

**注意**：推理时 CFG 会使图像生成计算加倍，因为同一序列要过两次 Transformer。patch size 增大（如 8×8 每图 16 patches）可以降低序列长度和注意力成本，论文称服务成本最多可降 64×（从每图 1024 patch 降到 16 patch，约 64 倍，§4.3.2）。但图像推理仍需 250 步，每步并行处理所有 image patches，因此扩散步数带来的延迟不因 patch 压缩而减少。

**与 Chameleon 的受控缩放对比（§4.2）**：论文用 FLOPs 代理量 6ND（N 为参数量，D 为 token 数）来画 scaling laws（Figure 5），对每个 benchmark 在 log-metric vs log-FLOPs 上回归线性趋势，并估计 parity FLOP ratio。Table 3 显示在 FID 上 Transfusion 的 parity ratio 是 0.029，意味着 Transfusion 只需 Chameleon 大约 1/34 的计算量就能达到同等的 FID；在 CIDEr 上 parity ratio 为 0.218，即约 1/5 的计算量；在 C4 PPL 上为 0.489，Wikipedia PPL 上为 0.526，Llama 2 eval accuracy 上为 0.600。注意：由于 Transfusion 用连续表示可以更少 token 表示一张图像，会缩短文档长度从而减少注意力成本，这一优势在 FLOPs 计算中被刻意移除（使用理论 FLOP 而非实际测得），以公平比较（§4.2 脚注 15）。

**Chameleon 的稳定性修改**（Table 4）：0.76B 实验显示 Chameleon 从 Llama 2 recipe 开始加入稳定性修改后，即使只训练 text tokens（1M），C4 PPL 从 10.1 增到 11.0，Llama Acc 从 53.7 降到 51.9；再加入 LM loss 处理图像 token 后，C4 PPL 进一步增到 11.8，Llama Acc 降至 48.9。Transfusion 加入 diffusion loss 和图像 patches 后 C4 PPL 仅从 10.1 增至 10.4，Llama Acc 降至 51.7。这说明 Chameleon 的文本性能下降部分来自稳定性修改，部分来自量化图像 token 对文本输出分布的竞争；Transfusion 的扩散损失对文本的冲击明显更小。

**最关键消融**是注意力掩码实验（Table 5）。线性 patch 编码器下，将图像内部双向注意力改成纯因果注意力，FID 从 20.3 恶化到 61.3，说明图像 patch 需要同时看到整个图像的空间上下文才能有效去噪。U-Net 编码器本身含有双向注意力，所以 U-Net 变体下 FID 差距较小（16.7 vs 16.8），但 CIDEr 仍从 23.3 升到 25.4（越高越好）。这证明不仅仅是有 U-Net 就够，Transformer 层的双向图像注意力对于文本到图像和图像到文本都有帮助。

**U-Net 与 patch size 联合消融**（Table 6 和 Table 7）证明：即使 Transformer 主体固定，U-Net down/up 编码器相比线性层带来了明显的图像质量提升，尤其在 patch size 增大时。8×8 patch 下，U-Net 变体保持 FID 16.1 和 CIDEr 29.5，而线性变体 FID 43.5、CIDEr 11.3。论文进一步解耦参数增加与归纳偏置：把 7B 主干与固定的 U-Net 参数（0.27B，仅占 3.8%）结合，U-Net 仍然带来 FID 从 18.6 降到 16.0（Table 7），说明收益不仅来自参数增加。论文也承认 U-Net 层没有随 Transformer 扩展，这是未来可以探索的方向（脚注 17）。

**尚未证明的主张**：  
- 7B Transfusion 在 GenEval 上 0.63 落后于 SD 3 的 0.68；论文承认 SD 3 使用了合成 caption 通过 backtranslation 来增强，其 GenEval 提升了 6.5 个绝对点（0.433→0.498），自己的实验只用自然数据，没有在相同数据条件下比较（Table 9 脚注）。  
- 图像编辑只在 8k 公开示例上微调（受 LIMA 启发），结果是人工检查的随机样例（Figure 6, Appendix C），没有数值指标，因此泛化能力未定量证明。  
- 论文没有在音频、视频等其它连续模态上验证 Transfusion 的通用性。  
- λ=5 只是初步实验的选择，没有系统调优，更大或更小 λ 的影响未回答（§4.1 Optimization）。  
- 用 flow matching 替代 diffusion loss 的影响被留作未来工作（§3）。  
- 参数量为 7B 的最大模型仍低于当时最先进扩散模型的一些指标，不能断言 Transfusion 已经全面超越扩散模型。  
- 在 scaling laws 实验中，较小的 Chameleon 模型在图像任务上表现差到出现离群点，因此使用了最小性能阈值（≤100 FID、≥17 CLIP、≥4 CIDEr）来移除这些点（§4.2 脚注 16）。

## 9. 与前作怎么选

**Transfusion vs Chameleon（离散图像 token + 语言模型）**  
Transfusion 的优势是保留连续图像表示，避免了量化信息瓶颈，在相同模型和计算下图像生成 FID 明显更低，文本 perplexity 也更好。论文表 3 的 parity FLOP ratio 显示 Transfusion 用约 1/34 计算达到 Chameleon 相同 FID，约 1/5 计算达到相同 CIDEr，约一半计算达到相同文本困惑度。另一方面，Chameleon 的特点是实现了完全离散的统一序列，训练目标单一，架构无需处理连续向量和扩散采样，且无需处理 BOI/EOI 的模式切换。  
**何时选 Chameleon**：如果工程上只想维护一套离散 token 流程，或者图像生成质量要求不高、文本为主；或团队已有大规模离散多模态训练经验，且可以接受其稳定性修改带来的效率代价。  
**何时选 Transfusion**：需要同时生成图像和文本，且图像质量重要，不想承受量化损失，愿意处理混合精度和扩散推理。

**Transfusion vs 拼接式多模态模型（如 Flamingo、LLaVA、GILL、DreamLLM）**  
这些模型通常把预训练语言模型与视觉编码器/扩散模型连接，组件独立预训练，通过投影或微调对齐。优点是训练成本低、可以复用大规模单模态模型。缺点是模态之间不是端到端共享参数，跨模态生成和推理可能受限。论文指出这些方法要么只覆盖视觉理解（Flamingo、LLaVA），要么只覆盖视觉生成（GILL），或同时覆盖但架构割裂（DreamLLM）；Transfusion 则是一个统一的端到端学习架构（§5 Related Work）。  
**何时选拼接式**：任务相对单一（如视觉问答或图像生成），且已有强大的单模态模型可以复用，预算有限。  
**何时选 Transfusion**：追求真正的多模态联合生成与理解，需要模型具备图像编辑、图文穿插输出等复杂能力，且愿意从头训练或大规模预训练一个统一模型。

**Transfusion vs 纯扩散模型（如 SDXL、DeepFloyd、SD 3）**  
纯扩散模型在文本到图像生成上可能更强（尤其使用更好的 caption），但它们通常需要单独的文本编码器，不能生成文本。Table 9 显示 Transfusion 的 COCO FID 6.78 略差于 DeepFloyd 的 6.66，GenEval 0.63 优于 SDXL 的 0.55 和 DeepFloyd 的 0.61，但低于 SD 3 的 0.68。  
**何时选纯扩散**：只做图像生成，或需要最高图像质量，且不在意文本生成能力。  
**何时选 Transfusion**：需要一个模型同时输出文本和图像，例如对话中生成图片并配文字说明；或需要按文本指令编辑图像（§4.5 的 8k 微调展示了初步能力）。

**总体判定**：如果任务要求统一生成离散和连续模态，且训练资源允许从头预训练一个 7B 级模型，Transfusion 提供了比离散量化更高效且不损失信息的方法。若只聚焦单模态或资源有限，则前作方案更成熟。

## 10. 工程判断：可行性、风险与上限

**数据**：训练需要大量成对图像-文本数据。小实验 0.5T token 中有 380M Shutterstock 图片及 caption；大实验 2T token 用了 692M 图片/epoch，涵盖 Shutterstock、220M 公开图片、CC12M，并升采样含人物的图片以平衡分布，最后 1% 步上权重高美学图片。文本使用 Llama 2 语料（2T tokens 分布）。数据比例是文本:图像 1:1 token。工程上需要清理、许可、去重和美学过滤。论文未明确披露数据清洗的完整细节。

**算力/延迟**：7B 模型用 batch 4M tokens 训练 500k 步，总计 2T tokens，算力需求巨大。推理时文本部分自回归，每个 token 一次前向；图像部分需 250 步扩散，每步一个 Transformer 前向，CFG 还会使计算翻倍。使用 8×8 patch size 可将每图 token 数从 1024 降到 16，从而降低注意力成本约 64 倍（§4.3.2），但扩散步数不减少。所以实时图像生成仍然较慢，除非采用更先进的采样器或蒸馏（论文未涉及）。

**实现难点**：  
- 混合序列：文本 token 是整数需要 embedding，图像 patch 是连续向量，两者在同一个 batch 中长度和 dtype 不同，需要自定义 attention mask 和损失计算。  
- 扩散损失与 LM 损失的数值尺度差异大，λ=5 是经验值，可能需要针对不同数据比例和模型大小重新调。论文明确承认未系统调 λ（§4.1）。  
- U-Net down/up 与 Transformer 的连接需要小心初始化，否则训练不稳定。论文将 U-Net 中的 AdaLayerNorm 换成普通 LayerNorm（§3 脚注 7），但未说明具体原因。  
- 推理时状态管理复杂：需要在一个序列中动态替换图像 patch 向量，切换 LM/diffusion 模式，BOI/EOI 的采样时机需要稳定。  
- 时间步 t 的 embedding 需要加到每个 patch 向量上，这要求 patch 编码器感知噪声进度，实现上要确保 t 与当前图像一致。

**可能失败环节**：  
- 如果注意力掩码实现错成全因果，图像生成会严重退化（FID 从 20.3 到 61.3，Table 5）。  
- 如果 patch 编码器太弱（线性）且 patch size 过大，模型无法从压缩后的表示重建图像，FID 会飙升到 43.5，CIDEr 降至 11.3（Table 6）。  
- 如果图像出现在文本前时噪声不受限，图像理解损失较大（Table 8 CIDEr 从 29.4 降到 25.4）。  
- 如果 CFG 系数选错，图像质量会下降。论文在 controlled 实验用 5，ablation 用 3，大模型对每个 benchmark 单独调（§4.1 Inference），说明没有固定最优。  
- 如果 Chameleon 式的稳定性修改被移除，Chameleon 本身会遇到优化不稳定（§4.1 脚注 12），这也提示多模态训练中架构选择对稳定性的影响。

**监控信号**：训练时最好同时记录 LM loss 和 diffusion loss 的曲线，防止一种模态的梯度主导另一种；验证可定期生成图像看 FID/CLIP 是否下降，文本 perplexity 是否稳定。如果发现文本性能快速下降，需要检查 λ 或数据比例；如果图像生成模糊或色彩异常，可能是 VAE 或 patch 解码器问题。论文在 Table 4 的 ablations 展示了各变体的文本性能变化，可以作为监控文本损失的参考范围。

**指标上限与未回答问题**：  
- 7B Transfusion 文本准确率 66.1 与 Llama 1 持平，但低于 Llama 2 的 66.3（Table 9），说明文本能力仍有轻微损失，可能是参数共享或多模态训练代价。  
- 图像 FID 6.78 接近 DeepFloyd 的 6.66，但 GenEval 0.63 低于 SD 3 的 0.68，且 SD 3 有合成 caption 优势。  
- 论文未回答：λ 的最优值、不同 patch size 与 U-Net 参数如何随模型规模扩展、flow matching 等替代扩散损失的效果、训练到更大规模（>7B）是否仍保持计算效率优势、以及多模态交错生成（比如图-文-图）的定量评估。  
- 图像编辑有样例但无指标，是初步能力展示而非严格证明。  
- U-Net 层未随 Transformer 规模扩展，如果扩展可能进一步提升性能（脚注 17）。

## 11. 放回研究脉络并收束

Transfusion 处在两条主线的交汇点：一是语言模型驱动的多模态统一（Chameleon、Fuyu 等，倾向离散化一切），二是扩散模型主导的连续图像生成（SDXL、Imagen、SD 3 等，依赖独立文本编码器）。论文没有发明新的损失函数或架构，而是证明了“把 LM 和 diffusion 放在同一个 Transformer 里、共享参数和序列”这个看似简单但之前未被深入验证的方案，能在受控比较中击败量化路线，并保持文本能力。它也为后续多模态生成模型提供了一个干净的 baseline：无需量化，无需拼接多个预训练模块，直接端到端训练。在相关工作层面，它还暗示了与离散扩散（如 Diffusion-LM）可能的汇合，尽管这些方法尚未达到自回归 LM 的性能。

**读完必须记住的 5 件事**：  
1. Transfusion 用同一个 Transformer 同时做文本的下一 token 预测和图像的扩散去噪，共享参数但不统一损失类型，λ=5 加权相加（式 4）。  
2. 图像通过 VAE 潜空间表示并 patchify，以连续向量进入序列，并用 BOI/EOI 标记边界；注意力对图像内部是双向，对文本和跨模态是因果。  
3. 与量化图像 token 的 Chameleon 相比，Transfusion 在 7B 受控实验中用约 1/34 计算达到相同 FID，文本 perplexity 也更好。  
4. 图像内部双向注意力很关键，全因果时 FID 从 20.3 恶化到 61.3；U-Net patch 编码解码器允许 8×8 patch（每图 16 patch）仍保持低 FID，降低推理成本约 64 倍。  
5. 7B 2T 模型文本准确率与 Llama 1 持平，图像 GenEval 0.63 优于 SDXL 但低于 SD 3，并可经 8k 微调做基本图像编辑，但该项尚未量化评估。

**5 道自测题**：  
1. 为什么 Transfusion 不把图像量化成离散 token？它认为量化有哪些代价？  
2. 画出 Transfusion 训练时一条混合序列的数据流，并标出 LM loss 和 diffusion loss 在哪里计算。  
3. 公式 `L_Transfusion = L_LM + λ·L_DDPM` 中 λ 的作用是什么？论文设为何值？  
4. 表 5 中线性编码器下 causal 与 bidirectional 的 FID 差距很大，这对注意力设计意味着什么？  
5. 推理时从 BOI 开始，图像生成要经过多少步？CFG 为什么会使计算加倍？

**最终一句话总结**：Transfusion 证明了一种“各用各的最优目标、共享一个 Transformer”的多模态训练配方，在连续与离散数据上都不妥协，可能成为未来统一多模态模型的重要方向。
