# 大白话深读《implicit-preservation》

## 1. 30 秒定位

这篇论文讨论的核心问题是**多轮对话式图像编辑中的“时间性遮挡恢复”**：有些内容在某一轮被新加或变换的物体暂时盖住，但用户从未要求改变它；等这些遮挡物稍后被移除、移动、缩小或替换，被盖住的内容应当按历史状态忠实恢复，而不是被模型重新“合理生成”成别的样子。论文把这种问题称为 temporal preservation（时间性保持）。作者的诊断是，现有系统主要会保持当前可见内容，但“看不见”并不等于“语义上被修改”；一旦区域被遮挡，当前图像就失去了恢复该区域的视觉证据。为量化这个失败，论文提出 **OCCUR-Bench**（Occlusion Consistency and Content Unveiling for Restoration）：含 4,400 个 2 至 5 轮“遮挡—中间编辑—揭示”场景，并提供历史参考状态作为恢复目标（§3、Table 3）。同时提出 **ReSpec**（Reference Selection and Preservation Specification）：一个训练无关框架，用 VLM 控制器推断应当保持的目标，从编辑历史中选择包含该目标的历史参考图，并把当前指令改写成恢复感知指令，再交给支持参考图输入的 in-context 编辑器生成结果（§4、Figure 4）。主要实验显示，对 Flux.2，ReSpec 把 temporal consistency（STC）从 0.455 提升到 0.584，restoration consistency 从 0.386 提升到 0.547（Table 1）。论文同时指出，该提升在长轨迹上更显著：Flux.2 的 5 轮恢复一致性从 0.131 提升到 0.544（Figure 7）。

## 2. 为什么这篇论文会出现

现有对话式图像编辑系统通常把“保持”理解为“保持当前图像中仍然可见的部分”。这在单轮或简单连续编辑里可能够用，但在多轮交互中，常见的添加、移动、缩放、替换、风格化操作都会临时遮挡某个已存在实体。例如 Figure 1 中，用户先在 owl 胸前添加 flowers，遮挡了 owl 原有的羽毛纹理；后来把 flowers 变成 single flower 时，被解放出来的胸前区域应回到原始羽毛纹理。但当前图像已经看不到原始纹理，模型若只依据 `I_{t-1}` 和当前指令，就会落入两种错误：要么重建出一个看似合理但与历史不一致的纹理，要么直接生成视觉伪影。

论文用形式化语言解释了这个问题。设 `S_t` 是第 t 轮的潜在场景状态，`I_t = R(S_t)` 是渲染后的观测图像。时间性遮挡发生时，实体 `o_i` 仍在 `S_t` 中，但 `¬visible(o_i, I_t)`（公式 5）。此时 `p(S_t | I_{t-1}, P_t) ≠ p(S_t | H_{t-1}, P_t)`（公式 6），即仅靠当前输入无法还原真实场景状态。作者进一步指出，现有评测（如指令跟随、保持当前可见区域、最终图像质量）不会专门测试“先被盖住、后应恢复”的情况，所以一个系统可能在常规评测上表现不错，却仍然丢失历史中可见但暂时缺席的内容。例如，已有基准如 MagicBrush、Seed-Data-Edit、ImgEdit 等主要关注指令跟随或可见区域保持；智能体类方法如 Agent Banana、PhotoAgent、IMAGAgent 评估的也是最终任务成功率或回溯，而不是“被遮挡但未修改内容必须按历史显式恢复”。OCCUR-Bench 的动机就是把这种“视觉缺席不等于语义改变”的失败模式显式构造出来，并用历史恢复参考区分“忠实恢复”和“合理幻觉”（§1、§2.2、§2.3）。

另一个推动因素来自方法侧。像 MC-Edit 和 Layer-wise Memory 这样的多轮编辑方法虽然显式建模跨轮一致性，但它们主要基于当前可见或空间局部区域来保持内容；一旦内容被完全遮挡且未在指令中出现，它们就没有机制回溯历史视觉证据。因此，本文不只是提出一个新基准，还指出现有方法需要增加一个“历史视觉 grounding”控制层。ReSpec 的设计动机正是把保持意图从隐式变为显式：用户指令只写明了要改什么，没有写明不要改什么；当不要改的内容已经不在当前图里时，就需要从历史中补上它（§1、§4）。

## 3. 读懂前需要的最小概念

**对话式图像编辑历史（conversational editing history）**：本文把一次多轮编辑形式化为 `H_{t-1} = {I0, P1, I1, P2, ..., I_{t-2}, P_{t-1}, I_{t-1}}`（公式 1），其中 `I0` 是原始图，`P_t` 是第 t 轮自然语言指令，`I_t` 是第 t 轮生成图。第 t 轮输出可依赖完整历史，而不仅是上一张图。这个定义的关键是，历史中每张中间图都可能在未来成为恢复证据。

**潜在场景状态与渲染（latent scene state and rendering）**：论文区分观测图像 `I_t` 与概念上的潜在场景状态 `S_t = {o_i^{(t)}}`，`o_i` 是第 i 个语义实体。`I_t` 被视为对 `S_t` 的渲染。这个抽象不要求显式估计，只是用于说明“实体仍属于场景，只是当前不可见”。在遮挡发生时，渲染过程丢失了被遮挡实体的外观，但潜在状态没有改变它。

**持久实体集（persistent entity set）**：第 t 轮的 `P_t` 表示所有从未被任何指令语义修改过的实体集合（公式 7）。论文要求这些实体即便暂时不可见也应可恢复。注意，OCCUR-Bench 中的 occludee 不一定必须从未被编辑过；如果它在被遮挡前已经被编辑过，那么恢复参考就是编辑后的可见状态，而不是原始图（Appendix A.4）。这一点很重要：恢复目标不是“回到最初的图”，而是“回到该实体最后一次可见且语义有效的状态”。

**遮挡者与遮挡目标（occluder / occludee）**：遮挡者是新引入或变换来盖住已有内容的实体；被遮挡目标 occludee 是保持不变的实体或区域。OCCUR-Bench 每个场景都显式标注这两者。在基准构造中，occluder 通常通过添加一个对象来引入，occludee 则是源图中具有明显纹理、logo、衣物细节或身体部位等可辨识区域（§3.2、Appendix A.1）。

**恢复参考状态（restoration reference）**：`Iref` 是最晚、且目标内容仍可见并语义有效的历史图像状态（公式 8）。它是评测用的 ground truth，不提供给模型或 VLM 控制器，只在评估和 oracle ablation 中可用（§3.1、Appendix A.4）。因此 OCCUR-Bench 衡量的是“从历史中自己找到正确恢复证据”的能力，而不是“给出答案再恢复”。

**训练无关 / in-context 编辑器**：ReSpec 不修改基础编辑器权重，也不改架构，只改变推理时输入的文本和参考图上下文。支持参考图的编辑器如 Flux.2、OmniGen2 可以用；封闭接口如 Gemini-2.5 不能传入可控历史参考图，只能使用改写指令（§4、§5.1）。因此 ReSpec 本质是一个推理期控制层，而不是训练方法。

**相似度函数**：OCCUR-Bench 的 `sim(·)` 是对归一化 PSNR、LPIPS 相似度（1 减去 LPIPS）和 CLIP 相似度三者的平均（公式 21）。所有分量被归一化到同一范围，分数越高代表越一致。这三者的组合能在像素级、感知级和语义级三个层面捕捉局部恢复失败，减少单一指标的偏差（Appendix A.5）。

## 4. 方法全景：先看数据流

先给出 ReSpec 在多轮编辑中的推理数据流：

```
编辑历史 H_{t-1} (图像 I0...I_{t-1} + 指令 P1...P_{t-1})
当前用户指令 P_t
                    |
                    v
          +----------------------+
          | VLM 控制器           |
          | 1. 推断保持目标 D_t   |
          | 2. 选择历史参考 Iref  |
          | 3. 改写指令 \tilde P_t|
          +----------------------+
                    |
          I_{t-1} (当前图)  +   \tilde P_t  +   Iref (可选)
                    |
                    v
          +----------------------+
          | In-context 编辑器     |
          | Flux.2 / OmniGen2    |
          +----------------------+
                    |
                    v
            最终生成图 \hat I_t
```

对应 OCCUR-Bench 的评估数据流：

```
源图 COCO/PIE-Bench/HQ-Edit
   -> VLM 生成合成候选场景
   -> 人工筛选验证
   -> 遮挡-中间编辑-揭示 轨迹
   -> 开放词表检测 + SAM 分割得到 mask
   -> 在 Rrestore 和 Rpreserve 上计算 PSNR/LPIPS/CLIP
   -> Srestore, Spreserve, STC, SIF
```

ReSpec 包含三个组件（§4.1–4.3）：

**Preservation Target Identification（PTI，保持目标识别）**：输入是编辑历史与当前指令，输出是保持目标的文字描述 `D_t`。在恢复轮，`D_t` 描述应重新出现的被遮挡目标；在非恢复轮，`D_t` 可能为空，或描述应保持不变的可见内容。其假设是用户指令没有明确提保持目标，所以需要从上下文推断。在 Appendix C.2 的实现中，恢复轮 prompt 会明确要求 VLM 分析“暴露区域”、追踪历史中哪些轮向该区域添加了内容、哪些轮修改了该区域内内容、哪些轮与区域无关；这一步的目的就是生成准确的 `D_t` 和后续参考选择。

**Historical Reference Selection（HRS，历史参考选择）**：当需要恢复时，VLM 控制器执行 `Iref = SelectRefVLM(H_{t-1}, P_t, D_t)`（公式 12），选择目标仍可见且语义有效的最晚历史图像。它的目的是给编辑器补上当前图中缺失的视觉证据。如果没有隐藏内容需要恢复，就没有参考选择步骤。控制器还会选择一个 `identity_anchor_id`，即最接近当前轮、能保持当前已编辑状态的图像，用来防止参考图引入旧身份导致背景回退。恢复 source 和 identity anchor 必须不同（Figure 12）。

**Restoration-Aware Editing（恢复感知编辑）**：控制器把 `P_t` 和 `D_t` 合成为 `\tilde P_t = RewriteVLM(P_t, D_t)`（公式 13）。这条新指令保留用户请求的编辑动作，同时显式写明应恢复的保持目标。例如 Figure 6 中，把 “Remove the large cardboard box with the white shipping label” 改写成含有 “Use image 1 as the source for the snowboarder's right leg” 的句子。随后编辑器执行 `\hat I_t = f_edit(I_{t-1}, \tilde P_t, Iref)`（公式 14）。非恢复轮可以不给 `Iref`。

在 Appendix C 中，ReSpec 用 Qwen3-VL-8B-Instruct 作为默认 VLM 控制器。VLM 返回 JSON 对象，字段包括 reasoning、restoration_source_id、identity_anchor_id、restoration_region、image_ids、synthesis_instruction。第一轮不调用 VLM，从第二轮起每一轮调用一次。解析失败的 fallback 规则：restoration_source_id 缺省设为 0（原始图），identity_anchor_id 缺省设为 t−1（当前编辑输入图），image_ids 缺省重建为 `[restoration_source_id, identity_anchor_id]`。如果所有选出的 image id 都无效，则回退到最新可用图 `I_{t-1}`。另外，论文强调 ground-truth reference id 不会传给 VLM prompt 或图像输入，只用于 runner 判断当前轮是否为恢复轮以及日志评估（Appendix C.1）。

## 5. 核心公式与直觉

这里只保留理解本文贡献必需的四个公式。

**公式 5：暂时遮挡条件**

```
o_i^{(t)} ∈ S_t, ¬visible(o_i^{(t)}, I_t)
```

变量解释：`o_i` 是第 i 个语义实体，`S_t` 是第 t 轮潜在场景状态，`I_t` 是第 t 轮观测图像。这个公式说：实体仍然属于当前场景状态，但在渲染图中已经不可见。直觉是，当前图像不再包含该实体的直接视觉证据。工程对应点就是：编辑器若只拿 `I_{t-1}` 和 `P_t` 作为输入，就会丢失恢复该实体的必要信息。相反，必须回到 `H_{t-1}` 里寻找该实体最后一次可见的证据。

**公式 7：持久实体集**

```
P_t = { o_i ∈ O | o_i ∉ M_k, ∀k ≤ t }
```

变量解释：`O` 是所有语义实体集合，`M_k` 是第 k 轮指令显式修改的实体集合。`P_t` 是直到第 t 轮从未被修改过的实体集。直觉是，这些实体无论当前是否可见，都应一直保持语义不变。OCCUR-Bench 的 occludee 就属于 `P_t`，因为它直到揭示前都没有被语义修改。工程实现中，PTI 的目标就是判断 `P_t` 中哪些实体在当前轮被重新揭露，并需要历史参考支持恢复。

**公式 9/10：恢复一致性与保持一致性**

```
S_restore = sim( \hat I_N[R_restore], I_ref[R_restore] )
S_preserve = sim( \hat I_N[R_preserve], I_ref[R_preserve] )
```

变量解释：`\hat I_N` 是最终生成图；`I_ref` 是历史恢复参考（对保持区域也复用同一个历史状态，因为它代表未变内容的有效目标）；`R_restore` 是根据历史 occluder mask 和最终新物体 mask 计算出的“以前被遮挡、现在应重新可见”的像素集合；`R_preserve` 是与遮挡和新对象无关、应保持不变的背景或非目标区域。`sim` 是归一化 PSNR、LPIPS 相似度和 CLIP 相似度的平均。直觉是，只比较恢复/保持区域，而不是整图，否则背景会淹没局部恢复失败。附录 D.5 用 Figure 8 说明，遮罩式恢复评分比整图相似度更敏感：一个局部恢复失败在整图指标上几乎不产生差异，但在 masked S_restore 上能清晰反映出来。

**公式 12 与公式 14：参考选择与最终编辑**

```
I_ref = SelectRef_VLM(H_{t-1}, P_t, D_t)
\hat I_t = f_edit(I_{t-1}, \tilde P_t, I_ref)
```

`SelectRef_VLM` 没有梯度优化，而是 VLM 从历史中做离散选择；`f_edit` 是基础编辑器。工程对应是：先由 VLM 输出 restoration_source_id，再把它对应的图像作为参考，与当前图和改写指令一起喂给编辑器。对非恢复轮，去掉 `I_ref`。这个公式也说明，ReSpec 不是一个新的可学习模型，而是把 VLM 当作一个符号控制模块，输出图像选择与文本改写。

## 6. 训练到底怎么跑

严格来说，ReSpec 没有训练过程。它不新增可训练参数，也不修改任何基础编辑器权重，只做推理期控制。因此本节把“训练/准备”拆成三部分，避免与推理流程混为一谈。

第一，基础模型全部使用预训练权重。Flux.2 使用 `FLUX.2-klein-base-9B`，30 个去噪步，guidance scale 4.0；OmniGen2 使用 50 个去噪步，text guidance 5.0，image guidance 2.0；Gemini-2.5 使用 `gemini-2.5-flash-image`，但只做改写指令版本；MC-Edit 与 Layer-wise Memory 作为多轮基线直接输出原始结果（§5.1）。如果基础编辑器支持固定种子，推理时启用固定种子以保证可复现。

第二，ReSpec 的 VLM 控制器也是预训练的，不微调。默认用 Qwen3-VL-8B-Instruct；诊断分析中也比较了 InternVL3-8B-Instruct（Appendix D.4）。VLM 被本地加载，不调用 GPT/Gemini API（Appendix C.4）。控制器的准备只是为恢复轮和非恢复轮分别写 prompt template，要求严格 JSON 输出，并设置解析和 fallback 规则。恢复轮 prompt 要求 VLM 识别暴露区域、追踪编辑历史、选择恢复源和 identity anchor、改写当前指令（Figure 12）；非恢复轮 prompt 要求把当前请求改写成自包含、不依赖历史上下文的指令（Figure 13）。这些 prompt 明确列出了当前输入包括 Image 0 作为原始图、Image 1...N−1 作为历史编辑图，以及对应的指令历史和当前请求。

第三，训练阶段唯一的“数据构造”是 OCCUR-Bench 本身。它从 COCO、PIE-Bench、HQ-Edit 中人工筛选含有显著可遮挡目标的源图，再由 VLM 生成候选场景，人工验证后保留 4,400 条。场景模板分布为：2 轮 1000 条、3 轮 1000 条、4 轮 v1 1000 条、4 轮 v2 200 条、5 轮 v1–v4 1000 条、5 轮 v5 200 条（Table 3）。其中 O 表示 occlusion（遮挡）、M 表示 intermediate edit（中间编辑）、S 表示 style transformation（全局风格变换）、R 表示 revelation（揭示）。遮挡阶段通过添加对象实现，揭示阶段通过移除、移动、缩放或替换 occluder 实现。中间轮可以添加新对象、改变已有对象的颜色/材质/图案，但不能语义上修改 occludee。每条标注 ground-truth restoration reference，不提供给评测模型和控制 VLM（Appendix A.2、A.4）。

此外，基准的 mask 提取依赖 YOLO-Worldv2（yolov8l-worldv2.pt）作为开放词表检测器，以及 SAM（vit-h）做箱形条件下的分割。检测置信度内部阈值设为 0.001，接受阈值 0.2；如果原始标签检测不到，会回退到标签最后一个词和单数化形式。这个流程是预计算的，不参与训练闭环，但决定评估区域准确度（Appendix B.1）。

如果非要从“单步”角度理解准备：一条 2 轮场景需要构造 1 个遮挡轮和 1 个揭示轮；运行时第一轮无 VLM，第二轮做一次 VLM 调用；没有反向传播，也没有参数更新。

## 7. 推理到底怎么跑

推理过程按轮执行。第一轮完全走基础编辑器：输入原图 `I_0` 和首条用户指令 `P_1`，直接生成 `I_1`，不调用 VLM（Appendix C.1）。

从第二轮开始，每轮执行以下顺序：

1. **收集上下文**：VLM 控制器收到完整图像历史 `{I_0, I_1, ..., I_{t-1}}`、指令历史 `{P_1,...,P_{t-1}}` 和当前指令 `P_t`。`I_{t-1}` 既是历史末尾也是当前输入图，不重复输入。

2. **选择 prompt 模式**：在 OCCUR-Bench 实时评估中，runner 用标注的最终轮类型决定调用恢复轮 prompt 还是非恢复中间轮 prompt；但 ground-truth reference id 不会传给 VLM。VLM 必须从视觉历史和指令历史自己判断暴露区域、恢复目标和参考图（Appendix C.1）。这意味着即使 runner 知道这是恢复轮，VLM 仍需要自行决定恢复源。

3. **VLM 推理**：VLM 返回 JSON。恢复轮字段主要有：`restoration_source_id`（提供恢复视觉证据的图）、`identity_anchor_id`（保持当前已编辑状态的锚定图）、`image_ids`（实际传给编辑器的图列表）、`synthesis_instruction`（最终合成指令）。非恢复轮只返回 reasoning 和 synthesis_instruction。里面还有 `restoration_region` 描述暴露区域，以及 `per_turn_classification` 对历史每轮做 ADD-INTO-REGION / MODIFY-IN-REGION / UNRELATED 分类（Figure 12）。

4. **解析与 fallback**：先寻找 fenced JSON 块；找不到则正则提取 JSON 对象。若 JSON 解析失败，恢复轮将 restoration_source_id 设为 0、identity_anchor_id 设为 t−1、image_ids 重建为 `[0, t−1]`，并把 raw VLM 响应当作合成指令；非恢复轮直接用 raw 响应。若 `identity_anchor_id` 缺失设 t−1；若 `restoration_source_id` 缺失设 0；若 image_ids 无效，保留可用图；全无效则回退到 `I_{t-1}`（Appendix C.3）。

5. **编辑器合成**：对支持参考图的编辑器，输入是当前图 `I_{t-1}`、选中的历史参考 `I_ref`、改写指令 `\tilde P_t`，生成 `\hat I_t`。对非恢复轮，只输入当前图和改写指令。对 Gemini-2.5，因为接口不支持可控历史参考条件，仅使用改写指令，不传 `I_ref`（Table 1 标记为 `†`）。

6. **输出记录**：最终图进入下一轮历史。长轨迹中，每轮编辑仍调用一次基础编辑器，VLM 只负责控制输入，因此编辑器的推理成本与原始流程一致，额外成本只在 VLM 控制上。一个 T 轮场景总共需要 T−1 次 VLM 调用（Appendix C.4）。

需要注意的是，整个推理过程中，VLM 不能访问 ground-truth 恢复源；如果它选错 `restoration_source_id`，编辑过程会将错误图像作为视觉证据，这正是论文在不同 VLM 控制器质量上观察到的性能差异来源（Appendix D.4）。

## 8. 实验和消融到底证明了什么

先看 Table 1 的主要结果。MC-Edit 与 Layer-wise Memory 的 STC 只有 0.345 和 0.290，说明纯多轮基线对临时遮挡内容恢复很不稳定。Gemini-2.5 本身已有 0.541，ReSpec 的仅改写指令版本提升到 0.598；Flux.2 本身 0.455，ReSpec 提升到 0.584；OmniGen2 从 0.370 提升到 0.402。指令跟随分数 SIF 同时上升或保持可接受水平，说明恢复增强没有以牺牲当前指令执行为代价。Gemini 变体只在 200 样本子集上评测，原因是 API 成本（Table 1 注释）。

最关键的消融是 Table 2：单独使用 HRS 或 PTI 都比 baseline 好，但组合最强。在 Flux.2 上，`+PTI` 带来的 STC 提升大于 `+HRS`，说明明确说出应恢复什么目标，比只给参考图更能引导编辑器；而 `+HRS` 仍然有增益，并且组合提升了多于单组件，说明它提供的是 PTI 所缺的视觉证据。OmniGen2 的趋势类似，但幅度较小。Table 4 还显示，Flux.2 在替换类揭示上增益最大（+0.194），移除类其次（+0.180），resize 类对 OmniGen2 反而小降（−0.016）。这说明恢复效果也依赖揭示操作类型。Appendix D.3 进一步显示，恢复区域越大，base editor 下降越明显：Flux.2 在 small-area bin 的 STC 为 0.618，large-area bin 为 0.550；ReSpec 在 large-area bin 带来最大增益 +0.122（Table 6）。这支持“参考图对大面积恢复更有用”的直觉。

人类评估细节也值得一提：它从 OCCUR-Bench 中采样 40 个场景、8 个模型设置，共 320 个 scenario-model 输出；每个输出由 3 位评估者打分，共 960 个原始评分。12 位评估者每人评 10 个场景，每个场景下评全部 8 个模型（Appendix B.2）。自动分数与人类评分的模型级相关性很强（Pearson r=0.912，Spearman ρ=0.881，Kendall τ=0.714），但样本级只有 r=0.409，说明自动指标适合聚合模型比较，不适合单条样本精细判断。

尚未证明的主张需要注意：OCCUR-Bench 是诊断性基准，不代表真实用户交互分布；人类评估只有 40 个场景、12 位评估者；自动指标依赖检测和分割模型，mask 错误会影响分数；ReSpec 只测试了少数编辑器和 VLM 控制器，未展示跨模型泛化；且 ReSpec 并未把 STC 推到接近 1，Flux.2+ReSpec 也只有 0.584，说明问题远未完全解决。

## 9. 与前作怎么选

最接近的比较对象有三类：MC-Edit、Layer-wise Memory 这类多轮编辑器；Flux.2、OmniGen2 这类支持参考图的单轮/上下文编辑器；Gemini-2.5 这类封闭接口模型。此外还可以把 ReSpec 与基于智能体规划的方法（Agent Banana、PhotoAgent、IMAGAgent）区分开，因为后者关注多步工具使用与视觉美学规划，但没有专门处理“被遮挡但未修改实体的历史恢复”。

**MC-Edit / Layer-wise Memory**：它们显式建模多轮一致性，但主要抓当前可见区域或局部定位，不把“已消失但未修改”的内容当作恢复目标。Table 1 中两者 STC 都显著低于 Gemini-2.5 baseline。如果你的场景几乎不发生遮挡后恢复，或你必须在单一自包含模型内完成编辑、不能外挂 VLM，这类方法仍有简单性优势；但一旦存在跨轮遮挡，它们会不可靠。

**Flux.2 / OmniGen2 基线**：它们指令跟随强，但直接给定当前图和指令时，缺少历史参考证据，恢复区域容易被重新生成成合理但不对的内容。选择基线的情况是：单轮编辑、无隐藏内容、或用户明确不关心历史一致性。需要长时间对话且存在遮挡-揭示时，应加上 ReSpec。

**Gemini-2.5 + 仅改指令 ReSpec**：封闭接口不能传参考图，因此只做显式保持目标说明。Table 1 中它从 0.541 到 0.598，远小于 Flux.2 参考条件组合的 +0.129。若只能用闭源模型且不能传参考图，可以使用 PTI 变体，但上限低。

**决策原则**：如果你有支持参考图输入的编辑器，优先用完整 ReSpec；如果控制器 VLM 强度不够，参考选择错误率会高，此时可先只开 PTI；如果对延迟敏感且对话很短，可以关闭 HRS 或 VLM 控制。总体来说，ReSpec 适合“以支持参考图的条件编辑器为底座、对历史恢复有强需求、但不想重新训练底座”的工程环境，而不是需要最低延迟或单模型闭合式编辑的场景。

## 10. 工程判断：可行性、风险与上限

**可行性**：ReSpec 是训练免，不需要新增训练数据或微调编辑器，接入成本主要是 prompt 设计、JSON 解析和图片池管理。基础编辑器之外的额外开销来自每轮一次的 VLM 推理。论文写明 T 轮场景需要 T−1 次 VLM 调用（Appendix C.4）。论文未明确披露 VLM 单次延迟或 GPU 型号，只提到使用本地 Qwen3-VL-8B-Instruct / InternVL3-8B-Instruct，因此实际延迟取决于部署硬件，不能从论文得出毫秒级或秒级结论。在成本上，论文提到该框架不调用 GPT 或 Gemini API，VLM 和编辑器都本地运行；但闭环推理中，每轮先 VLM 后编辑器，串行依赖会放大端到端延迟。

**实现难点**：VLM 要严格输出 JSON，但实际模型可能输出非 JSON 或错误 id，所以必须有 fallback。此外，图片历史越长，本地 VLM 可处理的视觉上下文越长；论文没有讨论历史窗口截断。再一个难点是，`restoration_source_id` 选择不准时，编辑器收到错误视觉证据，会直接把错误纹理复制回去；此时 `identity_anchor_id` 与恢复源冲突还可能带来身份混合或背景回退。监控信号应包括：VLM JSON 解析失败率、参考选择准确率（基准上可用）、S_restore 与 S_preserve 分项变化、以及 SIF 防止过度保持。还可以监控不同 `image_ids` 的输出差异，判断错误提交是来自 VLM 还是编辑器本身。

**失败环节**：最可能在三个位置失败。一是 VLM 识别暴露区域错误，导致 PTI 描述为错误目标。二是 HRS 选了过旧或语义已变的历史图，例如目标在遮挡前已经被编辑过，但 VLM 仍选了原始 `I0`；Table 5 显示参考距离增大时性能下降，因此选错历史距离的代价很高。三是基础编辑器不能有效利用参考图，或者参考图与当前图空间错位导致身份混合。论文在 Appendix D.4 明确说明 ReSpec 对参考选择质量敏感：Qwen 参考准确率 79.0% 对应 S_restore 0.398，InternVL 59.0% 对应 0.347（Table 7）。另外，人类评估显示即使应用 ReSpec，仍有部分案例失败；论文没有给出失败案例的具体分类统计。

**指标上限**：ReSpec 提升后 STC 仍然不高，Flux.2+ReSpec 为 0.584，OmniGen2+ReSpec 只有 0.402。即使参考选择完全正确，最终恢复还可能被编辑器自身生成能力限制。样本级人机相关只有 r=0.409，说明自动指标还不能完全替代人类判断单条样本。此外，OCCUR-Bench 本身的 mask 提取依赖 YOLO-Worldv2 + SAM，可能在新对象漏检或边界不精确时给出噪声分数；这些误差会压缩可观察到的模型差异。

**未回答问题**：论文没有刻画 OCCUR-Bench 与真实用户修复请求的分布差异；没有讨论多实体同时遮挡或交叉遮挡；没有给出 VLM 控制器在低分辨率历史图像或模糊提示下鲁棒性的系统分析；也没有说明如果把 ReSpec 与可训练的多轮模型结合，是否能获得更大收益。限制部分提到未来可以用轻量控制器、缓存视觉记忆或选择性调用来降低额外开销，但这些都没有在本文中实测。

## 11. 放回研究脉络并收束

本文处在“指令引导图像编辑”的研究线中：从单轮编辑方法（InstructPix2Pix、MasaCtrl），到多轮对话编辑（ChatEdit、MC-Edit、Layer-wise Memory、DialogDraw），再到大模型/智能体规划（Agent Banana、PhotoAgent、IMAGAgent 等）。已有评测主要衡量指令跟随、可见区域保持、最终质量；像 PIE-Bench、HQ-Edit 则关注局部编辑区域质量，但也不涉及跨轮临时遮挡恢复。本文的增量在于指出“时间性遮挡恢复”这一未被单独诊断的失败类型，并给出基准与训练免解法。

**读完必须记住的 5 件事**

1. 视觉缺席不等于语义改变；当前图不再提供证据时，必须回到编辑历史找视觉证据。
2. OCCUR-Bench 用 4,400 个遮挡-揭示场景隔离 temporal preservation，并用 `I_ref` 区分忠实恢复与合理幻觉。
3. ReSpec 的三个动作是：PTI 推断保持目标、HRS 选择历史参考图、改写恢复感知指令；全程不更新权重。
4. 实验表明 ReSpec 对支持参考图的编辑器（Flux.2、OmniGen2）有效；对封闭 Gemini 只能改指令，收益有限。
5. 主要限制是 VLM 控制质量、检测/分割误差、额外推理开销，以及 STC 绝对水平仍不高。

**5 道自测题**

1. 为什么仅输入当前图 `I_{t-1}` 和当前指令 `P_t` 不能恢复被暂时遮挡但未修改的实体？请用公式 6 的直觉回答。
2. OCCUR-Bench 中 `R_restore` 是如何从 `M_occ^{1:N}`、`M_occ^N` 和 `M_new^N` 构造出来的？
3. ReSpec 在恢复轮和非恢复轮分别给编辑器什么输入？
4. 根据 Table 2，PTI 和 HRS 各自解决了什么问题？为什么组合最优？
5. 为什么 OCCUR-Bench 使用遮罩式恢复评分而不是整图相似度？哪个附录案例说明了这一点？

最终一句话总结：这篇论文识别并量化了对话式编辑中一个被忽略的“暂时消失但应恢复”问题，并用训练免的历史视觉 grounding 给出了可操作的缓解方案，但它更像一个诊断性和控制层贡献，而不是彻底解决时间一致性的最终方案。
