> 读者：想知道"这些解读里的数字能不能直接引用"的人
> 目标：读完知道这一轮核了多少、怎么核的、查出什么、什么仍然核不了
> 元信息：186 个目录 · 覆盖 182 个 · 脚本 [`_work/factcheck.py`](../../_work/factcheck.py) + [`_work/unsourced_triage.py`](../../_work/unsourced_triage.py)
> 最后核对：2026-08-30

## 0. 先说清楚"未溯源"不等于"写错了"

脚本做的是一件很机械的事：把解读里出现的每个数字，拿去论文的 PDF 抽取文本里找。找不到就记一笔。

找不到的原因绝大多数与真伪无关——

| 原因 | 例子 |
| --- | --- |
| 解读自己做的算术 | pix2pix-zero「100 步反演 + 100 步重建 + 100 步编辑 = 300 次前向」，原文只有 100 |
| 表格被 pypdf 粘成一串 | directedit 原文抽出来是 `50.861177.7316 39511.7188`，三个数糊在一起 |
| 单位换算 | 解读写「1600 万」，原文写 `16M` |
| 章节号被当成数字 | 「§6.1」里的 6.1 |
| 数字只存在于图里 | 「Fig. 5(b) 显示各类别在 4,638 至 6,085 之间」——图不进文本 |

所以这份记录的价值不在那个百分比，而在**把机器挑出来的每一条都人工看过一遍**。

## 3. 查出来的错

### 3.1 directedit：Table 2 的 MSE 均值多了一位

- **原写法**：「Table 2 中 Vanilla Euler 的步级 MSE 均值高达 **11773.73**，最大 39511.72」（出现 3 处）
- **实际**：原文 Table 2 的 Vanilla 行是 `60 | 14.59 | 421.97 | 466.60 | 50.86 | 1177.7316 | 39511.7188`，
  对应 NFE / PSNR / LPIPS / MSE / SSIM / 步级 MSE 均值 / 最大。均值是 **1177.73**。
  同表 Stepwise Correction 的 `0.2857 | 11.7302`、DirectEdit 的 `0.0006 | 0.0757` 都能对上这个列序。
- **已改**：3 处 11773.73 → 1177.73。最大值 39511.72 原本就是对的。
- **证据**：[arXiv 2605.02417](https://arxiv.org/pdf/2605.02417) Table 2。

### 3.2 RISEBench：把论文外的基准细节写成了论文内容

- **原写法**：「例如，WISE 使用**知识图谱**构建 **800 个样本**评估文生图的世界知识」
- **实际**：RISEBench 原文里 WISE **只出现在参考文献**（第 787 行），正文一句没展开。
  同段提到的 LogicVista（第 812 行）、LEGO-Puzzles（第 837 行）、MagicBrush（第 843 行）也全都只在参考文献里。
  「知识图谱」和「800 个样本」这两个细节，RISEBench 这篇论文不支持。
- **已改**：删掉这两个无出处的细节，改成明写这段横向对比是**论文外信息**，各基准规模以各自原文为准。
- **证据**：[arXiv 2504.02826](https://arxiv.org/pdf/2504.02826)，References 起于第 704 行。

### 3.3 RISEBench：MagicBrush 的规模写成了约数

- **原写法**：「MagicBrush 包含 10,000 个手动标注的三元组」
- **实际**：MagicBrush 原文是 **5,313 个编辑会话、10,388 个编辑轮次**，每轮一个三元组。
  这两个数在本库 [`2023-06_MagicBrush`](../../papers/2023-06_MagicBrush/解读.md) 的解读里有，可交叉核对。
- **已改**：换成 5,313 / 10,388，并注明出处是 MagicBrush 原文而非 RISEBench。

### 3.4 Imagic：捏造了一个原文里没有的"ImageNet 预训练"

这条不是数字溯源查出来的（它查不出这类），是顺着 README §6 里已记的那个例子全库扫 `ImageNet` 时确认的。

- **原写法**：「Imagen 适配约 8 分钟…Stable Diffusion 约 7 分钟…**两者都是 ImageNet 预训练模型基础**」
- **实际**：`ImageNet` 在 Imagic 原文里出现 **0 次**。Imagen 是像素空间三级级联（64×64 + 两级超分），
  Stable Diffusion 是在预训练 autoencoder 的 4×64×64 latent 上做扩散、处理 512×512 图像。两者都不是 ImageNet 预训练。
- **已改**：换成原文实际写的架构差异，并补上原文给出的 SD 版超参（嵌入优化 1000 步 lr 2e-3、微调 1500 步 lr 5e-7）。
- **顺带**：全库 24 篇提到 `ImageNet` 的解读逐篇比对原文出现次数，**只有 Imagic 这一篇是原文 0 次**，其余都有实际出处。
- **证据**：[arXiv 2210.09276](https://arxiv.org/pdf/2210.09276) 第 396–436 行。

## 5. 顺带修掉的四个脚本 bug

这一轮 460 这个数比上一轮的 485 小，不是解读改好了，是脚本本来就在虚报。

| bug | 症状 | 修法 |
| --- | --- | --- |
| `[\d,]*` 吞逗号 | 「10,20,30,40,50」被粘成 `1020304050`，凭空造出一个原文当然没有的数。6 篇受影响 | 千分位分组单独匹配，其余按纯数字串取 |
| `normalize()` 三条规则串联 | 第三条 `(\d)\s+(\d)` 把第一条刚修好的 `1.13 79.05` 又粘成 `1.1379.05`，反而让 79.05 匹配不上 | 拆成 light / full 两级，取 raw / light / full 三版并集 |
| `meta['arxiv_id']` 直取 | 第二批 5 个目录没有这个字段，脚本直接 KeyError 跑不完 | 改 `.get()` |
| 无 arXiv ID 的目录被整篇跳过 | 抽取文本按 `txt_<arxiv_id>.txt` 命名，Inter-Edit 有 18 MB 的本地 PDF 却一个数字都没核过 | key 改成"优先 arxiv_id，没有就用目录名"，三个脚本同步改 |

另外 `strip_noise()` 现在会剔掉 URL、DOI、Semantic Scholar 哈希和 `HTTP 429` 这类标识符——它们是编号不是量，溯源无从谈起。

## 6. 怎么自己复跑

```bash
python3 _work/extract_missing_txt.py     # 补抽还没有抽取文本的 PDF
python3 _work/factcheck.py               # 全量比对，出总表
python3 _work/unsourced_triage.py        # 分类，写 _work/unsourced_triage.txt
```

看 `_work/unsourced_triage.txt` 的「待核」段即可，其余四段是已判定的噪声。
