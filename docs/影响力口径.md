# 影响力口径：这 20 篇是怎么算出来的

> 读者：想复现或质疑 Top 20 选择的人
> 最后核对：2026-08-31

## 0. 先破一个误解

**按引用总量排，选出来的一定是 2023 年的论文。** SDXL 5261 次、SD3 4606 次，2026 年的论文
再重要也不可能在 3 个月内攒到四位数。所以这里排的是**引用速率**：

```
引用速率 = 引用总量 ÷ 首发至今月数        月数 = (2026-08-31 − 首发日) ÷ 30.44 天，下限 1.0
```

速率也有偏差——3 个月的论文速率抖动极大，所以 2026 年的论文另看 upvote，并且只给 3 个名额。

## 1. 管线七步

```
scripts/discover_hf.py        HF 关键词检索 26 组 + daily papers（2025-01 起）   → _work/hf_pool.json
scripts/daily_sweep.py        2026-03 → 2026-08 逐日全覆盖，补最近半年           → 同上（6736 篇）
scripts/screen_candidates.py  标题 + HF 关键词筛图像生成相关，排掉视频/3D/音频   → _work/cand.json（1552 篇）
scripts/resolve_seeds.py      62 篇点名必查的经典，HF 池找不到就走 arXiv 标题检索 → _work/seeds_resolved.json
scripts/merge_candidates.py   合并 + 关注度门槛（23–24 需 upvote≥2 或 star≥50；    → _work/cand.json（1061 篇）
                              25–26 需 upvote≥6 或 star≥100；种子无条件保留）
scripts/fetch_cites.py        Semantic Scholar 批量取引用，失败逐条回退 OpenAlex  → _work/cites.json
scripts/rank.py               算速率，出两张表（按速率 / 近半年按 upvote）        → _work/rank*.tsv
```

`_work/` 被 `.gitignore` 挡住，重跑即可再生。全流程只用标准库。

## 2. 门槛为什么这么定

| 规则 | 原因 |
| --- | --- |
| 2023–24 门槛低（upvote≥2） | HF Papers 那两年还不活跃，GenEval 只有 1 个 upvote，用 2026 年的门槛会把经典全砍掉 |
| 62 篇种子无条件入池 | 门槛只能保证不漏「有热度的」，漏不漏「有引用的」得靠点名。SDXL 的 upvote 是 93，但 Consistency Models 只有 9 |
| 只用 Semantic Scholar 的引用数 | OpenAlex 会把同一篇拆成多条记录：VAR 的 arXiv DOI 记录只有 8 次引用，会议版才是 1139。混用会得出荒谬结论 |
| 2026 年只给 3 席 | 2026 年最高速率 6.7 次/月（pMF），第二名 4.6。再多给就是拿 upvote 当引用用 |

## 3. 已知的口径缺陷

| 缺陷 | 影响 |
| --- | --- |
| 候选池依赖 HF Papers 收录 | 没被 HF 收录的论文进不了池子。62 篇种子清单是唯一的补丁，它是人工列的，必然有漏 |
| Kolors、Simpler Diffusion、STAR 三篇种子没解析到 arXiv ID | Kolors 确实没有 arXiv 论文；另两篇是标题检索没命中，未追 |
| 引用速率假设引用是线性累积的 | 实际上论文引用先增后平，2023 年的论文速率被低估，2025 年年中的被高估 |
| GitHub star 只作参考，未进排序 | star 反映的是可用性而非学术影响，且强烈偏向有权重放出的模型 |
| 「路线代表性」是人判断的 | 从 1061 篇到 20 篇的最后一步没有公式。备选池 [docs/备选池.md](备选池.md) 把被换下的都列了出来，可复核 |

## 4. 第三条轴：厂商落地（2026-08-31 增补）

前两条轴（引用速率、upvote）漏掉了这个领域最重要的一类工作：**厂商技术报告**。三个失效场景：

| 场景 | 例子 | 前两条轴给出的错误结论 |
| --- | --- | --- |
| 报告不在任何索引里 | Kolors 的报告只在 GitHub，arXiv / S2 / OpenAlex 全无条目 | 根本进不了候选池 |
| 有报告但没人引 | Imagen 3 两年 27 次引用 | 判为不重要，而它是 Google 当代旗舰的公开材料 |
| upvote 与真实使用差三个数量级 | NextStep-1：146 upvote，权重每月 65 次下载 | 判为高关注度 |

所以厂商组改用落地信号，脚本 `scripts/hub_signals.py`：

```
HF Hub  近 30 天下载量 + likes        开源权重的实际使用强度
GitHub  star                          有独立仓库的补充（Kolors 4,612 star）
闭源     无 Hub 数据，落地栏写「闭源」   只能靠官方报告与产品级影响判断
```

⚠️ **下载量的三个坑**：统计口径是 repo 级请求数，社区量化版 / GGUF / LoRA 各自单独计数，
不能相加当作一个模型的总量（Qwen-Image 本体 28.0 万，社区蒸馏版 Qwen-Image-Lightning
另有 43.9 万，是两条数据）；likes 与下载量经常背离（BAGEL 每月 922 次下载但 1,214 likes，
属于被研究不被部署）；trending 榜单反映最近一周热度，不能当累积影响力。

## 5. 两组名额怎么分

12 席给厂商旗舰，8 席给技术路线。厂商组原则上一家一席（取当前旗舰），Stability AI 与
阿里通义各两席——SDXL→SD3、Qwen-Image→Z-Image 是不同代际的独立产品线且都还在被大量下载。

代价写在 [备选池.md](备选池.md)：MeanFlow、RAE、pMF、PixArt-α 四篇是纯名额损失，
Janus-Pro 按一家一席的规则本该进而没进。清单放宽到 24 篇这些都能收。
