## 0. 先破一个误解

读者最容易想当然的一个认知错误是：只要把图像、指令和文本一起交给更大的统一多模态模型，编辑一致性和评估可靠性就会自动变好。

| 你以为 | 实际 |
|---|---|
| 统一多模态模型把源图、文本、目标图放进同一序列，未编辑区域自然保持不变 | 统一序列仍出现条件泄漏和像素漂移，InternVL-U 必须把理解特征与 VAE 潜变量解耦；Qwen-Image-Layered 需要输出多层 RGBA 才能显式隔离编辑区域 |
| 用更大的 VLM/奖励模型当裁判，评估与 RL 更可靠 | EdiVal-Agent 换 OWL-ViT 后人类一致率从 81.3% 跌到 53.67%；banana100 里传统 NR-IQA 给后轮退化图更好或同等分数；T2I-R1 的单一 VQA 奖励会被策略 hack |
| 合成编辑数据越多，下游模型越好 | NoHumansRequired 基准提升仅 +0.03 且置信区间重叠；OpenGPT-4o-Image 数据从 30k 扩到 40k 已有回退 |
| 强化学习进入生成轨迹后，推理编辑任务会稳定提升 | reward hacking 仍只能缓解不能根除，多篇只能靠提前停止、正则或选早 checkpoint 规避，DanceGRPO 只用 HPS 会产出油腻图像 |

这些失败共同说明，把“更大/更统一”当成路线本身会掩盖真正的瓶颈：细粒度跨图比较、局部信用分配、表示解耦。模型规模没有自动解决编辑中的局部保持与语义对齐矛盾，反而把问题转移到奖励设计、评测锚点和数据验证上。技术判断应聚焦于表示层级解耦和可验证局部事实，而不是默认统一模型会顺手解决编辑问题。

## 1. 五年里真正的转折点

| 时间 | 转折 | 触发它的工作 | 之前怎么做 → 之后怎么做 |
|---|---|---|---|
| 2022 H2 | 编辑控制从外部掩码/噪声投影迁移到模型内部注意力表示 | Prompt-to-Prompt | 之前 SDEdit 加噪/掩码混合或 Blended-Latent-Diffusion 在潜空间按掩码混合，编辑区域由外部 mask 指定；之后交叉注意力图注入/引导，换词、加短语等语义编辑不再绑定像素级掩码 |
| 2022 H2–2023 H1 | 指令编辑从单图反演/无训练转向可训练的双条件扩散与配对数据合成 | InstructPix2Pix | 之前指令式编辑缺乏可扩展成对监督，真实图编辑多为 per-image inversion 或注意力注入；之后用 GPT-3 生成指令、Stable Diffusion + Prompt-to-Prompt 生成配对图，训练双条件潜扩散，MagicBrush、HIVE、HQ-Edit、UltraEdit 等后续沿用并改进该数据/条件范式 |
| 2023 H2 | 显式反演可被绕开，少步/免反演编辑可行 | InfEdit 的 DDCM 虚拟反演 | 之前真实图编辑先做 DDIM 反演或 Null-text Inversion 优化空文本嵌入，单图 40–120 秒；之后用特殊方差参数使去噪退化为一致性采样，ReNoise/TurboEdit 等少步模型直接适配，速度达数秒或亚秒 |
| 2024 H1 | 生成骨干从 UNet cross-attention 转向 MM-DiT token 共享注意力，条件 token 化 | SD3-RectifiedFlow | 之前 ControlNet/IP-Adapter 用特征加法或独立 cross-attention 注入条件，受 UNet 架构限制；之后 FLUX-Kontext、Qwen-Image 用序列拼接或双编码把参考图/文本直接放进同一序列，生成与编辑统一到同一 token 化底座 |
| 2025 H1 | 强化学习进入生成/编辑轨迹，推理步骤成为可训练策略 | Flow-GRPO、DanceGRPO | 之前 GoT 等只把显式推理链作为静态文本条件输入扩散模型；之后用 SDE 给确定性 ODE/流匹配采样注入随机探索，GRPO 组内优势训练生成模型，T2I-R1、Meta-CoT 等把规划/生成步骤作为策略优化 |
| 2025 H2–2026 H1 | 评估器自身可信度被质疑，评测从整体打分转向局部锚点/物理真值核对 | EdiVal-Agent 换 OWL-ViT 一致率暴跌；banana100 传统 NR-IQA 反向 | 之前用整图 VLM 开放打分或传统 NR-IQA 度量编辑质量；之后引入检测框 ROI 二值判断、HDR 开/关灯真值、场景图事实网格等可验证锚点，把“真伪”与“好不好”分开测量 |

这些转折之间不是单一因果链。Prompt-to-Prompt 建立的注意力控制被 InstructPix2Pix 直接用作合成配对图的编辑工具，后者把指令编辑从单图反演推进到可训练条件扩散；InfEdit 与少步骨干共同推动真实图编辑向免反演和实时化；SD3-RectifiedFlow 让生成与编辑共享 token 化底座，是 Flow-GRPO/DanceGRPO 在同一骨架上做 SDE 策略探索的前提。评估转折没有由上述任一转折直接触发，而是上游方法大量产出“看起来对”的结果后，评测端自身暴露出检测器替换和 NR-IQA 反向等不可信问题。证据最薄的是 InstructPix2Pix 这一条：素材对指令编辑线明确的后续转折是真实数据与 MLLM 编码器替代，而把它本身列为全局转折主要依赖后续多篇工作沿用其条件扩散与合成数据范式。

哪些算「转折」是判断题，不是算出来的。这里的标准是「之后大部分工作都改了做法」，而不是「这篇有影响力」——所以表里只有 6 行，第 3 节里更多有名的工作没进来。表末那段自己点出了证据最薄的一条。另外前两列的年份是我按素材里的论文日期改过的：模型原本给的是「早期/中期/后期」，评测那一行原写 2025 H2，但它引的 banana100 是 2026/04，所以改成 2025 H2–2026 H1。

### 反复出现的模式

- **冻结预训练主干，只训练新增适配器/LoRA/连接器** —— 在条件控制（ControlNet、T2I-Adapter、IP-Adapter、EasyControl）、个性化（Custom-Diffusion 只更新 cross-attention KV）、局部编辑（AnyDoor、PowerPaint、BrushNet）、统一多模态（MetaQuery、BLIP3-o、OmniGen2）和 2025H2 编辑模型（InstructX 用 LoRA 微调 VLM 并通过连接器接 DiT）中反复出现。它有效是因为保留预训练先验，避免灾难遗忘，同时能以低参数成本增加条件通路。

- **DDIM/反演轨迹缓存 + 注意力 Value/特征注入保持源结构** —— 在训练-free编辑（Prompt-to-Prompt、Plug-and-Play、MasaCtrl、Self-Guidance）、反演精度（注意力 Value 注入或特征共享）、拖拽编辑（DragDiffusion、DragonDiffusion 缓存潜变量与自注意力 K/V）和统一编辑模型（VAREdit、Qwen-Image-Layered 源图潜变量注入）中反复出现。它有效是因为去噪早期绑定源表示可保持布局与身份，后期释放可允许语义改变，从而在结构保持与编辑自由度之间取得折中。

- **VLM/MLLM 作为自动裁判或奖励信号，但需局部锚点和校准** —— 在指令式编辑（HQ-Edit、MGIE、ICEdit）、推理与 RL（T2I-R1、Flow-GRPO、GoT）、奖励模型（EditScore、EditReward、read-it-back）、推理编辑（UniREditBench、Meta-CoT）、数据工程（NoHumansRequired、X2Edit）和评测（EdiVal-Agent）中反复出现。它有效是因为自然语言视觉判断能近似人类偏好且可规模化，但整图打分易产生幻觉，所以在检测框 ROI 或场景图事实内做原子判断时更可靠。

- **合成数据 + 自动过滤/验证栈的冷启动** —— 在指令式编辑（InstructPix2Pix 用 Prompt-to-Prompt 生成配对图，MagicBrush 人工补强，UltraEdit 真实锚点+自动区域）、局部编辑（SAM 数据引擎、MimicBrush 视频帧自监督）、数据工程（NoHumansRequired 全自动验证栈、X2Edit、OpenGPT-4o-Image）和推理编辑（UniREditBench 合成 100K CoT 数据）中反复出现。它有效是因为成对编辑监督稀缺，自动合成能规模化产出，但需要过滤器抑制分布偏置和伪正确结果。

- **分阶段训练，先对齐视觉接口再联合微调** —— 在统一多模态（先对齐视觉接口再联合微调）、推理编辑（ReasonEdit 先训 MLLM LoRA、再训 DiT、最后联合微调；UniReason 先训生成分支再全参联合；Meta-CoT 先 SFT 后 Flow-GRPO 且 RL 只更新生成专家）和生成骨干（PixArt-α 三阶段复用）中反复出现。它有效是因为早期联合优化会造成语言/图像先验冲突或容量失衡，分段训练保护已有能力，后期再解冻有限参数。

- **组内归一化/自集成降低奖励方差** —— 在 RL 训练（Flow-GRPO/DanceGRPO 的 GRPO 组内优势）和奖励模型（qwen-image-rl 按 prompt 组归一化、Edit-R1 阈值过滤低方差组、read-it-back 的 sequence-level advantage、EditScore 的 Avg@4）中反复出现。它有效是因为不同 prompt 难度和奖励尺度不同，组内标准化能减少跨题噪声，自集成可提高排序准确率而不增加显存。

## 3. 十五条脉络各自的结论

### 1. 训练-free 扩散编辑：靠注意力和反演改图

`14 篇 · 2021-08 ~ 2026-03 · SDEdit、Blended-Latent-Diffusion、Prompt-to-Prompt…`

##### 这条线在解决什么
这条线要解决的是：在不训练、不微调预训练扩散模型的前提下做图像编辑，编辑控制信号只能从模型内部注意力图、中间特征或反演轨迹中借用。训练-free 意味着这些信号的分辨率、对齐精度和可编辑性都不是为编辑任务优化的，于是反演误差、注意力-外观纠缠、结构保持与语义改变之间的冲突会在去噪步中被不断放大。

##### 怎么演进的

| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| 噪声投影与全图重绘 | SDEdit | 对引导图加噪到中间时刻 t₀，再反向 SDE 去噪；掩码版本用 σ(t) 噪声保持未编辑区域 | 无需训练、任意像素引导，换来真实感与忠实度的 t₀ 权衡；代价是单图约 29 秒，边界一致性有限 |
| 潜在空间掩码混合与局部约束 | Blended-Latent-Diffusion, DiffEdit | 在 LDM 潜在空间按掩码混合前景/背景潜在；DiffEdit 用条件噪声差自动生成 mask，并用 DDIM 编码替代加噪 | 局部编辑和背景保持明显改善；代价是 VAE 有损重建、细掩码失效，对象插入/计数仍会失败 |
| 交叉注意力控制与文本嵌入反演 | Prompt-to-Prompt, Imagic, pix2pix-zero | Prompt-to-Prompt 早期注入源交叉注意力图、后期切到目标注意力；Imagic 优化文本嵌入并微调模型后插值；pix2pix-zero 用 CLIP 嵌入差找编辑方向，以注意力软引导并正则化反演 | 编辑控制从外部掩码转移到模型内部注意力，支持换词、加短语等语义编辑；代价是 Imagic 每图 7–8 分钟优化，pix2pix-zero 约 300 步扩散，注意力分辨率低且无法空间移动对象 |
| 自注意力/特征注入与跨图迁移 | Plug-and-Play, MasaCtrl, Self-Guidance, Cross-Image-Attention, StyleAligned, Add-it | Plug-and-Play 注入 decoder 特征与自注意力矩阵；MasaCtrl 用互自注意力借用源 KV；Self-Guidance 把注意力/激活变成可微能量做梯度引导；Cross-Image-Attention 跨图替换 K/V；StyleAligned 让非参考图单向关注参考图并对 Q/K 做 AdaIN；Add-it 用加权扩展自注意力结合结构迁移和潜在混合 | 支持姿态改变、外观迁移、风格一致、物体插入等更复杂编辑，无需训练；代价是计算与显存倍增，注意力-外观纠缠、反演误差和失败模式增多 |
| 高效反演与统一权衡分析 | LEDITS++, editing-manifold | LEDITS++ 用 sde-dpm-solver++ 在 20 步内完成完美反演，逐概念 CFG 引导与隐式交叉注意力/噪声差掩码；editing-manifold 用生成流形上的 Lipschitz 传播统一反演误差、CFG 强度、掩码边界和多轮累积 | LEDITS++ 重建误差 0.00、单编辑约 1.78 秒，多概念编辑可用；editing-manifold 给出形式化权衡框架，但实验数据是示意性的，不能当基准 |

真正的转折点在 Prompt-to-Prompt：它证明交叉注意力图已经编码词-像素空间绑定，编辑控制可以从外部掩码/噪声投影迁移到模型内部表示。此后大多数方法都围绕注意力图的注入、引导或跨图混合展开，而反演质量则成为新的共同瓶颈。

##### 已经稳定下来的做法
- **DDIM/编辑友好反演进入潜空间** —— 真实图编辑时普遍先做反演，只在反演质量可接受时继续；后续用高阶 solver 或正则化降低重建误差。
- **早期绑源表示、后期释放目标语义** —— 在去噪前半段注入源交叉/自注意力或特征，后半段停止注入，用来平衡结构保持与编辑自由度。
- **用交叉注意力/噪声差自动推断编辑区域** —— 不便手动画掩码时，用模型内部注意力图或条件噪声预测差生成软掩码或隐式掩码。
- **潜在空间按掩码混合源轨迹与编辑轨迹** —— 掩码外复用未编辑区域的加噪/反演潜在码以保持背景，掩码内使用编辑引导。
- **对 latent 施加能量梯度做软约束** —— 需要细粒度改变位置、形状、外观时，用注意力/激活构造可微损失并对去噪变量求梯度，而非硬替换。

##### 还没解决的
- **反演误差与可编辑性冲突** —— DDIM 反演不完美导致重建背景漂移或外观泄漏，正则化或高阶 solver 改善但未根本解决。
- **注意力图分辨率低** —— 交叉注意力/自注意力图受限于 U-Net 瓶颈或潜在空间分辨率，无法编辑精细纹理和像素级边界。
- **注意力与外观/布局相互泄漏** —— 高引导下外观特征携带空间信息、布局约束传递外观，导致对象联动、颜色漂移或身份改变。
- **空间移动、计数和未见姿态失败** —— 底层模型无法生成期望布局或处理“左边到右边”“两个变三个”等编辑，方法无法超越基座能力。
- **多轮编辑累积与硬掩码边界伪影** —— 多轮编辑误差逐步累积，硬局部锁定虽阻止泄漏但产生边界不连续，缺少自动权衡机制。

### 2. 反演精度：真实图片怎么无损映回噪声

`9 篇 · 2022-11 ~ 2026-07 · Null-text-Inversion、EDICT、InfEdit…`

##### 这条线在解决什么
真实图像编辑要求先把图像精确映射为扩散模型可重建的噪声潜变量，但标准反演在 CFG、少步采样、Rectified Flow 下因线性近似失效或引导误差放大而逐步漂移，导致重建失真；与此同时，提高反演精度往往增加计算开销或牺牲可编辑性，保真、可编辑、速度三者难以同时满足。

##### 怎么演进的
| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|------|----------|----------|------------------------|
| 优化显式反演轨迹 | Null-text Inversion, EDICT | Null-text 以 DDIM 反演为枢轴，逐时间步优化空文本嵌入补偿 CFG 误差；EDICT 用仿射耦合层构造双变量可逆系统 | 重建接近 VAE 上界且保持可编辑性；代价是单张图反演 40–120 秒（NTI）或双倍推理+双精度浮点（EDICT） |
| 免反演与少步适配 | InfEdit, ReNoise, TurboEdit | InfEdit 用 DDCM 虚拟反演（特殊方差参数）移除显式反演；ReNoise 每时间步内迭代加噪逼近不动点；TurboEdit 用时间偏移修正噪声统计、伪引导放大跨提示方向 | 速度大幅提升（InfEdit 2.22 秒，TurboEdit 0.412 秒），少步模型可用；代价是依赖 LCM/SDXL-Turbo 等特定模型，需手动调整超参数，保真度有上限 |
| 面向 Rectified Flow 的反演修正 | RF-Inversion, RF-Solver-Edit, DirectEdit | RF-Inversion 用 LQR 受控 ODE/SDE 进行反演编辑；RF-Solver 用二阶 Taylor 展开修正 ODE 求解误差；DirectEdit 记录反演残差对齐正向路径 | 在 Flux 等 RF 模型上实现高保真重建（DirectEdit 触碰 VAE 上界）；代价是依赖特定架构、需手动设置控制器参数或共享层，DirectEdit 依赖 MLLM+SAM 掩码 |
| 失败机制诊断 | cfg-inversion-fail | 用固定点反演对高 CFG 轨迹做受控生成-反演-重建分析，定义 prompt pressure，提出 SKIPINV 局部降 guidance | 揭示失败由 prompt 主效应和局部轨迹不稳定性决定；代价是诊断范围限 SD1.4/DDIM/CFG=7，未给出通用解决方案 |

真正的转折点在 InfEdit 的 DDCM 虚拟反演：当初始样本已知时，通过选择特殊方差参数使去噪步骤退化为一致性采样，可以完全绕开显式反演，这为少步模型和后续免反演方法提供了可行性依据。另一个关键转折是 RF 系列将反演修正从扩散模型迁移到 Rectified Flow，因为 RF 模型的反演误差累积问题在原有扩散反演框架下未被覆盖。

##### 已经稳定下来的做法
- **以 DDIM 反演或固定点反演作为基础轨迹/枢轴** —— 在标准扩散模型上做真实图像编辑时，先获取一条初始反演轨迹，后续优化或诊断都建立在此轨迹上。
- **对 CFG 引入的偏差进行补偿** —— 当使用高分类器自由引导（CFG）时，通过优化无条件分支、伪引导或局部调 guidance 来修正反演失真。
- **用残差或轨迹对齐代替重新求解反演** —— 在已有反演轨迹的前提下，通过记录残差、使用一致性项或高阶修正让正向去噪轨迹贴合反演轨迹，而不是重新计算反演。
- **注意力 Value 注入或特征共享保持源结构** —— 编辑时，在去噪早期步骤用源重建分支的 Value 或交叉注意力图替换目标分支，以保留源图像布局和细节。
- **针对特定模型架构调整反演策略** —— 当目标模型是少步蒸馏模型（SDXL-Turbo/LCM）或 Rectified Flow（Flux）时，需定制反演参数（如时间偏移、控制器引导、共享层选择）。

##### 还没解决的
- **复杂几何/姿态编辑失败** —— 素材中 Null-text 提到“大幅结构变化超出 Prompt-to-Prompt 能力”，TurboEdit 提到“属性泄漏、添加新物体、交叉手臂等几何变化”，DirectEdit 提到“尺寸变化、空间移动、视角变化、复杂推理是困难任务”。卡在注意力注入和掩码混合只能保持局部结构，无法推理大形变。
- **超参数自动选择缺失** —— 多篇论文需要手动调整早停阈值、混合系数 p、renoising 迭代次数、时间偏移 Δ、控制器 γ/η、注意力共享步数等。卡在没有统一的自动调参规则，换模型或任务需重新人工搜索。
- **VAE 压缩上界限制无损重建** —— 素材中 NTI、EDICT、DirectEdit 均指出重建无法超过 VAE 自编码器重建质量。卡在潜空间编码本身丢失细节，反演精度再高也无法恢复像素级完美。
- **高 CFG 反演的中间失败机制未解** —— cfg-inversion-fail 明确：intermediate prompt 的成败取决于 prompt-latent 配对，但压力曲线、峰值、熵等时间统计均无一致模式。卡在无法提前预测哪个 prompt-seed 对会失败，也无法从全局压力解释局部不稳定性。
- **少步模型反演容量限制** —— ReNoise 提到 SDXL Turbo 上重建 PSNR 仅 22.077，LPIPS 0.08469，说明少步模型的反演容量本身有限。卡在蒸馏模型步数少，误差累积难以通过反演完全补偿。

### 3. 指令式编辑：说人话改图，以及数据从哪来

`18 篇 · 2022-11 ~ 2026-07 · InstructPix2Pix、HIVE、MagicBrush…`

##### 这条线在解决什么
这条线要解决的核心矛盾是：用户只给一句自然语言编辑指令和一张输入图像，不给 mask、不给编辑前后 caption，也不做 per-example inversion；模型却必须同时做到“听懂要改什么”与“只改该改的地方”。由于真实成对“源图-指令-目标图”监督数据稀缺，而自动合成数据又天然存在分布偏差与指令定位误差，后续工作不得不在数据来源、条件建模与评估指标之间反复折中。

##### 怎么演进的
| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| 自动合成数据 + 条件扩散：先让编辑可学 | InstructPix2Pix、HIVE | 用 GPT-3 生成编辑三元组，Stable Diffusion + Prompt-to-Prompt 生成配对图，CLIP 过滤后训练双条件潜扩散；HIVE 再训练 BLIP 奖励模型，把离线 RL 目标转成加权/条件扩散损失 | 换来零样本前向编辑、无需 per-image inversion 或微调；代价是合成域偏差、真实图泛化有限，计数、空间推理、对象交换失败 |
| 人工与真实数据补强：把真实意图和区域控制拉进来 | MagicBrush、HQ-Edit、UltraEdit | MagicBrush 人工标注 10,388 编辑轮次并微调 InstructPix2Pix；HQ-Edit 用 DALL-E 3 生成双联画、GPT-4V 改写；UltraEdit 用真实图像锚点、SDXL-Turbo/P2P 和自动区域软掩码 | 换来更真实、更多样、支持区域编辑的监督；代价是人工成本或复杂数据管线，基准存在偏差且自动指标与人评错位 |
| MLLM 语义条件：让模型先理解再编辑 | MGIE、SmartEdit、Instruct-Imagen、Step1X-Edit | 用 LLaVA/LLaMA 系 MLLM 替换或前置文本编码器，生成表达性指令或直接注入隐状态；SmartEdit 用 BIM 让图像与文本特征双向修正；Instruct-Imagen 构造带 `[ref#?]` 的多模态指令 | 换来模糊指令和长尾表达的理解提升；代价是 7B/13B MLLM 推理延迟、视觉幻觉或定位错误，部分工作证据仍偏定性 |
| 多任务/专家数据与统一编辑架构 | Emu-Edit、AnyEdit、OmniEdit、ICEdit、SeedEdit 系列 | 任务嵌入/路由，多任务统一为生成目标；OmniEdit 用任务专家生成候选并由蒸馏 InternVL2 打分过滤；ICEdit 把编辑包装为 diptych + in-context prompt + LoRA-MoE；SeedEdit/Step1X-Edit 使用因果共享双支路或 MLLM-DiT token concatenation | 换来更宽任务覆盖、更可控的编辑类型与工程加速；代价是数据管线复杂，自动指标仍不可靠，组合指令、局部 grounding 和真实图高保真仍有明显缺口 |
| 多轮与时间性保持：显式处理遮挡恢复 | implicit-preservation | 提出 OCCUR-Bench 隔离“暂时遮挡—揭示”恢复问题，ReSpec 训练免地从编辑历史中选择参考图并改写恢复感知指令 | 换来多轮遮挡恢复的可诊断性与部分改善；代价是高度依赖 VLM 参考选择准确率，长轨迹一致性绝对水平仍不高 |

这条线真正的转折点有两处：一是从 InstructPix2Pix 的纯合成数据，转向 MagicBrush、UltraEdit、OmniEdit 的真实锚点、人工标注与专家/过滤管线，因为早期失败被后续工作反复归因到数据分布，而不只是模型容量；二是从 CLIP 文本编码器转向 MLLM 条件建模，这使“指令不理解”从嵌入空间问题变成显式语义与任务规划问题，但也带来了 MLLM 幻觉、定位错误和延迟代价。

##### 已经稳定下来的做法
- **用预训练 T2I/扩散模型与 Prompt-to-Prompt、SDEdit 制造合成“源图-指令-目标图”，并配 LLM 生成指令** —— 当缺少真实成对编辑数据时，作为默认冷启动/规模化数据生成路径。
- **源图条件以通道拼接送入 U-Net/DiT，并用双 classifier-free guidance 分开控制图像一致性与指令一致性** —— 单轮指令式条件扩散编辑的默认训练/推理骨架。
- **用 CLIP 图像相似度或方向相似度做数据过滤与初步评估** —— 自动管线里做快速筛选和相对比较；但已知它与人评会错位，不能作最终验收。
- **人工标注小规模真实编辑对或奖励排序，再微调合成预训练模型** —— 当合成数据对真实用户意图覆盖不足时，补真实监督或偏好信号。
- **用 MLLM 生成表达性指令或直接注入隐状态，把模糊指令先“说清楚”** —— 对复杂属性和世界知识类指令，仅靠 CLIP/静态文本编码器不够时引入。

##### 还没解决的
- **计数、空间推理与局部精确 grounding** —— 多个工作把“移到左边”“放两个杯子”列为失败；模型没有显式空间或计数监督，文本-图像扩散难绑定位置/数量。
- **组合指令、多轮误差累积与时间性保持** —— MagicBrush 显示多轮编辑误差累积，SEED-Data-Edit 的多轮数据被拆成单轮，implicit-preservation 显示遮挡恢复的绝对一致性仍低且依赖参考选择。
- **自动指标与人类偏好错位** —— CLIP 相似度会奖励保守编辑，方向相似度在 HQ-Edit 中与人类偏好负相关，ICEdit 也发现 CLIP 判据反而降低 GPT 分。
- **复杂推理、对象交换与语义消歧** —— HIVE、MGIE、SmartEdit、ICEdit 都报告错误对象识别、代词不可解析或多义词混淆，根因指向数据生成方式和文本编码器/MLLM 能力上限。
- **真实图像 OOD 与高分辨率/高保真/身份保持** —— 合成数据训练的模型在真实图上仍有分布偏移；Instruct-Imagen 的低分辨率主干使零样本编辑不可用或高分辨率伪影严重，OmniEdit、SeedEdit3 仍受底座质量和像素级细节限制。

### 4. 条件控制：结构、身份、参考图怎么注入

`14 篇 · 2023-02 ~ 2026-04 · ControlNet、T2I-Adapter、IP-Adapter…`

##### 这条线在解决什么

文本到图像扩散模型已经能用文本 cross-attention 处理语义条件，但结构图、身份参考图、多参考 token 这类条件无法自然进入文本序列。这条线必须在冻结主干的前提下为额外条件建立表示通道，并反复面对同一组矛盾：空间对齐与语义对齐会互相压制，多条件通道之间会串扰，附加条件的 token 或分支还会增加推理成本。从 UNet 到 DiT 的迁移又迫使条件注入方式从特征加法转向 token/通道拼接或隔离式分支。

##### 怎么演进的

| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| UNet 旁路适配 | ControlNet / T2I-Adapter / IP-Adapter | 冻结 U-Net；ControlNet 用 zero convolution 复制编码器，T2I-Adapter 用 pixel unshuffle + 卷积输出多尺度特征加法，IP-Adapter 在文本 cross-attention 旁新增独立图像 cross-attention | 不破坏预训练能力，轻量可插拔；每种条件要单独训练，多条件简单相加易冲突 |
| 身份与属性低秩参数化 | Concept-Sliders / PhotoMaker / InstantID | 在参数空间学 LoRA 属性方向（解耦保留概念），或将多张身份图编码为堆叠身份嵌入/人脸嵌入，只更新适配层 | 单次前向、可连续编辑；身份嵌入耦合面部属性，自动指标与用户研究错位，身份保真上限低于 DreamBooth 类微调 |
| DiT 条件 token 化与统一序列 | In-Context-LoRA / OminiControl / ACEpp | 条件从特征加法转向 token 拼接或通道拼接；OminiControl 给条件 token 动态位置编码和注意力偏置；ACEpp 用 LCU++ 通道拼接减少序列长度；In-Context-LoRA 拼图 + 合并字幕激活 in-context 生成 | 适配 FLUX 等 DiT，统一空间对齐与主体驱动；推理 token 数增加，ACEpp 多参考 token 随参考图数量线性增长，OminiControl 明确 token 效率是未解问题 |
| 多条件解耦与几何内化 | EasyControl / UNO / DreamO / care-edit / SpatialFusion | EasyControl 用条件分支 LoRA + Causal Attention + KV Cache 隔离并缓存条件；DreamO 用 \(L_{route}\)/\(L_{holder}\) 约束参考注意力；care-edit 用稀疏 Top-K 异构专家按时间步路由；UNO 用模型-数据协同演化合成多主体对；SpatialFusion 用并行 Spatial Transformer 预测深度并以加法注入潜变量 | 多条件零样本组合、延迟显著下降、数据效率提高；代价是路由坍塌、合成数据偏差、固定专家数量、复杂空间关系/度量距离仍低 |

真正的转折点有两个：一是从 UNet 到 DiT 的迁移，旧的特征加法在 DiT 架构假设下失效，OminiControl 把条件变成 token 才重新打开统一条件接口；二是多条件组合场景暴露了静态统一序列的串扰和推理成本问题，EasyControl 的 Causal Attention/KV Cache 与 care-edit 的稀疏专家路由都指向同一个判断——条件不能只被注入，还要在计算图中被隔离或按需激活。

##### 已经稳定下来的做法

- **冻结预训练主干，只训练新增适配器/LoRA/条件分支** —— 需要在添加控制能力的同时保留原生成质量时，这是默认选择。
- **新增分支权重零初始化或从预训练层初始化** —— ControlNet 的 zero convolution、IP-Adapter 从原始 \(W_k,W_v\) 初始化，都为了训练早期不污染主干。
- **条件图先编码为与主干特征/潜在 token 对齐的表示，再以加法、cross-attention 或 token 拼接注入** —— ControlNet/T2I-Adapter 用特征加法，IP-Adapter 用解耦 cross-attention，OminiControl 用 token 拼接，都是这条路径。
- **训练时随机丢弃文本或条件，保留无条件分支** —— ControlNet 50% prompt 置空、IP-Adapter 5% 同时丢图像文本、DreamO 50% 无占位符，用于 CFG 推理稳定。
- **推理时用可调缩放系数控制条件强度** —— IP-Adapter \(\lambda\)、Concept-Sliders \(\alpha\)、EasyControl 条件权重，用于调节图像提示影响或编辑强度。

##### 还没解决的

- **多条件冲突与解耦** —— 多条件简单相加或静态拼接没有自动冲突解决机制；EasyControl 显示语义矛盾输入会产生重叠伪影，DreamO 多参考解耦依赖注意力约束但自动评估缺失。
- **身份保真与文本/风格可控的权衡** —— IP-Adapter 明确达不到 Textual Inversion/DreamBooth 程度的主体一致，InstantID 人脸嵌入耦合属性使编辑困难，UNO 的 CLIP-T 不突出，说明“像本人”和“按指令改”还未同时解决。
- **推理 token/序列成本** —— OminiControl 把 token 效率列为未解问题，ACEpp 多参考 CU token 随参考图数量线性增长，EasyControl 1024×1024 25 步仍需 16.3 秒，DiT 条件 token 的延迟/显存没有通用压缩方案。
- **自动指标与人类判断错位** —— T2I-Adapter 的 FID/CLIP 不能反映控制准确性，PhotoMaker 的 CLIP-T 与用户研究相反，InstantID 没有定量报告，多条件组合缺少统一基准，仅靠自动指标无法判断控制成败。
- **合成数据/伪标签偏差** —— Subject200K、UNO、DreamO、SpatialFusion 都依赖上游模型生成或伪标签，误差会传播；PhotoMaker 的多模型数据管线错误级联，真实场景泛化上限不明确。

### 5. 个性化与主体保持

`4 篇 · 2022-08 ~ 2026-05 · Textual-Inversion、DreamBooth、Custom-Diffusion…`

##### 这条线在解决什么
这条线要解决的是：用同一主体的少量参考图，把该主体变成可被文本提示调用的生成条件，同时不破坏预训练 text-to-image diffusion model 原有文本跟随能力和类别多样性。独有的技术矛盾是：主体身份保持与可编辑性共享同一组条件参数，更新参数或 embedding 来记住主体，容易把背景、姿态、类别先验一起吸收，导致语言漂移、多样性下降或复杂关系组合失败；完全不更新又无法覆盖新主体身份。

##### 怎么演进的

| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| 文本 embedding inversion | Textual Inversion | 冻结 LDM，只优化文本 encoder 中单个伪词 embedding v*，用 CLIP 模板和去噪损失重建 3–5 张图 | 换来极低训练/存储成本与自然语言可编辑；代价是形状保持差、复杂关系提示失败，单 embedding 容量有限 |
| 全量微调 + 类别先验保留 | DreamBooth | 用稀有 token 绑定主体，微调整个扩散模型，并用冻结模型生成类别图作为 PPL 正则项 | 换来主体保真度显著更高；代价是每主体训练一次、保存完整权重，PPL 只能缓解不能根除多样性和语言漂移 |
| 只改 cross-attention KV 的少样本适配 | Custom-Diffusion | 只微调 cross-attention 层 Wk/Wv 和新增 token V*，用 LAION 检索真实图做正则化，多概念用约束最小二乘合并 | 换来约 6 分钟训练、75MB 存储和多概念闭式合并；代价是继承 SD 的组合生成上限，两个以上新概念不稳定 |
| 结构-外观解耦 | decompose-subject | 冻结 FLUX.1-dev，只训练两个 LoRA：先预测 Canny 图，再联合 Canny/源图/文本渲染 RGB；配套 TextingSubject100k 数据 | 换来高频细节和文字保持提升，参数约 47M；代价是两阶段推理至少 2 倍延迟，级联误差可能放大，骨干验证窄 |

转折点在 DreamBooth 把防遗忘显式写成 PPL：此前只是“学一个主体”，此后变成“改模型但维持类别先验”的约束优化。Custom-Diffusion 随后证明 cross-attention KV 是该约束下高性价比的更新点，decompose-subject 则把保真压力从条件注入转移到显式结构预测，才继续缓解高频细节丢失。

##### 已经稳定下来的做法
- **少样本同主体参考图集** —— 默认用约 3–5 张同一主体图片（Custom-Diffusion 实验中可到 4–12 张）而非单张；需要较强编辑性时，尽量让背景/姿态多样，避免背景进入概念。
- **稀有/修饰符 token + 类别名词** —— 给新概念绑一个稀有或新增 token（S*、[V]、V*），与 class noun 一起构成训练提示，降低原始词强先验干扰。
- **冻结主干或只更新极小参数子集** —— 在更看重训练时间和存储时，优先只改 token embedding、cross-attention 的 Wk/Wv 或 LoRA，而不是全量微调。
- **类别先验/正则化图集** —— 全量或部分微调时，加入 PPL 或从 LAION 检索的真实图正则化集，抑制语言漂移和输出多样性下降。
- **自动指标组合监控** —— 用 CLIP-T/CLIP-I 或 DINO 看主体/提示保真，用 KID/FID 看通用分布退化，用 OCR/VLM 看文字类细节；不只看去噪或流匹配损失。

##### 还没解决的
- **多概念与空间关系组合** —— Custom-Diffusion 显示 cat/dog 的 attention map 高度重叠，两个以上新概念只部分可用；Textual Inversion 在关系提示下会失败，卡在扩散模型底层组合能力。
- **严格形状与高频身份保持** —— Textual Inversion 明确形状保持不足，decompose-subject 在遮挡、复杂姿态、文字扭曲时 Stage 1 结构预测错误并导致伪影，尚未达到真实图像成对相似度水平。
- **级联系统的误差放大** —— decompose-subject 的 Stage 2 训练只见过真值 Canny，推理时若 Stage 1 输出断裂或异常密集边缘，Stage 2 缺少对应训练经验，误差会传导放大。
- **训练/推理成本与保真度无法同时最优** —— DreamBooth 每主体训练一次且保存完整权重，decompose-subject 两阶段采样至少 2 倍延迟；省钱省时路径往往要牺牲图像对齐或形状保持。
- **自动评测与真实分布鲁棒性缺口** —— CLIP 对细粒度图案和文字不敏感，GPT-4.1 评测未报告方差且缺乏人类评估；TextingSubject100k 的类别/文本分布统计未披露，低质量用户实拍图鲁棒性未验证。

### 6. 局部与对象级：抠图、补全、搬物体

`12 篇 · 2022-11 ~ 2026-06 · Paint-by-Example、Imagen-Editor-EditBench、SAM…`

##### 这条线在解决什么
局部与对象级编辑必须同时满足三个互相牵制的要求：在指定区域内接受文本或参考图条件并改变，区域外保持像素级不变，且边界自然融合。全局文本编辑不需要处理空间区域，全图生成不要求掩码外保持，而这条线引入参考对象或局部指令后，会集中出现复制粘贴退化、条件被上下文淹没、编辑泄漏到区域外三类失败。因此它独有的技术矛盾是：如何在冻结或微调的生成先验中显式分离“where”和“what”，既不破坏原图其余部分，又不退化为简单复制或忽略条件。

##### 怎么演进的

| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| 条件进入局部修复并防退化 | Paint-by-Example、Imagen-Editor-EditBench | 自监督边界框训练 + 信息瓶颈/强增强/掩码形状增强；用物体检测器掩码替代随机掩码 | 换来单次前向、局部文本/参考对齐；代价是 count/shape/text-rendering 弱，参考条件只有全局语义向量，不能处理空间定位 |
| 通用分割与 mask-free 组合交互 | SAM、Inpaint-Anything | 可提示分割任务 + 数据引擎生成 1.1B 掩码；SAM+LaMa+SD 点击即移除/填充流水线 | 换来通用 where 输入、免手动 mask；代价是分割误差会向后续级联，组合系统上限受各组件和 SD 固定分辨率限制 |
| 冻结主干 + 双分支/任务提示条件 | AnyDoor、PowerPaint、BrushNet | DINOv2 身份 token + Sobel 高频图 detail branch；学习任务提示词 P_obj/P_ctxt/P_shape；纯图像 UNet 分支 + 零卷积注入 | 换来零样本对象传送、单模型多任务、可插拔修复且减少文本干扰；代价是依赖外部分割、小 α 形状控制弱、基座模型领域偏差会传导 |
| 自动参考定位与交互/多任务统一 | MimicBrush、MagicQuill、Insert-Anything | 视频帧自监督双 U-Net K/V 拼接；MLLM 预测提示 + 边缘/颜色双 ControlNet；DiT 多联画统一掩码/文本插入 | 换来减少或免除参考框选和 prompt 输入，统一多任务；代价是外 ID DINO-I 低于有参考掩码的 AnyDoor、MLLM 意图预测 GPT-4 相似度仅 2.712、文本模式 FID 仍高 |
| 冻结 DiT 适配器与轻量化修复 | edit-where-you-mean、moebius-inpainting | SpatialGate + Region-Aware Loss + MaskPredictor 显式注入 where/what；Local-λMix 线性注意力 + 多粒度潜空间蒸馏 | 换来局部编辑不泄漏、0.226B 模型 20 步约 0.52 秒推理；代价是局部编辑专家而非全局编辑器、OOD 泛化弱、任务专用替代方案 |

真正的转折点不是单一模型，而是从直接微调主模型或采样阶段拼接，转向冻结扩散主干 + 可训练条件分支/任务提示。这之后的方法大多不再改动主干，而是把 where（掩码/边缘/高频图/参考位置）与 what（文本/身份/任务）作为额外条件注入；此后的交互简化和轻量化都建立在这个可插拔条件架构上。SAM 提供的可提示分割也很关键，它把局部编辑的 where 输入从手工掩码变成模型交互，但没有直接解决条件融合。

##### 已经稳定下来的做法
- **冻结预训练扩散主干，只训练条件分支/低秩适配器** —— 当需要在不同社区或微调模型间复用、避免全量微调风险时，默认在主干外插入可训练条件路径。
- **用 VAE 编码掩码图/参考图潜变量或高频图，再经逐层零卷积/cross-attention 注入** —— 需要像素级或细节级局部控制时，作为纯图像条件进入去噪器。
- **classifier-free guidance 作为条件强度或任务抑制旋钮** —— 需要调节生成内容多像参考、多符合文本，或抑制物体生成时，用正负条件与 scale 控制。
- **用自动检测/分割/视频帧对生成训练掩码和配对数据** —— 当手工掩码对昂贵时，用物体检测器、SAM 或视频一致性构造局部编辑监督。
- **自动指标与用户研究联合评估，且不只用 CLIP Score/FID 单指标** —— 需要判断局部融合、身份保持和文本对齐时，组合 CLIP-I/DINO-I/LPIPS/PSNR 及人工偏好。

##### 还没解决的
- **细粒度计数、形状、文字/logo 渲染弱** —— Imagen Editor、AnyDoor 等明确报告这些属性在局部对象编辑中系统性失败，卡在条件粒度和 VAE/分辨率压缩损失。
- **自动参考区域或多候选定位不可靠** —— MimicBrush 在小区域、多候选时会定位失败，Paint-by-Example 只有全局语义向量，MagicQuill 的 MLLM 会把 raspberry 猜成 candy，卡在缺少可靠的空间对应。
- **高分辨率细节保持与实时/端侧推理仍冲突** —— 多数方法受 512/768 分辨率限制，且未披露延迟；Moebius 做到 0.52 秒但 OOD 泛化下降，卡在任务专用压缩牺牲通用性。
- **未编辑区域保持与编辑强度/文本对齐没有自动平衡** —— edit-where-you-mean 的 CLIP-T 偏弱，PowerPaint 小 α 形状控制差，BrushNet 领域偏差随基座模型传导，卡在缺乏自适应的保持-改变权衡。
- **多区域、多主体或复合指令同时编辑缺失** —— edit-where-you-mean 只有单 mask 假设，AnyDoor 未定量验证多主体组合，Insert-Anything 未测试多物体插入，卡在单一编辑区域假设与用户真实指令复杂度不匹配。

### 7. 拖拽与点控编辑

`4 篇 · 2023-05 ~ 2024-02 · DragGAN、DragDiffusion、DragonDiffusion…`

##### 这条线在解决什么
点拖拽编辑要处理的核心矛盾是：用户只给出稀疏的手柄点/目标点空间位移，但生成模型内部没有天然的像素坐标对应；文本编辑或语义方向编辑无法表达这种“把这个局部挪到那个位置”的精确几何约束。这条线必须在保持图像真实感、身份和未编辑区域不变的前提下，把点级空间约束转化为 latent code 或中间特征的局部可微目标。

##### 怎么演进的

| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| GAN 潜空间点拖拽 | DragGAN | 在 StyleGAN2 第 6 个 block 特征图上做 patch 运动监督 + 最近邻点跟踪，只更新前 6 层 latent，迭代至手柄点抵达目标点 | 换来了多点像素级拖拽、无额外网络、约 2 秒编辑；代价是受 GAN 容量和训练分布限制，真实图需要 inversion，无纹理区域会漂移，亚像素精度不可达 |
| 扩散模型单步潜在优化 | DragDiffusion | 把运动监督/点跟踪迁到 SD1.5 的 DDIM inversion 潜在，只优化 t=35 单时间步，加入单图 LoRA 身份保持微调和参考潜在控制（自注意力 K/V 替换） | 换来了真实图和扩散生成图通用，DragBench 全部 10 类 IF/MD 优于 DragGAN；代价是单张约 36~57 秒，t 和 LoRA 步数敏感，点跟踪仍可能失效 |
| 无训练特征对应能量引导 | DragonDiffusion | 用 DDIM inversion 建立记忆库，把编辑定义为 UNet 中间特征对应变化，用能量函数在采样前 30 步做梯度引导，并用视觉交叉注意力保持一致性 | 换来了无需微调、准备约 3.62s，任务扩展到移动/缩放/外观替换/粘贴，一致性与质量优于 DragDiffusion；代价是点精度低于 DragGAN，大位移或复杂 mask 下仍会失败 |
| 区域随机性与图像提示增强 | DiffEditor | 在 DragonDiffusion 框架上加可训练图像提示编码器、区域 SDE（mask 内 η=0.4/外 η=0.2）、区域分数梯度引导、时间旅行内部循环 | 换来了 17/68 点 MSE 17.05/11.52、FID 33.10/33.02 低于 DragonDiffusion，推理约 13.88s；代价是图像提示编码器需 LAION 训练 1×10^6 步，仍受 SDv1.5 的 3D 理解限制 |

真正的转折点在 DragonDiffusion：它把编辑目标从“跟踪手柄点并优化 latent”改写为“改变中间特征对应并沿采样路径做梯度引导”，使拖拽编辑不再绑定 GAN inversion 和逐点优化，任务也从点拖拽扩展到移动、缩放、外观替换和粘贴；代价是点精度回到扩散特征对应能稳定的量级。后续 DiffEditor 是在这条路径上做区域化，而不是另起一条线。

##### 已经稳定下来的做法
- **用生成模型中间层特征而非 RGB 空间定义点对应和运动监督** —— 用于把手柄点/目标点位移写成可微能量或损失时。
- **对运动监督/能量损失中的参照特征 detach** —— 防止优化过程中参照项随被优化变量一起移动，用于单步或迭代点拖拽。
- **DDIM inversion 缓存潜变量与自注意力 K/V，并在采样阶段回投** —— 用于真实图像编辑中维持源图结构与身份。
- **编辑区域 mask 内强约束，mask 外弱约束或只做保真项** —— 用于抑制背景漂移，同时允许编辑区域生成新内容。
- **单图身份保持优先用冻结底模加 LoRA、cached K/V 或图像提示，不训练底模本身** —— 用于避免整底模微调开销和灾难遗忘，同时保持源图细节。

##### 还没解决的
- **点跟踪/特征对应漂移** —— 无纹理区域、遮挡或外观变化大时，最近邻或特征匹配仍会找错目标，导致手柄点偏离。
- **亚像素级点精度不可达** —— 受中间特征分辨率、扩散采样随机性和特征对应近似限制，当前扩散路径达不到 DragGAN 在 GAN 流形上那样的像素级约束。
- **大位移或 3D 姿态/视角变化失败** —— 训练分布外操作、旋转和大量内容想象仍会产生伪影，底模缺乏单物体 3D 理解。
- **关键超参数无自动选择** —— 如 DragDiffusion 的 t、LoRA 步数，DragonDiffusion 的能量权重，DiffEditor 的区域 SDE η/τ、时间旅行参数都靠人工调。
- **单图编辑延迟仍高** —— 真实图需要 DDIM inversion、LoRA 微调或时间旅行，单张准备加推理在十几秒到几十秒，难以做到实时交互。

### 8. 统一多模态：理解与生成同一个模型

`20 篇 · 2023-12 ~ 2026-06 · Emu2、SEED-X、VAR…`

##### 这条线在解决什么

统一多模态模型要让同一模型、同一批参数同时做图像/视频理解与生成。理解通常需要把视觉压缩成语义 token 或特征供自回归解码，生成则需要连续潜在变量或离散码本映射回视觉空间；这条线必须同时处理离散文本、连续/离散视觉表示，以及不同训练目标在同一 Transformer 里的容量与梯度冲突。

##### 怎么演进的

| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| 统一预测目标的早期尝试 | Emu2, SEED-X, VAR, Chameleon | 把视觉作为连续嵌入回归、离散 token 或 next-scale 多尺度网格进入自回归；用 QK-Norm/z-loss/norm reordering 稳定跨模态熵差 | 单模型出现交错图文生成能力，VAR 把图像生成步数大幅降低；但零样本弱、OCR/tokenizer 重建受限、视觉 token 长、训练后期易发散 |
| 混合目标与解耦视觉表示 | Transfusion, Show-o, Emu3, OmniGen, Janus-Pro | 文本继续自回归，图像改用双向注意力的扩散/流匹配或 MaskGIT 式离散扩散；或把理解与生成拆成两套视觉编码；统一图文序列占位格式 | 生成质量接近或超过同规模扩散模型，理解能力保持；但扩散多步推理、双编码器增加成本，分辨率与 tokenizer 上限仍存在 |
| 冻结理解骨干 + 轻量生成接口 | MetaQuery, BLIP3-o, OmniGen2, UniWorld-V1 | 冻结 MLLM/VLM；插入可学习查询、变长隐藏状态或 SigLIP 语义 token 作为生成条件；只训练连接器/扩散头，CLIP 特征或 VAE latent 用 flow/diffusion 建模 | 低成本复用已有理解能力，世界知识可迁移到生成；但条件上限依赖冻结骨干，编辑、文本渲染与复杂指令仍弱 |
| 大规模交错数据 + 整体 tokenizer + RL/DPO 课程 | BAGEL, Show-o2, Ovis-U1, nextflow, HYDRA-X | 自动构造视频/网页交错数据；视觉 tokenizer 统一或分解语义层；引入多任务 RL/DPO 课程、CoT 轨迹；用 next-scale 或整体 ViT tokenize | 复杂编辑、视频与多图能力提升，部分指标接近 GPT-4o 同项；但训练 token 达 T 级、多阶段工程复杂，长视频/动态/知识差距未闭合 |

真正的转折点不在单一模型，而在 Transfusion 与 BLIP3-o 所确立的组合：受控比较显示连续 VAE/CLIP 特征配合扩散/流匹配在统一模型里比把图像离散成 token 更有语义和效率优势；随后 MetaQuery、OmniGen2、UniWorld-V1 把理解骨干冻结、只训生成接口，使统一模型从“重训整个主干”变成“接入生成头”。离散 token 路线没有消失，但后续更多作为 Janus-Pro、NextFlow 中的一种生成策略，而不是默认语义表示。

##### 已经稳定下来的做法

- **理解/生成表示分离** —— 当同一模型需要兼顾理解与生成且不想明显牺牲一侧时，用两套视觉编码器或语义/低层两个流，而不是强迫一个视觉表示同时服务两个任务。
- **冻结自回归理解骨干，只训练连接器与生成头** —— 已有强 MLLM/VLM 且训练预算有限时，让骨干冻结，只更新可学习查询、投影层和扩散/流头。
- **生成侧用连续视觉特征 + 扩散或 Flow Matching/Rectified Flow** —— 避免离散 token 回归的生成长度和语义损失，图像用 VAE/CLIP 连续潜在或特征做条件或目标。
- **分阶段训练，先对齐视觉接口再联合微调** —— 先训练视觉投影、refiner、生成头或适配器，后期再解冻全模型或视觉编码器，以保护语言/图像先验。
- **QK-Norm、z-loss 与 norm reordering 稳定混合模态训练** —— 单一 Transformer 同时处理文本与视觉、跨模态熵差导致 logits 范数漂移时，作为训练稳定性修改。

##### 还没解决的

- **离散视觉 token 生成的偏好优化失败** —— VQ 自回归统一模型上生成 DPO 收敛到无信息基线（ln 2），逐 token 监督无法表达图像全局质量，只能换架构或在线策略。
- **OCR / 文本渲染与高频细节受视觉编码器和分辨率限制** —— Janus-Pro 的 384×384 限制 OCR、Chameleon 的 tokenizer 重建上限、Show-o2/UniWorld-V1 的文本编辑弱，都指向压缩丢失稠密文字信息。
- **理解与生成目标的梯度/容量冲突未消除** —— 共享参数下生成梯度可大于理解梯度约一个数量级，或一阶段联合训练直接损害语言能力；如何稳定配平目标和容量仍无定式。
- **复杂推理、世界知识与多图上下文一致性仍明显低于闭源模型** —— BAGEL、OmniGen2、UniWorld-V1 在 IntelligentBench、OmniContext、ImgEdit-Bench 等上均落后 GPT-4o，卡在高阶多步推理与跨图状态跟踪。
- **多图、长视频和高动态输入不稳定且计算密集** —— OmniGen 限制最多 3 张输入图，UniReal 超过约 5 张图不稳定，Show-o2 视频仅 2 秒 17 帧，HYDRA-X 动态程度低；序列长度与全注意力代价仍是硬约束。

### 9. 生成骨干：编辑方法赖以运行的底座

`10 篇 · 2021-12 ~ 2026-05 · Latent-Diffusion、Classifier-Free-Guidance、PixArt-alpha…`

##### 这条线在解决什么
这条线面对的是生成骨干固有的结构冲突：为了降低采样成本、提升文本跟随和少步质量，骨干不断压缩图像表示、做全局去噪并转向大 Transformer；但这些手段会削弱编辑所需的像素级保真、局部不泄漏和多轮一致性。这条线不能只靠后处理或适配器绕开，因为它决定的是编辑方法运行的底座的表示、条件路径和去噪/解码方式。

##### 怎么演进的

| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| 潜在空间扩散与条件引导 | Latent-Diffusion, Classifier-Free Guidance | 用预训练自编码器把扩散搬到 f=4~8 连续 latent；训练时随机丢弃条件，推理时线性混合条件/无条件分数 | 训练与采样成本显著下降，分类器引导被移除；代价是自编码器压缩损失限制像素级上限，CFG 每次采样需两次主网络前向 |
| Transformer 条件骨干与整流流 | PixArt-α, SD3-RectifiedFlow | PixArt 用三阶段复用类条件 DiT 并注入 SAM-LLaVA caption；SD3 用 MM-DiT 双流共享注意力替代 cross-attention，并引入 rectified flow + logit-normal 时间步采样 | 文本跟随和少步采样明显提升，训练数据需求下降；代价是训练工程/模型容量复杂，自编码器重建仍决定清晰度上限 |
| 稀疏/多模态扩展与统一生成编辑底座 | HiDream-I1, FLUX-Kontext, Qwen-Image | HiDream 用 MoE 替代稠密 FFN 并做双流/单流切换；FLUX-Kontext 用序列拼接把参考图 token 作为上下文；Qwen-Image 用 Qwen2.5-VL 语义特征 + VAE 像素特征双编码 | 生成与编辑进入同一主干，角色/原图一致性和中文渲染提升；代价是空间推理、低频字、多轮一致性等失败模式开始固化，且效率口径未统一 |
| 骨干表示与解码路径的再审视 | rethink-global-text, tuna-2, EditMGT | 将 CLIP pooled embedding 改为调制空间引导；去掉 VAE/视觉编码器直接像素 patch + 单体 Transformer；EditMGT 用掩码生成 Transformer 的局部 token 预测替代全局去噪 | 获得近乎零成本控制、编码器无关统一建模、架构级局部编辑能力；代价是均未全面超越隐空间强骨干，高分辨率像素空间和编辑泄漏度量仍有空白 |

真正的转折点在 SD3-RectifiedFlow：它把 U-Net 的固定 cross-attention 条件换成 MM-DiT 的双流 token 共享注意力，并让 rectified flow/logit-normal 成为少步训练基座。此后参考图像、文本条件和目标图像不再只是注入信号，而可以像 FLUX-Kontext 的序列拼接、Qwen-Image 的双编码那样直接放进同一序列；编辑方法才得以在大主干上不再依赖单独图像编码器或适配器。此前的 LDM/CFG/PixArt 更多是降低成本或改条件注入，还没把生成和编辑统一到同一 token 化底座的层面。

##### 已经稳定下来的做法
- **潜在空间生成** —— 用预训练 VAE 把图像压成低维 latent 再训练扩散或 flow matching 骨干；默认任务不是极端像素级控制或生僻文字渲染时采用。
- **无分类器引导** —— 训练时随机丢弃条件 token，推理时混合条件/无条件分数；需要提升条件遵循与单样本质量时采用，但少步/延迟敏感场景要承担双前向成本。
- **MMDiT / 双流 Transformer 条件融合** —— 图像 token 与文本 token 使用独立权重、共享注意力，替代单边 cross-attention；文生图与图像编辑共用同一骨干时采用。
- **少步流匹配 + 蒸馏** —— 用 rectified flow 训练，配合 logit-normal 时间步采样或 LADD/DMD 蒸馏；在需要秒级/少步生成时采用，代价是可能引入蒸馏伪影。
- **冻结大骨干、附加轻量控制机制** —— 用序列拼接、双编码、注意力注入或调制引导在不重训主干的条件下加入编辑/属性控制；已有强生成骨干但只需补充编辑或控制入口时采用。

##### 还没解决的
- **隐空间信息损失限制高精度像素编辑** —— SD3 的 16 通道 VAE 重建 FID 1.06，tuna-2 像素空间 rFID 仍差 FLUX VAE 一个量级，潜空间与像素空间在高频细节上尚未同时解决。
- **扩散式全局去噪导致编辑泄漏与多轮累积漂移** —— EditMGT 指出扩散每步全局去噪会改动非目标区域；FLUX-Kontext 六轮后出现身份漂移和 artifacts，说明局部保真与多轮一致性仍是失败模式。
- **复杂空间推理与精确属性控制弱** —— FLUX-Kontext 把“移动咖啡”执行成加奶泡；HiDream 的 GenEval Position 仅 0.60、DPG-Bench Global 76.44；Qwen-Image 中文 Level-3 低频字准确率仅 6.48%，这些精确控制问题未解。
- **少步蒸馏/引导会引入伪影或过度修改** —— FLUX-Kontext 的 LADD 蒸馏可能引入视觉伪影；rethink-global-text 的 modulation guidance w 过大出现 artifacts；EditMGT 的 λ 太大不生效、太小编辑泄漏，缺自动平衡。
- **效率主张缺乏统一硬件/延迟口径** —— HiDream 未披露单图延迟与 MoE 实现细节；Qwen-Image 推理延迟未披露；EditMGT 的速度优势缺逐模型延迟对照，少步高质量的可复现算力边界仍不清楚。

### 10. 推理、强化学习与评测

`8 篇 · 2025-03 ~ 2025-05 · GoT、RISEBench、Complex-Edit…`

##### 这条线在解决什么

这条线要解决的是：图像生成与编辑不能只停留在“直接执行指令”，而需要先完成语义、空间、知识或逻辑上的推理，再把推理结果落到像素上。独有矛盾在于，推理本身是隐式、不可直接监督的中间过程，而最终优化目标只能建立在生成结果和人类偏好上；因此这条线必须同时处理推理表示、奖励信号和评测标准三个相互耦合、但各自都可能出错的环节。

##### 怎么演进的

| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| 显式推理链注入生成 | GoT | 用 MLLM 生成含边界框坐标的语义—空间推理链，并通过 SSGM 注入 SDXL 系扩散模块 | 换来可解释、可交互的生成条件；代价是约 9M 自动标注数据与高算力，position 和 attribute binding 仍弱 |
| 推理编辑与知识基准化 | RISEBench、Complex-Edit、KRIS-Bench | 定义推理类型、指令复杂度、知识层级等维度，用 VLM 自动裁判和知识提示评测模型 | 换来对模型推理短板的诊断能力；代价是样本规模小、自动评分相关性上限有限 |
| 强化学习进入生成轨迹 | T2I-R1、Flow-GRPO、DanceGRPO | 将 GRPO 迁到生成模型，用 SDE 转换给确定性 ODE/流匹配采样注入随机探索，并用多奖励聚合优势 | 换来基准上的推理、组合和文本渲染提升；代价是 reward hacking 风险、训练成本高、奖励模型能力限制 |
| 数据与评判器联合工程 | ImgEdit | 构建 1.2M 对质量过滤编辑数据，训练 VLM+DiT 编辑器并配 ImgEdit-Judge | 换来数据质量和评测一致性；代价是仍落后于闭源模型，多轮能力与伪造痕迹未解 |

真正的转折点在强化学习进入生成轨迹这一阶段，尤其是 Flow-GRPO/DanceGRPO 用 SDE 把确定性 ODE/流匹配采样改造成可随机 rollout 的策略。原因在于：此前显式推理链和基准只能暴露推理短板或把推理作为外部条件，而这一阶段第一次让推理规划或生成步骤本身成为可训练策略，而不再只是输入到扩散模型里的静态文本。

##### 已经稳定下来的做法

- **GRPO 组内优势训练生成模型** —— 需要在线 RL 对齐生成模型时，同一 prompt 的一组样本共享初始化噪声，用组内标准化 reward 作为 advantage。
- **训练用 SDE、推理回 ODE** —— 对 rectified flow/扩散模型做 RL 探索时，训练阶段注入可控高斯噪声，评估与部署阶段回到确定性采样。
- **多奖励模型分散化组合** —— 单一偏好模型容易被 hack，训练时用多个奖励模型并行打分，并在优势层面标准化后求和。
- **VLM 作为自动裁判加人工校准** —— 编辑/推理评测中，用 GPT-4o 等 VLM 给多维度分数，并用少量人工评分验证相关性。
- **显式推理链作为生成前的中间条件** —— 先由 MLLM 输出文本或带坐标的推理链，再交给扩散模型，作为连接推理与像素结果的条件。

##### 还没解决的

- **复杂空间与属性绑定** —— GoT 的 position 0.34、attribute binding 0.27，Flow-GRPO 的 Non-Spatial 0.3195，说明关系约束仍难泛化。
- **逻辑与程序性知识推理** —— RISEBench 中逻辑推理只有 10.6%，KRIS-Bench 中程序性知识和 KP 普遍低于 IF，模型“改得对但改不通”。
- **奖励模型可靠性** —— T2I-R1 的单一 VQA 奖励会被 hack，DanceGRPO 只用 HPS 会产出油腻图像，规则奖励可能被检测器或编辑距离欺骗。
- **自动评测相关性上限** —— Complex-Edit 的 IF/IP/PQ 最高相关性约 0.53/0.23，RISEBench 与 KRIS-Bench 样本规模小，难以稳定区分强模型。
- **多轮编辑与生成痕迹** —— ImgEdit 中多轮能力连闭源模型也仅具雏形，所有模型输出 Fake score 接近 1.00，编辑痕迹检测远未解决。

### 11. 奖励模型与在线 RL（2025H2 起）

`9 篇 · 2025-09 ~ 2026-08 · EditScore、EditReward、Edit-R1-UniWorld-V2…`

##### 这条线在解决什么

图像编辑在线 RL 的特有矛盾是：策略优化器已经不是瓶颈，但奖励信号必须同时对“源图 + 指令 + 编辑图”给出细粒度跨图比较、绝对质量校准和低方差反馈，并且不能在训练中被策略反向利用。通用 VLM 直接打分不稳定甚至导致策略崩溃，而专用编辑奖励模型又各有盲区、成本与标注瓶颈；这条线本质上是在反复回答：什么形式的奖励信号才能稳定驱动在线 RL，以及各自要付出什么代价。

##### 怎么演进的

| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| 建立专用编辑奖励模型与基准 | EditScore、EditReward | 用 VLM 微调输出 SC/PQ 或 IF/VQ 分数，构建人工偏好对基准；EditReward 用不确定性感知双头，EditScore 用几何平均 | 换来通用大 VLM 直接当 RM 不稳定问题的替代路径；代价是主观任务准确率低、72B 推理吞吐低、训练数据依赖 GPT-4.1/专家标注 |
| 把奖励接入在线 RL 并控制方差 | Edit-R1-UniWorld-V2、ThinkRL-Edit | 用冻结 MLLM 的 logits 期望或二值清单作奖励，配合 DiffusionNFT/GRPO；低方差组过滤、UCPG 联合排序 | 换来 SFT 基座可继续在线对齐；代价是推理型编辑时间几乎翻倍、组过滤可能丢弃困难样本、奖励模型规模需谨慎 |
| 诊断奖励模型共同失败并修补 | reward-hacking-t2i、SpatialReward | 对 artifact 盲区用 APO 优化“无伪影概率”；对 attention collapse 用“Think-with-Boxes”空间锚点 | 换来跨奖励伪影盲区和跨图注意力坍塌被显式处理；代价是 ArtifactReward 准确率 0.80 非完备、空间推理必要性未严格证明、区域级信用分配缺失 |
| 系统化多任务 RL 训练与蒸馏 | qwen-image-rl | 任务专用复合奖励 + hybrid CFG + 异步奖励管线 + 按 prompt 组归一化 + OPD 多教师蒸馏 | 换来单模型兼顾 T2I 与编辑；代价是数据规模/奖励模型可靠性未披露、全参数 RL 成本高、reward hacking 仍需监控 |
| 用替代奖励路径绕过专用编辑奖励 | read-it-back、rl-no-edit-rewards | 冻结 MLLM 读回 prompt 平均对数似然；训练奖励对齐描述器把编辑投影到 T2I 奖励空间 | 换来无需偏好标注或专用编辑 RM；代价是主要捕捉显式语义、执行细节损失、存在自评估偏差与闭源 MLLM 依赖 |

真正的转折点在 EditScore/EditReward 之后：奖励信号质量问题从“用不用 VLM”转向“跨图比较与伪影盲区”。SpatialReward 和 reward-hacking-t2i 把这些失败模式显式化后，后续工作才分化出两条路线——要么给奖励加空间/伪影正则，要么完全放弃专用编辑奖励，转向冻结似然或 T2I 迁移。之所以是这里，是因为此前方法默认奖励越专用越好，而这两篇证明专用奖励仍有共同盲区，且会直接变成策略可利用的捷径。

##### 已经稳定下来的做法

- **冻结奖励模型并只更新策略** —— 在线 RL 中奖励信号必须来自冻结的 VLM/MLLM，否则策略会 hack 掉奖励或训练崩溃；EditScore、Edit-R1、qwen-image-rl 等均保持 RM 冻结。
- **奖励分数在同一个 prompt 的组内归一化，并过滤低方差简单组** —— 防止不同提示难度和奖励尺度相互污染，丢弃“均值高且方差低”的组以避免除以小标准差放大噪声；qwen-image-rl 公式(13)、Edit-R1 阈值过滤、read-it-back 的 sequence-level advantage 都采用此原则。
- **多维奖励分开建模再聚合** —— 指令遵循、视觉一致性、视觉质量要由不同维度/头分别给出，用几何平均或加权聚合成标量；EditScore 的 SC/PQ、EditReward 的 IF/VQ、qwen-image-rl 的复合奖励、SpatialReward 的 SC/PQ 均如此。
- **用冻结 VLM 的 logits 期望或 teacher-forced 似然，而非离散文本采样打分** —— 当需要连续、低方差奖励时，对评分 token 做 softmax 期望或计算 prompt 平均对数似然；Edit-R1 的 MLLM Score Logit、read-it-back 的 SpectraReward、qwen-image-rl 的点式期望均属此类。
- **自集成/多次采样降低奖励方差** —— 单次 VLM 打分不稳定时，多次采样后平均可提高排序准确率且不增加显存；EditScore 的 Avg@4、Edit-R1 的组内多候选都属于此思路。

##### 还没解决的

- **主观任务与组合指令的奖励评分仍不可靠** —— 卡在人类标注一致性低和模型对鲜艳度/背景改动的偏置，EditScore 在 Beauty/Hybrid 子任务、EditReward 在 VQ 维度均显示低准确率。
- **reward hacking 只能缓解不能根除** —— 卡在长期训练后期策略会突然刷高奖励或导致指标崩溃，多篇只能靠提前停止、正则或选早 checkpoint 规避。
- **细粒度执行与像素级身份保持无法被全局标量或文本奖励完整编码** —— 卡在跨图空间对应和低层视觉一致性的信用分配尚未实现，SpatialReward 的 region-level 信用分配留作 future work，Lever-Edit 明确文本条件不能编码像素级保持。
- **高质量奖励的推理延迟与在线 RL 吞吐冲突** —— 卡在奖励模型需要大 VLM 多抽样或复杂推理，而训练 rollout 对延迟敏感；ThinkRL-Edit 承认编辑时间几乎翻倍，EditScore 72B 吞吐仅 1.60 samples/s。
- **自动评测提升缺少独立人类偏好闭环** —— 卡在多篇论文以自动评测器或同源奖励作为证据，未给出一致的用户满意度/人类偏好验证，reward hacking 和自评估偏差难以排除。

### 12. 会推理再动手：think-then-edit

`7 篇 · 2025-10 ~ 2026-06 · ChronoEdit、ReasonEdit、UniREditBench…`

##### 这条线在解决什么

这条线要解决的是：图像编辑要求只改变指令指定的局部，同时保持整张图中未被明说的物理、语义、数量等约束不变；但模型的推理能力若不先被显式激活，MLLM 的自发发现召回很低（Direct 0.461），而推理一旦写成自然语言，又无法保证与像素编辑结果一致。这让“想”与“改”的接口成为编辑任务独有的瓶颈：纯生成线只需文本遵循，纯局部重绘线未把隐式约束显式化，绕不开这个对齐问题。

##### 怎么演进的

| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| 潜空间时间推理 | ChronoEdit | 把编辑建模为两帧视频生成，插入中间时间推理 token，前 \(N_r\) 步联合去噪后丢弃，只精修末帧 | 动作保真度从 4.01 提升到 4.31，延迟可控；代价是依赖视频生成先验，中间 token 固定为 6 未消融，且标准 14B 单张约 30.4 秒 |
| 显式文本 Thinking / Reflection | ReasonEdit、UniReason | Thinking 把抽象指令改写为具体指令；Reflection 拆成目标描述—单图评估—综合结论三步；UniReason 在生成前补世界知识，生成后用编辑式视觉修正 | 复杂指令理解与知识密集任务提升；代价是多轮 MLLM/DiT 前向使延迟显著增加，底层生成器能力仍限制上限 |
| 推理评测与训练数据标准化 | UniREditBench | 用文本参照 + GT 图双参照的 GPT-4.1 评分，构建 8 维度/18 子维度的 2,700 条样本，并合成 100K 条带 CoT 的编辑数据 | 把评测从“指令做没做”推向“模型是否真读懂因果与规则”；代价是数据管线依赖闭源生成模型，可靠性证据来自小规模人类实验 |
| 可执行 / 结构化推理与一致性激励 | CoCo、Meta-CoT | CoCo 把 CoT 写为可执行 Python 代码，经沙盒渲染成确定性草稿图再精修；Meta-CoT 把编辑拆成任务/目标/理解能力三元组，再分解为五个基础元任务，并用 CEC Reward + Flow-GRPO 做强化学习 | 空间布局、密集文字和跨任务泛化显著提升；代价是文本编辑仍易退化，且沙盒、代码执行和外部模型数据引入强依赖 |
| 约束发现诊断 | mind-the-gap | 用编辑诱导约束图 ICG 量化模型能否自发发现隐含约束，区分发现失败与验证失败，并做字段分解消融 | 定位到 Direct→Oracle recall 缺口来自发现失败而非验证失败；代价是纯 API 诊断，不训练模型，也不直接改善最终图像生成质量 |

真正的转折点有两个。第一是 CoCo 与 Meta-CoT 把推理从自由文本转向可执行、可奖励、可分解的中间表示：前者用代码执行得到确定性草稿，后者用 CEC Reward 直接约束“说到的”与“改到的”一致，这比 ReasonEdit 的文本 Thinking 更接近执行层。第二是 mind-the-gap 把瓶颈从“验证失败”前移到“发现失败”：Direct 与 Oracle 的 recall 差约 +0.476，说明模型不是不会按约束编辑，而是很多隐式约束根本没被激活；但下游规划实验也显示，只提高 recall 而不控制 precision，编辑计划不会自动变好。

##### 已经稳定下来的做法

- **先推理、后编辑/精修，而不是一步生成** —— 当指令抽象、包含未明说约束或需要保持物理/结构一致性时，ChronoEdit、ReasonEdit、UniReason、CoCo、Meta-CoT 都采用类似两段式流程。
- **在训练数据中显式加入 CoT、反思或约束字段** —— 当底模冻结 MLLM 无法自发推理时，用 ReasonEdit 的 Thinking Pairs/Reflection Triples、UniREditBench 的 100K CoT 数据、UniReason 的知识推理数据或 Meta-CoT 的三元组标注做监督。
- **用 VLM 作为自动评委或 reward 信号** —— 缺人工评测时，UniREditBench 用 GPT-4.1 打分，Meta-CoT 用 Qwen2.5-VL 的 CEC Reward，UniReason 用 Gemini 过滤数据；多篇均依赖此机制，但需注意与最终评估同源风险。
- **多阶段冻结/解冻训练，避免早期联合优化冲突** —— ReasonEdit 先训 MLLM LoRA、再训 DiT、最后联合微调；UniReason 先训生成分支再全参联合；Meta-CoT 先 SFT 后 Flow-GRPO 且 RL 只更新生成专家。
- **生成后反射或草稿引导精修** —— 单次生成不够可靠时，ReasonEdit 用多轮单图反思，UniReason 用编辑式视觉修正，CoCo 用草稿图精修，ChronoEdit 在丢掉中间帧后只精修输出末帧。

##### 还没解决的

- **文本编辑仍易退化** —— Meta-CoT 明确文本编辑是例外，CoCo 在 LongText-Bench 英文 0.755 仍落后 GPT-4o 的 0.956，ReasonEdit 处理“改成一个苹果”会把对象删光；卡在 VAE 潜空间对字符细节的保留与定位。
- **隐式约束发现召回不足，且假阳性抵消下游收益** —— mind-the-gap 的 Direct recall 仅 0.461，NL-Self 提高 recall 后 plan satisfaction 无改善；卡在模型知道约束但不会在任务提示下自发激活，或生成过多不相关约束。
- **推理延迟与算力不可忽略** —— ReasonEdit 4 轮反思约 200 秒，ChronoEdit 标准 14B 约 30.4 秒，CoCo 额外增加代码生成与沙盒执行；卡在端到端实时编辑需要同时压缩 MLLM 前向与扩散采样成本。
- **VLM 评委/奖励的可靠性仍不够** —— ReasonEdit 的 VIEScore 训练标签与最终评估部分同源，Meta-CoT 的 CEC Reward 依赖 VLM 校准到 r≥0.8，UniREditBench 可靠性证据只来自小规模人类实验；卡在缺乏像素级或物理仿真闭环，自动打分不能等同于真值。
- **隐式世界知识与物理推理仍不达标** —— ReasonEdit 处理“干冰倒水”没有生成升华雾，UniReason 在 KrisBench 上与 GPT-4o 差约 12 个点，ChronoEdit 没有真实物理引擎验证；卡在模型常识深度与生成器能力上限，仅靠推理数据难以补足。

### 13. 编辑数据工程：三元组从哪来

`6 篇 · 2025-07 ~ 2026-06 · GPT-Image-Edit-1.5M、NoHumansRequired、X2Edit…`

##### 这条线在解决什么
指令式图像编辑训练需要 `{指令, 源图, 编辑图}` 三元组，但高质量三元组必须同时满足像素级对齐、身份保持和指令遵循。生成模型的数据线可以直接采样，编辑数据线却要在规模化产出时避免源图结构被破坏，同时还要筛掉自动生成中的伪正确结果。这条线独有的技术矛盾是：成对编辑监督稀缺且人工标注不可扩展，而自动生成或蒸馏出的编辑目标又天然带有分布偏置、教师模型上限和验证不可靠的问题。

##### 怎么演进的

| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| 闭源模型精炼既有数据集 | GPT-Image-Edit-1.5M | 用 gpt-image-1 API 重生成 OmniEdit、HQ-Edit、UltraEdit 的输出图，GPT-4o 重写部分指令，再生成输入图；用冻结 Qwen-VL-7b/T5/CLIP 编码器做条件嵌入 | 数据质量与身份保持提升，GEdit-EN 达到 7.24；但成本不透明，继承源数据限制，OmniContext 上不如基础模型 |
| 全自动合成与验证栈 | NoHumansRequired、X2Edit | NoHumansRequired 用 FLUX.1-schnell 生成图像、内部 DiT 编辑器生成编辑，再以微调 Gemini 验证器做 4.7 阈值筛选，公开阶段生存率；X2Edit 用 VLM 生成指令，按 14 类任务构造数据，并用 VLM/美学/CLIP 过滤 | 实现无人工审查的百万级产出，数据可复现且成本可估算；但全合成分布偏置、类别倾斜，VLM 筛评可能引入同源偏差 |
| 细粒度任务分类与真实图源 | OpenGPT-4o-Image、Pico-Banana-400K | OpenGPT-4o-Image 先定义 51 个子任务再按类生成约 80k 指令—图像对；Pico-Banana-400K 在 OpenImages 真实照片上分 35 类编辑，Gemini-2.5-Pro 按指令遵循 40%/无缝度 25%/保留平衡 20%/技术质量 15% 评分，失败样本保留为偏好数据 | 数据从“高质量但难导航”变成可诊断、可归因，并支持偏好/多轮训练；但总量较小，Pico-Banana 未做下游训练验证，质量上限仍受闭源生成器限制 |
| 放弃三元组的方向先验 | bootstrap-generator | ByG 不用成对编辑图，仅用源图、源/目标描述和正反指令；用 EMA rollout 生成伪噪声目标，方向先验损失对齐冻结 T2I 速度差，配循环一致性训练 FLUX.1-dev/Wan2.2 | 训练数据门槛大幅降低，视频用户研究偏好达到 75.3%；但物体移除、文字编辑明显弱于监督基线，梯度路由与伪目标质量对工程要求高 |

这条线真正的转折点在 NoHumansRequired 的全自动验证栈：它把数据生产从“精炼已有数据库”转成“记录各阶段生存率的模块化流水线”。此后 X2Edit、OpenGPT-4o-Image、Pico-Banana-400K 都默认先分任务类、再做自动评分筛选；到 bootstrap-generator 则进一步丢弃编辑后图像这个三元组成员，说明该线后期开始绕过成对监督本身。

##### 已经稳定下来的做法
- **用闭源强模型生成或重生成编辑目标图** —— 当优先保证像素级编辑目标质量、且可接受 API 成本和速率限制时，调用 gpt-image-1、Nano-Banana 或内部 DiT 生成。
- **用 VLM 或微调过的多模态评判器做自动质量门控** —— 当样本量超过人工筛查能力时，对指令遵循、美学、无缝度等维度打分，设阈值过滤低质量样本。
- **先定义编辑任务分类/子任务，再按类生成样本与指令** —— 防止数据偏向简单编辑，使下游失败可归因到具体类别，而不是随机撒指令。
- **对训练指令和部署指令分开设计，或至少做指令重写** —— 长指令用于明确监督，短指令/自然俚语用于缩小与真实用户分布的 gap。

##### 还没解决的
- **闭源教师模型锁死上限** —— 用 gpt-image-1、Nano-Banana 生成的目标图，使下游模型最好只能逼近生成器能力；GPT-Image-Edit 仍低于 GPT-4o，OpenGPT-4o-Image 明确存在“蒸馏上限”，Pico-Banana 不能超过 Nano-Banana。
- **合成/伪真实分布与真实用户照片不一致** —— NoHumansRequired 全合成、X2Edit 合成任务存在风格偏差，Pico-Banana 的编辑仍是“伪真实”，其困难类型成功样本本身稀缺且偏向简单变体。
- **自动评判器无法可靠识别语义错误与文本/字形正确性** —— X2Edit 存在同源筛评风险，OpenGPT-4o-Image 指出高美学质量不等于语义正确，后置过滤效果有限；Pico-Banana 没有人类评估验证 Gemini 评分与用户偏好相关性。
- **困难编辑类别仍系统性偏弱且数据不足** —— 文本替换在 GPT-Image-Edit 仅 5.45，文本渲染/精细空间在 Pico-Banana 成功率约 0.58–0.66，ByG 物体移除仅 1.91，卡在缺乏显式定位或字符串监督。
- **数据量/质量对下游模型提升的收益尚未被证明或可能饱和** —— NoHumansRequired 基准提升仅 +0.03 且置信区间重叠，Pico-Banana 无训练实验，OpenGPT-4o-Image 数据缩放 30k→40k 已有回退，GPT-Image-Edit 的“开源最高”声明也存在表格不一致。

### 14. 2025H2–2026 的编辑与统一模型

`17 篇 · 2025-08 ~ 2026-06 · VAREdit、Seedream4、HunyuanImage3…`

##### 这条线在解决什么

这条线把图像编辑从专用扩散模型拉进统一多模态模型，但统一模型里理解、生成、编辑对视觉表示的需求互相冲突：理解要语义抽象，生成要像素/潜空间重建，编辑要未编辑区域像素级保持。已有的专用编辑模型可以把源图潜变量直接拼接作为条件，统一模型却要让源图、参考图、文本、目标图共享同一序列或同一参数流，导致条件泄漏和表示冲突在编辑任务上被放大；这条线的技术矛盾就是如何在一个统一框架里给编辑保留局部一致性，同时不被理解和生成的表示需求拖垮。

##### 怎么演进的

| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| 编辑进入自回归/统一骨干 | VAREdit、Seedream 4.0、HunyuanImage 3.0 | VAREdit 用 Scale-Aligned Reference 把最细尺度源特征下采样后只在第一层自注意力注入；Seedream 4.0 把 T2I/编辑/多图放进同一个 DiT，用高压缩 VAE 和 VLM 提示工程；HunyuanImage 3.0 用双编码器（VAE+ViT）和 Generalized Causal Attention 混合文本自回归与图像扩散 | 换来编辑进入统一模型，速度与多任务效率提升；代价是条件尺度对齐仍不完整，编辑一致性尚未系统解决，数据与硬件细节未披露 |
| 交错序列与离散扩散统一 | EditVerse、Emu3.5、Lumina-DiMOO | EditVerse 把文本/图像/视频 token 交错拼接，用 4D RoPE 和全自注意力做上下文学习；Emu3.5 用视频关键帧+ASR 的 13T token 预训练，再 DiDA 把图像解码从逐 token 改为并行离散扩散；Lumina-DiMOO 用完全离散扩散统一文本和图像，MaskGIT 式四步循环采样 | 换来图像知识向视频编辑迁移、采样加速、纯离散路线可行；代价是长序列全注意力延迟极高（EditVerse 110,822 token 50 步约 349 秒），编辑质量仍未超专用模型，视频一致性未系统评估 |
| 编辑专用连接与连续控制 | InstructX、DreamOmni2、Kontinuous-Kontext、Z-Image | InstructX 用 LoRA 微调 QWen2.5-VL-3B 并通过 learnable queries+MLP 连接 Wan2.1-14B DiT；DreamOmni2 给多参考图加索引编码和位置编码偏移，并用 VLM 重写指令；Kontinuous-Kontext 用 4 层 MLP 把标量强度投影到 Flux Kontext 的 modulation space；Z-Image 用 6B 单流 DiT + 3D U-RoPE 统一多任务，再 Decoupled DMD 蒸馏到 8 步 | 换来编辑语义在 MLLM 内形成、多图参考、连续强度滑块和 6B 高效模型；代价是与 GPT-4o 等闭源仍有差距，精确几何编辑弱，复现所需数据/超参缺失 |
| 一致性与表示解耦攻坚 | Qwen-Image-Layered、FireRed-Image-Edit、ChordEdit、InternVL-U、Qwen-Image-2.0、SenseNova-U1、ARM | Qwen-Image-Layered 输出多层 RGBA 并用 Layer3D RoPE 区分层；FireRed-Image-Edit 用一致性损失（σ<0.9）+DPO 非对称梯度+DiffusionNFT；ChordEdit 用 Chord Control Field 把朴素向量差替换为时间平滑低能量场；InternVL-U 解耦 ViT 理解特征与 VAE 潜变量，并引入 CoT；Qwen-Image-2.0 用 16× VAE + Qwen3-VL + GRPO + DMD 4步；SenseNova-U1 去掉 VE/VAE 直接像素+文字用 MoT 双流；ARM 用语义视觉 tokenizer + 7B 自回归 + GRPO | 换来编辑一致性、4B/7B 统一模型接近或超过更大基线、单步编辑实时；代价是编辑仍低于专用系统，长视频/高分辨率、抽象属性、训练复现仍是未解决 |

转折点不在“统一序列万能”被证明有效，而在后续工作不再把编辑一致性完全寄托于统一目标或合成数据。Qwen-Image-Layered 把问题从模型能力转到输出表示，用多层 RGBA 显式隔离编辑区域；InternVL-U 明确说理解与生成不应共享同一套视觉表示。这一转折发生的原因是：统一序列可以迁移能力，但在未编辑区域保持上仍会出现条件泄漏和像素漂移，只能靠表示层级的解耦或分层来补救。

##### 已经稳定下来的做法

- **源图潜变量/最细尺度特征注入** —— 当编辑需要保持未编辑区域和源图结构时，VAE 潜变量或最细尺度源特征被作为显式条件注入，而不是只依赖文本指令。
- **解耦理解与生成的视觉表示** —— 统一模型里，理解侧用 ViT/MLLM 特征，生成/编辑侧用 VAE 潜变量，避免语义抽象和像素重建互相干扰。
- **编辑对和生成数据都用 VLM/奖励模型过滤** —— 真实编辑数据稀缺，因此用专家模型/T2I 合成候选，再用 VLM 或 LPIPS/KL/美学模型过滤后才进入训练。
- **后训练用 DPO/GRPO/RLHF 对齐编辑指令跟随和一致性** —— 基础生成模型预训练之后，用偏好优化或强化学习显式加一致性奖励、文本编辑奖励等。
- **少步蒸馏或离散扩散降低 NFE** —— 当面向在线或实时编辑/生成时，模型被蒸馏到 4~8 步，或用离散扩散并行采样；编辑侧也有 1~2 NFE 方法。

##### 还没解决的

- **编辑一致性仍没有统一保证** —— Qwen-Image-Layered 推理层数未定，用户需手动合并/拆分图层；FireRed-Image-Edit 一致性损失只覆盖 σ<0.9 且多主体漏检；InstructX 复杂视频编辑中段崩溃。
- **统一模型的理解与生成/编辑上限尚未同时达到专用模型** —— ARM 理解 MMMU 40.2 低于 Bagel 55.3，生成 GenEval 0.86 低于 Qwen-Image 0.87；InternVL-U 在 GenExam、RISEBench 等知识密集型任务上与商业模型差距大。
- **长视频/高分辨率编辑的推理成本过高** —— EditVerse 110,822 token 50 步推理约 349 秒，全注意力未优化；InstructX 将 >1080P 列为局限；VAREdit 1024×1024 风险未验证。
- **训练数据规模、模型参数、GPU 成本和消融大量未披露** —— Seedream 4.0、Z-Image、FireRed-Image-Edit、Qwen-Image-2.0 未给出关键超参或组件消融，复现困难。
- **抽象属性和精确几何编辑仍不可靠** —— Kontinuous-Kontext 继承 Flux Kontext 几何弱点，s>1 外推失败；DreamOmni2 抽象属性人工成功率约 0.6829；Z-Image 物体计数 0.78 落后。

### 15. 新一代评测：物理合理性与多轮

`8 篇 · 2025-09 ~ 2026-07 · EdiVal-Agent、PICABench、reasoning-to-pixels…`

##### 这条线在解决什么
这条线面对的核心矛盾是：图像编辑模型在单次语义任务上已能产出“看起来对”的结果，但多轮编辑、物理合理性、跨任务一致性、光传输等深层要求下，生成器与评估器会同时失效——生成器累积退化或画错物理，而传统相似度指标和整图 VLM 裁判要么漏检，要么给出反向判断。要可靠评价这些新一代能力，不能再把编辑质量归约到单次 output-reference 相似度或整体审美分数，必须引入对象中心、物理真值、场景图事实、多轮复制等结构化锚点，把“真伪”与“好不好”分开测量。

##### 怎么演进的
| 阶段 | 代表工作 | 关键动作 | 换来了什么 / 代价是什么 |
|---|---|---|---|
| 对象中心多轮评估初步建立 | EdiVal-Agent | 用 Grounding-DINO 做符号验证 + Qwen2-VL 做裁剪框内语义判断，自动生成 3 轮编辑链 | 换来了比纯 VLM/CLIP 高的人类一致率 81.3%；代价是检测器假阳性成为主要失败源，换 OWL-ViT 后一致率跌到 53.67% |
| 物理真值与区域问答引入 | PICABench, lighting-edit-bench | 把“物理合理性”拆成光学/力学/状态转换，或构造开/关灯 HDR 对，让 VLM 在 ROI 内答二值问题、计算仿射不变的 SIE/LFE | 换来了物理错误的可诊断性；代价是数据集依赖合成管道或室内单灯，覆盖范围窄，PICA-100K 继承上游视频生成错误 |
| 跨模态与跨任务一致性诊断 | reasoning-to-pixels, beyond-accuracy | 用三种生成设置（直接/推理/去上下文化）和同一场景图事实网格，比较同一语义在文本推理、生成像素、理解答案之间的差异 | 换来了可计算的 Δ2→3 和 AW-CCTA 缺口；代价是依赖 LLM 生成/解析场景图，teacher 噪声压低上限，且只诊断不提供训练干预 |
| 多轮退化与奖励模型/系统体检 | banana100, edit-compass, IIE-Survey | 用 100 轮精确复制制造持续退化，用 RL 风格偏好对评测奖励模型，用 21 个任务人工评分体检指令编辑全貌 | 换来了生成器/评估器双失效的系统证据和细粒度排名；代价是成本高（$4000+，12 名专家），API 黑盒导致归因困难，开源模型深层推理差距仍未缩小 |

真正转折发生在“评估器本身也被证明不可信”之后：EdiVal-Agent 换 OWL-ViT 后人类一致率跌到 53.67%，banana100 里 21 个传统 NR-IQA 全部给后轮退化图更好或同等分数。这迫使后续工作不再追求更强的整图 VLM 裁判，而是引入局部检测、HDR 真值、场景图等外部锚点，把评估从“整体打分”转向“可验证的局部事实核对”。

##### 已经稳定下来的做法
- **局部接地评估** —— 在检测框、ROI 或场景图事实内让 VLM 只做原子二值判断，用于减少整图开放式打分带来的幻觉与像素感知弱。
- **混合符号与语义验证** —— 对可规则化的对象、光传输、场景图事实先用检测器或物理指标计算，剩下的语义细节再让 VLM 在受限区域内确认。
- **受控成对或复制设置** —— 用开/关灯 HDR 对、100 轮精确复制、直接/推理/去上下文化三种设置，把目标变量从内容变化和风格偏好中隔离出来。
- **人类一致性或人类 Elo 相关校验** —— 评测协议发布前先与人类判断或专家评分对齐（EdiVal 81.3%、PICAEval r=0.95、UReason 0.924），不一致就换 judge 或调整提示。
- **多模型/多 judge 稳定性测试** —— 换检测器、换 VLM、换奖励模型、换闭源模型复现排序，防止单一裁判导致错误结论。

##### 还没解决的
- **VLM 与 NR-IQA 作为评估器仍不可靠** —— VLM 会把生成伪影判为更真实，传统 NR-IQA 在迭代退化中给反向分数，像素级物理判断仍缺稳定自动 judge。
- **多轮编辑持续退化未解决** —— 生成器在 5–10 轮出现不可逆噪声累积和指令跟随失败，Qwen-Image-Edit 多轮暴露偏差从 78.36 跌到 41.93，无抑制方案。
- **空间/世界知识/深层推理普遍短板** —— 开源模型在空间理解平均 2.92，算法视觉推理和世界知识任务接近地板，开源最佳总体分仅 2.69。
- **数据与真值覆盖面受限** —— 3DLP 仅覆盖室内单灯，PICABench 合成数据继承上游模型错误，banana100 无 MOS 且初始图为 AI 生成，UReason 依赖 LLM 版本，不能直接迁移到真实用户请求。
- **只诊断未治疗** —— UReason 未给出缩小 Δ2→3 的训练方案，banana100 未解释退化归因，XTC-Bench 未验证哪类训练约束能提高一致性，edit-compass 未证明基准分数能带来 FlowGRPO 端到端编辑收益。

## 4. 全领域还没解决的

| 问题 | 具体表现（点名论文和现象） | 为什么难 |
|---|---|---|
| 多轮编辑累积退化与长期一致性无法保证 | MagicBrush 显示多轮误差累积；implicit-preservation 的 OCCUR-Bench 遮挡恢复绝对一致性低；FLUX-Kontext 六轮后身份漂移和 artifacts；InstructX 复杂视频编辑中段崩溃；banana100 100轮复制后持续退化，Qwen-Image-Edit 多轮暴露偏差从 78.36 跌到 41.93 | 每轮编辑条件泄漏、误差累积，缺少自动权衡机制；模型难以跨轮追踪未编辑区域与身份 |
| 高频细节、文字渲染与身份保持受 VAE/潜空间限制 | NTI/EDICT/DirectEdit 指出重建无法超过 VAE 上界；SD3 16 通道 VAE 重建 FID 1.06；tuna-2 像素空间 rFID 差 FLUX VAE 一个量级；Chameleon tokenizer 重建上限；Janus-Pro 384×384 限制 OCR；Meta-CoT 文本编辑退化，CoCo LongText-Bench 落后 GPT-4o | 潜空间编码丢失稠密高频信息，离散/连续表示都难以精确绑定字符和身份；底层 token 容量限制 |
| 空间推理、计数、组合关系与精确几何编辑弱 | 脉络1空间移动/计数失败，Prompt-to-Prompt 无法两点换位；Imagen Editor、AnyDoor 细粒度计数/形状弱；DreamO 复杂空间关系低；FLUX-Kontext 把“移动咖啡”执行成加奶泡，HiDream GenEval Position 仅 0.60；GoT position 0.34、attribute binding 0.27；Z-Image 物体计数 0.78 | 文本-图像扩散难绑定位置/数量，缺乏显式空间或计数监督；单图 3D 理解不足，底模能力上限 |
| 自动指标/奖励模型/评估器与人类偏好错位，且可被 hack | HQ-Edit 方向相似度与人类偏好负相关；ICEdit 发现 CLIP 判据反而降低 GPT 分；PhotoMaker CLIP-T 与用户研究相反；T2I-R1 单一 VQA 奖励被 hack；DanceGRPO 只用 HPS 产出油腻图像；banana100 传统 NR-IQA 给后轮退化图更好分数；EdiVal-Agent 换 OWL-ViT 后一致率 53.67% | 全局标量无法表达细粒度跨图比较与像素级身份保持；奖励/评估模型自身盲区与策略同源，区域级信用分配缺失 |
| 训练/推理成本与保真度/延迟冲突，效率口径不统一 | Null-text Inversion 单图 40–120 秒；Imagic 每图 7–8 分钟；DragDiffusion 36–57 秒；EasyControl 1024×1024 25 步 16.3 秒；EditVerse 110,822 token 50 步约 349 秒；ThinkRL-Edit 编辑时间几乎翻倍；decompose-subject 两阶段 2 倍延迟 | 高保真需要多步/大模型，实时/端侧需要少步/小模型；VAE 和大 MLLM 延迟无法简单压缩，统一硬件口径缺失 |
| 合成数据/伪标签偏差与闭源教师模型锁死上限 | InstructPix2Pix 合成域偏差真实图泛化有限；GEdit-EN 仍低于 GPT-4o；OpenGPT-4o-Image 明确蒸馏上限；Pico-Banana 不能超过 Nano-Banana；NoHumansRequired 全合成分布风格偏差；MimicBrush 外 ID DINO-I 低于有参考掩码的 AnyDoor | 高质量成对编辑监督依赖闭源模型，自动生成有分布偏置，验证不可靠；下游最好只能逼近教师，难以超越 |

这六条里，**空间推理**和**评估错位**是被最多脉络同时点名的两条。前者决定编辑能不能可靠执行，后者决定你有没有办法知道它可靠——一个模型在自动指标上变好，可能只是学会了少改一点。

## 5. 覆盖度自查与可信度边界

### 5.1 收了多少，漏了多少

分母是 arXiv 上 `abs:"image editing" AND cat:cs.CV` 的命中数（2026-08-28 实查，
2026 只统计到 8 月）。分母包含大量边缘论文，所以比例不代表「漏了九成」，只用来做**年份间的横向对比**。

| 年份 | 库里收了 | arXiv 命中 | 收录比例 |
| --- | --- | --- | --- |
| 2022 | 14 | 96 | 15% |
| 2023 | 27 | 228 | 12% |
| 2024 | 28 | 289 | 10% |
| 2025 | 51 | 428 | 12% |
| 2026 | 38 | 392 | 10% |

另有 2021 年 2 篇（SDEdit、Latent-Diffusion），因为后面几乎所有工作都建立在它们上面。

2026 这一年的收录方式和别的年份不一样，得单独说清楚。

建库时 `export.arxiv.org` 的 API 在本机不可达（curl 返回 000），只能靠已知论文名逐个抓，
严重偏向已经出名的工作——2026 当时只收进 5 篇，占比 1%。
2026-08-28 复查发现该 API 已恢复，于是把 2026 整年重跑了一遍：

```
15 条检索式 × 分页 ──► 1123 篇去重      submittedDate 2026-01-01 ~ 2026-09-01
        │  关键词预筛：正列表加权（标题命中权重 3），负列表剔除
        │  （video editing / 3D / 医疗 / 遥感 / 人脸识别 / knowledge editing / 水印 / 攻击 …）
        ▼
      410 篇 ──► DeepSeek 逐篇对着 15 条脉络打 1~5 分 ──► 111 篇拿到 ≥4 分
        │  111 个 arXiv ID 全部实抓 arxiv.org/abs 比对 citation_title + citation_date：111/111 命中
        ▼
      111 篇 ──► 同一模型横向比选（脉络均衡、同题只留最强）──► 33 篇入库
```

命中率从 1% 回到 10%，和其他年份齐平了。但比覆盖率更该注意的是下面这四条：

| 问题 | 说明 |
| --- | --- |
| 2026 没有引用量可以参考 | 最早的一篇也才 8 个月。Semantic Scholar 上 407/410 有记录但数值普遍是个位数，HF upvotes 只有 208/410 有。这两个信号只在**筛选阶段**用过、权重很低，没有写进任何一篇解读（prompt.md 禁止论文外信息） |
| 筛选是模型判断，不是人工判断 | 410→111→33 两道都是 DeepSeek 打的分，我只定标准和脉络配额。会漏掉"摘要写得平淡但实际重要"的工作 |
| 两条脉络 2026 收 0 篇 | 拖拽与点控编辑、以及不带奖励模型的那类 RL 编辑，1123 篇里没有够 4 分的。可能真的沉寂了，也可能是我的检索式没覆盖到——**未验证** |
| 33 这个数是配额定的 | 见第 1 节密度表下面那段。不是"2026 只有 33 篇值得读" |

### 5.2 这份总结是怎么产生的

```
160 篇 PDF ──pypdf 抽文本──► DeepSeek v4 Pro 按 prompt.md 逐篇写解读（160 次调用）
                                          │
              每篇取 §1 定位 + §10 工程判断 + §11 脉络位置
                                          ▼
                        按 15 条脉络分组 ──► 脉络级综述（15 次调用）
                                          ▼
                                  横向归纳（1 次调用）──► 本文第 0/1/2/4 节
```

脉络的划分是我人工定的，不是聚类出来的；分到哪条线带主观判断，有些论文本可以跨线。

### 5.3 已知会出错的地方

| 局限 | 说明 |
| --- | --- |
| 2026 靠模型筛选 | 见 5.1 的四条。2026 的 38 篇里 33 篇是模型从 1123 篇里选的，人工只定了标准 |
| 图表信息全部丢失 | 只有 PDF 抽出的文字进了模型，示意图、定性对比图读不到 |
| 公式细节会失真 | pypdf 常丢下标、希腊字母、矩阵记号，§5 的公式以原 PDF 为准 |
| 枝节描述可能出错 | 已发现一例：Imagic 那篇把 Imagen/SD 说成「ImageNet 预训练模型基础」，不准确 |
| 数字溯源有 5.3% 未命中 | 9214 个数字里 485 个没在原文抽取文本里直接匹配。逐篇看未命中率，只有 2 篇超过 25%（Kontinuous-Kontext 28.2%、Bootstrap-Your-Generator 27.5%），两篇都手工核过，**全部是检查脚本的误报**：pypdf 把表格单元格粘成 `6.696.932.17`（真值 6.69 / 6.93 / 2.17）、把 `110K` 写成一个 token，所以正则匹配不上。累计手工抽查 8 篇，无一例真错。但**没有全量核完** |
| 没有交叉复核 | 每篇只生成一次，本文的归纳也只跑了一遍，没有第二个模型独立验证 |
| 不含论文外信息 | 按 prompt.md 的规定不写引用量、社区评价、后续产品。选题时参考过影响力，但那部分判断没写进任何一篇 |

**可以放心的**：160 个 arXiv ID 全部实抓 `arxiv.org/abs` 比对过 citation_title 和 citation_date，
没有编造的论文。160 篇解读结构完整（11 节齐全）、PDF 全部可解析、篇幅全部 ≥6500 中文字。
prompt.md 要求 6500–8500，有 4 篇轻微超上限（MGIE 8830、FLUX-Kontext 8553、Kontinuous-Kontext 8551、MimicBrush 8536），没有截。
